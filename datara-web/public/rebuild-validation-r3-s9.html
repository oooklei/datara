引导首屏 · 未检测到短期验证 token

本页为隔离验证页，仅使用短期 token 调用受保护的新 Backend API。当前浏览器上下文未注入 window.__DATARA_TEST_TOKEN__，主操作面板保持锁定。本页不提供登录表单，也不接收验证 key、账号口令或 token 输入。

token 取得路径（二选一，注入后刷新本页生效）

  1. 自动路径（标准，推荐） — 受控验证运行器从部署环境读取统一验证 key，调用 POST /api/v1/rebuild/validation-token（请求头 X-Backend-Validation-Key）换取短期 token（validation-runner / DEV 角色），随后由运行器把 token 注入本页运行上下文并刷新页面。验证 key 不进入页面、源码、URL 或浏览器存储。
  2. ADMIN 签发路径（仅用于要求持久 admin 身份的操作，例如本页 I18 导入闸） — 由 ADMIN 角色账号调用 POST /api/v1/rebuild/login（请求体 {"username":"<账号>","password":"<口令>"}）签发 token，再由受控上下文注入本页。请在可信环境执行；账号口令不得出现在页面、URL、日志或证据材料中。

委托执行入口

无需本机手工操作时，可将本轮验证委托给验证 runner：由其完成 token 签发与注入后自动驱动本页真实控件，并产出 JSON+PNG 成对证据。委托内容（页面地址、目标操作、预期范围）提交给验证运行环境即可；执行记录与结果可回溯至 docs/increments/（约法与台账、增量计划）与 docs/increments/evidence/（逐轮证据索引）。

提示：token 为短期凭据，注入方式由验证运行环境决定；刷新后如已过期需重新签发。
