# Datara 数据治理工具 · 版本规划与工作量评估方案（修订版）

> 依据：系统功能讲解稿（2026-09-15 最新版）、`数据治理工具功能清单列表.xlsx`（V3.1）、`数据治理平台支撑工具需求沟通汇总表.xlsx`（P0 蓝本）、`数据平台建设模块问题与优先级汇总表-答复.xlsx`（王吉优先级答复）。
> 口径调整说明：本版采用**保守/实际人天**（较上版上调约 30–45%）。人天 = 单人 8 小时，**已含**需求确认与原型评审、跨引擎联调（多数据库/多数仓/实时链路）、测试与缺陷修复、部署环境搭建、文档与演示准备；**不含**专职安全合规评审与外部信创验收（V3 单列）。
> 修订点：①V1 新增流处理、元数据血缘全量；②工作量全面上调。

## 一、功能依赖关系分析

### 1.1 依赖分层（自底向上，下层为上层前置）

```
 L0 横切底座   图编排引擎（可视化/画布/血缘/拓扑，横切所有可视化）   参数配置体系（服务全部任务）
 L0 接入地基   数据源管理（数据源注册→连接池→探索→资产清单）
 ─────────────────────────────────────────────
 L1 开发生产   数据开发 IDE（查数）  数仓建模（建表/分层）  脚本任务（Shell/Python）
 ─────────────────────────────────────────────
 L2 数据加工   批处理（ETL/SQL/批量同步）   流处理（Kafka/Flink，V1 纳入）
                ↑ 由 DAG 工作流引擎调度编排（依赖、重试、告警、SLA）
 ─────────────────────────────────────────────
 L3 治理沉淀   元数据血缘全量（采集/目录/血缘/影响/资产地图/标签，V1 纳入）   数据质量
               数据标准 + 指标体系（依赖元数据、表与任务）
 ─────────────────────────────────────────────
 L4 安全/运维/共享   数据安全（权限/脱敏/审计）   运维监控   远程节点   数据共享
 L5 应用出口   工作台 / 指标看板 / 资产地图 / 数据共享 API
```

### 1.2 关键依赖链

1. **数据源是唯一地基**：IDE 查数、批量同步、ETL、流处理、质量检查、元数据采集全部依赖已注册数据源 → 数据源管理必须最先落地，且支撑类型需收敛（王吉答复：最优保障万里/高斯/达梦/MySQL/Oracle + 数仓 + 实时架构）。
2. **表结构先于加工**：数仓建模产出表 → 物理化建表 → 批量同步与 ETL 才有目标表 → 质量规则才能绑定表、元数据才能采集。
3. **任务先于调度**：ETL/SQL/脚本/流任务 → 才能编排进 DAG 工作流 → DAG 是任务价值放大器。
4. **参数服务于任务**：全局/时间/工作流变量被 SQL、脚本、DAG 引用。
5. **血缘/质量/指标后置沉淀**：血缘依赖同步与 ETL/流已运行产生真实血缘；指标依赖表与任务定义就绪。
6. **安全/运维/共享/远程为增强层**：不阻塞主流程（沟通结论：均为非 P0）。

### 1.3 沟通结论对范围的约束（依据）

| 约束项 | 沟通结论 | 对版本的影响 |
|---|---|---|
| 支撑类型收敛 | 万里/高斯/达梦/MySQL/Oracle + 数仓 + 实时架构 | 数据源/IDE/同步按收敛类型开发，不做全类型 |
| 数据安全 | P1，脱敏/加密暂缓，支持列级权限 | 移出 P0，放入最全版 |
| 运维监控 | P1，告警优先邮件/短信 | 移出 P0 |
| 远程节点 | P2，优先 SSH，Agent 排后 | 移出 P0 |
| 数据共享 | 建议暂不做（韦鑫已有 API 工具） | 移出 P0，仅最全版按需 |
| 明确暂缓项 | 凭证 KMS、可视化 ER 图、UDF、CEP、执行计划分析、Java 在线编译 | 不进入普通版 |

## 二、三个版本方案

### V1 · 最小可运行（离线 + 实时 + 血缘 全流程版）

**定位**：跑通"数据接入 → 查数 → 建表 → 离线加工 + 实时加工 → 调度 → 血缘追溯 → 质量 → 看板"的**离线/实时双链路 + 血缘可追溯**端到端闭环，可用于演示、试运行与首版交付。相比原"纯离线最小版"，本版同步纳入流处理与血缘全量，使首版即具备实时与血缘能力，演示价值与数据可信度更高。

**功能范围**：
- 数据源管理（注册/连接池/探索/标签/诊断）
- 数据开发 IDE（编辑器/多源/预览/导出/历史）
- 数仓建模（字段设计/物理化建表/分层/逆向/模型血缘）
- 批处理：批量同步（选表向导/自动建表/自动分区/类型映射/数据量核对/进度看板）+ ETL/SQL/脚本任务
- **流数据处理**（新增：Kafka CDC / SQL 流计算 / 窗口 / 水位线 / 状态 / Checkpoint / 实时预览）
- **元数据血缘全量**（新增：采集/目录/表级+字段级血缘/影响分析/资产地图/标签）
- DAG 工作流（可视化编排/任务依赖/失败重试/告警）
- 参数配置（全局/内置时间/工作流变量/引用检测）
- 数据质量（规则/检查任务/评分卡/报告/异常查看下载）
- 图编排引擎（基础底座 + 血缘画布）
- 工作台（统计/入口/资产地图）

**明确不含**：数据标准与指标全量、数据安全、运维监控、远程节点、数据共享、一键部署。

### V2 · 普通版本（中间需求正常版）

**定位**：**对应王吉 P0 全部承诺（12 模块 / 121 项功能）**，覆盖实施路线图 1–5 阶段可交付内容，是"满足合同/承诺"的标准版本。（流处理与血缘已在 V1 纳入，V2 聚焦 P0 其余全量。）

**在 V1 基础上新增**：
- 数据标准全量（数据元/代码/命名/映射合规/审批）
- 指标体系全量（目录/分层/定义/表-任务关联/血缘追溯/核查/版本/审批/看板/一致性）
- DAG 增强（跨工作流依赖/SQL 结果表解析/表级依赖/周期 T-T-N/依赖校验/SLA）
- 脚本增强 + 远程 SSH 执行（环境依赖/参数传递/执行日志/SSH 节点管理）
- 一键快速部署（Doris/Kafka/Flink/Redis 等指定组件 + 套件 + 前置/健康检查）
- 工作台/资产地图/指标看板整合

**明确不含**：数据安全 P1、运维监控 P1、远程节点 Agent、数据共享、信创全栈联测、高级暂缓项。

### V3 · 最全版本

**定位**：全功能、可对外商用、信创全栈适配版本。

**在 V2 基础上新增**：
- 数据安全全量（RBAC 行列权限/脱敏/加密国密 SM4/访问审计/敏感数据发现/分级分类）
- 运维监控中心全量（集群部署/中间件/性能/多渠道告警/日志/资源/容量规划/备份）
- 远程节点执行全量（SSH + Agent/远程文件管理/执行监控/自定义文件类型）
- 数据共享服务（库同步/文件导出/API 自动生成/API-Key 鉴权/限流/缓存/脱敏/Swagger/监控）
- 数据源全类型 + 凭证安全 KMS/Vault
- 高级功能（可视化 ER 图/UDF/CEP/执行计划分析/Java 在线编辑）
- 信创全栈适配与联测（麒麟 V10 / 鲲鹏 920 / 万里数据库 / 国密）

## 四、各版本功能建议与理由

### V1 建议（最小可运行，含流+血缘）
- **离线 + 实时双链路齐发**：流处理纳入 V1，避免"先离线后补实时"造成的重复架构改造，Flink 链路一次打通，演示即可覆盖实时场景（沟通要求"实时数据处理架构选型"）。
- **血缘全量随主链沉淀**：血缘依赖真实运行数据，V1 同步纳入采集与血缘，首版即可追溯"数据从哪来到哪去"，提升数据可信度，为 V2 指标血缘打底。
- **收敛数据源/引擎类型**：按王吉答复只保障万里/高斯/达梦/MySQL/Oracle + 目标数仓，避免全类型投入。
- **理由**：V1 定位升级为"可自证全链路（含实时与血缘）"的版本，虽投入升至 ≈145 人天，但换来实时与血缘能力，演示与试用价值显著提升。

### V2 建议（普通版 = P0 全量）
- **以"完整交付 P0 121 项"为验收红线**：这是与需求方约定的 P0 范围，普通版即"合同版"。
- **补齐标准与指标体系**：标准是治理规范化基础、指标是数据价值的最终出口（均 P0），二者缺一不可。
- **部署纳入一键化**：P0 含一键快速部署，用于降低现场/信创交付门槛。
- **仍不放数据安全/运维/共享**：沟通已明确其非 P0，且脱敏/加密联调成本高，避免挤占 P0 主干资源。
- **理由**：V2 是"该交付的都交付"，质量与承诺优先，与 P0 蓝本匹配，进入验收。

### V3 建议（最全版）
- **仅在商务/信创硬需求明确时启动**：V3 是增强与合规收口，多为 P1/P2/暂缓项。
- **数据安全与运维排最优先**：面向商用与等保合规，权限/审计/告警/备份是安全基线，先于共享与高级功能。
- **信创全栈适配单独立项**：麒麟 V10 / 鲲鹏 920 / 万里 / 国密需专用联测环境，与功能开发解耦，避免阻塞主线。
- **高级功能按需裁剪**：ER 图/UDF/CEP/执行计划分析等沟通已明确暂缓，仅当确有需求才做。
- **理由**：V3 价值在"可商用 + 可交付信创项目"，投入最高（≈324 人天），须以明确外部需求（招投标/合规/信创验收）为前提，避免资源浪费。

## 五、总体结论

1. **依赖主线清晰**：数据源 → 建模/IDE → 加工（离线+实时）→ DAG 调度 → 治理沉淀（血缘/质量/标准/指标）→ 应用出口，版本沿此链递进。
2. **推荐路线 V1 → V2 → V3 迭代**：V1 快出含实时与血缘的全链路闭环（≈145 人天 / 3 人约 8–9 周），V2 兑现 P0 全量（≈217 人天），V3 按需增强（≈324 人天）；每步均有可验收中间成果。
3. **范围以沟通结论为铁律**：数据安全/运维/远程/共享均移出 P0，避免超范围投入；支撑类型收敛、明确暂缓项不做，是控制工作量的关键。
4. **若复用现有 datara-web 前端原型**：前端骨架、图引擎、mock 交互已具备，V1–V2 前端工作量仍可再省约 30%（本表已按"含前端开发"计，复用后前端人天可下调）。
