# Datara 文档总入口（当前有效口径）

更新：2026-10-01

## 1. 权威顺序

发生冲突时，按以下顺序解释和实施：

1. 用户最新明确裁定与 `docs/increments/决策记录.md`；
2. 已在 192.168.1.9 形成运行证据、且已进入当前 Git 历史的实现；
3. 当前增量设计、实施计划和验证单；
4. `docs/数据处理主业务流程和规范.txt` 的业务分层主线；
5. I1～I12 历史设计与验证单；
6. 其他说明、讲解、映射和规划文档；
7. `Datara需求规格说明书_V3.0.docx` 仅作早期背景参考，不构成遵循依据。

## 2. 当前总目标

以统一 DAG 工作流为产品主干，形成“目录定义—画布引用—发布校验—执行路由—运行证据—血缘回写—监控告警”的闭环。当前优先级：

1. 组件目录与基线化工作台；
2. 血缘分析新增量；
3. 运行时节点与集群监控基础设施。

数据开发 IDE 已收口：前后端功能冻结，只允许不改变行为的展示微调。当前增量不得修改其 API、数据模型、交互流程和执行逻辑。

## 3. 演进脉络

- 早期 V3：产品范围草案，现仅供追溯。
- 新重置版本：确立五进程后端、统一 DAG、SQL 优先、变量/同步/流/SSH 组件化与 1.9 实测制度。
- I1～I10：完成平台骨架、调度执行、数据源/同步/血缘/HA/流处理/界面归拢与 IDE。
- I11～I12：形成组件分类目录、内置组件全栈、用户组件治理、基线化工作台、`componentRef`、四类 20 个用例以及真实运行证据。
- 2026-09-30～10-01：补齐基线修订和血缘三层汇总、设计态/运行态合并、字段挂靠与性能/稳定性修复。
- I13：不重造已有能力，集中清除运行基础设施中的“假成功、假监控和隐式依赖”。

## 4. 文档取舍

- **继续遵循**：决策记录、业务流程规范、I12 当前实现文档、最新 baseline/lineage specs 与 plans。
- **吸收后改进**：早期组件清单只保留组件化原则；具体数量、契约与执行路由以 `components/catalog.py` 和生成的 `common/dag_catalog.json` 为准。
- **仅作历史证据**：I1～I11 已被后续增量覆盖的实现细节、旧菜单映射、旧工作量评估。
- **不进入当前方案**：演示态随机指标、无真实服务支撑的 Prometheus/Flink/Doris/DolphinScheduler 状态、告警“记日志即发送成功”、与当前目录并行的第二套组件注册表。

历史文件保留用于审计，不再通过物理删除制造新的追溯断层；本入口负责明确其效力。
