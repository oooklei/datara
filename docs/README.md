# Datara 文档总入口（当前有效口径）

更新：2026-10-20（D5 文档权威化刷新）

## 1. 权威顺序

发生冲突时，按以下顺序解释和实施：

1. 用户最新明确裁定与 `docs/handoff/STATE.md` 裁定记录；
2. 唯一需求真源 = `docs/increments/2026-10-19-纠偏重构前端权威设计.md`（v3）；验收基线 = `docs/increments/2026-10-17-核心业务功能实现规范与验收标准.md`（v4）；开发计划 = `docs/increments/2026-10-20-单线多增量WBS开发计划.md`（WBS）；协作行为唯一权威 = `docs/agents/协作规程.md`；
3. 已在 192.168.1.9 形成运行证据、且已进入当前 Git 历史的实现；
4. 当前增量设计、实施计划和验证单（`docs/increments/` 活跃件）；
5. 验收基建：`docs/contract-freeze-registry.md`（G 组门禁 FE-13~19 逐门消费的契约冻结登记簿）、`docs/gate-acceptance-matrix.md`（逐门验收矩阵模板）；
6. 需求输入：`docs/数据开发IDE.md`（SQL IDE 需求规格，验收 v4 认可其独立核心）；
7. 其余历史说明、讲解、映射与规划文档 → 一律归档考古（`docs/archive/2026-10-20/`、`docs/increments/archive/2026-10-20/`、`docs/handoff/archive/`），只读不写、不作现行依据；`Datara需求规格说明书_V3.0.docx` 及用户手册已于 2026-10-20 裁定**作废归档**。

## 2. 当前总目标

纠偏重构：以 `2026-10-19-纠偏重构前端权威设计.md`（v3）为唯一目标，按 WBS 单线多增量模式推进（三实施线围绕同一增量序列，⛏ 包拆票后派单）。当前阶段：增量 0 预研与前置件（0.4~0.8）、15 张 WBS 生产库存预研在飞。

数据开发 IDE 已收口：前后端功能冻结，只允许不改变行为的展示微调。当前增量不得修改其 API、数据模型、交互流程和执行逻辑；新增 SQL IDE 能力以 `docs/数据开发IDE.md` 为需求输入。
