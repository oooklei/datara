一、缺口与裁决
-----------------------------------------------------
新域 POST /api/v1/rebuild/execution/workflow-instances 的 STREAM 分支
此前仅校验并落实例行，不触发任何执行（僵尸实例）。前会话用户裁决：
「STREAM 无图执行器 → 列入本轮后端修补」。

二、方案（Option B：独立 legacy 引擎复用完整 legacy 链）
-----------------------------------------------------
- rebuild 会话（datara_rebuild_i0 库）不能直接写 legacy 表（datara_meta），
  双库隔离不可跨会话混用 → rebuild-api 侧另建独立 legacy 引擎，
  env REBUILD_LEGACY_DB_URL 注入；未配置时 fail-closed 抛 5031，
  不静默产生僵尸实例。
- 复用 api/streamjob.py 完整 legacy 链零改动：extract_stream_spec
  （混编/缺源汇/入边校验）+ preflight_stream（引用数据源校验）+
  register_stream_job（t_stream_job upsert + legacy 实例/任务/日志行 +
  Redis 广播 datara:flink:ctl）。
- doc_id 命名空间："rebuild-{workflow_id}"（legacy 画布为数字 id，
  零撞号；worker 完全不读 doc_id，只消费 spec_json + jobId）。
- 观测面打通：StreamJobRecord 按 legacy_job_id 幂等注册（重跑复用），
  worker engine 主动回报四类镜像（state/checkpoints/metrics/failure）
  经 legacy_bridge 落新域 STREAM 域表。
- 实例行与桥记录同事务落库；legacy 链失败整体回滚，不残留实例行。

三、关键修复
-----------------------------------------------------
api/streamjob.py instance_id 改毫秒精度：新前端一键重跑同秒可达，
旧秒级时间戳 stream-{id}-{ts} 撞 t_workflow_instance.instance_id
唯一约束（真实健壮性修复，由重跑用例暴露）。

部署面：docker-compose.yml / docker-compose.rebuild.yml 为 rebuild-api
注入 REBUILD_LEGACY_DB_URL；日志卷 datara-logs ro→rw
（register_stream_job 需在共享日志卷建 TaskLog 目录）。
