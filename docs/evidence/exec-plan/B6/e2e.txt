六、SYNC 样例修复专项（wf39 试运行——用户裁决「修复并重验」，已闭环）
----------
现象：POST /trial/definitions/39/snapshot(code=0) → /run → 首验 instance 26 FAILED；
tasks：source_base SUCCEEDED / sys_exec_endpoint FAILED / target_base SUCCEEDED / file_route SUCCEEDED
日志：`SYNC runtime snapshot lacks project/source/target bindings`
根因链（三层）：
1. 组件 spec 契约（1.9 实测 /components/spec?workflow_type=SYNC）：endpoint_select params =
   [baseMode, srcDs, srcTable, probe, …, tgtDs, tgtTable, autoCreate]——数据源绑定按契约是 srcDs/tgtDs
2. seed（infra/seed_ecommerce_demo.py）：wf39 endpoint 节点 params 仅 {baseMode,srcTable,tgtTable}——缺 srcDs/tgtDs；
   且 seed 验收链只试运行 NORMAL（run_normal_sample），SYNC 从未入链；schema/object 值（ecommerce/orders）与
   内置栈真实数据面不符（实际 ec_retail.ods_order）
3. 后端 sync_runtime.py：file_sync 分支认识契约键 tgtDs 并合成 target；但 src_base/tgt_base 分支只认
   source.datasource_id/target.datasource_id，未接 srcDs/tgtDs——物化器（trial/runner.py）companions 仅
   field_map/field_map_union/condition_set，schema 未并入；prepare_sync_execution 要求 source/target 各含
   非空 schema/object（schema.object 库表限定名 = SQL 读取依据）
定性：后端缺口（sync_runtime src_base/tgt_base 路径未接 spec 契约键）+ seed 缺口（未填数据源绑定与真实表）；
前端无缺陷——FAILED 态与任务级状态忠实呈现（健康行「失败有界面反馈」的实证）
