# 多终端多智能体协作开发范式（Multi-Terminal Multi-Agent Collaboration Paradigm）

> 依据：Datara 平台重建 2026-10-16 全程实测总结（Codex × Trae 双终端 + 用户裁定信道 + 质量监督评审员留痕）。
> 维护：质量监督评审员持续记录；后续项目按本范式启动，实践中的新裁定与事故继续回写本章。
> 性质：可复用技能范式——角色、基础设施、循环、治理规范、纪律、案例库、审计清单、启动清单。
>
> **定位注记（2026-10-18 用户裁定精简重构）**：协作流程/角色/门禁/证据纪律的唯一行为权威已收敛至 `docs/increments/多终端多智能体项目管理标准规范.md`（v1.1）；本文档保留"案例库（§7）+ 审计清单（§8）+ 实测成效（§9）+ 启动清单（§10）"参考价值，§1–§6 与标准重叠之处以标准为准，不再作为独立行为权威。

## 1. 角色拓扑

| 角色 | 职责 | 权力边界 |
|---|---|---|
| 用户 | 唯一裁定权威；批准委托 + 事后查阅证据 | **不做页面操作员**；违反可操作性规范的确认请求有权直接拒绝 |
| 质量监督评审员 | **主责代码质量与交付物质量监督**（裁定 7）：基线实测复现、交付物对标审计、事故根因归类、全程记录留痕、机制沉淀 | 只评审与记录；代码/文档修改需用户授权 |
| 终端主 agent（执行者） | 文件域独占执行；内部可分多子智能体；交叉互审；**主责过程质量监督与用户要求/命令的传递**（裁定 7） | 只写本方文件域；验收前不提交实现（RED 红线） |
| 子智能体 | 主 agent 内部并行单元，落独立 worktree/文件域 | 无共享可变状态；完成即回报主 agent |

**域划分原则**：Backend / Frontend / Docs / Evidence 物理目录切分，零文件重叠为硬性约束；共享文件（handoff、台账、权威文档）以 append-only 或"仅修引用"方式协作。

## 2. 基础设施五件套

1. **单一权威文档链**：设计/计划/台账各一份权威版本；历史稿 SUPERSEDED 后归档至 `docs/archive/` 并改指针；被引用内容缺失时"先报裁定、缺口注记"，不得静默改写权威文件。
2. **共享 handoff 信道**：单一 Markdown 文档 append-only。消息格式：`### 日期 Sender → Recipient（主题）` + 要点列表；用户裁定编号下达（裁定 1..N）；**心跳制度**——每轮循环必留：当前任务、所在 worktree、进度四态（RED/GREEN/证据/提交）、阻塞点、预计产出物。
3. **worktree 隔离**：每任务独立 worktree + 分支；canonical main 为集成单点；集成前 `merge-tree` 预检；跨分支架构契约（迁移序列、Mixin、路由表）开工前对表。
4. **门禁套件与量化基线**：后端 pytest/Ruff/compileall，前端 vitest/vue-tsc/vite build，部署 pytest；每增量验收后基线数字回写台账（允许演进，禁止多版本漂移不收敛）。
5. **证据目录纪律**：`docs/increments/evidence/<增量>/` 下 JSON+PNG 成对；**失败证据保留不覆盖**，失败 run 编号登记；页面证据 SHA-256 四方比对（本地/暂存/远端/服务响应）。

## 3. 执行循环（单终端标准节拍）

```text
Scope authority 对表（引用指向权威版 + 章节映射核实）
→ RED 契约冻结（哨兵模式：未接线方法抛 NOT_WIRED；xfail 标记）
→ 交叉评审（对方独立复核后 GREEN 解锁）
→ GREEN 实现（TDD 红绿；合同断言钉死架构契约）
→ 回测门禁（全量套件 + 静态检查）
→ 证据 + pathspec-only 提交
→ 心跳回报 handoff
```

## 4. 交叉评审与回测机制

- **双向互审**：每方关键交付物由对方独立复核——前端复核实测页面 bit-exact（SHA-256 逐字节）+ 契约字段与服务端 fail-closed 双侧一致；后端复核导入计划形状/预检全面性/安全链清理。评审意见按 Resolved 标记闭环。
- **竞争架构拦截**：跨分支并行实现同一域时，先派侦察核对（迁移撞号、契约方向、FK 目标）；发现冲突即**实合中止 → 回滚 → 按主流水线移植**，主分支零污染。Datara 实例：I19/I20 迁移撞号 + 溯源 Mixin 契约相反，40 分钟内拦截，零损失。
- **回测**：集成前全量门禁复跑（不信转录数字，实测复现）；基线随增量演进（829→848），台账只保留最终收敛值。
- **评审发现的价值证明**：致命缺陷（非安全上下文 `crypto.randomUUID` 整页崩溃）由交叉评审抓出而非运行时暴露——互审不是仪式，是第一道防线。

## 5. 用户裁定治理规范（由裁定 1–7 提炼）

| 规范 | 内容 | 来源 |
|---|---|---|
| R1 文档治理 | 历史稿归档不硬删；Scope authority 修指权威版；断链清单全量扫描（含权威文件自身指针） | 裁定①③ |
| R2 放行与委托 | 用户可授权 agent 委托执行用户专属闸；证据如实标注"经用户委托"，不得伪称亲自操作 | 裁定 2 |
| R3 用户可操作性四条 | 可操作（凭据获取路径明确，严禁"要求输入 X 无处获取 X"）／可查阅（首屏呈现待确认内容，不得空壳）／可委托（默认提供委托执行+证据链）／可回溯（结果落证据目录+台账）。违反即无效请求 | 裁定 3 |
| R4 可观测与强制并行 | 心跳制度；**可并行任务（无共享可变状态+无依赖+独立 worktree）必须多子智能体并行**；串行须在心跳写明依赖依据，无依据串行违规 | 裁定 4+补强 |
| R5 页面自驱动 | 按钮/输入/浏览一律 browser-use/Playwright/TDD 自行验证；输入绕行优先用预置输入（预填值/测试凭据/演示账号/预置按钮/localStorage 预置点）；**无预置输入导致 agent 无法自驱动 = 页面缺陷**，登记修复不得回退用户；绕行仅限验证路径，生产安全闸走委托授权+留痕 | 裁定 5 |
| R6 监督分工 | 监督评审员线主责**代码质量与交付物质量监督**（基线复现/交付物验收/事故归类）；执行终端线主责**过程质量监督与用户指令传递**（心跳/并行/闸门纪律 + 用户命令信道）；双线编号各自系列，台账互认不互斥 | 裁定 7 |

**裁定流转闭环**：用户裁定 → 信道下达 → 各方循环拾取 → 执行 → handoff 回报（含映射依据/缺口注记）→ 用户确认。全程无需用户重复催办。

## 6. 信道与提交纪律

- **pathspec-only commits（硬纪律）**：共享 worktree 上一律 `git commit -m "..." -- <pathspec>`，禁止 add-then-commit。
- **临时索引纪律**：`GIT_INDEX_FILE` 指向临时文件时，PowerShell 下 `$env:GIT_INDEX_FILE = $null` 会**移除变量**使后续 git 命令作用于主索引——结束前必须显式恢复或验证；`.git` 隐藏属性导致 `Get-Item .git` 返回 null 的环境要先修复再操作。
- **事故披露协议**：即时披露 → 影响评估（良性/有害）→ 不回滚不改写历史（避免与在飞循环竞态）→ 恢复过程与证据留痕 → 根因归类 → 纪律升级。Datara 三起暂存区事故全部按此闭环。
- **失败处理**：失败证据保留；同一问题不静默重跑覆盖；阻塞如实写明卡点而非降级标准。

## 7. 事故案例库（范式输入）

| 竞争架构（迁移撞号 r3_0002 + 溯源契约相反） | 跨分支未先对表架构契约 | 侦察-中止-移植路径；契约开工前对表 |

| token 死路（要求输入无处获取） | 验证页按运行器设计却把用户当操作员 | 裁定 3 四条规范 |
| 弱 PASS 判定（接受中间态） | 判定闸不区分过程态与终态 | 2xx + 终态文案 + runtime complete 三重闸 |
| BSTR/SecureString 泄漏路径 | 非托管内存清理遗漏 Dispose 作用域 | 二审清单 + 源码合同断言 |
| 验证页 onboarding 首屏白屏（`.grid` 作者样式覆盖 UA `[hidden]` 隐藏语义，e219add） | 隐藏语义依赖 UA 默认样式而非显式 CSS；仅测 token 注入路径未测无 token 分支 | 显式覆盖 `.grid[hidden]{display:none}`；无 token 引导首屏纳入双路径自驱动验证（裁定 5 首次实战） |

| 权威易主未逐字确认（2026-10-14 评审以薄壳修订版替换用户逐字讨论的原始设计/计划权威并打 SUPERSEDED 归档；用户 2026-10-16 发现，裁定 A 恢复正本、修订版降级 `-执行附录`） | 评审产出的文档经一次批准入口即自封"唯一权威"，权威切换未回到用户逐字确认；原始正本被静默冻结，40+ 提交锚定修订版放大漂移 | 权威性文档的替换/降级必须单列用户确认项（逐字或明确选项），不得捆绑在其他裁定里顺带完成；降级原正本前须先并回独有批准内容（追加式，不回写用户原文）；权威链变更必须在头注双向留痕（正本↔附录互指）并全局重锚引用 |

## 8. 质量监督评审员审计清单

1. **对标设计列表逐项**：红线类（不做清单/时间戳/证据门/验收要素）与能力类（按增量分布）分开判——红线必须全绿，能力类只看流水线位置对不对。
2. **基线数字实测复现**：所有"passed N"声明必须本地复跑验证，不信转录；复现一律用干净 detached worktree（main 工作区常存在遗留 staged/未跟踪态，直接跑会被未跟踪测试文件污染）；临时 worktree 用后即清理，并以 `git worktree list` 复核归零后才能登记"已清理"。
3. **事故根因归类**：每起事故归入案例库并检查纪律是否已覆盖同类。
4. **三方一致性**：设计文档 ↔ 计划/台账 ↔ 代码与现实（含 worktree 状态、证据文件时间戳）比对，记录漂移。
5. **输出格式**：进展节点表（执行线×状态×证据）+ 设计对标表 + 质量问题清单（已闭环 / 现存按优先级）+ 下一步动作序列。
6. **连续审计留痕**：每轮审计在会话记忆更新状态，跨会话可恢复上下文。

## 9. 实测成效（Datara 2026-10-16 单日）

- 信道 20+ 轮往返；4 条前端分支并行合并全绿；竞争架构 40 分钟拦截零损失；页面致命缺陷运行前拦截。
- 门禁基线演进：后端 829→848 passed，前端 vitest 774，deploy pytest 37/37，全程红绿纪律。
- 用户从"被迫操作页面"转为"批准委托 + 查证据"；3 起提交事故即时披露闭环且零数据损失。
- 机制沉淀：本范式文档 + 项目记忆（角色任命、裁定 1–7、纪律条款）。
- 裁定 5 首次实战：验证页 onboarding 首屏由契约测试揪出 2 处违规（token 读取面唯一性、key 字面量禁入页面）+ Playwright 自驱动揪出白屏缺陷，双路径验证全程零用户操作（287152b→eb2f1df→e219add→e4207a2，失败证据对保留）。
- 交叉评审闭环实证（Q1→修复→验证）：监督员发现生成链断裂（P1）→ 执行者从根因修复（JS 注释剥离正则误截字符串内 URL，`27b3499`）→ 监督员干净 worktree 全链实测（74 组件导出成功）+ 根因定性更新（Python 崩溃仅为下游症状）+ 顺带登记产物两代差技术债 Q2。质量发现→根因修复→独立验证全程零返工。
- 遗留态治理：13 文件长期暂存 WIP 经逐文件甄别后分批收口（std 七文件入库 `2a9868e`，门禁 848→854 演进吻合；3 文件高危演进分叉拦截在提交前，避免治理补丁回退）——**入库前逐文件甄别 + 门禁复现**为遗留态收口的标准动作。

## 10. 新项目启动清单（套用本范式）

1. 建立权威文档链（设计/计划/台账各一份，历史稿即归档）。
2. 划分执行者文件域（零重叠）并写入手 handoff 首条消息。
3. 建 handoff 信道 + 心跳格式 + 裁定编号约定。
4. 建门禁套件并记录初始基线数字。
5. 建证据目录结构（成对、失败保留、SHA 比对惯例）。
6. 把第 5 章治理规范作为默认生效条款宣告（用户可裁剪）。
7. 每任务：worktree + RED 契约 + 交叉评审 + GREEN + 回测 + pathspec 提交。
8. 用户专属闸一律走"委托授权 + 证据留痕"，页面预置输入满足自驱动。
9. 质量监督评审员按第 8 章清单定期审计（建议每增量收口一轮 + 用户质询即时审计）。
10. 项目结束：范式文档回写新裁定与新案例，供下一项目复用。
