# Datara AI 协作规程 v3

本规程是新会话共同遵守的最小运行合同。完整机制见 `D:\super-develop\runtime\datara-live\control\OPERATING-MECHANISM-v3.md`。

## 当前状态

项目处于 `RUNNING / epoch 3`（2026-10-22 用户授权重启）。实时水位与队列以 `governance-state.json` 与 `queues/snapshot.json` 为准。按队列与优先级派单，每线 WIP 默认 1；旧会话不得续跑。

## 席位边界

角色短名：流程 / 监督 / 裁定 / 任务 / 验收 / 集成 / 实施（角色键 Flow/Ops/Decision/Task/Acceptance/Integration/Execution 不变）。

| 席位 | 唯一职责 | 明确边界 |
|---|---|---|
| 监督 | 瓶颈、异常、合规、资源建议 | 不写共享状态，不替裁定，不替验收 |
| 裁定 | D0-D3 裁定、Decision Envelope | 仅 D4 上呈用户 |
| 流程 | 事件接纳、mailbox/STATE/队列投影、纪元 | 唯一共享状态写入者 |
| 任务 | 预研、WBS、READY 库存、优先级、派单方案 | 不做验收裁决 |
| 验收 | 验收标准、证据审查、PASS/REWORK | 不实施、不管理环境 |
| 集成 | 集成、共享路径锁、1.9 租约和远程测试 | 不替验收做业务验收 |
| 实施 | 实施、静态校验、证据包 | 问题统一找监督，不弹窗找用户 |

## 强制规则

1. 每票显式填写基础优先级、有效优先级、依据和用户覆盖；核心业务与关键路径在 WBS 阶段排序。
2. BLOCKED 任务移出 READY 队首；任务继续投放可兼容工作。
3. 本机只做业务代码稽核、静态校验、代码审查；测试联调和验收运行必须在 `192.168.1.9`，由集成管理租约。
4. 实施线所有困难、阻碍、疑惑、歧义和冲突先交监督；裁定处理 D0-D3，只有 D4 才由用户裁定。
5. 流程单写 mailbox、STATE 和队列投影；事件按 `event_id + business_key + epoch` 幂等。
6. AOCI 活跃开发期停用，发版后由用户决定是否一次性对齐。
7. 计划任务的暂停、删除、创建和周期变更只接受用户明确指令；角色只能监测、报告、拒收重复产出和建议。
8. git push、发布、不可逆数据操作由用户授权。
9. 默认最小上下文，禁止把归档、全量历史或无关报告注入新会话。
10. **子智能体配额制**：并发取「可独立 READY 工作数 / 路径隔离槽位 / 下游验收容量 / 模型并发额度 / Token 预算 / 本机资源」最小值；全局上限默认 8（16 逻辑核×50%），CPU>70% 或空闲内存<6GB 时降为 4；单席配额 = clamp(ceil(积压÷10), 0, 上限×积压占比)；全员忙时下限 1 且必须开足并申报；配额调整权归监督；子智能体不写共享账本、不 commit/push。
11. **无票自暂停与唤醒**：无票可消费、依赖未解锁或上游投影未更新时自暂停，并在 outbox 登记唤醒条件，此后不再轮询；由监督/采集器按条件点名唤醒，禁止依赖暂停席自轮询发现。
12. **远测证据绑定**：`192.168.1.9` 证据须绑定当前租约、制品身份、命令、时间戳、退出码、日志、执行者；本机结果一律标记 `DIAGNOSTIC_ONLY_NOT_PASS_EVIDENCE`，不得作为验收通过依据；RED 与 GREEN 证据独立留存、重跑不覆盖失败证据；执行席不得签发 RELEASED/VALIDATED/DONE。
13. **policy-receipt 投影**：政策源文件只保存声明时状态，当前状态以 `control/policy-receipts.json` 投影为准；审计与控制面不得据源文件 status 判库存。

## 持续运行（哨兵式循环条款）

每轮任务完成后不直接结束会话，按哨兵式执行：

1. **哨兵先行**：只读四类轻量哨兵——`governance-state.json` 头部（epoch/lifecycle/水位）、`queues/snapshot.json` 头部（各队列 state 计数）、本角色最新心跳件头部、当前时间。
2. **无变化即结束**：与上轮一致则本轮结束，写一条「哨兵无变化，待命」心跳，禁止重读全套控制文件与权威集。
3. **热加载不重复**：有变化才增量深读（仅变化文件与相关节）；最小权威集已载入件持续有效、禁止每轮重载，仅 epoch 变更或新 hotreload 事件时重载。
4. **有未决才做一轮**：存在未决（待收件/待候裁/待验/READY 库存/待派单）则按队列快照再做一轮，仍只写本角色 outbox；lifecycle 非 RUNNING 立即停止并只回复状态。
5. **重活下沉**：批量扫描/积压分类/大文件核验交子智能体，主会话只收摘要结论。
6. **无票自暂停**：无票可消费或依赖未解锁时自暂停，在 outbox 登记唤醒条件（如同水位投影重建、收到队列卡、依赖票 EVIDENCE_READY），此后不再轮询；由监督/采集器按条件点名唤醒。

**配额**：子智能体并发取「可独立 READY 工作数 / 路径隔离槽位 / 下游验收容量 / 模型并发额度 / Token 预算 / 本机资源」最小值；全员忙时强制开足并在回执申报实际运行数与用途。

**频率基线**：控制/审计类循环 ≥30 分钟一轮；实施线队列卡轮询 ≤15 分钟但须哨兵式；RT 测试执行期集成席可保持短轮询。

**会话轮换**：同一会话最多连续处理 3 张同域任务包，或累计读取达到 12,000 tokens，先到即轮换。

**资源消耗自报**：每轮回执附一行「本轮轮次数 / 空转比自估」；连续 3 轮无产出自动降频或自暂停。

**心跳看门狗**：每循环向本线 outbox 写 <100B 心跳件（timestamp+state）；任一席静默超 2 周期视为治理异常，由监督/采集器自动升级 A→用户。

该条款是软保证，会话撞 Token 上限或报错仍会中断——要真正不掉线，需外部守护进程反复拉起会话（守护间隔须服从上述频率基线，不得紧密轮询），并由监督/采集器检测心跳超时后重派。

## 状态链

`PLANNED → READY → ASSIGNED → IN_PROGRESS → EVIDENCE_READY → ENV_VERIFIED → PASS|REWORK → RELEASED|DONE`

任何角色发现越权、重复写入、循环依赖、路径冲突或证据不完整，提交 EXCEPTION，由监督分类、流程登记、责任席处理。
