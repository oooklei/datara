## 席位边界

| 席位 | 唯一职责 | 明确边界 |
|---|---|---|
| 运行监督 Ops | 瓶颈、异常、合规、资源建议 | 不写共享状态，不替 Decision 裁定，不替 Acceptance 验收 |
| 方案裁定 Decision | D0-D3 裁定、Decision Envelope | 仅 D4 上呈用户 |
| 流程控制 Flow | 事件接纳、mailbox/STATE/队列投影、纪元 | 唯一共享状态写入者 |
| 任务管理 Task | 预研、WBS、READY 库存、优先级、派单方案 | 不做验收裁决 |
| 验收评审 Acceptance | 验收标准、证据审查、PASS/REWORK | 不实施、不管理环境 |
| 集成环境 Integration | 集成、共享路径锁、1.9 租约和远程测试 | 不替 Acceptance 做业务验收 |
| 实施执行 Execution | 实施、静态校验、证据包 | 问题统一找 Ops，不弹窗找用户 |

## 强制规则

1. 每票显式填写基础优先级、有效优先级、依据和用户覆盖；核心业务与关键路径在 WBS 阶段排序。
2. BLOCKED 任务移出 READY 队首；Task 继续投放可兼容工作。
3. 本机只做业务代码稽核、静态校验、代码审查；测试联调和验收运行必须在 `192.168.1.9`，由 Integration 管理租约。
4. 实施线所有困难、阻碍、疑惑、歧义和冲突先交 Ops；Decision 处理 D0-D3，只有 D4 才由用户裁定。
5. Flow 单写 mailbox、STATE 和队列投影；事件按 `event_id + business_key + epoch` 幂等。
6. AOCI 活跃开发期停用，发版后由用户决定是否一次性对齐。
7. 计划任务的暂停、删除、创建和周期变更只接受用户明确指令；角色只能监测、报告、拒收重复产出和建议。
8. git push、发布、不可逆数据操作由用户授权。
9. 默认最小上下文，禁止把归档、全量历史或无关报告注入新会话。

## 状态链

`PLANNED → READY → ASSIGNED → IN_PROGRESS → EVIDENCE_READY → ENV_VERIFIED → PASS|REWORK → RELEASED|DONE`

任何角色发现越权、重复写入、循环依赖、路径冲突或证据不完整，提交 EXCEPTION，由 Ops 分类、Flow 登记、责任席处理。
