## 3. 修订二：R8-A / R8-B 子门禁定义

### 3.1 权威依据

- 设计正本 §13.9「AI 契约纳入冻结范围」：AI 工具注册表、工具参数模型、工具返回结构、权限上下文和审计字段**属于 Backend 契约的一部分，必须在 Backend 冻结前完成**；AI 首期可以不接真实 LLM，但必须先完成工具契约、假 Agent 测试和悬浮助手测试页，避免 Backend 冻结后重新解冻接口。
- 设计正本 §11「AI 助手」：AI 仅作为全系统悬浮图标和侧边抽屉，**不新增一级菜单**；页面上下文携带十类（项目/工作流/节点/SQL/数据源/变量/运行记录/数据统计/元数据/血缘）；AI 通过统一工具调用，**不允许另建执行引擎**。
- 设计正本 §13.17.1 第 1 条：原 R11 AI 工具契约**按所依赖领域冻结，浮动助手与全平台验收归 R8**。

### 3.2 R8-A：AI 八工具契约冻结（R8 GREEN 硬前置）

| 项 | 定义 |
|---|---|
| 冻结对象 | 八工具逐一冻结：`search_schema` / `validate_sql` / `run_sql` / `get_workflow` / `validate_workflow` / `inspect_workflow_run` / `get_task_metrics` / `get_lineage` |
| 冻结内容 | 每工具的请求/响应 schema、错误语义、权限上下文字段、审计字段（§13.9 五要素：注册表 + 参数模型 + 返回结构 + 权限上下文 + 审计字段） |
| GREEN 前证据 | 工具契约冻结 + 假 Agent 测试通过 + 悬浮助手测试页存在；不接真实 LLM **不豁免**契约冻结 |
| 门禁效力 | 并入 P1 契约冻结评审面（与 N-B/N-D 同属 R8 冻结面，同批评审）；R8 GREEN 的硬前置——契约未冻结不得接线 |
| 红线 | 工具调用走统一执行/校验链路，不允许另建执行引擎（§11） |

### 3.3 R8-B：悬浮助手实现 + 系统级验收（R8 退出门禁组成部分）

| 项 | 定义 |
|---|---|
| 实现范围 | 全系统悬浮图标 + 侧边抽屉；页面上下文携带十类：项目/工作流/节点/SQL/数据源/变量/运行记录/数据统计/元数据/血缘（§11） |
| 系统级验收 | 全平台验收归 R8（§13.17.1）：悬浮入口全页面可用、上下文携带正确、八工具调用结果可视化、审计可追溯 |
| 红线核验 | AI 不新增一级菜单（§11）；AI/跨域能力按原设计修订映射完成，不因本轮九项客户要求被永久移除（执行附录 R6-R8 节） |

### 3.4 落点（执行附录两处）

1. §6 表 R8 行：「核心范围」列尾追加「AI 子门禁 R8-A/R8-B」；「退出门禁」列追加「R8-A 契约冻结为 GREEN 硬前置；R8-B 系统级验收」。
2. 「R6-R8：调度、监控、流和最终验收」checklist 节增补两条 checkbox：
   - [ ] R8-A：冻结 §13.9 八工具契约（五要素），完成假 Agent 测试与悬浮助手测试页；首期不接真实 LLM 不豁免契约冻结。
   - [ ] R8-B：悬浮图标 + 侧边抽屉落地，十类上下文携带；系统级全平台验收；不新增一级菜单红线核验。

### 3.5 设计说明

R8-A 是契约面（冻结在先），R8-B 是消费面（实现与验收在后）；两者拆开正是为防「Backend 冻结后重新解冻接口」（§13.9 明文风险）与「AI 能力被九项客户要求挤掉」（执行附录 R6-R8 节明文约束）两个已钉死的风险。子门禁是 §13.9/§11 权威条款的执行映射，不新增第二套门禁体系。
