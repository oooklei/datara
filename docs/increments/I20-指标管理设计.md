## 1. 总体架构

```
指标定义 = 业务口径 biz_def（文档） + 技术口径 tech_def（SQL/公式文档） + 结构化取数配置（唯一可执行通道）
来源解析 = src_kind=model → t_dw_model(ds_id/db_name/物理表) ；src_kind=table → {ds_id}/{db}/{tb}
看板取数 = 受控聚合 SQL（白名单聚合函数 + quote_ident 字段 + filter 条件校验）走 dsconn，60s 超时
一致性   = 纯元数据规则实时扫描（不落表）
```

## 2. 数据库表（2 张新表，含 create_time/update_time）

**`t_indicator` 指标主表**

```python
id: int PK auto
code: String(64) unique        # 英文名（如 pay_amount）
name: String(128) unique       # 中文名，禁同名不同义
type: String(16)               # 原子/派生/计算
biz_domain: String(64)         # 主题域 → t_biz_domain.name
biz_def: String(512)           # 业务口径定义（必填）
tech_def: String(512)          # 技术口径（SQL/公式，文档性）
src_kind: String(16)           # model / table
src_ref: String(255)           # model_id 或 {ds_id}/{db}/{tb}
src_field: String(128)         # 来源字段
out_table / out_task: String(128) nullable   # 产出登记（仅登记不调度）
period: String(16)             # 日/近7天/本月/实时/无
dims: String(255)              # 维度说明
unit: String(16)               # 单位
status: String(16) = 'draft'   # draft / published
version: int = 1
owner: String(64)
base_metric_id: Optional[int]  # 派生指标引用的基础指标
# —— 结构化取数配置（看板唯一取数通道，R1）——
agg_fn: String(16) nullable    # SUM/COUNT/AVG/MAX/MIN/COUNT_DISTINCT
num_field: String(128) nullable # 取数字段
time_field: String(128) nullable # 时间字段（趋势 X 轴）
dim_field: String(128) nullable  # 拆解维度字段（donut，可空）
filter_cond: String(255) nullable # 过滤条件（AND 条件表达式，后端校验）
```

**`t_indicator_version` 版本快照**：`id PK / indicator_id Index / version / snapshot_json MEDIUMTEXT（口径+取数配置全量）/ change_note（变更原因，必填）/ created_by`。UniqueConstraint(indicator_id, version)。

状态机：`draft --publish--> published`；published 口径冻结，变更走 POST /change（v+1 直接生效）。

## 3. 后端 API（/api/v1 前缀，ok()/ApiError 规范）

```
GET    /indicators?type=&domain=&status=&keyword=&page=&size=
                                   # 列表 + facet 计数（type/domain/status）
POST   /indicators                # 新建（name/code 唯一 409；biz_def 必填；同名→400「禁止同名不同义」）
GET    /indicators/{id}           # 详情 + 版本历史
PUT    /indicators/{id}           # 全量更新，仅 draft（409 published 引导口径变更）
DELETE /indicators/{id}           # 被 base_metric_id 引用→409 附引用清单
POST   /indicators/{id}/publish   # draft→published（409 非 draft）
POST   /indicators/{id}/change    # 口径变更 {reason必填, biz_def, tech_def, 取数配置...}
                                  # → 快照写 version 表、v+1 直接生效（R3）、响应附「已触发一致性复检」
GET    /indicators/{id}/versions  # 版本列表
GET    /indicators/{id}/trend?days=8
                                  # 趋势：按 time_field 逐日聚合
                                  # 返回 {series:[{date, value}], stats:{today, dod, avg_n, vs_n}}
                                  # SQL 生成白名单：agg_fn 枚举 + 字段 quote_ident + filter 校验（仅 AND 条件、禁分号/注释/多语句）
GET    /indicators/{id}/breakdown?date=
                                  # 维度拆解：按 dim_field 分组占比（donut 数据）
GET    /indicators/consistency    # 实时扫描结果：
                                  # ①同名不同义：name 同而 tech_def/biz_def 异 → fail（拦截历史/导入脏数据）
                                  # ②同义不同名：tech_def 完全相同而 name 异 → warn 提示合并
                                  # places = 派生引用(base_metric_id) + 血缘下游（t_lineage_edge 按 src 表 code 匹配任务/模型名）
                                  # 返回 {checked, pass, fail, items:[{metric, places[], result, detail}]}
```

- 未配置取数的指标：trend/breakdown 返回 400「未配置取数」；time_field 缺失→400「未配置时间字段」
- 权限：`ROLE_PERMS` 增补 `ind:write`（admin/dev）；看板/一致性读登录即可
- 审计：create/change/publish/delete 写 logger（`audit.ind`：`ind.{op} user code version`）

## 5. 关键规则

- 同名禁建（原型规则）：name 重复→400「已存在同名指标，禁止同名不同义」
- 口径变更必填原因；快照不覆盖历史（对齐 I18 回滚语义）
- 取数 SQL 仅由结构化配置生成；tech_def 永不直接执行（R1 安全边界）
- 一致性实时计算不落表；fail 闭环=口径变更后自动消除
- trend 聚合粒度按 period 语义：日=按天；近7天/本月=窗口聚合；实时=最近一小时按分钟（无 time_field 则 400）

## 6. 错误处理

| 场景 | 处理 |
|---|---|
| name/code 冲突 | 409（表单定位） |
| published 直接编辑 | 409 引导口径变更 |
| 删除被派生引用 | 409 附引用清单 |
| 变更原因缺失 | 400 |
| 取数查询失败/超时 | 60s（对齐 meta_ops READ_TIMEOUT）；看板卡片显示错误+重试，不阻塞其他卡片 |
| 未配置取数/时间字段 | 400，前端未绑定引导 |
| filter_cond 非法（分号/注释/多语句/非 AND 结构） | 400 校验失败明细 |
