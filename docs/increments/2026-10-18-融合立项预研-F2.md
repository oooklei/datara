## 4. R8-A FE camelCase ↔ BE snake_case 映射盘点

FE 统一请求/响应类型使用 camelCase；BE bridge 按 snake_case 读写 wire JSON。通用递归转换器已在 `datara-web/src/services/rebuild/adapterKit.ts` 实现，但 `aiToolsApi.ts` 未导入或调用它。更关键的是 `createAiToolsContract()` 的九个方法仍全部拒绝 `R8A_BACKEND_NOT_WIRED`；因此目前类型定义不是实际 HTTP 映射证据，页面契约测试走 mock，不存在真实 service→BE JSON 往返验证。

### 4.1 信封字段

| 方向 | FE 语义字段 | 目标/实际 BE wire 字段 | 当前状态 |
|---|---|---|---|
| 请求 | `toolCallId` | `tool_call_id` | 类型/BE校验已存在；实际 FE transport 未接线 |
| 请求 | `tool` | `tool` | 同名 |
| 请求 | `toolVersion` | `tool_version` | FE类型/BE读取存在；未实测转换 |
| 请求 | `params` | `params` | 顶层同名；内部参数必须 snake_case，不可只转换外层 |
| 请求 | `pageContext` | `page_context` | 目标转换存在于命名契约，未由真实 service 执行 |
| 请求 | `contextType` / `contextRef` | `context_type` / `context_ref` | 嵌套键需要递归映射 |

| 注册表 | `requiredPermissions`、`timeoutMs`、`retryPolicy.maxAttempts/backoffMs` 等 | `required_permissions`、`timeout_ms`、`retry_policy.max_attempts/backoff_ms` | FE/BE类型面对应；实际接口未接线 |

## 6. 风险、前置和待确认事项

1. **契约先行**：Phase 3 启动条件是规范 §10 的后端冻结门逐项通过；当前 R5-A、R4/FE service 多有未闭环或未接线项。此报告不等于后端冻结。
2. **DataX 参考缺口**：独立源码未找到；当前只从 DolphinScheduler 的 DataX plugin UI 取得可用交互字段。需未来补提供 DataX checkout/文档，再确认 DataX 产品自身交互、默认、校验与结果反馈。
3. **DBX 对象编辑边界**：P1-7 已对 DBX 能力和旧 IDE 融合矩阵复评通过，但 R5-A/A5 仍须冻结驱动×对象编辑能力和只读阶段约束；不能将矩阵 PASS 写成实现验收 PASS。
4. **DataX/DS 概念边界**：DataX 是 DS 任务插件能力之一，不代表需要引入独立 DataX 服务/容器；是否采用独立服务架构需另有架构决策，F2 不替其裁定。
5. **Vanna 交互和授权分离**：聊天页面只能收集意图、展示 SQL 和状态；明确用户确认之后才由 Datara 授权通道执行。SSE/poll 只能作为 UI 传输参考，不改变 R8-A API/工具面。
6. **OM/DataHub**：限 R3 治理 UI 的参考输入；当前 AI 语义真源和权限/身份仍为 Datara。引用前应保持与标准 S5、R3 冻结状态一致。
7. **映射未实现**：FE 类型使用 camelCase，BE wire 为 snake_case；通用 `adapterKit` converter 存在但 `aiToolsApi` 未接入，且当前 service 全 RED。须在 FE 接线单独立测试，不能靠 mock 绿灯替代。

## 7. 建议结论

- F2 预研可以作为 Phase 3 启动输入的初稿；页面行为参考按 DBX/DolphinScheduler/DataX/Vanna 分域使用，不以 Datara 旧正式页面反推第三方规范。
- 优先补齐 DataX 独立源码/文档可得性与 FE service transport 映射验收计划；DBX 复用既有 P1-7 成果，不重复造矩阵。
- 当前没有任何页面改造、接口 service 接线或第三方依赖部署被授权为本次 F2 执行内容；需后续 Phase 3 立项/冻结门通过后再进入实现。
