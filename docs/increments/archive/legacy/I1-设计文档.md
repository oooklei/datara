| 7 | **t_data_source** | t_ds_datasource | id, name, type(mysql/greatdb/…), host, port, db_name, user, pwd(加密), env, group_name, tags(json), owner_id, status（I1 建表，CRUD 归 I4） |

### 5.3 冒烟链路（F3 骨架实证，1.9 可演示）

复刻海豚"命令→DAG 构建→派发→执行→状态回写"主链路的最小闭环：

```
① api  POST /api/v1/smoke/run
      → 写 t_command(command_type=START_PROCESS_SMOKE, param={name, delay_sec})
② master scheduler 循环（2s 轮询 t_command state=wait）
      → 取命令 → 生成 instance_id → 建 t_workflow_instance(submitted)
      → 建 1 条 t_task_instance(type=smoke, submitted)
      → 任务消息 LPUSH redis 队列 datara:tasks
③ worker BRPOP datara:tasks → executor.smoke 执行（echo hello + sleep param）
      → t_task_instance: running → success + outputs(json: hello回显)
      → LPUSH datara:task_state（状态上报队列）
④ master 消费状态上报 → 实例状态机推进 → t_workflow_instance: success
⑤ api  GET /api/v1/instances?page_no=1 → 前端运行实例页可查
```

- 状态机最小版仅 submitted/running/success/failure 五态流转，完整状态集（含 Kill/Skip/容错/重试）I3 按 02 文档 §1.1 实现。
- 队列容错：worker 崩溃未 ACK 由 BRPOP 超时重投（Redis List 无原生 ACK，I3 换 Stream + pending list 精化；I1 接受 at-most-once 冒烟语义）。

### 6.2 会话机制

- 登录 `POST /api/v1/login {user_name, user_pwd}` → 校验 bcrypt → 生成 token（uuid）→ `SETEX datara:token:{token} 86400 user_json` → 返回。
- 后续请求 header `token: xxx`；api 网关依赖统一校验并注入 `request.state.user`。登出 DEL。TTL 24h。

### 6.3 REST 规范

- 路径前缀 `/api/v1/...`；统一响应包 `{"code":0,"msg":"success","data":...}`；失败 code≠0。
- 错误码分段（对齐海豚 Status 枚举思路）：1xxx 用户/鉴权、2xxx 工作流定义、3xxx 实例/命令、4xxx 数据源/参数、5xxx 系统。
- 分页参数 `page_no/page_size`（默认 1/10），响应 data 含 `{total, list}`。
- 时间字段统一 `YYYY-MM-DD HH:mm:ss` 本地时区（既有 toISOString 教训）。

## 8. F60 统一组件模型与动态表单框架

### 8.1 NodeSchema 扩展（src/graph/profiles/types.ts）

```ts
interface NodeSchema {
  // …既有字段不动（type/label/icon/color/defaults/form/ports/summary/shape/related）
  code?: string                       // 'C1'~'C23'，对应 02 文档组件编号
  page?: PageDef                      // F61 页面化声明
  template?: TemplateDef              // F63 聚合模板声明
}
interface FieldSchema {  // type 扩展
  type: 'text'|'number'|'select'|'textarea'|'script'|'branches'   // 既有
      | 'params-table'    // 键/值/来源(全局|工作流|环境组|字面量|时间变量) 表
      | 'kv-table'        // 键/值/说明 通用表
      | 'expr'            // 表达式输入 + 变量引用弹窗（下拉已注册变量 + 预览）
      | 'var-ref'         // 变量引用选择器
      | 'bool'            // 开关
}
```

### 8.2 六区块框架级注入（Inspector.vue 改造）

六区块**框架自动渲染**（不进 schema.form），各组件只写业务表单（02 文档 §1.2）：

```
Inspector 结构（自上而下）：
[节点名 + C编号徽标 + 类型标签]
① 输入     上游连线只读列表 + 输入引用（上游输出参数/结果表下拉）
② 输出     输出参数注册表(kv-table) + 结果表注册表
③ 参数     params-table（键/值/来源五选一）
④ 条件     expr（运行条件表达式）
⑤ 限定约束  超时(时长+策略)/重试(次数+间隔)/失败策略/优先级/worker分组（固定字段组）
⑥ 排除     跳过条件 expr + 禁用开关
—— 业务配置（schema.form 按 type 渲染，既有机制升级）
—— 关联信息（既有 related 不动）
```

- 六区块数据存 `node.data`：`inputs / outputs / params / condition / constraints / exclude` 键；老节点无字段 → 显示默认空值（向后兼容既有裁定）。
- `constraints` 固定字段组框架内置（超时/重试/失败策略/优先级/worker 分组），组件无需重复定义——对齐海豚任务定义通用参数。
- 变量引用控件：统一"下拉已注册变量 + 表达式输入 + 解析预览"（优先级：节点参数>工作流变量>环境组>全局，既有裁定；I1 仅 UI 层，解析引擎 I3）。

### 8.3 验证位

DAG 设计器任一节点 Inspector 呈现六区块；conditions 节点业务区=branches（既有）+ 六区块共存；保存后六区块数据随 GraphDocument 落库并还原。

## 10. F63 工作流模板通用机制（框架）

### 10.1 声明与展开

```ts
interface TemplateDef {
  modes: {
    key: string; label: string; desc?: string
    /** 设计时物化：返回要插入的节点+边（普通节点，展开后与手工编排无差别） */
    build: (ctx: { doc: GraphDocument; pos: { x: number; y: number } }) => { nodes: GNode[]; edges: GEdge[] }
  }[]
}
```

交互时序（Palette.vue + Workbench）：
1. 拖入声明了 `template` 的组件 → 先弹**模式选择**弹窗（列出 modes）
2. 选定模式 → 调用 `build(ctx)` → 生成的节点链**物化插入** GraphDocument（自动布局，节点 id 重新生成防冲突）
3. 聚合占位节点**不保留**（展开即普通工作流，引擎零改动，意见⑬）
4. 展开后每节点标准六区块+业务表单可配、可增删插节点

### 10.2 演示模板（框架验证位，非业务交付）

`demo_pipeline`：模式「最小管道」→ 生成 `C1 开始 → C11 SQL 占位(空 SQL) → C2 结束` 三节点链。仅证明 build/物化/再编辑闭环；**同步两模板按裁定归 I6**（C23），流三件套 I8 依 F35。
