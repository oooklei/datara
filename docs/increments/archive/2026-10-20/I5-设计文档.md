## 3. 解析器设计（common/sqlparser.py，F20~F23）

### 3.1 核心契约

```python
@dataclass
class StmtLineage:
    stmt_no: int          # 语句序号（分号拆分序）
    stmt: str             # 语句原文（截断 2000）
    from_tables: list[str]  # 输入表（JOIN/子查询/UNION/CTE 之外的实体表）
    to_tables: list[str]    # 输出表（INSERT/CREATE/UPDATE 目标）
    fields: list[FieldMap]  # 字段级映射（仅 INSERT..SELECT / CREATE..AS）
@dataclass
class FieldMap:
    to_table: str
    to_field: str
    from_table: str      # 空串=常量/无来源
    from_field: str
    transform: str       # 加工表达式（sqlglot mysql 方言回写，如 "o.amount * 0.9"）
```

- `parse_sql_lineage(sql: str, default_db: str = "") -> list[StmtLineage]`：sqlglot.parse（mysql 方言）逐语句遍历。
- 表名补全：语句内未限定库的表补 default_db（SQL 节点执行数据源所在库），血缘节点名统一 `db.table`。
- CTE 名不算实体表（WITH cte AS 的 cte 排除，其 SELECT 体来源正常收）。
- INSERT..VALUES：to_table 有、from 空（无字段映射）。
- UPDATE：to=目标表，from=SET 右值与 WHERE 引用表（字段级按右值表达式解析）。
- 解析容错：单语句解析异常 → 该语句记 parse_error（日志），返回空血缘，**不抛出**（血缘是旁路，绝不阻断任务执行）。
- 纯 SELECT：to_tables 空 → worker 侧直接跳过不落库。

### 3.2 临时表名映射（待确认点③）

worker 采集层（非解析器）负责：落库前用 `ref → t_tmp_data.name` 映射（同实例）把临时表名替换为注册名，并在 t_lineage_edge.to_table 加注形态（`raw_txt`，配套 from/to 维度实例查询仍可回溯原名）。解析器保持纯函数不掺库查询。

## 4. 运行时采集（worker sql.py，F24）

- 时机：任务执行成功后（终态 SUCCESS 回写前），对本次**实际执行成功**的语句逐条 `parse_sql_lineage`（语句即 param_resolved 已解析版本，与 [sql] 主语句#N 日志同源）。
- 落库：INSERT ... ON DUPLICATE KEY UPDATE（uk 见 §9）——重试/容错重跑/整体重跑同 instance 重放不产生重复行。
- 过滤：纯 SELECT / SHOW / DESC 不落；失败语句不落（仅成功语句）。
- 日志：`[sql] 血缘采集: 语句 N 条 → 表级边 M / 字段映射 K（临时表映射 J）`；outputs 增加 `lineage_edges`/`lineage_fields`。
- 失败隔离：解析或落库异常仅记日志告警，任务终态不受影响（旁路原则）。

## 8. 实测基准设计（§12 #5/#6 依赖）

I3/I4 既有 SQL 节点均为 SELECT COUNT 类（无加工产出），实测需造加工语句：新建工作流 `I5-血缘-实测`（src 库 ec_retail 内）：

```sql
INSERT INTO dwd_i5_order_wide
SELECT o.id, o.order_no, u.username, o.amount * 0.9 AS net_amount, o.create_time
FROM ods_order o JOIN dim_user u ON u.id = o.user_id
WHERE o.status = 'DONE'
```

- dwd_i5_order_wide 先建表（IDE 执行 CREATE TABLE，IDE 查询不入血缘——建表语句经工作流 INSERT 走血缘）。
- 对账口径：①血缘表名全部 ∈ ec_retail 真实表（解析无幻觉）；②JOIN ON `u.id = o.user_id` 与 tables.yaml relation `dim_user.id → ods_order.user_id` 方向一致；③字段映射抽查 net_amount ← ods_order.amount（transform=`o.amount * 0.9`）、username ← dim_user.username。
