## 2. 各组件研读切入点（对接 R8）

### 2.1 Vanna（`D:\vanna-main`）→ R8-A 工具调用方法论

- 核心机制：`src/vanna/base/base.py`（VannaBase 接口）+ `src/vanna/openai` 等适配器；**ask→generate_sql→run_sql** 链路；`train`（DDL/文档/SQL 三类训练数据入向量库）+ 检索增强（问题相似度召回 DDL/文档/示例 SQL 拼提示词）。
- 与 R8-A 对照点：八工具（search_schema/validate_sql/run_sql/…）即 Vanna 工具集思想的 Datara 化——工具注册表+参数模型+权限上下文+审计字段已冻结 v1；研读重点=训练/检索语义如何映射到 Datara 数仓语义层（S5 四能力之二）与 `${scope.name}` 变量引用（S3）。
- `papers/` 目录含 Vanna 方法论论文（RAG-for-text-to-SQL），方法论研读首选。

### 2.2 OpenMetadata（`D:\OpenMetadata`）→ 元数据语义源 + 治理域参照

- 元数据模型：`openmetadata-spec/src/main/resources/json/schema`（entity JSON Schema 定义——table/database/schema/glossary/tag/lineage/quality 等），类型系统与 Datara 治理五域（metadata/lineage/quality/data_asset/data_transfer）逐域对照。
- 服务层：`openmetadata-service/src/main/java/org/openmetadata/service`（REST 资源+治理工作流：glossary 评审发布、tag 密级分类、quality 测试套件）。
- 与 R8-A 对照点：`search_schema` 工具的语义源=OpenMetadata 的实体搜索与血缘图谱思路；AI 助手检索元数据的 API 形态参照其 REST 面。
- 文档入口：`docs/` 目录（docusaurus md）。

### 2.3 DataHub（`D:\datahub`）→ 元数据图模型参照

- 元数据图：`metadata-models/src/main/pegasus`（aspect 模型）+ `metadata-service`（GMS 图服务）；实体-aspect 框架、血缘（datajob/table lineage）、治理（glossary/tags/domains）。
- 与 OpenMetadata 差异研读点：OM=JSON Schema+REST 实体中心；DH=aspect+图查询中心。两库对照后裁定 Datara 语义层取舍（S5「OpenMetadata **或** DataHub」——择一为主参照、另一补差，裁定随 R8 批次或 A5 同批进行）。
- 文档入口：`docs/` 目录。
