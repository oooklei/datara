## 1. 总体架构

```
数据元/码表：draft → 提交评审（payload 快照）→ 标准审批（通过=published+version+1；驳回=draft+意见）
校验引擎 std_engine：四类检核（命名规范/类型精度/取值域/码表引用）→ t_std_check_report
命名扫描 + 映射合规：模型字段为主 + 可选数据源；整改登记 → 人工核验闭环（open→fixed→verified）
```

- 后端新增 `api/std.py`（tag "std"）+ `common/models.py` 新增 7 张表 + `common/std_engine.py`
- 受控 SQL 原则同 I20/I21（quote_ident、条件校验、60s 超时）；稽核/扫描异步执行（返回任务态，报告列表轮询）

## 2. 数据库表（7 张新表，含 create_time/update_time）

| 表 | 关键字段 |
|---|---|
| `t_std_element` | code(DE-xxx unique) / cn / en(snake_case) / type(BIGINT、DECIMAL、VARCHAR、CHAR、DATE、DATETIME、TINYINT、TEXT) / len（长度/精度） / format（格式约束） / domain / desc / cat(基础、指标) / status(draft、review、published) / version / owner |
| `t_std_code` | code(C-xxx unique) / name / remark / status(draft、review、published) / version / owner |
| `t_std_code_value` | std_code_id Index / c（码值） / n（含义） / seq / remark |
| `t_std_naming_rule` | name / rule_type(prefix、regex、layers) / pattern / target_layer(nullable) / enabled / remark；种子对齐原型 NR 清单 |
| `t_std_mapping` | name / target（模型字段或目录表字段路径） / element_id(nullable) / code_std_id(nullable) / status(pending、ok、violated、fixed) / last_check_json（差异明细） / remark |
| `t_std_approval` | biz_type(element、code) / biz_id / action(变更、发布) / payload_json（变更前后快照） / proposer / reason / status(pending、approved、rejected) / opinion / approver / handled_at |
| `t_std_check_report` | scope(single、audit、naming、mapping) / summary_json（通过/问题统计） / issues_json（问题项：描述/建议/状态 open→fixed→verified） / created_by |

## 3. 校验引擎（std_engine）

- **四类检核**（单数据元 sxCheck / 全量稽核 sxAudit·sxTask 共用）：
  1. 命名规范：en snake_case + t_std_naming_rule 规则
  2. 类型精度：映射字段实际类型 vs 标准类型/长度
  3. 取值域：映射字段样本值 ∈ 码值域（dsconn LIMIT 抽样）
  4. 码表引用有效率：引用的码表必须 published
- **命名扫描**：规则（prefix/regex/layers）对模型字段全量 + 可选数据源字段 → 报告
- **映射合规**：类型/长度比对 + 取值域抽查 → 差异明细写 last_check_json

## 4. 后端 API（/api/v1 前缀，ok()/ApiError 规范）

```
CRUD /std/elements[/{id}]                 # 数据元 CRUD（draft 可改；published 变更走提交评审）
POST /std/elements/{id}/submit            # 提交评审 → t_std_approval（payload 存变更前后快照）
GET  /std/elements/{id}/check             # 单数据元四类检核 → 报告卡
POST /std/elements/audit                  # 全量稽核（异步，返回任务态；报告列表轮询）
CRUD /std/codes[/{id}]                    # 码表 CRUD
CRUD /std/codes/{id}/values               # 码值维护（增删改排序）
POST /std/codes/{id}/submit               # 提交评审（发布）
GET  /std/codes/{id}/used                 # 使用位置（映射引用清单）
CRUD /std/naming-rules[/{id}]             # 命名规则 CRUD + 启停
POST /std/naming-rules/{id}/test          # 单规则测试（输入字段名试匹配）
POST /std/naming/scan                     # 全量扫描 {include_ds:[ds_id]}（异步）→ 报告
CRUD /std/mappings[/{id}]                 # 映射 CRUD
POST /std/mappings/run-all                # 一键全量映射检查（同步 60s）
POST /std/mappings/{id}/fix               # {note} → fixed
POST /std/mappings/{id}/recheck           # 复检
GET  /std/approvals?status=&page=         # 审批单列表
POST /std/approvals/{id}/approve          # 通过 → 对象 published（version+1，快照生效）
POST /std/approvals/{id}/reject           # {opinion 必填} → 驳回回 draft
GET  /std/reports[/{id}]                  # 报告列表/详情（pass/issues 分栏）
POST /std/reports/{id}/issues/{idx}/fix   # 登记整改 {note 必填} → fixed（AI 修复后置，R3）
POST /std/reports/{id}/issues/{idx}/verify   # 人工核验 → verified（闭环完成）
```

- 权限：`ROLE_PERMS` 增补 `std:write`、`std:approve`（均 admin/dev，系统权限从简）
- 审计：增删改/提交评审/审批/扫描写 logger（`audit.std`）

## 6. 错误处理

| 场景 | 处理 |
|---|---|
| code/cn 重复 | 409 表单定位 |
| published 直接改 | 409 引导提交评审 |
| 重复审批/无 pending 单 | 409 |
| 稽核/扫描大对象 | 异步执行+报告列表轮询；映射检查同步 60s 超时 |
| 取值域抽样连接失败 | 该项检核记 error，不阻塞其他项 |
| 码值删除被映射引用 | 409 附引用清单 |
