## 2. 数据库表（7 张新表，全部含 create_time/update_time，SQLAlchemy 2.0 风格）

### 2.1 字典表（3 张）

| 表 | 字段 | 说明 |
|---|---|---|
| `t_dw_layer` | code(String16 PK), name(String64), rule(String255 命名规范), color(String16), seq(Integer) | 分层字典；种子数据：ODS/DWD/DWS/ADS/DIM（code/名称/规范对齐 DB.dwLayers 原型） |
| `t_biz_domain` | id(PK auto), name(String64 unique), remark(String255) | 业务域字典；元数据/质量/权限模块后续复用 |
| `t_engine_type` | name(String64 PK), ddl(String32 方言标识), xc(Boolean 信创) | 引擎字典；种子：mysql(MySQL)、Apache Doris(doris)、GreatDB(greatdb, xc=true) |

### 2.2 主数据表（4 张）

**`t_dw_model` 模型主表**

```python
id: int PK auto
code: String(64) unique          # 物理表名，如 dwd_order_detail
name: String(255)                # 中文名
layer: String(16)                # FK 语义 → t_dw_layer.code
type: String(16)                 # 事实表/维度表/宽表/明细表
biz_domain: String(64)           # → t_biz_domain.name
engine: String(64)               # → t_engine_type.name
ds_id: Optional[int]             # 目标数据源 → t_datasource.id（物理化必填）
db_name: Optional[String(64)]    # 目标库
security_level: String(16) = '内部'   # 密级，本期只存值（sec 模块接入）
status: String(16) = 'draft'     # draft/published/built/produced
version: int = 1                 # 当前修订号（乐观锁基准）
er_pos: Optional[JSON]           # ER 画布节点坐标投影 {x,y}
last_ddl: Optional[MEDIUMTEXT]   # 最近一次物理化 DDL 快照
built_at/built_by: Optional      # 最近物理化时间/操作人
owner: String(64)
remark: String(255)
```

**`t_dw_model_field` 模型字段**：`id PK / model_id Index / seq（字段序）/ name / data_type / length / precision / nullable(bool) / default_value / comment / is_pk(bool) / is_partition(bool) / dict_ref(String128 关联字典或维表 code)`。整表读写采用**全量替换**（PUT /fields 一次提交），seq 唯一由后端重排。

**`t_dw_model_relation` 模型关系（ER 边=血缘声明）**：`id PK / src_model_id / tgt_model_id / rel_type(1:1|1:N|N:N) / src_fields(JSON 字段名数组) / tgt_fields(JSON) / join_desc(String255) / created_by`。UniqueConstraint(src, tgt, src_fields, tgt_fields) 防重。

**`t_dw_model_version` 版本快照**：`id PK / model_id Index / version / snapshot_json MEDIUMTEXT（主数据+fields+relations 全量）/ change_note / created_by`。UniqueConstraint(model_id, version)。

> 物理化执行记录不建独立表：结果写回 t_dw_model（status/last_ddl/built_at/built_by）+ 审计日志；历史 DDL 随版本快照留存。

## 3. 状态机与修订链

```
draft --POST /publish--> published --POST /physicalize(exec成功)--> built
   ↑                        ↑                                          │
   │ 新建/逆向导入           └─ redraft(开 vN+1 修订草稿) <──────────────┘
   └────────────────────────────────────────────────────────────────┘
```

- **draft**：字段/主数据可编辑（乐观锁）
- **published**：字段冻结；仅主数据（remark/owner/密级等）可改；开新修订须走 redraft
- **built**：已物理化；字段编辑必须 redraft → 修订发布 → 重新物理化（对齐原型闭环：投产模型变更走版本管理，旧版本可回滚）
- **produced**（自动）：当 `t_dw_model_relation` 存在以该模型为 src 的边，或 `t_lineage_edge` 运行时血缘存在以该 code 为上游的边 → 自动升级；永不手工设置，不可回退
- redraft 语义：复制当前快照为 vN+1 草稿（status=draft），发布时字段冻结并 version+1（复用基线化 redraft 交互先例：工作台只读态「开新修订」按钮）

## 4. 后端 API（/api/v1 前缀，ok()/ApiError 响应规范）

### 4.1 模型与字段

```
GET    /models?layer=&status=&domain=&keyword=&page=&size=
       → {list, total, layers:[{code,count}], domains:[{name,count}]}   # 统计含交叉过滤
POST   /models                     # 新建草稿 {name,code,layer,engine,type,biz_domain}
                                   # 校验：code 唯一(409) + 分层命名规范(400) + code 正则 ^[a-z][a-z0-9_]*$(400)
GET    /models/{id}                # 详情（含 fields[]）
PUT    /models/{id}                # 主数据更新（published/built 仅允许 remark/owner/security_level/ds_id/db_name）
DELETE /models/{id}                # built/produced→409；被下游血缘引用→409 附引用清单
PUT    /models/{id}/fields         # 字段全量保存 {rev, fields[]}；rev≠当前 version→422 附最新 rev
                                   # 仅 draft 可保存（409）；保存成功返回新 rev
POST   /models/{id}/publish        # draft→published（409 非 draft）；审计
POST   /models/{id}/redraft        # published/built→vN+1 draft（409 已是 draft）
```

### 4.2 物理化与 DDL

```
GET    /models/{id}/ddl?engine=    # 方言预览（不落库，供可编辑框）
POST   /models/{id}/physicalize    # {engine, ds_id, db_name, mode: exec|script, ddl}
                                   # exec：open_connection 执行（单语句分拆、逐条执行、失败整体已执行部分提示）
                                   #   成功→status=built，写 last_ddl/built_at/built_by；失败→状态不变，附错误
                                   # script：仅校验并返回脚本文本（状态不变）
```

### 4.3 版本

```
GET    /models/{id}/versions                       # 列表（含 change_note/created_by）
POST   /models/{id}/versions                       # 手动保存快照 {change_note}
GET    /models/{id}/versions/{vid}/diff?base={vid} # 结构化差异：{added,removed,changed} 字段级+主数据级
POST   /models/{id}/versions/{vid}/rollback        # 快照内容写入新版本（version+1，不覆盖历史）；built 模型回滚后状态回 draft
```

### 4.4 逆向工程

```
POST   /models/reverse/scan        # {ds_id, db_name?} → information_schema 内省表清单（表名/注释/列数/行数估算）
POST   /models/reverse/import      # {ds_id, tables:[{tb, layer, biz_domain, name?}], db_name}
                                   # 逐表建草稿模型（字段从内省列直转；已存在 code 跳过并计入 skipped）
POST   /models/reverse/import-ddl  # multipart 文件（.sql，≤5MB）→ sqlparser 解析 CREATE TABLE → 生成草稿
```

### 4.5 血缘与 ER

```
GET    /models/{id}/lineage        # 合并图 {nodes, edges, sources:{declared:[...], runtime:[...]}}
                                   # declared=t_dw_model_relation 双向展开；runtime=t_lineage_edge 按 code 匹配
GET    /models/{id}/impact         # 下游递归清单 [{model, path}]
GET    /models/er?layer=&domain=   # ER 投影：{nodes:[{id,model,er_pos}], edges:[relation...]}（GraphDocument 兼容形态）
PUT    /models/er                  # {positions:{id:{x,y}}, relations:{added,updated,removed}} → 写回 er_pos + t_dw_model_relation
```

### 4.6 权限

- `ROLE_PERMS` 增补 `model:write`（admin/dev）；全部写操作注入 `require_perm("model:write")`
- 读操作登录即可（get_current_user）
- 数据权限：`security_level`/`biz_domain` 本期仅存储；I19+ sec 模块按「密级+业务域」统一拦截（IDE canSeeTable 同机制）

## 5. DDL 方言生成器（common/ddlgen.py）

纯函数 `gen_ddl(code, name, fields, engine) -> str`：

| 方言 | 要点 |
|---|---|
| mysql | `CREATE TABLE` + 列注释 + PRIMARY KEY + ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 |
| greatdb | 同 mysql 语系 + GreatDB 兼容参数；xc 徽标由前端按 t_engine_type.xc 渲染 |
| doris | `DISTRIBUTED BY HASH(pk)`；is_partition→`PARTITION BY RANGE(...)` 动态分区子句；字段类型映射（varchar→varchar(n)、datetime→datetime、decimal(p,s)） |

- 标识符一律经 `quote_ident` 校验（复用 common/dsconn）；注入面与 meta_ops 同标准
- is_partition 在 mysql/greatdb 方言下不生成分区子句，预览区提示「该引擎不支持分区声明」

## 7. 审计

审计事件写入统一 logger（`get_logger("audit.model")`），格式 `model.{op} user={user} code={code} version={v}`，覆盖：create/delete/publish/redraft/physicalize/rollback/reverse_import/er_save。查询入口由 I19+ sec-审计模块统一提供。

## 8. 错误处理

| 场景 | 处理 |
|---|---|
| code 重复 / 命名规范不符 / code 非法字符 | 400，表单定位提示 |
| 乐观锁冲突（fields/redraft 并发） | 422 附最新 rev，前端提示刷新 |
| 非法状态流转（重复发布/draft 下 redraft） | 409 |
| 物理化执行失败 | 状态不变；last_ddl 保留本次脚本；错误落响应+审计；前端提供「重试 / 导出脚本手工执行」 |
| DDL 执行超时 | 60s（对齐 meta_ops READ_TIMEOUT），超时即失败处理 |
| 删除被引用 | 409 附引用清单（下游模型/运行时血缘） |
| 逆向导入部分失败 | 逐表结果 {imported, skipped:[{tb,reason}]}，成功者落库 |
| DDL 文件解析失败 | 400 附解析错误行号 |
