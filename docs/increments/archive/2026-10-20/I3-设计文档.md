## 3. 执行架构总览（F42）

### 3.1 引擎模型（对齐海豚 WorkflowExecuteRunnable + EventService）

```
api: 写 t_command（启动/停止/补数/重跑/定时 CRUD）
                     │
master（leader） ────┼─ ① 命令消费线程：2s 轮询 t_command(wait) → 按类型展开
                     │     START_PROCESS → 建 t_workflow_instance(submitted)
                     │       → graph_json 解析 DAG → 逐节点建 t_task_instance
                     │       → 注册 WorkflowExecuteRunnable（线程）→ 激活入度=0 节点
                     │     COMPLEMENT_DATA → 按日期范围展开 N 条 START_PROCESS（参数注入周期变量）
                     │     REPEAT_RUNNING / START_FAILURE_TASKS → 任务状态重置重派
                     │     STOP → 实例全部未终态任务置 kill + datara:kill:{taskId} 标记
                     │
                     ├─ ② 状态消费线程：XREADGROUP datara:stream:task_state
                     │     → 终态事件路由到对应 Runnable 队列 → 拓扑推进
                     │
                     ├─ ③ 定时调度线程：10s 扫描 t_wf_schedule(online)
                     │     → croniter next_fire_time 到期 → 写 START_PROCESS 命令（schedule_time=计划时间）
                     │
                     ├─ ④ 超时扫描线程：10s 扫描 running 任务超时 → kill 标记 + 按策略处置
                     │
                     └─ ⑤ 容错恢复（启动/接管时）：扫描 running 实例
                           → recovery=1 → 未终态任务重派（attempt 保留、状态 fault_tolerance 后重跑）
                           → delay 任务按 delay_until 重算 → dependent/loop 状态重建

worker（每实例） ── XREADGROUP datara:stream:tasks:{high|normal|low}
                     → 幂等校验（任务已终态/已被接管则丢弃）→ 置 running + 建日志索引
                     → 执行器执行（增量写日志 + 周期检查 kill 标记）
                     → 终态 + outputs → XADD task_state → XACK
```

- **线程模型**：master 主进程 5 个常驻线程 + 每实例 1 个 Runnable 线程（实例结束退出）；全部状态写库以 DB 为准，线程间经内存事件队列（Runnable 私有 queue.Queue）通信。
- **选主联动**：仅 leader 持有 ①~④ 线程；从主不消费（ZK watch 接管时重建）。I1 registry 选主机制复用。
- **幂等派发**：任务消息带 taskId；worker 执行前查 t_task_instance.state，非 submitted/retry/fault_tolerance 可接受态则丢弃（Stream at-least-once 的重复投递防护）。

### 3.2 Redis Stream 队列精化（I1 遗留回填）

| 项 | 设计 |
|---|---|
| 任务流 | `datara:stream:tasks:{high\|normal\|low}` 三条，按节点 constraints.priority 映射（1~5 → 三档）；worker 每轮依次 XREADGROUP（high 非空优先，全部空则 block 1s） |
| 状态流 | `datara:stream:task_state` 单条，master 消费组读取 |
| 消费组 | `datara-worker-{hostname}` / `datara-master`（XGROUP CREATE MKSTREAM 幂等创建） |
| ACK 语义 | 处理成功 XACK；**at-least-once** + 任务幂等校验（§3.1）= 不丢不重执行 |
| 僵尸认领 | worker 启动时 XAUTOCLAIM（idle>60s）认领 pending 消息补执行；master 状态流 pending 由消费循环自然兜底 |
| 兼容 | I1 List 队列（datara:tasks/datara:task_state）删除，queue.py 重写为 Stream 封装（接口名保留 push/pop 语义改流式） |

### 3.3 状态机（F42）

- **实例状态**：`submitted → running → success / failure / kill / fault_tolerance(过渡,终态前) `；补数实例同链路。实例状态**仅 master 写**。
- **任务状态**（02 文档 §1.1 全集）：`submitted / waiting_dependency / running / success / failure / kill / skip / fault_tolerance / retry`。
  - submitted/retry/waiting_dependency/skip/fault_tolerance 由 **master** 写；running/终态由 **worker** 上报、master 落库；kill 由 master 写。
- **流转要点**：入度=0 节点激活 → submitted；执行条件（④区块）不满足 → skip；失败无重试余额 → failure；重试中 → retry（attempt+1 延迟重派）；worker 掉线 → fault_tolerance → 重派。
- **Skip 级联**：条件分支未命中下游、禁用节点、跳过条件命中 → skip 并向下游传播（下游若无其他非终态前驱则同置 skip，对齐海豚条件跳过传播）。

### 3.4 容错设计（F42，海豚 FailoverService 对齐）

| 场景 | 机制 |
|---|---|
| master 崩溃/重启 | ZK 临时节点消失 → 备主接管（或本机重启再选主）→ §3.1 ⑤恢复流程：running 实例 recovery=1、未终态任务重派，host 更新，日志续写（append） |
| worker 崩溃 | master ZK watch worker 临时节点消失 → 扫 t_task_instance(host=该节点, state=running) → 置 fault_tolerance → 重派（attempt 保留）→ 新 worker 接管 |
| 任务消息丢失 | Stream pending 认领（§3.2） |
| 同任务重复执行防护 | worker 幂等校验（§3.1）+ DB 状态为准 |

> 1.9 单 worker 容器：kill worker 容器 → restart 策略自动拉起 → 启动时 XAUTOCLAIM + 容错重派闭环可实测（多主机转派 I7）。

## 5. DAG 构建与拓扑执行（F42）

### 5.1 graph_json → 执行图

- 解析 nodes（id/type/data）与 edges（source/target/sourceHandle）→ 邻接表 + 入度表；非法（无 C1、有环除回环边外）拒绝启动（命令置失败+原因写命令参数）。
- **回环边识别**（C10）：target 为 Loop 节点且 Loop.data.loop 配置声明其为回边 → 不计入常规入度/无环校验。
- sourceHandle 语义：conditions 分支边 handle=分支名；switch 边 handle=分支值；普通边 handle=null。取边时按 handle 匹配激活。

### 5.2 拓扑推进规则

1. 节点激活条件：全部前驱到达「有效完成」（success / skip / merge 规则放行）；父节点 skip 时按 §3.3 级联。
2. 节点激活动作：评估运行条件（④区块表达式，不满足→skip）→ 排除区块（跳过条件命中/禁用→skip）→ 变量解析（F48）→ 逻辑节点内联执行（§6）或数据节点派发（§7）。
3. 实例终态：全部任务终态 → 有 failure（且失败策略=终止链路已断）/kill → failure/kill；否则 success。

## 6. 逻辑节点语义（F44，master 内联执行，逐个定义）

> 逻辑节点不派发 worker，Runnable 内瞬时/等待处理；瞬时节点的输出写 t_task_instance.outputs。

| 组件 | 执行语义 |
|---|---|
| C1 开始 | 瞬时 success；生成 instance_id（I1 既有）注入 ${run.instanceId}；输出=启动时间 |
| C2 结束 | 前驱全部终态后瞬时 success；输出=汇总输出参数表（⑤区块 inputs 引用收集） |
| C3 条件分支 | 瞬时评估分支表达式（按优先序首个命中）；命中分支下游激活、未命中下游整链 skip；输出=命中分支名 |
| C4 切换 | 瞬时：取判断变量值 → 按「值→目标节点」映射路由唯一分支，其余 skip；默认分支兜底；输出=命中值 |
| C5 并行 Fork | 瞬时 success；全部下游同时激活（拓扑天然并行）；输出=并行度 |
| C6 汇聚 Join | 汇聚策略（全部成功/任一成功/全部到达终态）满足→瞬时 success；输出=各上游状态汇总 |
| C7 合并 Merge | 任一上游到达终态即瞬时 success；输出=首个到达上游的输出 |
| C8 延时 | 激活时置 running + delay_until=start+分钟数（或时间变量到点如 $[yyyyMMdd 0800]）；Runnable 定时唤醒（Event.wait 至最近 deadline）；到期 success；输出=实际等待秒数 |
| C9 依赖 | 置 waiting_dependency；Runnable 每 10s 查被依赖「工作流+节点」最近任务实例状态=期望状态（成功/失败/完成）→ 满足 success / 超时（constraints.timeout）failure；输出=被依赖实例编号与状态。周期匹配不做在组件内（意见②，条件区块表达式承担） |
| C10 循环 Loop（自创） | 见 §6.8 |

### 6.8 Loop 最小语义（自创，可执行定义）

- **循环体**=Loop 的全部下游节点子图中、回到 Loop 的回边源节点为止的路径；**回边**=循环体尾节点→Loop。
- Loop 激活：评估终止条件表达式（可用 ${run.loopIter}）→ 满足：瞬时 success，放行**非回环出边**下游；不满足：<max_iterations（默认 100，超出 failure）时**重置循环体**（体内节点新建任务实例行：同 node_id、loop_iter+1、状态 submitted）并重新派发循环体入口。
- t_task_instance.loop_iter 记录各节点所属迭代号（迭代历史保留可追溯）；输出=迭代次数/最后迭代输出。

## 7. worker 执行器（F43，C11~C14）

### 7.1 统一契约

- 注册表延续 I1：`@register(node_type)` → `executors/{sql,shell,python,ssh}.py`。
- 消息载荷：`{taskId, instanceId, nodeType, name, param, param_resolved, var_snapshot, constraints{timeout_sec, retry_times, retry_interval, fail_strategy, priority, worker_group}}`。
- **运行中实时日志**：置 running 时先建日志文件+t_task_log 索引 → 执行器经 log 回调增量 append（前端轮询可见，F47）。
- **中断检查**：执行器在等待循环周期查 `datara:kill:{taskId}`（EXISTS）→ 命中则 terminate 子进程/中断执行 → kill 终态上报；1s 间隔。
- **输出参数解析**（对齐海豚 ShellTask 约定）：stdout 中 `KEY=VALUE` 行 → outputs.params；SQL 查询结果集 → outputs.result_preview（≤200 行截断）+ row_count。
- ExecResult 状态映射：exit=0 → success；非 0 → failure；异常 → failure（日志留 traceback）。

### 7.2 四类执行器

| 执行器 | 实现 | 要点 |
|---|---|---|
| C11 SQL（node_type=sql） | pymysql 连接池（按数据源 id 建 LRU 连接） | 数据源解析：param.datasource_id → t_data_source（**本期内置 seed 2 条**，I4 做 CRUD/加密 UI）；SQL 类型查询/非查询/DDL（autocommit 区分）；多语句分号拆分顺序执行；每语句影响行数/结果集注册 outputs；**变量占位替换在 master 侧完成后下发**（param_resolved，worker 不做解析）；查询结果 ≤200 行进 result_preview（完整导出 I4/F18） |
| C12 Shell（shell） | subprocess bash -c（容器内） | 运行目录：/datara/tmp/{instance_id}/（自动建，实例结束随清理脚本清理）；环境变量注入（param.env）；exit code/KEY=VALUE 解析 |
| C13 Python（python） | subprocess python（容器 3.11） | 同 Shell；依赖清单 requirements 字段本期**仅校验格式并打印日志提示**（不做运行时安装，依赖预装归镜像层——运行时装依赖慢且不幂等） |
| C14 SSH（ssh） | paramiko（requirements 追加） | 读 t_runtime_node（id=param.runtime_node_id）：主机/端口/用户/密钥（auth 字段本期支持密码与密钥内容两种）；远端 bash -c 执行于配置的 runtime_dir；退出码/stdout 回收同 Shell 约定；连接失败→failure（日志含原因） |

## 8. 重试 / 超时 / 失败策略 / 取消（F45）

| 机制 | 设计（对齐海豚 retry/timeout/failover） |
|---|---|
| 失败重试 | worker 上报 failure 且 attempt ≤ retry_times → master 置 retry，延迟 retry_interval 秒重派（Runnable 定时唤醒）；重试耗尽 → failure 并按失败策略传播 |
| 超时 | constraints.timeout_sec>0 时 master 超时扫描（§3.1 ④）；命中 → datara:kill:{taskId} 标记 → 任务 failure（日志注明超时）；超时策略=失败（默认，告警策略随 alert 通道后置） |
| 失败策略 | fail_strategy=continue：该任务 failure 但下游照常激活（下游判断前驱 failure 也算「到达终态」）；end（默认）：下游 skip（等待依赖永不满足→实例终态时统一 skip）+ 实例倾向 failure |
| 优先级 | constraints.priority(1~5) → §3.2 三档 stream 映射（4~5→high，3→normal，1~2→low） |
| worker 分组 | constraints.worker_group：本期单分组校验（指定不存在分组→派发失败日志留痕；多分组调度 I7/F53） |
| 取消 | API STOP → t_command(STOP) → master：实例置 kill、全部未终态任务置 kill + datara:kill:{taskId} 标记 → worker 中断上报；逻辑节点由 Runnable 自查实例状态中断 |

## 9. 定时调度 / 补数 / 重跑（F46）

### 9.1 定时 crontab

- t_wf_schedule CRUD + 上线/下线（api 路由 §11）；master 定时线程 10s 扫 online，croniter 计算 next_fire_time（首次上线即算并缓存内存），到期 → 写 START_PROCESS 命令（command_param={wfCode, wfVersion, run_mode=schedule, schedule_time=计划时刻}）→ 正常引擎链路。
- 补齐海豚 schedule 字段：start/end_time（有效期外不触发）、fail_retry_times/interval（下发给该实例全部任务缺省）。

### 9.2 补数 complement

- API：POST /workflow-definitions/{code}/complement {date_from, date_to, parallel: bool} → master 展开为 N 条 START_PROCESS（run_mode=complement，schedule_time=各日 00:00:00）；parallel=true 同时展开（Runnable 并发天然支持），false 串行（前实例终态后再消费下一条：命令参数带 complement_group，master 串行控制）。
- 每实例 variables 注入对应日期 → $[yyyyMMdd] 按实例 schedule_time 计算（§10.2）。

### 9.3 重跑与停止（命令枚举对齐海豚子集）

| 命令 | 语义 |
|---|---|
| START_PROCESS | 启动（手工/定时/补数共用） |
| REPEAT_RUNNING | 整实例重跑：实例内全部任务**新建任务实例行**（loop_iter 同、attempt=1），实例新 instance_id 复用原实例变量快照 |
| START_FAILURE_TASKS | 失败节点重跑：仅 failure 任务及其下游重置重派（成功上游不重跑）——同一实例 id 内续跑 |
| STOP | 实例停止（§8） |

## 10. 变量解析链与时间变量（F48/F49）

### 10.1 四级解析（既有裁定优先级）

```
节点参数（node.data.params，来源标注五选一） > 工作流变量（t_wf_variable by wf_code）
> 环境组（t_env_group.config，实例运行时指定 env_group_id，缺省跳过该层） > 全局参数（t_global_param）
+ 运行时变量：run.instanceId / run.loopIter（引擎注入，最高不可覆盖）
```

- 占位语法：`${var}`（四级引用）；替换发生在 **master 激活节点时**（param_resolved 随消息下发，worker 零解析）；未解析占位保留原样并在变量快照中标注 unresolved。
- **加密/脱敏裁定取消**（2026-09-18 用户裁定：内部系统、内部人用，没有加密这一说）：t_wf_variable.encrypted 与 t_data_source.pwd 均为普通字段，**明文存储、明文打印**（变量快照/日志不做任何脱敏；I4 数据源「密码加密存储」功能取消，后续增量同口径）。

### 10.2 内置时间变量（海豚 System Variables 子集）

- 基准 = 实例 schedule_time（定时/补数）或启动时刻（手工）：`$[yyyyMMdd]`、`$[yyyy-MM-dd]`、`$[HHmmss]`、`$[yyyyMMdd-1]`（±N 天）、`$[yyyyMMdd 0800]`（当日定点，C8 延时用）。
- 运行条件/分支表达式中的比较经 **simpleeval**（requirements 追加）安全求值：支持数值/字符串比较、and/or/not、算术；禁 import/属性访问。

### 10.3 变量快照打印日志（意见[09-17晚]③，强制）

- master 解析完成后生成 var_snapshot：`{变量名: {value(明文，不脱敏), source(节点参数/工作流变量/环境组/全局/运行时/时间变量), resolved: true|false}}`。
- worker 置 running 时**首行块**写入日志：

```
===== 变量快照 instance_id=... node=... =====
wf.period=20261002        (工作流变量)
biz_date=20261002         (时间变量 $[yyyyMMdd])
run.instanceId=...        (运行时)
unresolved: ${xx}         (未解析占位)
============================================
```

- 快照同时存 t_workflow_instance.variables（实例级汇总）与消息内（任务级）。
