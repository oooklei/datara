# Datara 增量迭代 · 流程与记录规范

> 本规范由用户于 2026-09-17 裁定，全程有效。

## 流程规则（每阶段固定动作）

1. **设计先行**：每个增量（I0/I1/…）动工前，先产出《设计文档》（`I{n}-设计文档.md`），内容含：目标与验证门、详细设计、资源依赖、待用户裁定项。
2. **确认后执行**：设计文档交用户确认/修订，未经确认不进入编码执行。
3. **执行留痕**：执行期间用户的一切输入、提示、裁定，实时记入《决策记录.md》（按时间正序追加，不删改历史条目，修正以新条目方式追加）。
4. **本地语法验证 + 1.9 运行实测**（用户 2026-09-18 修订裁定："测试运行环境以 1.9 机器为准，本地只做语法验证"）：
   - **本地验证门（语法级，不做运行测试）**：vue-tsc 0 错 + vitest（可本机跑的用例）+ Python 语法/lint（py_compile、ruff，兼容目标 py3.11）+ 逻辑自查（与设计文档比对）
   - **远端实测门（1.9 为准）**：一切运行时测试（容器健康、接口/页面实测、数据对账、容错/HA 演示、性能）一律部署 192.168.1.9 后执行
5. **验证单收口**：每增量结束输出验证单（本机验证 / 远端实测 / 真实场景演示 3 组全绿），才进入下一增量。
6. **跨阶段复用**：下一增量设计文档必须引用决策记录中的相关历史裁定，保证主线不漂移。
