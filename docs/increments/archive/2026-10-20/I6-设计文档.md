## 3. C23 同步编排聚合组件（F28）

### 3.1 交互与展开框架

拖入画布 → 弹**模式选择**（一次性）→ 按 `template.modes[i].build(ctx)` 设计时物化展开为普通节点链 → 占位节点移除（与 demo_pipeline 同机制，I1 已验证）→ **展开后每节点=标准组件节点**（六区块+业务表单照常、可增删插节点）→ 保存工作流时自动打 `同步` 标签（WfDefinition.tags）。

### 3.2 内置模板两套（build 生成函数）

**模板 A：源表基准**（知道源库表，选好读写端一次到位）

```
开始 → [C17 读端写端一体同步节点] →（可选）[C11 对账校验 SQL] → 结束
```
- C17 节点 defaults 预置：`strategy=union`（单源缺省）、读端/写端类型待用户配置；
- 对账校验节点预置 SQL 模板：`SELECT COUNT(*) FROM {目标表}` 与源行数比对注释说明（用户可改）。

**模板 B：目标表基准**（以目标表为基准，动态返选多 schema 源）

```
开始 → [C17 同步节点（strategy=标识列 默认、schema 返选表单）] →（可选）[C11 对账校验] → 结束
```
- C17 节点 defaults 预置：`strategy=src_flag`、`autoSchema=true`（裁定②自动纳入）、标识列 `src_schema`；
- 读端表单进入"按目标表返选"形态：填目标库表名 → 前端按 `ds.tree` 列出该数据源全部库中同名表 → 勾选参与 schema 集。

两模板差异仅 C17 节点 defaults 与表单预填形态；展开后均可增删插节点（如读写间插 C11 SQL 校验、C22 文件对照、C3 分支告警路由——02 文档 C23 声明）。

## 4. C17 同步执行器（F33，worker/executors/sync.py）

### 4.1 节点参数结构（ctx.param，master 已做变量替换）

```json
{
  "readerType": "mysql", "readerDs": "内置源库-ec_retail",
  "readerTable": "ods_order", "readerSchemas": ["ec_retail_east", "ec_retail_south"],
  "readerFile": {"format": "csv", "path": "samples/orders.csv", "encoding": "utf-8",
                 "delimiter": ",", "header": true, "sheet": ""},
  "incremental": {"column": "create_time", "expr": "$[yyyyMMdd-1]"},   // 可选
  "writerType": "mysql", "writerDs": "内置数仓-datara_dw", "writerTable": "ods_order_sync",
  "autoCreate": true, "truncate": false,
  "strategy": "union | src_flag | partition",
  "flagColumn": "src_schema", "autoSchema": true,
  "fieldMap": [{"from": "id", "to": "id"}, {"from": "amount", "to": "amt"}],  // 空=同名全列
  "batchSize": 1000, "errorThreshold": 0
}
```

### 4.2 执行流程

1. **准入检查**：读端连通（连接型 open_connection / 文件型 resolve_file_path+head_rows）、写端连通；目标表存在或 autoCreate（按源 schema 建表，类型映射 int/float/str/datetime→MySQL，文件源用 infer_schema 推断）。
2. **读端解析**：
   - 连接型单 schema：`SELECT {字段} FROM {db}.{table}`（增量条件附加 WHERE）；
   - 连接型多 schema（union/src_flag 策略）：逐 schema 生成 `SELECT {字段}, '{schema}' AS {flagColumn} FROM {schema}.{table}` 分支，UNION ALL 连接（strategy=union 不带标识列；src_flag 带；partition 逐 schema 独立读不 union）；
   - 文件型：iter_rows 流式读（复用 FileSpec，CSV/TXT 自定义分隔符/Excel）；
   - `${tmp.<名>}` 上游临时数据引用：反查 t_tmp_data 解析为物化表名或文件路径（I4 机制）。
3. **写端落库**：`executemany` 分批（batchSize）INSERT；truncate=true 时先 TRUNCATE；partition 策略写 `{writerTable}_{schema后缀}` 多目标表。
4. **逐行来源识别**：src_flag 策略标识列落库即天然逐行可查（`WHERE src_schema='ec_retail_east'`）。
5. **脏数据容忍**：单批 executemany 异常 → 逐行重试定位，坏行计数；超 errorThreshold → failure（日志列出坏行号与原因），未超 → 剔除坏行继续。
6. **统计输出**：outputs = `{read_rows, write_rows, bad_rows, rows_per_sec, batch_id(=instance_id), schemas_included}`；实时进度经 ctx.log 打 `[sync] 进度: 已读 N / 已写 M（速率 x 行/s）`。
7. **血缘落库（裁定④）**：成功后按 §8 调用。
8. **旁路原则**：血缘采集/探测日志异常不阻断任务终态（对齐 I5 口径）。

### 4.3 C17 业务表单（Inspector 分步 Tab，六区块自动附加）

## 5. 动态 schema 返选细节（F29/F30/F31）

- **schema 列表来源**：`GET /datasources/{id}/tree` 既有接口（SHOW DATABASES 过滤系统库 `_SYSTEM_DBS`），前端返选控件多选 schema，同名表自动对齐（目标表基准=各库下同名表集合）。
- **标识列自动附加**：src_flag 策略下每个 union 分支附加常量列；前端预览生成 SQL（变量未解析形态）供用户确认。
- **运行时探测（裁定②）**：执行器按 readerSchemas 已选集 + autoSchema 开关 → SHOW DATABASES 求差集 → 差集库存在同名表即纳入分支集合；纳入明细打印任务日志；schemas_included 输出参数记录实际参与集。
- **建表口径**：autoCreate 按首个参与 schema 的表结构建目标表；标识列/无标识列策略分别追加 `src_schema VARCHAR(64)` 列（src_flag 时）。

## 6. 数据面与批次（F34 落地口径）

- **同步批次号 = instance_id**（裁定③）：C17 outputs `batch_id` 显式输出；实例日志、血缘 instance_id 维度、临时数据标签同一主键。

- **api 新增**：api/sync.py 一个文件两个接口：`GET /sync-tasks`（列表聚合）、`GET /sync-tasks/{wf_code}/instances`（实例明细含读写统计）。零 DDL。
