## 二、EVENT 触发（RT-05 / RUNTIME 报告 RT-19）

### 裁定
**暂缓** EVENT 触发实现，判定为**设计契约缺口**（非实施侧缺陷）。

### 核实证据
| 证据点 | 内容 | 结论 |
|---|---|---|
| 设计正本 L611 | 仅列出触发类型名 `EVENT`（五类之一） | 无事件源/订阅/实例关联契约 |
| 设计正本 §13.3（L603-642） | 调度字段与运行拓扑，无 EVENT 事件源章节 | 入站事件契约缺失 |
| `execution_event` 表 | 对应 `ExecutionEventRecord`（`workflow_instance_id`/`event_kind`/`payload_json`/`event_time`），含 `(workflow_instance_id, event_kind)` 联合索引、`RESULT_STAT_EVENT_KIND` 幂等收据 | **出站运行记录**，非入站触发源 |
| `master/event_bus.py` | 仅 `PROGRESS_EVENT`（进度事件） | 进度事件非触发事件 |

**结论**：设计正本确无 EVENT 触发契约（事件源标识 → schedule 订阅 → 运行实例关联）。Codex 报 T55 阻塞属实，属设计层缺口，非实施侧可自解。

### 落地方案
- T55 收缩：剔除 EVENT（RT-05）部分，保留**调度四字段（RT-01~04）+ failover 跨进程 fencing（RT-06）**，重发单 `s108-t55-shrink`。
- WBS §6.2 RT-05 行标注为「暂缓（S109）：设计契约缺口」。
- RUNTIME 报告 §四编号映射：报告 RT-19=EVENT触发、RT-21/22=调度字段、RT-24=failover fencing；本任务池实锚采用 WBS §6.2 编号（RT-01~04=调度四字段、RT-05=EVENT、RT-06=fencing）。派单以 WBS 编号为准。

### 后期启动条件
1. 设计正本补充「事件触发契约」章节，定义：事件源类型与标识、事件载荷 schema、schedule 订阅关系（`event_source_id`/`event_type` 字段）、事件→运行实例关联规则、幂等与去重策略；
2. 用户明示解禁。
