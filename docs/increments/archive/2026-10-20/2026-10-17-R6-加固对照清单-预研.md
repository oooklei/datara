## 范围澄清

本清单中的“P2-1 执行引擎加固”是 Datara 自研 DAG 引擎按 DolphinScheduler（DS）语义加固，遵循“复刻语义，不重写、不外挂 DS 运行时”。它不是 P1 冻结宣言的“R6 调度 API”域（`listQueue`、`listRuntimeEvents`、`listAlerts`）；API 契约冻结不表示端点实现或 GREEN，两个域分开跟踪。

## 优先顺序与关门条件

1. **先完成 P0 retry + failover 语义裁定**：配置单位、attempt 表达、deadline、人工恢复与 failover 的关系、幂等保证。Retry 与 failover 共用 attempt/run/idempotency 约束，不应分开设计后再拼接。
2. **再完成 P1 backfill**：冻结 batch/date/timezone/order/parallelism/partial-recovery 契约后实现逐日实例追踪与恢复。
3. **最后完成 P2 priority**：在任务与队列语义稳定后裁定 DS enum 映射、两级以上排序及公平性；不与补数或 R6 查询 API 混为一个需求。
4. 四项都必须有 Datara 实现锚、自动化边界/故障测试和可复核运行结果；本预研只说明现状与待办，任何一项缺证均保持 RED，不能宣称 R6 执行引擎 GREEN。

工作量按相对规模待设计契约裁定后评估；本清单不报未经验证的人日。若增加持久 attempt/batch 迁移、multi-master fencing 或远端 HA，需重新估量范围。
