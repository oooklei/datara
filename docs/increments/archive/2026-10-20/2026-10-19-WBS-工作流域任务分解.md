### A. 草稿快照机制（§4.1「生成草稿快照」）

|---|---|---|---|---|---|
| WF-10 | `workflow_draft_snapshot` 模型 | WF-01 | §4.1/§3.1 | 新增 `rebuild/trial/models.py`（或 `workflow` 子模块）映射 `workflow_draft_snapshot` 表：`id / definition_id / snapshot_digest / node_snapshot_json / edge_snapshot_json / status / created_by / created_at`；`UniqueConstraint(definition_id, snapshot_digest)`；`__table__` 正确；纳入 `app.py` 的 `create_all` 表清单。pytest：建表后 `select count(*)==0` | S |
| WF-11 | 草稿快照 repository | WF-02、WF-10 | §4.1 | `TrialSnapshotRepository.create_from_draft(definition_id)`：读当前草稿 node/edge（version_id NULL）→ 计算 `snapshot_digest` → 写快照行（status=ACTIVE）；`get` 返回快照 + 解析 JSON；重复草稿幂等（同 digest 不重复建行）。pytest：草稿变更后 digest 变化；同草稿二次 create 不产生新行 | M |

## 5. 风险与边界

1. **版本不可变边界**：WF-21「结果转正式版本」必须经 `publish()` 生成 PUBLISHED 版本，不得直接改草稿行；WF-04 的 `WF_VERSION_IMMUTABLE` 守卫需保持。
2. **草稿快照 ≠ 发布快照**：`workflow_draft_snapshot`（WF-10）与 `workflow_version.snapshot_digest`（WF-03）是两套独立机制，前者服务 TRIAL 试运行、后者服务 FORMAL 正式运行，不可混用。
3. **execution 域 api 缺口**：`rebuild/execution/` 仅有 models.py + repository.py，WF-23 必须补 api.py，否则 TRIAL/FORMAL 实例无法经 HTTP 暴露。
4. **时间戳约定**：新增表遵循 §9（`created_at`/`updated_at`/`generated_at` DB 生成），WF-10 需对齐。
5. **变量域归属**：WF-17 测试变量覆盖只写 `task_instance_variable_runtime`（运行时快照），不污染 `variable_definition`；草稿内嵌变量属 `variables` 域，读取而非改写。
