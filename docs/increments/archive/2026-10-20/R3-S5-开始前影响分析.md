## S4 改动对 S5 的影响

- 新 API 已在 `datara-backend/rebuild/governance/api.py` 实现，并使用 `governance/service.py` 与 `governance/repository.py` 处理项目权限和事务内审计。
- 前端可用契约：资产筛选/分页/详情、字段、项目标签与资产标签替换、表/字段血缘、质量规则和已持久化质量运行历史、标准、语义指标、审计查询。
- R3 API 并未注册数据库自动迁移；应用 startup 仍只创建 I1 核心表。S5 页面开发不会运行远程 DDL、导入或写入远程库。S6 才可对隔离 `datara_rebuild_i0` 进行 dry-run/迁移演练；S7 才做正式页面端到端操作和日志/数据库核验。
- 兼容边界：独立静态验证页部署在 Web `18091`，不改正式 Vue 页面、菜单、路由、SPA bundle，也不引入旧 Datara 前端组件。页面通过部署在服务端的验证运行器注入短期受限 token；key 不入浏览器。

## 参考交互与范围

参考 OpenMetadata 官方资产详情交互：资产详情以 Schema、Activity/Tasks、Sample Data、Queries、Data Observability、Lineage 等按资产类型呈现的标签组织；Lineage 显示上下游与表/列关系，并能从节点查看资产摘要。目录页使用类型和属性过滤发现资产。参考依据：[OpenMetadata Detailed View of the Data Assets](https://docs.open-metadata.org/v1.12.x/how-to-guides/data-discovery/details)、[How to Discover Assets of Interest](https://docs.open-metadata.org/v1.13.x-SNAPSHOT/how-to-guides/data-discovery/discover)。该页仅借鉴交互组织，不复制旧 Datara 视觉或功能实现。

本验证页是用于真实后端验收的独立工作台，不是 API 控制台：

1. Catalog：项目选择、资产搜索、类型/域/标签筛选、分页；资产行展示来源、schema、owner、域、更新时间和标签。
2. Asset detail：概要与字段清单；Lineage 面板可选方向/深度并显示真实图边；Quality 面板分开显示规则和真实运行历史/行数；治理信息显示标签、标准、语义指标和审计事件。
3. 操作表单：新建资产及字段、建/选标签并关联资产、创建血缘、定义质量规则、标准和语义指标；成功/拒绝/重复冲突均显示后端响应与页面操作时间。
4. 权限闭环：用 token 的 dev 权限演示允许操作；由服务端受限角色完成只读/拒绝用例，不伪造 403；日志和审计时间戳用于对账。
