# WF 工作流域预研报告

## 现有任务池完整性评估

- **WF-01~WF-09**：已提交（20f1e06b），状态：已完成。`rebuild/workflow/` 下六模型（models.py）、repository.py（含 `snapshot_digest`、`WF_VERSION_IMMUTABLE`、`WF_DEFINITION_HAS_PUBLISHED` 守卫）、api.py（12 端点）、app.py 挂载、auth/permission 门、9 域测试均已成型。
- **WF-10~WF-12（A 组 草稿快照）**：代码已大量实现。`rebuild/trial/models.py`（WF-10）、`TrialSnapshotRepository`（WF-11）、`build_trial_router`（WF-12）均已存在。**但 WF-12 仅暴露 2 个快照端点**（`POST /definitions/{id}/snapshot`、`GET /snapshots/{snapshot_id}`），缺少运行/输出/promote 端点（见缺陷 #1）。
- **WF-13~WF-23（B 组 TRIAL 八能力）**：代码已大量实现。`TrialValidator`（WF-13）、`TrialRunner` + `TrialRunOptions` 六维度（WF-14~WF-20）、`TrialPromoter`（WF-21）、`TrialOutputAggregator`（WF-22）、`build_execution_router`（WF-23）均已存在。**但 WF-21/WF-22 无 HTTP 端点暴露**（见缺陷 #2），**SKIPPED 状态未真正实现**（见缺陷 #3）。
- **WF-24（E2E）**：`test_trial_e2e.py` 存在，**但未真正覆盖全链路**——promote/run 被注释绕过（"if not mounted, this will 404"），仅验证快照链。
- **WF-25（收尾）**：⬜ 待做。

**结论**：WF-01~WF-23 的**领域逻辑层（models/repository/runner/validator/promoter/output）已基本成型**，但 **HTTP 暴露层（trial router 端点）严重缺失**，导致 WF-14~WF-22 的八能力无法经 API 调用，WF-24 E2E 全链路测试无法真正跑通。

| 序号 | 功能描述 | 现状 | 建议任务单 |
|---|---|---|---|
| #1 | **TRIAL 运行 HTTP 端点缺失**：`trial/api.py` 仅有 2 个快照端点，缺少 `POST /trial/runs`（创建 TRIAL 运行，承载 WF-14/15/16/17/18/19/20 六能力）、`GET /trial/runs/{run_id}`（输出聚合，WF-22）、`POST /trial/runs/{run_id}/promote`（转正式，WF-21） | `TrialRunner`/`TrialPromoter`/`TrialOutputAggregator` 均已实现但无路由暴露 | 新增 WF-26 |
| #2 | **TrialPromoter 无 HTTP 暴露**：`promote.py` 模块完整（验证 TRIAL 实例、取快照 digest、幂等、调 `publish`、写 PROMOTED 事件），但无 `POST /trial/runs/{run_id}/promote` 端点 | 模块已实现，路由缺失 | 并入 WF-26 |
| #3 | **SKIPPED 状态未真正实现**：`runner.py` L156-162 注释明确 "TRIAL has no SKIPPED state; we use FAILED with a skip marker log"，但 WF-15/16/18 验收标准要求"未指定节点 `status==SKIPPED`"。且 skipped task 创建后未显式 transition 到终态，会停留在 PENDING | 用 FAILED+WARN 日志模拟，未落 SKIPPED 终态 | 新增 WF-27 |

| #7 | **skipped_nodes 未显式 transition**：`runner.py` L157-162 对 skipped 节点只 `create_task_instance` 后注释说用 FAILED+log 模拟，但未调用 `transition_task_instance`，task 会停留在 PENDING 终态 | skipped task 状态不完整 | 并入 WF-27 |
| #8 | **task_id 存储 node_code 而非 task_definition id**：`runner.py` L132 `create_task_instance(task_id=node_code)` 将 node_code 字符串作为 task_id，与 execution 域 task_id 语义（应指向 task_definition）可能不一致 | 语义混用 | 新增 WF-29（需确认设计正本 §3.2 对 task_id 的定义） |
