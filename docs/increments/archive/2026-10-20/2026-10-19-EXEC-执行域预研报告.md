## 遗漏/缺陷功能清单

- [D-1] **TRIAL 统计隔离缺失（P0 实质缺陷）**：`record_result_stat`（repository.py L222-291）不区分 `instance_type`——TRIAL 实例上报的统计会按 `(workflow_id, run_date)` 累加进 `workflow_result_stat`，与 FORMAL 混算。直接违反 EXEC-07 验收标准"试运行结果不影响正式运行统计（隔离验证）"。需按 instance_type 过滤或 TRIAL 不累加，并补隔离单测。
- [D-2] **执行六表未注册 lifespan（P0）**：app.py `create_all(tables=[...])` 28 表清单不含 EXECUTION_TABLES；EXEC-05 验收"lifespan 包含六张执行表"未达。当前全部为未提交修改。
- [D-3] **EXEC-09 验收标准职责重叠（WBS 缺陷）**："位点记录（checkpoint）"属 I8 流表域——stream 域已建 `stream_checkpoint` 表（T47 产出），models.py 注释亦明确"stream job runtime state 是 I8 stream-table slice"。execution 域只需管 STREAM 实例生命周期，checkpoint 不应列为 EXEC-09 验收。
- [D-4] **EXEC-10 旧线文件名错误（WBS 缺陷）**：旧线文件为 `datara-backend/api/instance.py`（单数），prefix `/instances`，含 stop_instance/rerun_instance/rerun_failed/stream_instance 六个端点；WBS 所写 `/api/instances.py` 不存在。
- [D-5] **EXEC-11 表数错误（WBS 缺陷）**："十六张表"应为 **15 张**（逐一点名设计 §13.13 清单）。
- [D-6] **EXEC-09"长驻 RUNNING"验收无对应机制**：STREAM 实例 RUNNING 可长期停留是状态机自然结果（无超时字段），无专门实现项；验收标准应改为"验证无超时限制"而非暗示需开发心跳机制（心跳属 stream 域）。
- [D-7] **大量产出未入库（P0 风险）**：EXEC-02~06 全部产出（6 源文件 + 4 测试文件 + app.py）处于 M/?? 未提交状态，距 e9a5a36 之后未落盘，与 EXEC-01 要解决的"被清理风险"同源。
- [D-8] **execution/api.py 跨域 import 边界模糊（P2）**：api.py 直接 import `TrialSnapshotRepository` 与 workflow 三模型用于编排，而 models.py 强调"plain integer reference、不 import workflow 域"。编排需求合理，但"模型层解耦、API 层可编排"的边界原则未在文档明确，后续易被误改。
