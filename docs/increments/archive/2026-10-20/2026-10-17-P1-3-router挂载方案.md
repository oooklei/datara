# P1-3 R8-A Router 挂载准备方案

日期：2026-10-17（Asia/Shanghai）  
状态：只读调研方案，非实现；须与 R8-A v1 契约冻结结果复核后再接线。

## 1. 调研结论

R8-A router 应挂载到 `datara-backend/rebuild/api/app.py:create_app`，由 Rebuild API 工厂注入认证、项目授权、审计和既有 SQL 执行服务；不挂到旧版 `datara-backend/api/main.py`。

理由：`rebuild/api/app.py` 已是可注入依赖的应用工厂，当前将 router builder 接收的 session/token/权限服务以 `include_router(..., prefix="/api/v1/rebuild/...")` 方式装配（`rebuild/api/app.py:78-91,706-736`）。旧 `api/main.py:create_app` 是另一个服务入口，统一将旧模块 router 挂到 `/api/v1`（`api/main.py:34-35,52-55,85-121`），没有 Rebuild 项目授权及 R8-A 服务注入面。把 AI 工具放入旧入口会造成两套身份/权限宿主分叉。

## 2. 挂载点、URL 与 OpenAPI 标签

### 推荐装配形式（供 P1-3 实施采用）

- Router builder 放在 AI 模块边界内，例如 `datara-backend/ai_copilot/api.py`，提供 `build_copilot_router(...)`；构建器接收明确的服务端依赖，不在路由模块自行创建全局数据库、Vanna 或执行器实例。
- `rebuild/api/app.py:create_app` 在建立 `current_user`、项目权限、审计仓储及 R5-A 执行服务后，构建并挂载该 router。router builder 必须能在应用工厂调用时接收这些依赖，生命周期由 Rebuild API 负责。
- 建议统一挂载前缀 `/api/v1/rebuild/ai`，OpenAPI 标签 `rebuild-ai`。router 内部路径保持短且稳定：
  - `GET /tools`：工具注册表；
  - `POST /tool-calls`：R8-A 统一工具调用信封。
- 不建议把每个 tool 注册成独立 HTTP endpoint，也不建议另造 SQL 执行路由。`tool` 名称、版本、参数及响应均走 R8-A 信封。

### 契约路径差异（需在 R8-A 冻结时修订）

《R8-A 八工具契约》v1 草案第 2.1 节写为 `/api/rebuild/ai/tools` 与 `/api/rebuild/ai/tool-calls`，而 Rebuild API 现有正式挂载惯例为 `/api/v1/rebuild/...`。建议将草案路径统一改为：

- `GET /api/v1/rebuild/ai/tools`
- `POST /api/v1/rebuild/ai/tool-calls`

这是 API 版本前缀的一致性修订，不改变信封字段或工具清单。实现前需让 R8-A 契约 owner 将该修订纳入正式版本；不要在路由代码中同时兼容两个未定路径。

## 3. 与 P1-0 步骤 3 的桥接清单

P1-0 步骤 3 定义最小 PoC 链路为 `generate_sql` → Datara 只读授权校验 → `run_sql` 既有执行链路，并要求 `generate_sql`、`run_sql`、`search_schema` 三工具通过契约测试（`2026-10-17-R8-V-Vanna-PoC-实施计划.md:31-35`）。R8-A v1 草案则定义统一的 `GET tools` 与 `POST tool-calls` 信封，并列出八个工具；其工具清单不含 `generate_sql`（`2026-10-17-R8-A八工具契约.md:19-26,32-40`）。两者接口层次需明确分开：

1. `CopilotService` / Vanna adapter 的 `generate_sql` 是内部生成能力，返回 SQL 文本，不获得 SQL runner，不执行 SQL。
2. R8-A router 只提供统一工具注册/调用入口。`search_schema` 由 Datara 元数据目录服务处理；`run_sql` 由 R8-A handler 完成权限、预算、审计后委托 R5-A 既有执行服务。
3. 若 P1-3 PoC 页面/调用方必须直接请求生成 SQL，应由契约 owner 决定是否在统一 `tool-calls` 工具表中新增 `generate_sql`，或定义受控的 Copilot 编排入口；不得由 router 私自增加第九个工具或把内部 adapter 方法伪装成已冻结的 R8-A 工具。
4. SQL 生成与执行必须是两个明确步骤。生成响应仅含待审阅 SQL；未通过 Datara 授权的 `run_sql` tool-call 不得触达 R5-A 执行服务。

## 4. 注入边界与可验收路由约定

- 身份：从 Rebuild API 的认证上下文取得 user/project；不得相信请求体自报身份作为授权依据。
- 路由层只负责解析统一信封、取得可信上下文、调用 R8-A registry/dispatcher 并形成约定响应；不直接导入 Vanna 类，也不自行连接数据源。
- `run_sql` 必须注入既有 R5-A 执行服务/授权 handler；禁止通过 Vanna `run_sql` 或新建 SQLAlchemy connection 绕行。
- 每个工具调用（成功/失败）均由 R8-A 审计服务产生 `audit_id`，并贯穿 `tool_call_id`、user/project、run/datasource refs；AI 路由不在 adapter 内记录 SQL/提示词正文。
- Router builder 的单元/契约测试应覆盖：`create_app` 返回应用后 OpenAPI 中存在目标两条路径与标签；未认证/跨项目请求在 handler 前被拒绝；成功调用经过 registry 与审计注入；`run_sql` 仅调用既有执行端口；异常按 R8-A envelope 映射。

## 5. 主要风险与冻结前决策

| 项 | 观察 | 处理建议 |
|---|---|---|
| 前缀不一致 | R8-A 草案缺 `/v1`，Rebuild router 使用 `/api/v1/rebuild/...` | R8-A owner 在冻结时统一路径；实施按冻结版，不做双路径别名 |
| `generate_sql` 是否为注册工具 | P1-0 PoC 需要生成能力，R8-A 八工具枚举未列该工具 | 冻结前决定新增工具或内部编排入口；本方案不擅自扩展八工具 |
| 权限宿主 | 旧 API 与 Rebuild API 是独立 FastAPI app | 挂载到 Rebuild API factory，使用 Rebuild 项目身份与授权上下文 |
| 执行绕行 | Vanna 生态本身存在 SQL runner 能力 | Vanna adapter 仅生成；R8-A `run_sql` handler 唯一进入 R5-A 的路径 |
| 生命周期/共享状态 | `create_app` 为 Rebuild 服务依赖的装配点 | 依赖按应用工厂注入，避免模块级全局 client 或跨应用共享用户态 |
