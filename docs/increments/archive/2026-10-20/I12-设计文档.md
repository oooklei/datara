## 1. 四分类语义模型与组件矩阵

### 1.1 分类语义
| 分类 | 语义定义 | 场景特征 |
|---|---|---|
| **同步** | 数据搬运：以结构映射为主，不做业务变换 | 库→库全量/增量、文件→库、反向以目标表为基准反推源 |
| **ETL** | 批量加工：SQL 为变换主体（含 ELT 先入仓后加工） | ODS→DWD→DWS 分层、清洗/聚合/拉宽、入仓前校验 |
| **流** | 持续摄入 → 窗口聚合 → 融合 → 服务化输出 | 多源接入、周期窗口聚合、union/join 融合、API+看板 |
| **普通** | 通用编排（未显式分类即此类） | 脚本巡检、HTTP 拉取、SSH 批执行、出仓归档（调度壳不做，R7） |

## 3. 新增组件规格（构件五要素：属性/方法/输入/输出/参数）

### 3.1 C24 文件同步（sync 类主件）
- **用途**：Excel/CSV/TXT 文件 → 库表，补齐同步类「文件源入仓」场景。
- **输入**：上游任意节点（可独立起头）；**输出**：目标表 + 批次号 `${instance_id}`；**状态**：对齐 ExecutionStatus（成功/失败/终止）。
- **属性表单**（六区块）：
  | 区块 | 字段 | 控件 | 来源 |
  |---|---|---|---|
  | 输入 | 文件来源 | `dir-select`：SSH 注册目录浏览下拉（运行时节点→目录树） | 新 API /runtime-nodes/{id}/ls |
  | 输入 | 备选：上传暂存 | 上传控件 → 存 worker 暂存目录 `{instance_id}_` | 已有上传通道 |
  | 输入 | 文件类型 | select：csv/txt/excel | 硬编码 |
  | 输入 | 分隔符/编码/表头行数 | text/select | 手填（文件语义无法枚举） |
  | 参数 | 目标数据源 | datasource 下拉 | 已有 |
  | 参数 | 目标 schema→表 | `table-picker` 级联下拉 | 新 API /datasources/{id}/tables |
  | 参数 | 新建表 | 开关 + DDL 预览（按文件头推断类型，可编辑） | 前端生成 |
  | 参数 | 写入模式 | select：追加 union / 覆盖 / 标识列（对齐 C17 合并策略语义） | 硬编码 |
  | 排除 | 字段映射 | 自动按表头对齐 + 可调（复用 C17 映射交互） | — |
- **执行**：worker 新执行器 `file_sync`（内部复用 C22 文件解析 + sync 写端链路）；**三处同源注册**：master/engine.py WORKER_TYPES + failover.py + worker EXECUTORS（I6 教训）。
- **日志**：任务日志含文件行数、写入行数、忽略行数；临时文件 `{instance_id}_` 前缀，随保留策略清理（F50 脚本口径）。

### 3.2 C25 数据校验闸门（etl 类主件）
- **用途**：流程内自动化验收——行数/唯一性/空值/自定义断言，不达标断流。
- **输入**：上游结果表或任意表；**输出**：双出口（通过→下游继续 / 失败→断流或告警继续）+ 校验报告入任务日志；**状态**：对齐 ExecutionStatus，失败=节点失败。
- **属性表单**：
  | 字段 | 控件 | 说明 |
  |---|---|---|
  | 校验对象 | 上游节点引用下拉（列出直接上游节点，对象表自动取该节点声明的输出表：SQL 节点=结果引用表、C17/C24=目标表）/ `table-picker` 手选 | 二选一 |
  | 规则集（可多行） | 行类型+参数：行数区间[min,max] / 指定字段主键唯一 / 字段非空率≥x% / 自定义 SQL 断言（首行首列=1 通过） | 字段选择走 `field-select`（新 API /datasources/{id}/fields） |
  | 不达标动作 | select：断流失败 / 告警继续 | 硬编码 |
- **执行**：master 内联逻辑节点（同 C1~C10，不进 worker 队列）。
- **用例价值**：P2 各类用例的「验收标准」可在流程内由 C25 兜底验证。

### 3.3 C26 通知（通用件）
- **用途**：工作流/分支收尾通知（webhook + 日志），流类服务化与普通类巡检场景收口。
- **输入**：上游任意节点；**输出**：无数据输出；**状态**：对齐 ExecutionStatus。
- **属性表单**：
  | 字段 | 控件 | 说明 |
  |---|---|---|
  | 通道 | select：webhook / 仅日志 | 硬编码 |
  | URL | text，支持 `${var}` 引用 | 变量链已有 |
  | 触发时机 | select：上游成功 / 上游失败 / 无论成败 | 覆盖失败通知场景（不另设错误处理组件） |
  | 消息模板 | textarea，内置变量提示：`${wf.name}` `${instance_id}` `${node.name}` `${node.status}` `${sys.now}` | 渲染走 vars_render |
- **执行**：worker 执行器 `notify`（http POST + 日志落盘，超时 10s，失败不重试、可配置是否影响工作流状态：默认失败仅告警不断流）。

### 3.4 备选池（本期不实现，构件明确后另行裁定）
- **stream_sql 流 SQL 窗口件**：流上窗口 SQL（复杂度高，I8 语义已覆盖 union/join/窗口聚合，后置）。
- **webhook 触发器**：HTTP 触发启动工作流（依赖开放接口通道，后置一并考虑）。
- 触发器/循环迭代等 n8n 件：现有 conditions/loop/变量已覆盖用例需要。

## 4. 表单动态化「选择代替填空」（全栈）

### 4.1 后端新增 4 个轻量 API（均挂 /datasources、/runtime-nodes 现有路由文件，鉴权一致）
| API | 用途 | 底层 |
|---|---|---|
| GET /datasources/{id}/tables?schema= | 库/表列表 | 复用 I10 dsconn 元数据能力 |
| GET /datasources/{id}/fields?schema=&table= | 字段列表 | 同上 |
| GET /stream-sources/{dsId}/topics | Kafka topic 列表 | 经注册流源连接拉取（启动预检同级超时口径） |
| GET /runtime-nodes/{id}/ls?path= | SSH 目录浏览 | paramiko（远程文件管理既有 SSH 通道） |

### 4.2 前端控件扩展（FieldSchema 新控件类型）
- `table-picker`：datasource→schema→table 级联（Inspector 内联动，选中即写回字段值）。
- `field-select`：依赖已选表，多选/单选。
- `topic-select`：依赖 dsRef，拉注册源 topic。
- `dir-select`：依赖运行时节点，懒加载目录树（复用 IDE 资源树交互模式）。

### 4.3 既有组件表单改造清单
| 组件 | 改造点 |
|---|---|
| C11 SQL | datasource 保留；新增库/表侧栏选择器（点选插入 SELECT 骨架/表名 token，不替代 SQL 手写）；pre/post/超时/结果引用名维持 |
| C17 sync | 读端/写端 ds 下拉已有 → 表升级 `table-picker`；字段映射自动对齐保留；合并策略三选一保留 |
| C23 模板 | 模板选择→物化链不变；物化后各 sync 节点继承 C17 新表单 |
| C24/C25/C26 | 按 §3 规格新建 |
| 流三件套 | stream_input：dsRef 引用后 brokers/topic/group 由注册源**带出只读**（可覆盖开关）；窗口类型 tumble/sliding/session 下拉 + 结构化参数（大小/滑动步长/水印延迟）；stream_fuse：union/join 语义标注维持（W1），join 键选择升级 `field-select`；stream_output：四通道结构化（API/库表/Kafka/文件），库表通道走 `table-picker` |
| Dependent | 工作流下拉已有（复用），节点选择保留 |
| 变量组件 | 引用提示补齐「优先级：节点参数>工作流变量>环境组>全局」 |

### 7.2.1 S3 反向同步方案细化（遵 I6 既定设计，不得走偏）
> 依据：I6-设计文档.md §4 模板 B、§5 动态 schema 返选（F29/F30/F31）；C17/C23 现有实现。**本用例不新造机制，全部复用既有语义，仅做用例化包装与表单口径校验。**

**固定操作流（用户裁定顺序）**：
1. **选目标表（前置依赖先行）**：目标实例 → 目标库 → 目标表，级联选择（`table-picker`，走 /datasources/{id}/tree）。
2. **选源实例后探测**：选定源实例（数据源）后，按用户**输入的表名**（默认带出目标表名）或**选择的表名**，在源实例全部 schema 中探测同名表（`ds.tree`），前端列出「schema × 同名表」清单供勾选参与 schema 集。
3. **union 或其他方案（新增溯源字段）**：合并策略三选一——追加 union（不带溯源）/ **schema 标识列（默认）**：每个 union 分支附加常量列 `'<schema>' AS src_schema`（溯源字段名可配，逐行来源 `WHERE src_schema='…'` 可查）/ 分区隔离（逐 schema 独立读不 union）。
4. **运行时探测（既有裁定②延续）**：设计时选项 autoSchema（默认自动纳入）——执行时 SHOW DATABASES 对比已选集，新增 schema 同名表自动纳入分支并打印日志、输出 schemas_included。
5. **建表口径**：autoCreate 按首个参与 schema 表结构建目标表；src_flag 策略追加 `src_schema VARCHAR(64)` 列。

**验收锚点**：结果行数 = 各参与 schema 同名表行数之和；溯源断言 `WHERE src_schema='ec_retail_east'` 命中该 schema 行数；运行前新增第三 schema 同名表验证 autoSchema 自动纳入（日志 + schemas_included）。
