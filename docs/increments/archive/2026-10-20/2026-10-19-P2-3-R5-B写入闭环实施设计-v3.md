## 2. 数据模型

### 2.1 核心模型（`rb_models.py`）

```python
@dataclass(frozen=True)
class ObjectRef:
    datasource_id: int
    database: str
    catalog: Optional[str]
    schema: Optional[str]
    kind: str          # table/view/function/procedure/trigger
    name: str
    parent: Optional[str]

@dataclass(frozen=True)
class PolicySnapshot:
    snapshot_id: str           # UUID
    project_id: int
    datasource_id: int
    object_ref: ObjectRef
    source_version: str        # ETag from getDefinition
    next_ddl_digest: str       # SHA-256 of nextDdlText
    policy_version: str
    findings: list[PolicyFinding]
    blocked: bool
    created_at: datetime
    expires_at: datetime

@dataclass(frozen=True)
class PolicyFinding:
    level: str                 # block/warn/info
    code: str
    message: str
    impacts: list[str]

@dataclass(frozen=True)
class ImpactSnapshot:
    snapshot_id: str           # UUID
    project_id: int
    datasource_id: int
    object_ref: ObjectRef
    source_version: str
    next_ddl_digest: str
    policy_snapshot_id: str    # 绑定同一 policy snapshot
    impacts: list[ImpactItem]
    unknown_reasons: list[str]
    created_at: datetime
    expires_at: datetime

@dataclass(frozen=True)
class ImpactItem:
    object_ref: ObjectRef
    relation_type: str         # dependent/downstream/permission
    detail: str

@dataclass
class ExecutionRecord:
    record_id: str             # UUID
    project_id: int
    datasource_id: int
    object_ref: ObjectRef
    action: str                # DDL action type
    script_hash: str           # SHA-256 of executed DDL
    executed_at: datetime
    status: str                # success/failure/rolled-back/compensated/recovery-failed
    failure_summary: Optional[str]
    policy_snapshot_id: str
    impact_snapshot_id: str
    compensation_refs: list[str]  # record_ids of compensation actions
    actor_id: int              # user who confirmed
```

### 3.1 G-B6 Policy Snapshot 绑定（`policy_snapshot.py`）

**职责**：将 `ddl_policy.py` 的纯函数输出绑定到持久化 snapshot，提供版本漂移检测。

**接口**：
```python
class PolicySnapshotService:
    def evaluate_and_snapshot(
        self,
        project_id: int,
        datasource_id: int,
        object_ref: ObjectRef,
        source_version: str,
        next_ddl_text: str,
    ) -> PolicySnapshot:
        """执行策略评估并创建持久 snapshot。
        - 计算 next_ddl_text 的 SHA-256 digest
        - 调用 ddl_policy.py 评估
        - 任何 block 级别 finding → blocked=True
        - snapshot 绑定 project/object/sourceVersion/digest
        - 过期时间 = now + POLICY_TTL (默认 30min)
        """
        ...

    def validate_snapshot(
        self,
        snapshot_id: str,
        project_id: int,
        datasource_id: int,
        object_ref: ObjectRef,
        source_version: str,
        next_ddl_text: str,
    ) -> PolicySnapshot:
        """验证 snapshot 仍然有效（版本/digest/过期）。
        - source_version 漂移 → 409 IDEMPOTENCY_CONFLICT
        - DDL 文本变更 → 409
        - snapshot 过期 → 409
        - 返回原 snapshot 供 audit 重读
        """
        ...
```

### 3.5 G-B1 DDL 执行器（`ddl_executor.py`）

**职责**：按 ObjectRef/driver capability 执行受控 DDL。

**接口**：
```python
class DdlExecutor:
    def execute(
        self,
        project_id: int,
        datasource_id: int,
        object_ref: ObjectRef,
        ddl_text: str,
        confirmation: Confirmation,
        policy_snapshot: PolicySnapshot,
        impact_snapshot: ImpactSnapshot,
    ) -> ExecutionRecord:
        """执行 DDL 写入。
        前置条件（全部满足才执行）：
        - policy_snapshot.blocked == False
        - impact_snapshot 有效
        - confirmation 有效
        - source_version 未漂移
        - 调用者有写权限

        执行步骤：
        1. 获取写连接（与只读连接隔离）
        2. 保存前像（原定义）
        3. 执行 DDL
        4. 记录结果
        5. 失败时调用 RollbackManager

        返回 ExecutionRecord，状态为 success/failure/rolled-back/compensated
        """
        ...

    def _get_write_connection(self, project_id: int, datasource_id: int):
        """获取写连接。写账户与只读账户分离。"""
        ...

    def _save_pre_image(self, object_ref: ObjectRef) -> str:
        """保存原定义前像，返回 pre_image_id。"""
        ...
```

## 6. 安全边界

| 边界 | 规则 |
|---|---|
| 只读 vs 写连接 | R5-A 只读连接与 R5-B 写连接使用不同凭据，写连接权限最小化 |
| Agent 禁止代填 | confirmPhrase 只能由用户通过 UI 输入，agent 不得代填 |
| driver editable | DBX `ObjectSource.editable` 不授予 Datara 用户写权限 |
| 凭据隔离 | 写连接凭据不进入日志/审计/错误响应 |
| 项目隔离 | 跨项目资源统一返回 404，项目内无权限返回 403 |
| 审计独立 | DDL execution ledger 不随 SQL history 删除级联，保留 ≥365 日 |

## 9. 攻坚点专项设计

### 9.1 #23 血缘分析（G-B4）

**问题**：当前无血缘分析服务，`DatasourceEngineRegistry` 是连接池注册表，不是对象目录/血缘服务。

**方案**：
1. 基于 `information_schema` 实现只读依赖查询（MySQL/PostgreSQL 通用）
2. 解析 DDL AST 确定影响范围
3. 方言不支持/无法解析 → 返回 unknown_reasons，不伪称无影响

**验收**：
- 真实关系：视图依赖表、存储过程依赖表
- 无关系：独立对象
- 权限拒绝：不可见对象
- 方言 unsupported：返回 unknown

### 9.2 #24 DDL 执行器（G-B1）

**问题**：当前无生产 DDL executor，R5-A readonly port 明确不得承接 DDL 写操作。

**方案**：
1. 独立 `DdlExecutor`，使用写连接（与只读连接隔离）
2. 执行前保存前像（原定义）
3. 执行 DDL 并记录结果
4. 失败时调用 `RollbackManager` 补偿

**验收**：
- DDL 成功：记录 success，原定义变更
- 确定性失败：记录 failure，目标状态不变
- 部分变更：记录 failure，触发补偿
- 补偿成功：记录 compensated，原定义恢复
- 补偿失败：记录 recovery-failed，进入人工恢复
