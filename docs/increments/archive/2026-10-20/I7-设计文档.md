## 3. 实现要点

### 3.1 C21 变量组件（F51）
- **前端表单**：变量表内联编辑（行：变量名/值/类型 select[字面量|表达式|时间变量]/覆盖开关）；defaults 含示例行 `wf.period=20261001`；summary 显示变量名清单。
- **后端语义**：master 执行流识别 `type==='variable'` 节点 → 逐条求值（表达式=沙箱求值沿用现有变量求值器；时间变量=F49 求值器）→ 写入实例运行时变量存储（`run_vars[instance_id][name]=value`，Redis Hash）→ variables.py 解析链第 2 级优先读运行时注入 → 任务日志打印变量快照（F48 衔接）。
- **覆盖开关**：开=直接写；关=仅当运行时与定义级均无该变量时写入。

### 3.2 Dependent 语义（F52）
- **前端**：C9 form 升级为依赖项列表编辑器（每行：工作流下拉（listDefinitions 接真）/ 节点下拉（随工作流定义级联）/ 可选变量条件表达式）；ports 不变。
- **后端**：master 执行 dependent 节点 → 逐条查依赖工作流最近一次成功实例（meta 实例表）→ 校验该节点状态=success → 可选变量条件求值匹配 → 全部通过→success；任一失败→按失败策略（默认失败，走重试）。
- 日志打印：`[dependent] 依赖检查：WF:A/节点a=success ✓；WF:B/节点b=failed ✗`。

### 3.3 SSH 节点 HA（F53）
- **DDL**：`t_ssh_node(id, name, host, port, ssh_user, cred_enc, tags, enabled, heartbeat_state, last_seen, created_at)`（幂等建表）。
- **接口**：POST/GET/PUT/DELETE `/api/v1/ssh-nodes` + POST `/api/v1/ssh-nodes/{id}/probe`（手动探活）。
- **派发路由**：ssh 执行器启动时按任务参数 `exec_node_tag`（节点表单新增"执行节点标签"select，选项来自 t_ssh_node）选节点：健康且匹配标签的 SSH 节点 → 连接执行；失败/不可达 → 同标签其余节点轮转 → 无可用 → 走失败策略。转派过程打日志留痕。
- **心跳**：master 起心跳线程：30s/节点 SSH `echo ok` 探活 → 更新 heartbeat_state/last_seen；连续 3 次失败标记 offline（派发路由自动剔除）。
- **master worker 容错**：任务投递后 N 分钟未领取（Pending 消息 claim）→ 回队重派（Redis XAUTOCLAIM），日志留痕「任务 xxx 由 worker-A 超时未领取，转派重试 r 次」。

### 3.4 集群化分配与监控（F54/F55）
- **心跳扩展**：worker/heartbeat.py 心跳循环追加 psutil 采集 → Redis `monitor:{module}:{node}`（TTL 90s）。
- **api/monitor.py**：GET `/api/v1/monitor/nodes` → ZK live 路径列举（master/worker/ssh 三类）+ 合并 Redis 指标 + 心跳状态。
- **前端接真**：DeployRuntimeView 节点表（类型/节点/CPU/内存/心跳/状态列，30s 轮询）；DeployMonitorView 叠加真实节点状态标记；mock 通道删除。

## 11. 1.9 实测门（八项）

1. C21 拖入画布→配 2 变量（含 1 时间变量）→运行→下游 SQL 节点 `$[wf.period]` 引用生效且任务日志含变量快照。
2. C21 覆盖开关实测：与工作流定义变量同名时，开/关两态取值正确。
3. Dependent：建 A/B 两工作流，B 的 dependent 节点配 A+节点 → A 最近实例成功时 B 通过；A 失败时 B 按失败策略。
4. SSH 节点：注册 1.9 本机（localhost）为 SSH 节点 → 探活通过 → ssh 任务带标签派发成功执行。
5. 容错转派：SSH 节点探活失败（停 sshd 或配错端口模拟）→ 任务转派其他节点或按失败策略，日志留痕。
6. kill 一个 worker 容器 → 在途任务超时回队重派成功（其余 worker 领取），实例终态 success。
7. 多 worker 分摊：worker scale=2 连续派发 N 任务 → 两节点均有执行留痕。
8. 监控页：/dep/runtime 展示 master/worker/ssh 节点 CPU/内存/心跳实时值；kill worker 后页面状态转离线。
