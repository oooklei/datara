## 0. 背景与目标

I8 已交付流引擎三件套（C18 流输入 / C19 流融合 / C20 流输出，功能项 F35~F41，裁定②：master 只注册/透传、不持有引擎）。I11 为流任务收尾增量（决策记录 [09-18]：I11 收尾交付保留第一期），目标：

1. **源面补全**：流输入由 I8 的四分型（kafka/cdc/http/file）扩为**七分型**（新增 simulate 模拟数据 / redis Redis Stream / mqtt），演示与联调零外部依赖（02-DAG组件清单 I12 回写：原「四源」口径修正为七源，I11 增模拟数据/Redis Stream/MQTT）。
2. **连接性注册化（09-21）**：kafka/redis/mqtt/http 四分型支持 `dsRef` 引用数据源中心注册源（连接层=注册源，业务语义=节点参数），启动预检校验引用与状态；cdc 沿用既有 `cdcDs` 引用式。
3. **生命周期收口**：流任务 `t_stream_job` 独立于批处理实例/调度链，注册（upsert）→ 启动（Redis 广播 + worker 原子认领）→ 运行（常驻线程）→ 停止/删除全链路 API 化；同画布唯一、**先停再起**互斥。
4. **W1 修复**：流节点表单 schema 必填标注修复 + 必填完整性/流子图结构校验三处共用（详见 §8.1）。
5. **看板展示件**：`page_board`（代码内曾标 C24，I12 回写让出编号）注册进流画布，不参与管道装配，消费本画布流任务 API 通道数据做实时看板。
6. **画布收敛与冒烟**：流设计器 palette 只暴露可执行组件 + 看板；以 stream-realtime-demos 三个 use_case 为蓝本的三工作流冒烟脚本收口（§7）。

## 4. 数据流与生命周期

### 4.1 注册 → 启动 → 运行 → 停止 → 删除

```
画布保存(t_wf_definition.graph_json，I8/I11 语义不变)
        │ 用户点「启动」
        ▼
POST /stream-jobs/start（api/streamjob.py L192-204）
  extract_stream_spec 抽流子图+结构校验 → preflight_stream 预检（§5）
        ▼
register_stream_job（L169-189）：upsert t_stream_job（一画布一行）
  generation+1 / status=starting / host=NULL / last_error=NULL / spec_json=流子图规格
        ▼  Redis 发布 datara:flink:ctl {action:start, jobId, generation}
worker._handle_ctl（engine.py L191-223）
  本地同代号幂等忽略；旧代号先停让位 → _claim 原子认领（L225-245）
  → 读 t_stream_job.spec_json → submit 起常驻线程（先停再起）
        ▼
_pipeline_once（L359-474）：装配（边队列 maxsize=10000，源/算子/汇各一线程）
  读 t_stream_offset 位点注入 → status=running → 消费循环（2s 指标 / 5s 位点）
        ▼
停止：POST /{id}/stop → 终态 stopped + host=NULL + 广播 stop（worker 本地命中即停线程）
删除：DELETE /{id}（?with_def= 默认 true）→ 先广播停止 → 删任务行 → 连带删画布定义（L226-248）
```

要点（以代码为准）：

- **spec 冗余与解耦**：`spec_json` 在 register 时快照入 `t_stream_job`，worker 认领后只读任务行——画布后续编辑不直接影响运行中任务，下次 start（重启）才生效；
- **restarted 语义**：同画布已有任务行时 start 返回 `restarted=true`，即「先停再起」幂等重启（L171-173、L198）；
- **删除连带**：delete 的 `with_def=true` 会连带删除 `t_wf_definition`（画布）；I12 D3 将对定义删除增加运行中实例/流 job 的 409 拒绝保护（见 §9）。

### 4.2 先停再起互斥与 generation 代际守卫

- API 侧：register 对同 doc_id 仅 upsert 单行，每次 start generation 自增并重置 starting/host=NULL（L176-184）；
- worker 侧：`submit` 与 `_handle_ctl` 均先 `request_stop` + `_join_job`（8s deadline）再起新线程（L123-133、L205-211）；旧代号线程退出写终态前经 `_db_update` 代际守卫（L612-627），代号已被接管则放弃写入，杜绝「旧代号线程 stopped 覆盖新代号 starting → 认领 0 行 → 任务卡死」的重启竞态（该竞态 I11 期已修，I12-D6 回归确认）。

### 4.3 状态机、恢复与自愈

- 状态机：`starting → running ↔ reconnecting`（管道级异常指数退避重连，连续 30 次 → `failed` + 告警记录 `t_alert_record`，channel=system/state=wait）；`stopped/failed` 终态（engine.py L309-357）；
- worker 重启恢复：`recover()` 扫 `host=me` 且 status 活跃的任务按 `t_stream_offset` 位点续跑（L142-159）；
- 宿主失联自愈：reaper 每 30s 扫描——alive 键（45s TTL）缺失的宿主被清 host 并广播 start，健康 worker 抢占接手（L284-303）；本地对账保证他机接管/外部停止/代号变化时本地线程退出（L262-268）；
- 位点续跑语义：kafka（partition offset，组分配就绪后 seek，不丢不重）/ cdc（file:pos）/ http（cursor）/ file（pos+inode+表头，inode 滚动从头）/ redis（消费组 last-delivered-id，组内续跑）/ mqtt、simulate（无位点，重启按参数重来）。

### 4.4 观测面

- 指标 Hash（2s 周期，TTL 90s）：`status / ratePerSec（EMA 平滑）/ totalIn / totalOut / errors / windowEmits / offsets / lastBeat`（engine.py L594-610）；
- 日志 List Last-500：`_log` LPUSH+LTRIM，API `logs?lines=`（≤500）倒序取尾翻正；
- 实时数据：poll/SSE/WS 三形态（streamdata.py），页面化载体为 stream_output 的 StreamDataPage 浮窗、page_board 的 BoardPage 看板浮窗与流设计器指标卡浮窗（前端 §2.4）。

## 5. 四源注册化（连接性注册化，09-21）

口径：**连接层=注册源（数据源中心），业务语义=节点参数；连接性测试归注册层，启动只校验引用与状态**（streamjob.py L37 注释、sources.py L7-8）。kafka/redis/mqtt/http 四分型支持 `dsRef` 引用（cdc 沿用 `cdcDs`，file/simulate 无连接性概念）。

**API 启动预检 `preflight_stream`（streamjob.py L131-166）**——错误聚合一次返回可读清单：

- 引用模式：`dsRef`/`cdcDs` 非空 → `_lookup_ds`（名称优先、纯数字兜底 id，L122-128）存在 → 类型匹配 `_REF_EXPECT`（kafka→kafka；redis→redis；mqtt→mqtt；http→http；cdc→mysql/greatdb，L38-44）→ `status=online`（未连通提示先到数据源中心测试）；
- 内联模式（无引用，存量画布零改动）：仅校验 `_CONN_INLINE` 连接参数必填（kafka brokers / redis redisUrl / mqtt mqttHost / http httpUrl，L46-52）；
- 业务必填 `_BIZ_REQUIRED` 无论引用/内联均校验（kafka topic / redis streamsText / mqtt mqttTopics，L54-58）。

**worker 侧运行时兜底 `resolve_ds_ref`（sources.py L45-55）**：同口径解析（存在+类型匹配，异常抛 SourceError 引擎重连）；各源构造器消费注册层参数——kafka 取 `params.brokers`（L150-155）、redis 组装 `redis://[pwd@]host:port/db`（L709-714）、mqtt 取 host/port/user/pwd（L799-807）、http 取 `baseUrl`+基础鉴权头并与节点业务头合并、URL 按相对/完整三级拼接（L406-424、L442）。

## 6. 与 DAG 工作流的关系

- **画布同源**：流任务画布仍以 GraphDocument 存 `t_wf_definition.graph_json`（streamjob.py `_load_doc` L65-75），profile=stream；一画布一流任务（doc_id 唯一锚点）；
- **执行面独立**：流任务不进入 `t_wf_instance` / master 调度引擎 / worker @register 执行器链——执行载体是 `t_stream_job` + worker 内常驻线程（§2.2），生命周期完全由 `/stream-jobs` API 驱动；
- **组件口径**：`STREAM_TYPES`（stream_input/stream_fuse/stream_output）+ `DISPLAY_TYPES`（page_board）前后端同口径（api/streamjob.py L34-35、dag.ts L53-54）；流画布不允许混编批处理组件（前端 validators error 提示、后端 start 硬拦截 400）；
- **page_board 展示件**：不参与管道装配与 spec 抽取（extract_stream_spec 只收 STREAM_TYPES），消费本画布流任务 API 通道（SSE/轮询）数据，窗口行按 `win_start` 分桶渲染（最新窗口→指标卡/分布，历史→趋势曲线，事件行→告警列表，dag.ts L704-712）；代码内曾标注 code:C24，I12 回写让出编号（展示件不占 C 编号，02-DAG组件清单 §311）。

## 7. 三 use_case 冒烟（tools/smoke_stream_i11.py）

对齐 stream-realtime-demos 三 use_case，流程统一「创建定义 → 保存画布 → POST /stream-jobs/start → 轮询 running → 观察窗口后拉 API 通道快照按语义断言」（L163-238）：

| 用例 | 拓扑 | 断言要点 |
|---|---|---|
| WF1 电商大盘 | 3 模拟源（ecommerce：order_pay/user_click/cart_event，eps 2/3/2）→ 各 10s 滚动窗口（sum:amt_total / count:ord_cnt / count_distinct:uv；goods_id count:click_cnt；goods_id count:cart_cnt）→ union → API（keepLast=600）→ page_board ecommerce | 三路窗口行齐备（gmv/click/cart），最新窗口 GMV/订单/UV 取值 |
| WF2 IoT 监控 | 4 模拟源（iot：temp/press/vib/alert）→ 温/压/振按 device 5s 窗口（avg/max/rms）+ 告警透传 → union → API → page_board iot | 三聚合窗口行齐备 + 设备分组数 + alert 事件行到达看板通道 |
| WF3 站点分析 | Redis Stream 双源（order_stream/user_stream，redis://redis:6379/0，组 datara-flink）→ 全局 10s 窗口 sum:gmv + page 分组 count:page_pv → union → API → page_board visit | 双流窗口行齐备 + 最新窗口 GMV 与页面分布；外部 feeder 线程持续 XADD 灌数（宿主机 6380→6379 同库，L240-269） |

实现注记：API 通道 `keepLast=600`——窗口行速率低（~0.3 行/s）而原始行持续透传占缓冲，缓冲过小会把最新窗口行挤出（L96-98）；`--only wf1|wf2|wf3` 单跑、`--wait` 观察窗口秒数（默认 45）。
