# Datara 前端 UX v3 评审与新设计目标

票号：F-UX-V3-REVIEW-01  
日期：2026-10-27  
输入：`handoff-2026-10-27-datara-ux-v3.md`、`D:/super-develop/datara-ux-prototype.html`、当前主目录代码、192.168.1.9 已部署版本。

## 1. 评审裁定

UX v3 的总体方向通过，作为下一轮前端融合的视觉与交互蓝本；不能把原型直接视为功能完成。实施目标是“保留现有真实业务能力，以 v3 重构信息架构和交互外壳”，不重写已有 API，不用静态演示数据替代真实后端。

必须在实施前修正四项：

1. 原型/交接声称侧栏 16 项，但原型实际为 19 项：A 1 + B 1 + C 2 + D 2 + E 13。新目标冻结为 19 项。
2. 375px 视口虽无横向滚动条，但内容被 228px 固定侧栏压缩成单字竖排，属于响应式失败。目标要求桌面完整、窄屏折叠侧栏。
3. ECharts 通过公网 CDN 加载，离线时出现资源错误并退化。生产实现必须使用项目已安装的 `echarts` npm 包，禁止 CDN 运行依赖。
4. 原型 84 个按钮的“有响应”多数是演示态。生产验收必须逐项绑定真实路由、API、弹窗或明确受控 gate，toast 不等于业务完成。

## 2. 新设计目标

### 2.1 产品壳层与作用域

- 保留现有登录表单与 admin/dev/analyst/viewer 登录闭环；登录后进入项目选择，默认演示项目为“电商全域数据治理项目”。
- 项目即当前系统实例（USE 语义）。所有业务查询默认携带当前 projectId，切换项目后刷新项目态数据并清理旧项目瞬态缓存。
- 顶栏固定提供：项目切换/项目管理、面包屑、部署运维、系统管理、明暗主题、当前用户与退出。
- 项目侧栏仅承载 A-E 五组 19 项；部署运维、系统管理、项目管理属于全局顶层，不出现在项目侧栏。
- `/dag`、`/ide` 等旧全局业务路径保留兼容，但在存在项目上下文时重写到 `/p/:projectId/...`；无上下文时返回项目选择，不猜测项目。

### 2.2 视觉系统

- 采用瑞士国际主义信息骨架：明确网格、紧凑密度、清晰字阶；用包豪斯几何形作为有限品牌点缀。
- 统一色板、间距、圆角、阴影、状态色和交互态，浅色/深色由根主题变量控制。
- 生产页面不得复现当前部署版的大面积无意义空白；工作区域自适应占满可用高度。
- 1440px 为像素级主验收宽度；1024px 保持全部功能可用；小于 768px 侧栏折叠为抽屉，标题与 KPI 不得单字竖排。

### 2.3 项目工作台

- 双 KPI 带：管线运行与数据治理；移除标签数量 KPI。
- 三张图：近 7 天运行趋势、工作流类型分布、运行状态分布；均使用真实聚合数据并提供 loading/empty/error 状态。
- 最近运行实例可进入运行监控，KPI 卡可进入对应业务页。
- 优先新增一个项目工作台聚合 API；若先用前端 fan-out，必须限制并发、支持取消和部分失败，不允许 N+1 逐工作流拉取调度。

### 2.4 任务中心与 DAG

- 保留现有真实工作流、运行监控、同步/流、SQL/Python/Shell/依赖组件执行能力。
- 采用 v3 的任务视角页签、工具栏、Palette/画布/Inspector 三栏布局及可持久化分割条。
- 同步与流处理继续作为特别工作流/组件承载，不回到侧栏独立菜单。
- 变量管理、版本、试运行、依赖和血缘为贯穿能力；所有节点表单必须使用真实组件 spec 和后端校验，不复制原型静态表单。
- 所有发布、运行、回滚、对比、变量校验、错误聚合按钮必须有真实成功/失败反馈和可复查结果。

### 2.5 SQL IDE

- 数据源根树展示当前用户可见的全部数据源；同源跨库 DML 可执行，跨数据源执行显式拒绝。
- 将当前 textarea 换为 CodeMirror 6；使用 splitpanes 实现元数据树、编辑器、结果区分割并持久化尺寸。
- 保留并完善执行、停止、格式化、变量引用校验、脚本保存、历史、分页结果、CSV 导出、血缘跳转。
- GlobalParamDrawer 复用变量域 API；引用校验统一返回 SYNTAX/UNDEFINED/TYPE_MISMATCH/SCOPE_INVISIBLE/CYCLE 五类结果。

### 2.6 全局能力

- 部署运维：运行时节点、集群监控、SSH 节点位于 `/dep/*`。
- 系统管理：用户角色、API Key、API 管理、LLM 模型等位于 `/sys/*` 或兼容别名；不混入项目业务侧栏。
- AI 助手全局挂载且可拖动，调用真实工具与模型；没有可用模型时展示可操作的配置指引。
- 弹窗默认可拖动并越界钳制；菜单、页面、Inspector、Palette、弹窗和 AI 面板均有正确滚动容器。

## 4. LLM 三模型恢复目标

- 不把 API Key 写入源码、前端静态产物、URL、日志或普通 seed SQL。
- 增加一次性、幂等的受控导入：从服务器 secret 文件或部署 secret 环境读取 LongCat、Ark、SiliconFlow 三项，调用模型管理 API 写入并由当前 `LLM_ENCRYPTION_KEY` 加密。
- 本地主后端 `.env` 只确认仍有 LongCat 旧式配置；可作为 LongCat 恢复源，但不得回显 key。
- Ark、SiliconFlow 在当前 7 个 rebuild 数据库、现存回滚 API 容器及部署环境中均无记录；恢复实施前需要从原始 secret/人工保管值重新注入，不能伪造。
- 恢复后验证：模型列表 3 项、三 provider 连通性各一次、默认模型唯一、重启后仍存在；证据只记录 provider/model/status，不记录 key。

## 5. 实施顺序与门禁

1. P1 壳层：路由作用域、顶栏、19 项项目侧栏、全局入口、主题、响应式折叠。
2. P2 工作台：聚合 API/查询、KPI、ECharts、最近运行。
3. P3 DAG：视觉融合、三栏分割、Inspector/变量/版本/试运行贯穿。
4. P4 SQL IDE：CodeMirror、MetaTree、GlobalParamDrawer、HistoryDrawer、分割布局。
5. P5 横向收口：所有按钮响应矩阵、角色权限、空/错/加载态、三模型恢复、1.9 最高优先级 E2E。

每阶段先跑目标测试，票尾一次全量 vitest 与 vue-tsc；最终仅在 192.168.1.9 做部署和关键路径 E2E。静态原型数据不得进入生产 seed，电商演示 seed 必须通过后端幂等初始化产生并可重复验证。

## 6. 验收基线

- 19 个项目侧栏入口全部可达且展示真实页面；三类全局入口不污染项目侧栏。
- 关键按钮无死链：登录、项目切换、DAG 保存/发布/运行、变量校验、SQL 执行/历史/导出、同步/流观摩、运行统计、LLM 配置。
- 工作流结果后台表可见成功/失败记录数；流样例持续产生数据并展示实时处理结果。
- 1440/1024/375 三档无内容不可达；375 使用折叠导航，不接受单字竖排。
- 无 CDN 运行依赖；控制台无未处理错误；API 401/403/409/5xx 都有明确界面反馈。
- 1.9 最终统一联调一次，覆盖四账号角色、默认电商项目、核心工作流、SQL IDE、三模型列表与至少一个可用模型调用。
