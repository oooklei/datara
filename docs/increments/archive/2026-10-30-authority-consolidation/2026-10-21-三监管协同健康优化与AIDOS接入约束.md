# Datara 三监管协同健康优化与 AIDOS 接入约束

> 日期：2026-10-21（Asia/Shanghai）  
> 性质：运行优化设计与约束补充  
> 适用范围：监管 A/B/C、Trae/Claude/Codex 实施线及后续 AIDOS 健康评估接入  
> 实施边界：本文只定义行为约束、指标和未来接入契约；不授权修改 `mailbox.jsonl`、`STATE.md`、`agents/mailbox_loop.py`，不改变当前值班权、任务归属和在飞任务。

## 0. 当前事实

Datara 目前没有系统化固化三监管三实施机制。整个协作过程由用户手工完成多端切换、提示词下达、唤醒和调整；各 AI 端通过读取 Markdown 文档理解任务和上下文。mailbox、STATE、outbox 及零散脚本只承担辅助记录或局部操作，不具备统一调度、自动派单、自动验收、自动裁定和跨端状态一致性能力。

本文描述的是对人工协作方式的约束和未来 AIDOS 接入契约，不能被引用为“Datara 已经实现协同管理系统”的证据。

## 1. 目标

在保持现行协作不中断的前提下，降低任务生产、验收、裁定和上下文管理的等待与重复消耗，并为 AIDOS 后续只读接入提供稳定口径。

## 2. 三监管职责边界

| 角色 | 唯一主责 | 正常输入 | 正常输出 | 越界条件 |
|---|---|---|---|---|
| 监管 C | 预研、WBS、拆票、依赖分析、派单和 READY 库存 | 需求、设计、缺口、返工请求 | 可执行任务包、Context Pack、依赖与验收契约 | 执行验收终判或政策裁定 |
| 监管 A | 消费交付、证据核验、组织独立验证、关闭或退回 | DELIVERY_READY | ACCEPTED、REWORK、DECISION_NEEDED | 扩张需求、日常任务生产或修改用户承诺 |
| 监管 B | 对规则无法唯一判定的差异进行分级裁定 | DECISION_NEEDED | D1–D3 裁定，或压缩后的 D4 用户决策卡 | 重跑例行测试、代替 A 做常规验收、代替 C 生产任务 |

临时代行必须在 STATE 心跳中写明：原 Owner、代行原因、范围、TTL、交还条件。代行结束后职责自动回归，不形成惯例。

## 3. 五队列语义

1. `RESEARCH`：需求或缺口尚未形成可执行契约。
2. `READY`：目标、文件域、依赖、验收方式和证据要求齐全。
3. `EXECUTING`：已被实施线认领，具有唯一任务 Owner。
4. `VALIDATION`：实现完成，等待机器门或监管 A 验收。
5. `DECISION`：只有现有政策不能唯一决定，且补证或缩小范围仍不能收敛时进入。

当前 mailbox/STATE 尚未实现上述机器状态时，各角色在心跳标题和回报中使用同名标签表达语义，不新建第二套台账。

## 4. 运行水位与 SLA

| 指标 | 目标 | 触发动作 |
|---|---:|---|
| READY 库存 | 不低于实施总 WIP 的 1.5 倍 | 监管 C 优先预研和拆票 |
| 交付至首次验收 P50 | ≤10 分钟 | 超标时 A 减少非验收工作 |
| 交付至首次验收 P90 | ≤30 分钟 | 批量验收、临时代行或降低实施 WIP |
| DECISION/交付 | ≤10% | B 将重复裁定固化为规则 |
| 用户 D4/全部裁定 | ≤5% | 先补证、缩小范围或转可逆实验 |
| 非法/重复消息 ID | 0 | 停止继续追加同 ID，登记纠偏 |

## 5. 最小 Context Pack

每张票默认只携带：

```yaml
task_id: 唯一任务号
goal: 一句话目标
authority_refs: 最多三个权威锚点
file_scope: 文件白名单
dependencies: 直接前置及契约版本
acceptance: 可执行检查和结果判据
evidence_required: 证据清单
stop_rules: 越界、冲突、失败和裁定条件
next_event: 完成后投递目标
```

权威设计、WBS、验收规范和历史报告不默认全文注入。需要时按锚点读取相关片段；原始日志和长报告保存为证据引用。

## 6. 健康评估方法

AIDOS 后续只读采集以下来源：

- `docs/handoff/STATE.md` 及归档；
- `docs/handoff/mailbox.jsonl` 与 outbox；
- Git 提交和工作区状态；
- `docs/increments/evidence/`；
- 各平台能够导出的 token 使用记录。

固定分析步骤：采集证据 → 标准化事件 → 关联任务/交付/验收/裁定 → 计算指标 → 发现异常 → 定位根因 → 生成分级建议 → 保存证据锚点。

首期 AIDOS 接入必须为只读影子模式。报告不得自动改写 Datara 文件、改变任务状态、派单、验收或裁定。只有影子结果与人工台账连续对账一致并获得用户批准后，才另行设计双写或切换。

## 7. Token 治理

1. 衡量 `tokens / accepted task`，同时观察周期、首过率和返工率。
2. 监管主会话、实施会话和验证会话分别计量，禁止用总量掩盖单角色异常。
3. 例行格式校验、哈希、状态归类优先使用程序；摘要和普通分类使用低成本模型；D3/D4 与架构冲突使用强模型。
4. 子智能体只获得本票 Context Pack，不继承监管会话全部历史。
5. evidence 默认注入 manifest；只有失败、抽样或争议时展开原文。
6. AOCI、MCP 与 skills 按实例职责按需加载；没有当前义务的工具不进入任务上下文。

## 8. 当前实施口径

- 现行协作规程和用户最新指令继续生效；本文不替换其权威地位。
- 当前在飞任务按原派单完成，不要求重新登记。
- 监管线可以立即采用职责边界、Context Pack 和指标口径进行人工运行优化。
- AIDOS MVP 只展示冻结样本和分析模板，不连接或修改本项目运行数据。
