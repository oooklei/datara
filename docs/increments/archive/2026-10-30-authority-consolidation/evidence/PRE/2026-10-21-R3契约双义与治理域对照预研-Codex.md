# R3 契约双义与治理域对照预研（Codex）

- 日期：2026-10-21 Asia/Shanghai

- 对照范围：权威设计、`rebuild/governance` 当前路由与模型、`datara-newweb` 契约注册及菜单消费

## 1. 结论

当前文档中的 **R3 有两套不同语义**，后续票面必须加限定词：

1. **R3-GOV**：Datara 自研 metadata/lineage 治理域，承接 I18–I23。依据为《核心业务功能实现规范与验收标准》L77 与《纠偏重构前端权威设计》L244-L247、L387。
2. **R3-SYNC**：SYNC 新域契约收口门禁。依据为《纠偏重构前端权威设计》L228、L428、L548、L862、L888、L916。

两者不应继续共用裸称“R3”。本预研主题解释为 **R3-GOV 契约对照**；R3-SYNC 只作为同名风险登记，且其解禁状态以监督线最新心跳和 L12-03 证据为准。

完整矩阵见同目录 `2026-10-21-R3治理域契约对照.csv`。

## 3. 契约与权限现状

### 已对齐

- 路由统一挂在 `/api/v1/rebuild/governance`，满足 rebuild 新域前缀。
- 端点返回主干使用 `{code,msg,data}` 信封。
- 资产、标签、血缘、质量、标准、指标、审计均落在 `governance/models.py`；I18–I23 旧语义另有迁移批次、映射和遗留明细表承接。
- 项目路径端点均先经过项目成员与权限判定；通过 asset_id 间接定位项目的端点也会回查资产所属项目。

### 需后续正式票裁定

1. **权限粒度未用足已定义权限**：运行期质量写入/执行仍用 `EDIT_DEFINITION`，质量读取仍用 `VIEW_ALL`；标准创建也用 `EDIT_DEFINITION`，而 `Permission` 已定义 `QUALITY_READ/WRITE/RUN` 与 `STANDARD_READ/WRITE/APPROVE`。`standards/check` 是少数使用 `STANDARD_READ` 的端点。建议正式契约票逐端点冻结权限映射后再改实现。
2. **产品 CRUD 面不完整**：资产无更新/删除；标签无列表/更新/删除；血缘无删除；质量规则无更新/删除；标准与指标只有创建/列表；审计只有列表。应依据产品验收清单确认哪些是有意只读/追加，哪些是缺口，不能直接按传统 CRUD 补齐。
3. **迁移工具面与产品面混在同一路由模块**：I18–I23 import/preview 是一次性或受控迁移能力，不应被前端当作日常治理 CRUD。建议 OpenAPI 分 tag，并在前端契约注册时明确 `migration-only`。
4. **端点数快照漂移**：设计 23、当前 28。建议以自动生成的路由清单替代手填总数，并在设计状态列标注基线 SHA。

## 4. 前端消费边界

- `datara-newweb/src/services/rebuild/CONTRACT_REGISTRY.md` 当前没有 governance 契约模块。
- 导航已规划治理组 13 项：8 项 `formal`、5 项 `future`，批次均指向 inc14；但 `router/routes.ts` 当前仅注册 `/login` 与 `/`，13 个治理路径均未注册，`src/views` 也没有治理页面。
- 现有 `metricsApi.ts` 指向 `/rebuild/metrics`，它承载 I9 统计/质量/血缘写回，不能视为 `/rebuild/governance` 的前端适配层。
- `/sec/audit` 当前仍标为 `future/inc15-post`，也不是 governance audit 的正式消费。
- `COPY_LEDGER.md:72` 明确旧前端 `lineageApi/metaApi/indApi` 零复制，支持按新治理契约重新实现，不能回迁旧服务层。

因此 R3-GOV 后端虽有运行期接口，前端仍缺独立契约适配、注册、页面绑定和契约测试；权威功能清单中“✅ I18-I23 承接收口”只能说明后端迁移承接，不能推导为用户面闭环完成。

## 5. 建议拆票顺序

1. **R3-GOV-01 契约冻结**：确认 16 条运行期产品面、是否补 CRUD、逐端点权限、错误码、分页字段；同步修订 23→当前基线数。
2. **R3-GOV-02 迁移面隔离**：给 12 条迁移工具端点加明确 tag/可见性/运维权限和退役条件。
3. **R3-GOV-03 前端契约层**：新增 governance API 适配、`CONTRACT_REGISTRY`、契约测试；不要复用 metricsApi 冒充治理域。
4. **R3-GOV-04 页面消费**：依次接资产/元数据、标签、血缘、质量、标准、指标、审计，并做项目越权负断言。
5. **命名治理**：所有后续票和心跳使用 `R3-GOV` 或 `R3-SYNC`，禁止裸称 R3。
