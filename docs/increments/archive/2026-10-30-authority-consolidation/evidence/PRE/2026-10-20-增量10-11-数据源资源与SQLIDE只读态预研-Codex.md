## 三、目标方案

### 3.1 10→11 依赖关系

```text
增量 3 项目上下文
        │
        ▼
增量 10.1 数据源正式页 ──► 可选择且已测试连通的数据源 ──► InstanceBar / 对象树 / 查询执行
        │                                                    │
        └──────── 项目权限、capability、元数据入口 ─────────┘

增量 10.2 资源正式页 ──► 项目级不可变资源与引用入口 ──► SQL/Python/Shell 等后续资产消费

增量 5 变量正式能力 ──► GlobalParamDrawer / SQL 引用校验 / 当前值 / 执行快照
```

10.1 是增量 11 的硬前置：IDE 不应要求用户手填 datasourceId；只能从当前项目可见、连接型且连通的数据源选择，能力位驱动树与执行入口。10.2 是 WBS 合并前置的一部分，但当前 R5-A scripts/exports 属 SQL IDE 自有契约，不能强行改走 resources；两域只共享项目上下文和正式资源入口。

增量 11 开工门建议定义为：项目上下文已注入；数据源列表/详情/测试连接正式链可用；R1 capability 可供 IDE 消费；R4 正式页已具最小上传/版本/引用闭环；R2 variables 契约与组件可复用。

### 3.2 数据源正式页

建议路由落在项目工作区，例如 `/p/:projectId/datasources` 与详情子路由。页面必须覆盖：

1. 查询展示：项目数据源列表，类型、环境/分组、连通状态、能力摘要；
2. 注册/编辑：按 profile schema 渲染真实字段，凭据只提交不回显原值；
3. 连接测试：注册前 validate/probe 与注册后 test 的语义分开显示；
4. 元数据查看：schemas→objects→columns 级联，错误与空态明确；
5. 删除：显示服务端约束错误，不用前端假成功；
6. IDE 入口：仅对可用连接型数据源显示“打开 SQL IDE”，携带 projectId 与 datasourceId，不携带凭据。

正式 `datasourceApi` 应按 0.7 进入 `src/services/rebuild/` 或在契约登记中明确归属，不能直接复制旧 `/datasources` 非项目路径。

### 3.3 资源正式页

建议路由 `/p/:projectId/resources`，页面分资源列表与版本抽屉：

- multipart 上传，服务端规则为真源；
- 按 kind 筛选、显示最新版本、大小与摘要；
- 查看不可变版本链与具体版本；
- 建立 workflow version × task slot 到具体资源版本的绑定；
- 错误反馈保留 `RES_*` 稳定码；禁止“latest”隐式绑定。

下载闭环与 WBS 10.2 的“上传下载”要求存在缺口：当前五端点能读版本元数据，未见文件内容下载端点。实施前需裁定新增下载端点，或把退出标准修正为“上传、版本查询、引用”，不得用元数据 GET 冒充下载。

### 3.4 SQL IDE 正式页

正式页继承旧 `/ide` 的信息架构，但全部状态改由新前端契约/store 驱动：

- `InstanceBar`：当前项目数据源选择、在线/能力状态、环境/模式提示；选择变化需取消或隔离旧数据源的在飞请求、树缓存和结果。
- 对象树：database→schema→relation/routine/index/column，支持 table/view/procedure/function 等；每层消费 cursor 和 capability/constraints，unsupported 显式灰置，不能显示空树冒充无对象。
- 编辑器：SQL 文本、lint、变量补全/校验/当前值；DDL 只允许读取 definition 或手写文本，不提供对象编辑落库。
- 查询执行：提交后以 taskId 关联 SSE；同时有 status 兜底，支持多语句事件、多结果集、取消与断线恢复。
- 结果区：以 `historyId + resultSetId` 读取不可变快照，分页边界遵守契约，不用当前执行内存覆盖历史结果。
- 历史/资产/导出：历史与 scripts 分区，导出有创建→状态→下载/取消闭环；权限不足与过期快照明确反馈。
- `GlobalParamDrawer`：只消费 R2 variables，提供 `${scope.name}` / `$[时间]` 的候选、校验、当前时点预览；执行响应展示 snapshot ref/digest，重跑不得静默用新值覆盖旧快照。

### 3.5 契约状态治理

实施起点应在新前端 `CONTRACT_REGISTRY.md` 分别登记 datasource、resource、sqlIde，而不是仅复制“GREEN”文字：

- datasource：当前 0.7 的 11 文件模板未列 datasourceApi，必须新增登记行或由监督线裁定其归属；
- resourceApi：GREEN，五方法与正式页行为逐项映射；jar/download 缺口不得标已覆盖；
- sqlIdeApi：GREEN，但应先统一 17 方法常量、接口额外方法与后端 24 路由的覆盖矩阵；
- sqlIdeDdlApi：保持 RED，不得被正式页 import 或路由触发；
- variableApi：GREEN，作为 GlobalParamDrawer 与执行变量链依赖单独登记。

## 六、验收风险

| 风险 | 典型误通过 | 防线 |
|---|---|---|
| GREEN 等同正式完成 | 契约测试绿就宣布增量 10/11 完成 | 正式产品路由与 Playwright 用户旅程为独立门 |
| 项目越权 | datasource/resource/sql-ide 接口手填其他 projectId | 路由守卫、服务端权限负测、跨项目 ID 不泄露 |
| 凭据泄露 | 编辑详情回显密码、日志/URL 保存 secret | masked/keep-existing 语义，静态与网络证据审计 |
| 假连通状态 | 前端按最近点击成功永久标在线 | 服务端状态真源、过期态、失败态和重新测试 |
| 元数据空态混淆 | unsupported/失败渲染成空列表 | capability/constraints/错误/真空数据四态分离 |
| 资源类型私设 | 前端自行加入 jar | 枚举契约测试，O3 裁定前拒绝未知 kind |
| “下载”名不副实 | 只读取版本元数据就算下载通过 | 校验响应文件字节、文件名、digest 与权限 |
| SQL 写路径越界 | R5-A 引入 DDL 保存或对象编辑 | sqlIdeDdlApi RED import/route 负断言；写 SQL 策略测试 |
| SSE 丢失/重复 | 重连不带 cursor，SSE 与轮询重复落终态 | Last-Event-ID/reset/终态幂等/任务隔离测试 |
| 结果串任务 | 切数据源或新执行覆盖旧 history/resultSet | 以不可变复合身份取页；并发双任务测试 |
| 变量只做文本替换 | 无五诊断、当前值或 snapshot | UI+API+执行记录三处断言；重放旧任务验证 digest 不变 |
