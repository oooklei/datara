# 17.1 B7 SSH 节点旧实现对照登记

> 日期：2026-10-20  
> 派单：`s187-t175-step1`  
> 性质：五步迁移第①步，只读盘点与契约冻结输入；未修改后端或前端代码  
> 承载任务：WBS 17.5（P4 SSH 节点迁移）

## 结论摘要

旧实现由 `datara-backend/api/sshnode.py` 提供 5 条 API，统一挂在 `/api/v1/ssh-nodes`，数据真源为 `t_ssh_node`。它不是孤立 CRUD：Master 探活线程持续写 `heartbeat_state/last_seen`，Worker SSH 执行器按 `enabled + online + tags` 路由，旧前端同时在运行时节点管理页和画布 SSH 节点标签下拉中消费。

新后端 `datara-backend/rebuild/` 当前没有 `sshnode` 域、SSH 节点 ORM、对应路由装配或等价端点。WBS 已明确由 17.5 新建 `rebuild/sshnode/` 并联通 F 组挂载页。因此当前结论是“待迁移的真实缺口”，不能以旧 API 仍可用或 `runtime_node` 相近能力判作等价承接。

## 一、端点清单与冻结契约

### 1. 公共契约

- 路由前缀：模块 `APIRouter(prefix="/ssh-nodes")`，实锚 `datara-backend/api/sshnode.py:23`；应用再以 `/api/v1` 装配，实锚 `datara-backend/api/main.py:106`。完整路径均为 `/api/v1/ssh-nodes...`。
- 请求模型 `SshNodeBody`：`name: str`、`host: str`、`port: int = 22`、`sshUser: str = "root"`、`cred?: str = ""`、`tags: string[] = []`、`enabled: bool = true`，实锚 `datara-backend/api/sshnode.py:26-33`。
- 节点响应字段：`id/name/host/port/sshUser/cred/tags/enabled/heartbeatState/lastSeen/createTime`，实锚 `datara-backend/api/sshnode.py:36-49`。时间格式为本地时间字符串 `YYYY-MM-DD HH:mm:ss`，实锚 `datara-backend/common/resp.py:113-117`。
- 成功响应统一包裹为 `{code: 0, msg: "success", data: ...}`，实锚 `datara-backend/common/resp.py:120-122`。下表“data”均指该包裹内数据。
- 不存在节点统一抛出 HTTP 404、业务码 `4101`、消息“SSH 节点不存在”，实锚 `datara-backend/api/sshnode.py:52-56`。
- 所有端点要求登录。读端点使用 `get_current_user`；写端点及探活使用 `require_perm("edit_definition")`。会话从 `token` header、Bearer header 或 query token 读取，并查 Redis token 与 `t_user`，实锚 `datara-backend/api/auth.py:83-108`；权限检查实锚 `datara-backend/api/auth.py:111-119`。

## 三、旧前端消费点与调用链

### 1. 主消费页：运行时节点 `/dep/runtime`

路由在 `datara-web/src/router/routes.ts:110`，菜单入口在 `datara-web/src/App.vue:93-96`，页面为 `datara-web/src/views/deploy/DeployRuntimeView.vue`。

调用链如下：

1. 页面从 `services/graphApi` 导入 SSH 节点 5 个 API 及监控聚合 API，`DeployRuntimeView.vue:12-15`。
2. 页面加载及 30 秒轮询通过 `fetchMonitorNodes()` 获取展示表；调用在 `:51-59`，服务路径 `/monitor/nodes` 在 `graphApi.ts:586-587`。SSH 行由监控 API从同一 `t_ssh_node` 合并，因此管理 API 与列表展示共享 DB 真源。
3. 注册/编辑抽屉组装 `{name,host,port,sshUser,cred,tags,enabled}`，然后调用 `updateSshNode` 或 `createSshNode`，`DeployRuntimeView.vue:120-131`。
4. 页面另行调用 `listSshNodes()` 建立 `node name -> SshNodeRow` 映射，`DeployRuntimeView.vue:138-145`，供按钮取得 API 主键。
5. 手动探活调用 `probeSshNode(row.id)`，`DeployRuntimeView.vue:147-157`；删除调用 `deleteSshNode(row.id)`，随后刷新监控表和 SSH 行，`:159-173`。
6. API 封装最终经 `http` 追加 `/api/v1`、携带 `token` header、解包 `{code,msg,data}`，实锚 `datara-web/src/services/http.ts:1-12,39-46`。

### 2. 次消费点：画布 SSH 节点“执行节点标签”候选

`datara-web/src/graph/workbench/fields/fieldCtxFactory.ts` 导入 `listSshNodes`（`:22`），在真实后端模式调用列表端点并只保留 `{id,tags}`（`:481-485`）；随后将所有非空标签去重形成候选（`:235-240`）。这些标签最终进入 SSH 节点参数 `execNodeTag`，Worker 按标签选择健康节点。

### 3. 关联页面而非该 API 的直接调用者

`ScriptRemoteView.vue` 将 `/dep/runtime` 声明为 SSH 主机信息唯一维护入口（`:3-7,19-20`），并在无可导入节点或按钮操作时导航至该页（`:85-90,465-466,541`）。`DeployCenterView.vue:434-438` 也提示 SSH 配置来自运行时节点页。这些页面强化了 `/dep/runtime` 的产品入口地位，但当前源码中没有直接调用 `/ssh-nodes`。

## 四、外部服务、配置与中间件

- **SSH 客户端**：`paramiko>=3.4`，实锚 `datara-backend/requirements.txt:23`。探活创建 `SSHClient` 并使用 `AutoAddPolicy` 接受未知主机密钥，`common/sshprobe.py:39-40`；连接和命令超时均为 3 秒，`:10,42-56`；远端执行固定命令 `echo ok`，`:56-58`。
- **凭证形态**：`cred` 以 `-----BEGIN` 开头时依次尝试 RSA/Ed25519/ECDSA 私钥，否则当密码；实锚 `common/sshprobe.py:13-23,51-54`。当前 API 会在响应中原样回传 `cred`（`sshnode.py:43`），属于迁移时必须显式裁决的敏感契约。
- **Master 定时探活**：30 秒一轮、仅 leader 执行，连续 3 次失败才置 offline，成功写 online 与 `last_seen`；实锚 `master/ssh_probe.py:19-20,23-33,37-65`。线程由 `master/main.py:53-60` 启动。
- **Worker 路由**：`execNodeTag` 优先于旧 `runtimeNode`；从 `t_ssh_node` 选 `enabled=true AND heartbeat_state=online` 再按 JSON tags 过滤，实锚 `worker/executors/ssh.py:60-73,168-183`。迁移不能只搬 CRUD，否则执行路由会断链。
- **监控聚合**：`api/monitor.py:5,16,23` 明确从 `t_ssh_node` 合并 SSH 行；这与 WBS 17.3 集群监控、17.4 运行节点存在跨包契约依赖。
- **鉴权/权限**：旧 API 读权限仅要求登录，写与探活复用 `edit_definition`，见端点表；Token 状态依赖 Redis queue（`auth.py:94-103`）。
- **HTTP 中间件**：旧应用 CORS 开发期全开，`api/main.py:37-44`；异常由 `ApiError` 统一响应处理（类定义 `auth.py:53-61`，应用约定见其注释 `:54`）。
- **新后端运行配置**：重构 API 使用独立 `REBUILD_DB_URL` 与 `REBUILD_TOKEN_SECRET`，`rebuild/api/app.py:127-132`；Compose 运行在 8001，`docker-compose.yml:161-168`。迁移实现应接重构 session/auth 体系，不能直接复用旧 `get_db/get_current_user` 造成双栈。

## 五、迁移风险、冲突与 17.5 承载建议

### 1. 新后端现状核查

- 对 `datara-backend/rebuild/**` 及重构测试目录搜索 `sshnode`、`ssh-nodes`、`SshNode`、`t_ssh_node` 无命中；`rebuild/api/app.py` 当前路由装配区 `:898-966` 亦没有 SSH 节点路由。
- WBS 将 17.5 明确为 `rebuild/sshnode` + F 组挂载页联通闭环，实锚 `docs/increments/2026-10-20-单线多增量WBS开发计划.md:490-507`，其中 17.5 在 `:504`。
- 权威设计将 B7 `api/sshnode.py` 定为迁移候选，`docs/increments/2026-10-19-纠偏重构前端权威设计.md:897-906`；用户裁定已纳入迁移，WBS `:557-558,608-609`。

结论：不存在新后端等价实现，也没有代码级命名冲突；潜在命名风险是旧名 `sshnode`（无下划线）与相邻域 `runtime_node`（有下划线）风格不一致。17.5 已冻结承载域名 `rebuild/sshnode/`，除非 17.1 契约评审统一调整，否则不应另造 `ssh_node` 域。

### 2. 风险登记

| 风险 | 证据与影响 | 17.5 处置要求 |
|---|---|---|
| 凭证泄露/误语义 | 列名为 `cred_enc`，但注释和实现明确存明文；列表、创建、更新响应还回传完整凭证 | 契约冻结必须裁决是否保留回显。建议返回掩码/`hasCredential`，更新时支持“空值保持原凭证”；若改变旧契约，前端同步切换并登记破坏性差异 |
| 主机密钥校验缺失 | `AutoAddPolicy` 自动接受未知主机 | 迁移时至少登记安全债；若改为 known-hosts 校验，需配置与错误契约一起冻结 |
| CRUD 与运行链强耦合 | Master、Worker、Monitor 均直接读写 `t_ssh_node` | 不能只实现 5 条 API；需决定沿用同表还是迁表，并验证探活、监控、执行器在切换后的唯一真源 |
| 双写竞态 | 手动 probe 明确不落库，状态只由 Master 写 | 保持单写者原则；新 API 不应在手动探活时顺手覆盖 `heartbeat_state/last_seen` |
| 权限语义过宽且跨域 | SSH 基础设施写操作使用工作流权限 `edit_definition` | 映射到重构 identity 权限时需冻结具体权限点；不能默认为任意登录用户可写 |
| 名称唯一与更新竞态 | API 先查重，DB 另有唯一约束；并发仍可能抛 IntegrityError | 重构 repository 捕获唯一约束并稳定映射 HTTP 409/code 4102 |
| 请求校验不完整 | 旧模型未限制端口范围、名称长度、host 语法、tags 数量；Pydantic 类型错误可能走通用 422 | 契约冻结要决定保持还是收紧；收紧须列出错误码与前端提示 |
| 删除引用悬空 | 删除前不检查工作流中 `execNodeTag` 的使用；标签本身也无独立实体/FK | 删除验收需覆盖“仍被工作流引用”的产品裁决；至少保持当前警告语义并验证执行失败路径 |
| 状态时序 | 新建后默认 unknown；停用节点不会再探活，旧 heartbeat 值不会自动清空 | 页面需以 `enabled` 与 heartbeat 联合解释；迁移测试覆盖启用、停用、重新启用和连续三次失败 |
| API 路径/响应包差异 | 旧前端调用 `/api/v1/ssh-nodes` 且期望旧 envelope；重构域通常挂 `/api/v1/rebuild/...` | 17.1 冻结最终路径和 envelope，17.5 必须同步新前端服务层；旧路径下线留给 17.6 |
| 跨包落地顺序 | 页面同时依赖 monitor、runtime node、ssh node，分别归 17.3/17.4/17.5 | 17.5 联通验收应以 17.3/17.4 已冻结契约为前提；未就绪时采用明确适配层，避免复制监控/运行节点实现 |

### 3. 建议冻结的最小等价范围

17.5 至少应交付：SSH 节点模型与持久化、上述 5 条端点的等价能力、重构鉴权与权限映射、探活服务端口、Master/Worker/Monitor 的单一真源适配、F 组页面注册/编辑/删除/探活闭环，以及画布 `execNodeTag` 标签候选。自动探活和任务派发属于该注册表的可运行性契约，不能从“SSH 节点迁移”范围中剥离。
