## 四、成因推断：与 A6-18/19 的「分流闸」混同

漂移并非随意取值，而是把**逆向端点（A6-18/19）的分流闸口径**误套到了 physicalize：

| 端点 | 闸结构 | 不存在 | 非连接型 |
|---|---|---|---|
| **physicalize（A6-17）** | **单一合并闸** `ds is None or ds.type not in (...)` | **4001** | **4001** |
| **reverse（A6-18/19）** | **两段分流闸** `_conn_ds` / `_require_conn_ds` | 4001 | 4002 |

旧侧 `api/model.py` 逆向用 `_conn_ds`：

```python
def _conn_ds(db, ds_id):            # 旧侧逆向专用
    ds = db.get(DataSource, ds_id)
    if ds is None:
        raise ApiError(DS_NOT_FOUND, status=400)                                  # 4001
    if ds.type not in ("mysql", "greatdb"):
        raise ApiError(PARAM_INVALID, "逆向导入仅支持连接型数据源（mysql/greatdb）", status=400)  # 4002
    return ds
```

已入库 `_require_conn_ds`（`service.py:724-729`）与之逐字一致 ⇒ **A6-18/19 卡「4001 不存在 / 4002 非连接型」正确**。

⇒ **A6-17 卡把逆向端点的「非连接型=4002」误植到 physicalize 的合并闸上**，故写成了「4002 数据源不存在或非连接型」。physicalize 与逆向的闸语义**本就不同**，这是旧侧既有的、有意的不对称，实现侧忠实保留了。

## 五、更正建议（供监督线采纳）

**A6-17 冻结卡「错误码」建议改写为**：

> 8001/404 模型不存在；**4002/400** mode 非法/引擎不支持；**8003/400** DDL 生成失败（非法标识符/类型/空字段）；**4001/400** 物理化需选择 mysql/greatdb 连接型数据源（数据源不存在或非连接型，**单一合并闸**）；8009/400 DDL 解析失败/执行失败（data 带 executed/error）

要点：
1. `数据源不存在或非连接型` 归入 **4001**（对齐旧侧 `DS_NOT_FOUND` 合并闸），不再写作 4002；
2. 补列 **8003/400**（与 A6-16 卡口径一致）；
3. `mode 非法 / 引擎不支持` 保留 4002（正确，无需改动）。

**其余 21 卡无需改动。**

## 八、次要注记：A6-21 `edges[].relType` 仅 declared 边携带

冻结卡 A6-21 出参把边形状写作 `{from, to, kind, relType}`。实际：

- **declared 边**（`service.py:903`）：`{"from","to","kind":"declared","relType"}` —— **有** `relType`；
- **runtime 边**（`service.py:921-925`）：`{"from","to","kind":"runtime"}` —— **无** `relType`。

**旧侧 `api/model.py:766-771` 同构**（runtime 边同样不带 `relType`）⇒ **实现忠实照抄，非漂移**。

建议（**注记级，非阻塞**）：A6-21 卡出参注记可补一句「`relType` 仅 `declared` 边携带，`runtime` 边无」，供前端判空。
