## 三、保存语义逐行照抄（`api/model.py:288-305`）

```
① record = get(DwModel, model_id)          → None 即 8001/404
② if record.status != "draft":             → 8007/409（状态闸先于乐观锁）
③ UPDATE t_dw_model SET version = version + 1
     WHERE id = :model_id AND version = :rev
   rows == 0 → refresh(record) 回读真实 version → 8006/422 data={"currentRev": ...}
④ record.version = rev + 1                 （ORM 对象 version 已被 ③ 的批量 UPDATE 绕过，须显式置值）
⑤ 全量替换字段：delete 该模型所有字段 → 按提交顺序 enumerate(..., 1) 重排 seq 后逐条 insert
⑥ commit；返回 {"rev": record.version}
```

**三处照抄要点（易错，逐项标注）**：

1. **状态闸先于乐观锁**：非 draft 时即便 `rev` 错误也返回 8007，不返回 8006（用例 4 断言）。
2. **乐观锁用条件 UPDATE 的 rowcount，而非先读后比**：`rev` 已被他人推进时 rows=0；
   此时 `session.refresh(record)` 回读**真实** version 作 `currentRev`（用例 5 断言 `currentRev == 3`）。
3. **`record.version = rev + 1` 显式置值**：`.update()` 走 SQL 层绕过 ORM 身份映射，
   不置值则 ORM 对象仍是旧值，返回的 `rev` 会错（用例 3/6 断言回读 `version` 与 `data.rev` 一致）。
4. **全量替换非合并**：先 `delete()` 再按提交顺序重排 `seq`；旧字段不留存（用例 3 断言 `old_a` 消失）。

## 四、路由可达性（与 17.2-04/05/07 静态段风险的**区别**）

`/models/{model_id}/fields` 为**三段**路径；Starlette 按**段数**匹配，两段的
`/models/{model_id}` 不可能吞并三段请求，故**不存在** 17.2-07 那类吞并风险。

- 本票将 A6-9 注册于 A6-7 之后，次序**不影响**匹配（用例 9 的 `rivals` 断言据此写为
  「其前无**末段为路径参数**（`{...}`）的同段数路由」而非「须先于两段路由」）。
- **勘误（自披露，17.2-10/11 批修正）**：本节用例初版 `rivals` 过滤写作「同段数且路径不同」，
  过宽 —— 字面尾段不同（如 `/fields` vs `/publish`）的路径永不匹配，不构成吞并。
  已在 17.2-10/11 批修正为「末段以 `{` 开头」，修正后本文件 SHA 为
  `b23c9681495d94b4af572d91c410261140bf41b9471d34ddeeade3bc1a87699a`。
- 用例 9 行为验证：同一 `model_id` 上 `PUT .../fields`（stale rev → 422/8006）与
  `PUT .../{model_id}`（→ 200 + `data.remark`）各自语义独立。
- **候核**：此处若监督线要求与 A6-4/5/7/8 统一「静态段整体先行」的注册风格，可零成本前移，
  行为不变；本票按「同前缀聚合可读性」放置，已在 `api.py` 模块 docstring 注明三者互不前缀吞并。
