## 二、语义逐行照抄（`api/model.py:687-735` → `api.py:585-630` + `service.py:827-870`）

### 2.1 分层：路由 vs 服务（★与旧侧同构）

旧侧把「分块读取 + 5MB 闸 + 解码 + 解析 + 建模特写在一个路由函数体内」。rebuild 按**关注点**拆成两层，但**每步语义逐行对应**：

| 层 | 职责 | 旧侧行 | rebuild 落点 |
|---|---|---|---|
| API（HTTP IO） | `file.size` 快速拒绝 + 分块读取二次校验 | `:692-705` | `api.py:604-622` |
| 服务（纯逻辑） | 解码 → 解析 → 逐表建模特 → 提交 | `:706-735` | `service.py:827-870` |

**为何这样拆**：`decode_ddl`（`service.py:121-131`）与 `parse_create_tables`（`ddlparser.py`）是**纯函数**，拆出后可直接单测/差分；分块读取是 HTTP IO 关注点，留在 API 层。旧侧两步 5MB 闸**两道都保留**（见 §2.2）。

### 2.2 5MB 上限：双层闸（★照抄）

| 旧侧行 | 语义 | rebuild 落点 |
|---|---|---|
| `:692` | `limit = 5 * 1024 * 1024` | `api.py:603` |
| `:693-694` | `if file.size is not None and file.size > limit:` → 4002（**size 可能为 None**） | `api.py:604-606` |
| `:696-704` | `while True` 分块（`1MB`）读取；`total > limit` → 4002；`if not chunk: break` | `api.py:608-622` |
| `:705` | `raw = b"".join(chunks)` | `api.py:623`（作为服务入参） |

边界测试：`test_reverse_import_ddl_oversize_is_4002`（5MB+3 → 4002）与 `test_reverse_import_ddl_exactly_at_limit_is_not_rejected_by_size_gate`（恰 5MB → **不**被拦）双侧夹逼。

### 2.3 解码兜底（`decode_ddl`，★照抄）

| 旧侧行 | 语义 | rebuild 落点 |
|---|---|---|
| `:706-709` | `raw.decode("utf-8")`，`UnicodeDecodeError` → `raw.decode("gbk", errors="replace")` | `service.py:121-131` |

测试 `test_reverse_import_ddl_gbk_fallback` 以 GBK 字节（含中文注释）上传 → 断言注释原样落库。

### 2.4 解析失败 → 8010（★照抄）

| 旧侧行 | 语义 | rebuild 落点 |
|---|---|---|
| `:710-715` | `parse_create_tables(sql)`；`except Exception` → `line = getattr(exc, "line", None)` → `ApiError(MODEL_DDL_INVALID, f"DDL 解析失败：{exc}" + (f"（第 {line} 行）" if line else ""), status=400)` | `service.py:831-840` |

**照抄要点**：`except Exception`（**不是**只捕 `ParseError`）+ `from None` 断链；`line` 为 `None` 时**不**附行号（falsy 三元）。

### 2.5 逐表建模特（★照抄）

| 旧侧行 | 语义 | rebuild 落点 |
|---|---|---|
| `:718-720` | `code = (t["name"] or "").strip()`；`if not code: continue`（**不计入 skipped**） | `service.py:842-845` |
| `:721-723` | 同名模型 → skipped「同名模型已存在」 | `service.py:846-848` |
| `:724-728` | `_check_code(db, code, "ODS")` 不过 → skipped（`e.msg or "校验未通过"`） | `service.py:849-853` |
| `:729-731` | `_reverse_create(db, code, "ODS", "", "", "MySQL", owner, t["fields"], remark=t["comment"] or "DDL 导入")` | `service.py:854-857` |
| `:732` | `db.commit()` | `service.py:858` |
| `:733-734` | `audit.info("model.reverse_import user=%s ddl imported=%d skipped=%d", ...)` | `service.py:859-862` |

**四处「照抄而非优化」的刻意为之**：

1. **`layer` 恒 `"ODS"`、`engine` 恒 `"MySQL"`**（旧侧硬编码字面量，非入参、不查字典表）。
2. **`name` 传空串** → `_reverse_create` 的 `name or code` 回落为编码。测试 `test_reverse_import_ddl_creates_ods_draft` 断言 `m.name == "ods_trade_order"`。
3. **`remark = t["comment"] or "DDL 导入"`**：有表注释用注释，无则用标记串。两测试分别锁定（`..._creates_ods_draft` / `..._remark_falls_back_to_marker`）。
4. **`code` 为空 → `continue` 不计 skipped**（旧侧 `:719-720`）：与「同名模型/校验不过」的 skipped 语义刻意不同。

### 2.6 `_check_code` 复用 17.2-19 的放宽

`self.session.get(DwLayerRecord, "ODS")`（`service.py:850`）—— 复用 17.2-19 已放宽的 `Optional[DwLayerRecord]` 签名。默认种子 ODS 层 rule 前缀为 `ods`，故 DDL 表名须以 `ods_` 开头（旧侧同语义）。测试 `test_reverse_import_ddl_skips_naming_rule_violation` 锁定。

## 三、随票下沉：`rebuild/model/ddlparser.py`（★候裁 ①）

`parse_create_tables` 逐行移植 `common/sqlparser.py:289-337`，落新增模块 `rebuild/model/ddlparser.py`（3453 B）。

- **为何独立成模块**：与既有 `rebuild/model/ddlgen.py`（模型 → DDL 文本）**互为反向**（DDL 文本 → 契约字段），语义方向不同，混放会误导。
- **为何不并入 `common/sqlparser.py` 的其余部分**：该模块其余为**血缘**（`StmtLineage`/`FieldMap`，17.2-21/22 分片），语义与本票无关。已在模块 docstring 注明：血缘票建议另立 `rebuild/lineage/` 承载，避免血缘语义混进 DDL 导入模块。
