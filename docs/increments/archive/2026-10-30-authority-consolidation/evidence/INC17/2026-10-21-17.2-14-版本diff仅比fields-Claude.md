## 二、diff 语义逐行照抄（`api/model.py:377-394`）

```
_get_model(db, model_id)                     → None 即 8001/404（内置 msg）
cur  = query(DwModelVersion).filter(id == version_id, model_id == model_id).first()
cur is None                                  → 8001/404（**显式 msg**「版本不存在」）
prev = query(...).filter(model_id == model_id, id == base).first() if base else None
a = json.loads(prev.snapshot_json) if prev else {"fields": [], "model": {}, "relations": []}
b = json.loads(cur.snapshot_json)
af = {x["name"]: x for x in a.get("fields", [])}
bf = {x["name"]: x for x in b.get("fields", [])}
added    = [bf[k] for k in bf.keys() - af.keys()]
removed  = [af[k] for k in af.keys() - bf.keys()]
changed  = [{"name": k, "before": af[k], "after": bf[k]}
            for k in bf.keys() & af.keys() if af[k] != bf[k]]
return {..., "relationsChanged": a.get("relations", []) != b.get("relations", [])}
```

**五处照抄要点**：

1. **两次 8001 判定对象不同**：模型缺失用**内置** msg（「模型不存在」）；版本行缺失用**显式** msg
   「版本不存在」。用例 8/9 分别断言，用例 10 断言他模型的版本 id 对本模型不可见（`(model_id, id)` 双重限定）。
2. **`base` 缺省或指向不存在的版本 id → 静默按空基准处理，不报错**：旧侧 `if base` + `.first()` 返回 `None`
   即走空快照分支。用例 3 断言 `base=424242` 时全量计入 `added` 而非 404。
3. **diff 仅比较 fields**：快照 `model` 块不同**不**体现在出参。用例 7 断言 `remark` 由「旧备注」改「新备注」
   时 `added/removed/changed` 皆空、`relationsChanged` 为 `False`。
4. **`relationsChanged` 为全量关系列表的相等性布尔**（非关系列表 diff）：任一处不同即 `True`。
   用例 2（同关系 → `False`）与用例 6（`joinDesc` 变 → `True`）双向断言。
5. **`added`/`removed`/`changed` 的顺序为 set 迭代序**（旧侧用 `dict.keys()` 差集/交集，非插入序）。
   rebuild **照抄**该集合运算，**不**做排序「优化」；用例对 `added`/`removed` 断言时按名字集合比较
   （用例 2 断言单元素列表故顺序确定；用例 3 用 `sorted(...)`）。
   **候核**：若监督线要求 diff 输出稳定排序（便于 FE 展示/快照测试），属行为变更须走变更单。

## 六、候办 / 候核

1. **两次 8001 的 msg 不同**（§三1）：模型缺失 → 内置「模型不存在」；版本缺失 → 显式「版本不存在」。
   旧侧同形，候核确认。
2. **`base` 指向不存在版本时静默按空基准**（§三2）：不报错、不 404。候核确认该「宽松」口径。
3. **diff 仅比较 fields**（§三3）：`model` 块差异不体现。候核确认。
4. **`relationsChanged` 为关系列表相等性布尔**（§三4）：非逐条 diff。候核确认。
5. **`added`/`removed`/`changed` 顺序为 set 迭代序**（§三5）：照抄未排序；若要求稳定排序属行为变更。
6. **`base` 语义为版本行 id 而非版本号**：契约卡与旧侧实现一致（均按 `id == base` 查），
   但参数名 `base` 未体现该语义 —— 候核确认无需重命名（重命名属 FE 契约变更）。
7. **审计留痕未迁**（沿用前票口径）：旧侧 `api/model.py:377-394` **无** `audit` 调用，本票一致。
8. **`test_execution_models` 全量基线失败归属**（§4.2）：同前票。
9. **17.2 链续行**：17.2-15（`POST /models/{model_id}/versions/{version_id}/rollback` 版本回滚，
