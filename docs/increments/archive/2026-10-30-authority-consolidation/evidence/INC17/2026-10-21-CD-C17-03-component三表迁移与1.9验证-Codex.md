# CD-C17-03：component 三表迁移与 1.9 验证（Codex）

## 交付范围

- 通过共享 `MigrationRunner` 注册 `i4_0001_component_catalog`，创建 `t_component`、`t_component_version`、`t_component_log`，没有绕过迁移台账直接执行部署 DDL。
- 启动装配在 `create_app()` 的建表阶段调用 `apply_component_spec_migrations(engine)`。
- migration 带固定 SHA-256 checksum、幂等跳过、已有结构兼容性检查、索引与唯一约束校验，以及完成记录后的全量 schema 再校验。
- 已有表结构不完整、索引缺失、checksum 漂移或完成后 schema 被破坏时均 fail closed。

## 1.9 部署验证

首次远端启动在 MySQL Inspector 返回列元数据不含 `primary_key` 字段时 fail closed；部署流程随即回滚，服务恢复 `healthy`。修正主键内省为 `Inspector.get_pk_constraint()` 后重试成功。

成功部署后的数据库实测：

```text
t_component         exists=true columns=17 rows=0
t_component_version exists=true columns=12 rows=0
t_component_log     exists=true columns=11 rows=0
i4_0001_component_catalog status=completed
```

随后执行第二次 restart，服务仍为 `healthy`，迁移重复执行保持幂等，三表与 `completed` 台账记录保持不变。

无 token 的 curl 返回 HTTP 401，仅证明网关鉴权生效；本票不把它表述为业务 API 200 或业务链路通过。
