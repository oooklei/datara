### 2.2 内省（`reverse_scan`）

| 旧侧行 | 语义 | rebuild 落点 |
|---|---|---|
| `:578` | `target_db = body.dbName or ds.db_name or ""` —— **falsy 链** | `service.py:648` |
| `:579` | `open_connection(ds)` —— **不传 `db`** | `service.py:649` |
| `:581-586` | 查询①`information_schema.TABLES`（`TABLE_TYPE='BASE TABLE'`，`ORDER BY TABLE_NAME`），参数 `(target_db,)` | `service.py:652-658` |
| `:587-591` | 查询②`information_schema.COLUMNS`（`GROUP BY TABLE_NAME`），参数 `(target_db,)` | `service.py:659-664` |
| `:592-595` | `col_counts = {r[0]: int(r[1] or 0) ...}` | `service.py:665` |
| `:596-598` | `cur.close()` / `conn.close()` 双层 `finally`（**游标非上下文管理器**） | `service.py:666-671` |
| `:599-600` | `tables = [{tb, comment: r[1] or "", rows: int(r[2] or 0), cols: col_counts.get(r[0], 0)}]` | `service.py:672-677` |
| `:601` | `return ok({"db": target_db, "tables": tables})` | `service.py:678` |

**五处「照抄而非优化」的刻意为之**：

1. **连接不传 `db`**：连接落在 `ds.db_name`，`target_db` 只进 SQL 的 `TABLE_SCHEMA = %s`（`information_schema` 跨库可查）。测试 `test_reverse_scan_connects_without_db_override` 断言 `connector(ds)` 被调用且 `db is None`。
2. **`dbName or ds.db_name or ""` 的 falsy 链**：`dbName=""` 视为未填 → 回退数据源库；两者皆空 → `target_db=""`（**空串库名合法，不报错**）。两测试锁定（`_db_name_empty_string_is_falsy_fallback` / `_empty_target_db_when_both_blank`）。
3. **表序由 SQL 决定**：Python 侧**不重排**，输出序 = `ORDER BY TABLE_NAME`。测试 `test_reverse_scan_shape_and_values` 断言 `["t_order","t_user"]`。
4. **`None` 兜底**：`comment` `None → ""`、`rows` `None → 0`、`cols` 查不到 → `0`（`col_counts.get(..., 0)`）。同测试断言 `{"tb":"t_user","comment":"","rows":0,"cols":3}`。
5. **双层 `finally` 释放**：`cur.close()` 与 `conn.close()` 各自独立 `finally`（旧侧游标**不**用 `with`）。测试 `test_reverse_scan_closes_cursor_and_connection` 断言两者皆 `True`。

## 四、★本票无差分锁定件（如实说明）

17.2-16 有 `ddlgen` 纯函数差分、17.2-17 有 `open_connection` 参数差分，**本票刻意不加差分件**，理由如实记录：

- `reverse_scan` 的全部逻辑是**两条 SQL 文本 + 一处 dict 装配**，SQL 为路由内联字面量（旧侧同形态）。把字面量抽成模块常量再做「字符串 == 字符串」的差分，只是**拿副本比对自身**，不构成独立证据。
- 真值证据已由契约测试承担：SQL 形态（`information_schema.TABLES` / `TABLE_TYPE='BASE TABLE'` / `ORDER BY TABLE_NAME` / `GROUP BY TABLE_NAME`）、参数 `(target_db,)`、`None` 兜底、表序、释放顺序 —— 均有断言（`test_reverse_scan_two_information_schema_queries_and_params` 等）。
- 若监督线认为仍需差分锁定，建议在 192.168.1.9 真库上做**双侧同库对拍**（同一 `target_db` 跑旧侧与新侧，比对 `tables` 列表），那才是本票唯一缺失的证据类型。
