## 1. 交付范围

- execution 域新增 `workflow_run_stat` run 级权威统计表；`workflow_instance_id` 唯一。
- 新增 `workflow_run_reconcile_detail` 表级明细；`(run_stat_id, source_object, target_object)` 唯一并 upsert。
- 新增版本化 migration `r9_0002_run_statistics`，纳入 execution migration registry。
- `/result-stat` 归属明确为 execution 域 executor 贡献入口：只登记绑定 instance/task/attempt 的贡献；终态聚合由 `RunStatisticsService` 统一生成快照。
- workflow instance 进入终态时自动聚合；最终有效 attempt 定义为该 task 具有终态的最大 attempt 序号，无终态 attempt 不贡献。
- STREAM checkpoint 路由已挂接可覆盖快照；无贡献的首个 checkpoint 建立 0/0/0 快照，计数下降以 4109 拒绝。
- 新增 `GET /api/v1/rebuild/execution/workflow-instances/{id}/run-stat` 明细查询及 `GET /api/v1/rebuild/execution/run-stats` 项目级分页/过滤查询。
- `data_param` 在写入与输出前做敏感键遮蔽；端点继续使用 TokenService/项目权限门。

## 2. 核心行为证据

- 重试场景：attempt 1 的 2/3 被 attempt 2 的 9/1 替换，终态统计为 9/1/10，不重复累加。
- 普通任务允许零条表级明细；无终态 attempt 的 99 条贡献不进入终态统计。
- 表级明细计算 `difference_count=target_count-source_count`，重复聚合保持单行。
- STREAM checkpoint 若从 5 降至 0，返回领域错误 4109。
- API 查询返回 `{code,msg,data}` 信封，项目隔离，敏感 `api_token` 输出为 `***`。
- reconcile detail 的 bool、负数计数均以 4107 拒绝，缺失源/目标计数保持 `NULL` 且不计算伪差值。
