## 1. 总体理解与边界

D9 的优先级是明确的：遇到 DBX 与旧版 SQLIDE 的业务语义冲突时，SQL IDE 重构按 DBX 语义确定基线；旧版可贡献可辨识的交互优势，但吸收项须不破坏该语义。该规则属于参考和复刻优先级，不授权直接复制 DBX Tauri 壳、Web API 私有形态或凭证实现。设计 D4 规定 DBX 不深绑，D6 规定身份、项目、变量、权限、审计和运行关联 ID 由 Datara 持有；因此 R5 应复刻已核实的能力语义，并通过 Datara 自有契约与数据模型实现。

P2-2 是 R5-A 的自研只读 SQL IDE，承接查询、只读目录/元数据、跨 Schema 上下文和冻结后的查询生命周期；R5-B 承接 DDL 与数据写入闭环。旧版或 DBX 中的写入能力只能登记到 R5-B / A5 议程，不能因为出现在融合清单就混入 R5-A。所有“支持”必须按 `databaseType × objectType × operation` 逐项限定；源码有通用 RPC 或 UI 类型声明，不等于具体驱动/数据库版本可用。

## 2. DBX 优先冲突判定及可执行映射

| 冲突 | 评审结论 | P2-2 / 后续可执行落点 | 冻结前约束或风险 |
|---|---|---|---|
| C1 编辑器内核 | 采纳 DBX CodeMirror 6 与 composable 分层；旧版 Monaco 专有实现不作为内核基线。`datara-sql` 与 `${...}` 语言规则作为迁移输入。 | R5-A 选定 CM6 后，将变量高亮/补全的功能需求映射到 Datara 变量服务和编辑器扩展点；列明扩展注册、资源释放、跨 tab 隔离及无数据源时的降级验收。 | 变量解析/快照以后端 R2 契约为准；编辑器补全和交互校验属于后端冻结后的前端阶段，P2-2 只冻结后端接口需要的上下文。 |
| C2 语句切分与执行目标 | 采纳 DBX 语句边界完整性优先；选区只是执行目标收集输入，不能截出半条语句。 | R5-A 契约用明确例子冻结边界：光标所在语句、完整语句范围、多语句选择、注释/字符串内分号、选择跨越部分语句。将旧版“选中片段直接执行”列为兼容选项评审。 | “显式确认后允许半条语句”也会违背当前 DBX 优先判定；如要保留该能力，须 A5 明确裁定其语义，不能作为普通前端快捷行为悄然实现。 |
| C3 对象枚举及只读门控 | 采纳 DBX 对象粒度，不能退化成旧版仅 database/table/column 三层；同时不能将 DBX 13 个 `ObjectSourceKind` 误当成每种驱动均支持。 | P2-2 先冻结只读对象树映射（DBX 13 类与 Table/Index 独立结构的关系、R5-A MetaTree 9 类收敛、扩展回补门槛）；使用 §2.4 的逐路由 L/G/N 证据作为“可读”边界，并在契约中保留 C/U/N/NA。 | 此矩阵只覆盖特定对象/操作及静态源码证据，不能证明权限、版本、Agent/JDBC 插件能力或运行成功。对象写入、生成、校验、依赖、执行、回滚在矩阵证据不足时不得宣称完成。 |
| C4 连接模型 | 采纳 DBX 的连接池/metadata pool/驱动适配分级作为设计参照；保留 Datara 数据源中心作为管理界面与主权边界。 | P2-2 查询契约只依赖 Datara 的 datasource/connection ID 和授权上下文；把连接池能力等级、schema/catalog 选择及驱动差异作为后端上下文/能力协商输入。 | 不照搬 DBX PoolKind 成为 Datara 外部契约，不要求 P2-2 重造数据源管理。连接池分级具体实现归后端/运行时设计，需与 D6 权限审计一致。 |
| C5 凭证存储 | 方向上采纳 DBX 密文存储与显式迁移/失败关闭原则，具体实现遵循 Datara 安全基线和 R6 裁定。 | P2-2 只消费受控连接，不获取/持久化数据库密码；在接口设计中传递受授权连接标识。凭证实现作为依赖，不把密码放入 SQL 历史、资产或执行事件。 | DBX SecretCodec/AES 与迁移状态机是来源证据，不自动等于 Datara 已完成同等方案；不能据此复刻密钥路径或将 DBX 凭证做真源。 |
| C6 编辑器交互工程 | 采纳 DBX composable/语义交互为基线；Monaco 原生能力逐项评估价值与迁移成本。 | 以用户任务编列可验收交互：补全、悬停、表结构 Peek、表名拖入、搜索/goto、诊断、键位；每项指定后端数据依赖、空/错误状态、键盘可达性与前端验收用例。 | “DBX composable 巨阵”是结构参考，不是必须照搬每个实现。与后端能力无关的 Vim 等能力可独立排序，不能成为 R5-A 后端阻塞项。 |
| 查询生命周期（§1） | 语义上采纳 DBX 单连接会话串行、结果集返回、取消/超时/错误模型；Datara 的 taskId/SSE 可作为传输适配。 | A5 必须把执行状态机、提交/查询/取消/超时/事件恢复、并发约束、单连接串行与多语句行为写进 BE 契约；R5-A 按冻结语义实现并确保 transport 不增加隐式重试/重放。 | DBX Tauri 前端请求响应形态与其内部 Tokio 异步任务是不同层次。不得把“请求响应”误读为内部同步执行，也不得把 Datara SSE 生命周期误判成 DBX 执行语义。等待 A5 裁决时不宣称语义冻结。 |

## 3. DBX 融合点的阶段与落地方式

| 清单 §4 融合点 | 建议处理 | 阶段/验收输入 |
|---|---|---|
| 连接池分级、metadata pool、驱动适配 | 作为 Datara 后端连接抽象能力参照；建立数据库类型、驱动类型与操作能力映射，不暴露 DBX 内部枚举。 | P2-2 查询与目录契约消费能力信息；基础池化由后端基础设施落实，注明连接耗尽、超时、释放语义。 |
| Agent/ExternalDriver/Plugin 驱动进程治理 | 只纳入与 Datara 已批准驱动范围相关的生命周期需求；先补精读/风险说明，再确认实现。 | 有目标驱动时成为独立基础设施任务；不能从进程监控 UI 直接推导可部署/可重启能力。 |
| 结果网格语义（key columns、变换、详情、筛选） | 将只读结果呈现与大结果集浏览纳入 R5-A 前端验收输入；明确分页、截断、排序和筛选在服务端还是客户端。 | P2-2 冻结 BE 分页/游标/结果元数据契约，前端网格工作由后续重构实施。编辑操作放 R5-B。 |
| 数据编辑闭环（插入行、DML 预览、危险确认） | 有价值但写入能力；按 Datara 权限→依赖→影响预览→快照→确认→执行→审计/补偿闭环重新设计。 | R5-B；不可由 DBX UI 行为替代 Datara §13.6 要求。 |
| 语句边界与执行目标选择器 | 纳入 C2 后端执行目标规则及前端操作设计。 | A5/R5-A；边界案例须有契约例子和验收用例。 |
| 编辑器工程功能（搜索/goto、Peek、拖拽、Vim、快照） | 逐项判断与 SQL 开发任务相关性。搜索/goto、Peek、拖拽可作为生产力候选；Vim 与代码快照可排序为后续选项。 | 前端重构候选；仅 Peek/补全等需要对象元数据能力的项目对 P2-2 提供接口需求。 |
| schema/data diff、schema cache、全局搜索 | 先区分对象结构差异、跨源迁移、工作区文件搜索三种产品能力；不能都标成 SQL IDE 核心已具备。 | schema diff/data compare 与写入闭环放 R5-B 或独立治理；缓存失效/权限范围是后端设计输入；工作区文件搜索属于可选工具能力。 |
| 类型化错误 | 采纳错误分类思想，并由 Datara 定义稳定错误码/可重试性/脱敏消息。 | P2-2 查询错误契约与 FE 用户反馈；覆盖取消、超时、权限、驱动不可用、SQL 错误、部分成功及结果过期。 |

## 4. 原版 SQLIDE 特色吸收项：逐项结论

| 项 | 结论 | 可执行验收描述 | 所属边界 |
|---|---|---|---|
| 1. 表/视图悬浮菜单生成 SQL 草稿 | 采纳交互方式，适用范围经只读对象能力限制。 | 对可读表/视图展示操作菜单；选操作后只将生成的 SQL 草稿填入编辑器，不自动执行；无权限/不支持对象时隐藏或禁用并说明原因。 | UI 后续实现；其生成 SQL 不代表 DBX 方言 builder 能力，R5-B 才能执行写入。 |
| 2. 结果 Tab 回显原始 SQL、单元格复制 | 采纳。 | 每个结果 Tab 稳定关联原 SQL 与语句序号；切回 Tab 可查看/复制；复制单元格成功/失败提供反馈，并支持键盘操作。 | 前端验收；需后端稳定返回执行/语句标识及 SQL 展示策略，按权限和敏感信息规则脱敏。 |
| 3. Ctrl+Enter / Ctrl+S / Ctrl+Shift+F | 有条件采纳。 | 快捷键仅在 IDE 编辑上下文生效；焦点在输入控件时不劫持浏览器/系统行为；保存无名称时进入命名反馈；格式化失败保留原文并说明。 | 前两键对应执行/资产 API；格式化属编辑器能力。需与 DBX 键位/平台差异一起做可配置及帮助提示。 |
| 4. 结果页间数据漂移提示 | 采纳。 | 当服务端重放分页可能跨快照发生变化时，明确展示“结果可能变化”；若后端提供 snapshot/version 则据其决定是否显示，不伪称稳定快照。 | R5-A 后端结果分页语义+前端提示。 |
| 5. 服务端重放分页 | 有条件采纳其可复看价值，不照搬“历史 SQL 重执行即得历史页”的不稳定假象。 | 优先采用同一执行结果的服务端 cursor/物化快照分页；若实现只能重新执行 SQL，必须明示副作用、权限、数据漂移与资源成本，默认不得对任意 SQL 静默重放。 | A5/R5-A 冻结分页/结果保留方案。原版接口锚点说明这是重放分页，需校验其实际查询行为后再定复刻方式。 |
| 6. `${var}` 变量分色与分类补全 | 采纳需求，语义以 Datara R2 变量契约为准。 | 变量命名空间、作用域、时间表达式分类展示；执行前由后端共享变量服务解析并生成不可变快照；前端高亮/补全不能自行成为变量解释器。 | 后端契约属于 P2-2 输入；完整编辑器交互属于后续前端阶段。 |
| 7. 失败即停、警告收集、取消标记 | 有条件采纳。 | 多语句失败时按冻结策略停止后续语句并保留每条状态；警告与错误分离；取消是明确状态且可与超时区分；部分成功不可冒充全批回滚。 | A5 查询生命周期裁定后实现。DBX 单连接串行与 Datara SSE transport 必须分层。 |
| 8. 数据源中心独立页面 | 采纳信息架构边界，不在 SQL IDE 重做数据源管理。 | IDE 用受授权的数据源选择器/连接状态入口；新增、编辑、凭证和权限管理跳转/调用 Datara 数据源中心，切换回 IDE 保留合理上下文。 | P2-2 依赖 Datara 数据源契约；主要是前端结构与导航验收。 |

## 5. 当前可用结论、剩余裁定及建议进入 P2-2 的工作序列

1. **可直接作为 P2-2 需求输入**：CM6 基线与变量服务边界；对象树按 DBX 粒度建模并逐驱动声明能力；跨 Schema 的 database/schema/catalog 上下文；查询结果/历史/资产/导出 API 所需数据；DBX 执行语义与 Datara 传输层分开；原版可用性吸收项的验收草案。
2. **A5 冻结前要明确**：语句选区与完整语句规则；执行任务状态/取消/超时/恢复/并发；多语句事务与 continue-on-error；分页是同一执行结果 cursor 还是重新执行；SQL 历史和变量快照的敏感信息/审计策略；驱动能力声明与权限错误/空目录的区分。
3. **不得放进 R5-A 只读验收**：table/object DDL 写入、数据行编辑、保存即执行、危险确认后的 DDL/DML、依赖/影响分析和回滚。这些进入 R5-B，并按 Datara 写操作治理标准实现。对象树和定义读取仍以实际 R5-A 白名单及逐驱动证据为准。
4. **实现顺序建议**：先冻结 P2-2 依赖的 Datara 后端查询上下文/能力发现/只读目录/结果生命周期与变量快照契约；再实现 R5-A 查询链及只读对象导航；以真实任务流验收快捷键、草稿生成、结果分页/复制/警告等前端体验；最后独立评审 R5-B 写入闭环。前端交互样本可并行整理，但不替代后端契约冻结。
5. **清单精度说明**：v2.3 已修正 §2.4 N 列规则④，格值保持不变；该版本从文档闭环角度解决了已知矛盾。§9 仍明确 DataGrid 后端 SQL 校验链、特殊驱动生命周期深语义、schema/data diff 算法等有待精读，因此相关融合点仍是条件输入，不应声称全源码所有细节已定。清单整体为议程与证据清单，不是 SQL IDE 设计规格或完成报告。

## 6. 一句话交接

P2-2 应以 DBX 的能力语义与边界为 SQL IDE 参考基线、以 Datara 自有契约承载连接/变量/项目/权限/审计，并将旧版的高价值操作反馈作为可验收 UI 要求逐项吸收；所有写入闭环、依赖/影响验证、版本/审计和补偿按 R5-B 独立满足 Datara 标准。清单 v2.3 的证据已足以作为设计输入，但 A5 生命周期、执行目标与分页决策仍须冻结后才能作为实现规范。
