## 3. 复刻映射

### 3.1 依赖组件 → R4 契约（A2 v2 修订依据）

DS 结构与我方草案 `groups[{join, conditions}]` 同构（dependTaskList↔groups、组内 relation↔join）。v2 补齐（详见 A2 v2 节）：

1. 条件项新增 `kind: workflow|task|file|table_state|external_task`——workflow/task 为 DS 原生复刻（dependentType 映射，task 缺省=整工作流成功对应 `DEPENDENT_ALL_TASK_CODE`），file/table_state/external_task 为设计 §6.5 的 Datara 扩展项。
2. 条件项新增 `dependResult`（成功/失败极性——可依赖上游失败；D1 定性：DS 执行路径不消费该字段（`DependentExecute.java:L392-L416` 组合判定无 `getDependResult()` 调用，本线实证），属 **Datara 扩展**非 DS 原生等价，须单独定义极性转换/两级 AND/OR 三态合成/NON_EXEC 映射）。
3. 配置级新增 `checkInterval`（轮询周期）、`failurePolicy: fail|waiting` + `failureWaitingTime`（失败策略）、依赖超时配置（对应注解"超时"）。**F1 单位落位（v2.1 按用户裁定修正，心跳 #41/#42）**：契约字段名直接带单位（`check_interval_seconds`/`failure_waiting_seconds`）；DS `failureWaitingTime` 源单位=分钟，实现层强制登记「源分钟 ×60 → 契约秒」精确换算（正整数分钟、禁隐式舍入、乘法范围校验、换算测试强制列入 R4 验收）；字段归属与 DS `Dependence` 嵌套对齐（五字段为配置级、与 groups 同级保存，F2 对齐）。**checkInterval 实证注记（v2.1）**：本 DS 源码树中该字段仅声明+校验（`DependentParameters.java:L47/L64`，可空须正数），后端执行路径未消费（全库零调用）、UI 无默认值——契约按 Datara 自有轮询实现消费，**不宣称「DS 默认 10 秒」**。
4. 时间窗（v2.1 按 D4 修订）：`dateValue` 为窗口计算**权威输入**（DS `DependentUtils.getDateIntervalList` 返回 `List<DateInterval>` 多区间实证，`DependentUtils.java:L71-L72`），`cycle` 仅作表单分组/校验；计算层保留我方 ISO 8601 窗口输出；v1 `begin_offset/end_offset`（offset-ISO）为 **Datara 扩展**，未经逐窗口多区间验证不得宣称 DS 等价。
5. 组合判定语义照搬 DS DependentUtils 三态机（satisfied/pending/failed + timeout 分支）。
6. `parameterPassing`（v2.1 按 D3 修订，原「观察项」表述作废）：独立建模为运行时值透传（条件项 `parameter_passing` 缺省 `false`；依赖判定 satisfied 后 VarPool OUT 透传+同名值选择规则），与变量解析分开建模、分开验收，不以变量引用静默替代（详见 A2 §7.6；`DependentItem.java:L33-L38`、`DependentExecute.java:L392-L414`）。
7. **组间 relation 复刻（本线连带发现，超出监督线 #38 清单）**：DS `Dependence.relation` 为组间 relation，DS 原生支持组间 OR——我方 v1「多组之间固定 AND」是复刻令下的静默收窄偏离；A2 §7.8 修正为 `groups[]` 同级新增 `group_relation: AND|OR`（缺省 `AND` 向后兼容 v1 wire）。验收覆盖组间×组内四组合（AND/AND、AND/OR、OR/AND、OR/OR）。

### 3.2 SQL IDE → R5/A5 契约（A5 冻结前议程依据）

按 DBX 九能力对照 R5-A 17 方法覆盖度，A5 评审逐项裁定纳入/延后：异步执行模型（提交/轮询或事件流/取消/超时）、多语句批执行（continue_on_error/事务）、结果网格语义（key columns/preview/分页截断）、SQL 历史（保存/搜索/清理）、SQL 资产（文件式组织）、数据导出（结果集导出+表导出+取消）、跨 Schema 执行上下文（schema 注入策略按库类型分级）、对象树（库→schema→对象列表；列级及函数/存储过程等粒度随 DDL 精读补锚，见 §1 G2）、数据源能力分级（枚举抽象）。**G1 补登记**：原版 SQLIDE 融合对照亦为 A5 议程项（S1 融合规则：冲突歧义以 DBX 为准；原版 SQLIDE 界面操作层特色优势吸收项逐项登记）。

### 3.3 变量统筹（用户裁定落位）

- 变量体系和规范契约化治理：**所有文本输入位可引用命名空间变量**（`${scope.name}` + `$[时间表达式]`）；旧版已有该实现逻辑，本版拔高为全系统统一契约（R2 已冻结域）。
- SQL IDE 的变量工作分工：**后端=资源管理与变量引入**（执行前经共享变量解析服务消解引用、产出不可变解析快照，沿 R2 run-snapshot 语义）；**编辑器补全/校验交互=前端重构阶段**（后端冻结后单独立项）。
- 行动：A5 议程追加"执行 API 变量集成"（SQL 文本承载引用 + 服务端解析 + 快照回传）；`parameterPassing` 与变量引用的关系随该议程裁定。
