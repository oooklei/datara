## 1. 范围及权威规则

1. R5-A 只允许目标数据源的结构化元数据读取、只读对象定义读取、lint、只读 SQL 执行、结果读取、历史、SQL 脚本资产、查询结果导出，以及由 Datara 设计 §7.3/§13.6 与 DBX 表数据导出能力支持的只读表数据导出。表数据导出是显式的 A5 contract extension：仅按授权 ObjectRef 读取、使用只读游标和行/字节限额，不接受任意 SQL；不构成 R5-B 变更能力。目标数据源禁止 DDL/DML 写操作和无法确定只读性的操作；R5-B 独立承接对象定义修改、表结构保存、策略校验、影响预览、人工确认/发布/审计/回滚。只读定义读取属于标准 v4 R5-A；P1-7 把 getDefinition 列入 R5-B 是指 B 写入流程复用该读取能力，不将读取本身升格为写操作。
2. “只读”限定目标数据源。Datara 自身历史、脚本、审计、任务、结果快照和导出物料可写入平台存储，但必须执行项目授权、审计、并发控制、过期清理；平台写入绝不授权目标数据库写操作。
3. R5-A 可按 driver/object capability 返回只读对象定义文本（包括等价于 SHOW CREATE 的定义），不得执行或保存定义变更。FE `RoutineMeta.ddlPreview` 由共享 `getDefinition(ObjectRef)` 提供；候选响应携带 `sourceVersion/etag` 与 capability，R5-B 的 policy/impact/confirm 必须引用同一快照，版本不匹配返回 409。DBX 的 `ObjectSource.editable` 只代表 driver 声明，不授予 Datara 用户写权限；所有修改仍通过 R5-B 人工闸。A5 agenda §A5.7 的只读 source 与标准 v4 §R5-A 定义读取规则一致。
4. DBX 提供查询、对象树、结果网格、历史、资产、异步和导出的行为参考；不将其 Tauri、本地文件系统或 UI 行为直接等同 Datara 服务端的授权、持久化或驱动能力。能力只有经 Datara 目标驱动集成证据确认后才能标 supported。
5. 变量语义复用 R2。R2 Q11 已裁定：业务数据变量值依原值忠实呈现，唯一例外是 Datara 自身用户登录密码；不得按“敏感”标签或变量名擅自打码。平台连接凭据及 Datara 登录凭据不属于业务变量展示值，严禁写入 SQL 历史、普通日志、错误、事件或导出元数据。

## 2. 通用 HTTP、身份和能力合同

### 2.1 路由及 envelope

- SQL IDE 路由按项目隔离：`/api/v1/projects/{projectId}/sql-ide/...`。前端从当前项目上下文填入 projectId；后端必须从已认证 principal 校验其项目成员资格，再校验 datasource 属于该项目。body 中的 projectId 只是请求上下文，不能作为授权凭证。浏览器不得提交 DSN、数据库口令或 driver 私有连接串。
- JSON 响应沿用 `common/resp.py` 的 `{code,msg,data}`。成功 `code=0`；失败保留现有数值 code 兼容，同时在 `data.errorCode` 给稳定域错误枚举、`data.details` 给安全的结构化信息。HTTP 状态至少区分 400 参数/SQL 策略、401 未认证、403 对已可见资源的操作权限不足、404 不可见或不存在资源、409 幂等/版本冲突、410 已过期资源/cursor、422 不支持能力、429 有界并发/额度、502 驱动失败、504 超时；新增 `CAPABILITY_CONDITION_NOT_MET`、`CAPABILITY_UNSUPPORTED`、`CAPABILITY_UNKNOWN`、`OBJECT_AMBIGUOUS`、`RESULT_NOT_AVAILABLE`、`RESULT_EXPIRED`、`CURSOR_INVALID`、`EVENT_CURSOR_EXPIRED`、`IDEMPOTENCY_CONFLICT`、`SCRIPT_REVISION_CONFLICT` 稳定域错误。响应不得包含凭据或 driver 原始异常。
- 项目和用户以认证上下文为真源；task/history/script/result/export 的每次读取均重新验证资源归属。资源属于其他项目/用户或因隐藏策略不可见时统一返回 404，避免资源枚举；资源对当前项目可见但当前身份缺少特定操作权限时返回 403。datasource 与其资源遵循相同区分，不允许在同一可见性情形下随机选择 403/404。

### 2.2 标识、分页及能力

- `taskId` 使用不可枚举 URL-safe string；FE 已有 number 类型的 `historyId`、`script.id` 沿 wire 使用安全整数（不超过 JS `Number.MAX_SAFE_INTEGER`）；`datasourceId` 沿现有 FE 类型使用 number。若迁移为 string，必须由 FE service adapter 显式兼容，不得静默精度损失。
- 驱动/对象/操作 capability 统一为 `supported | conditional | unsupported | unknown`。元数据列表数据统一为 `{items, capability, constraints, page}`；`conditional` 必须带约束，满足约束返回数据并保留 conditional 状态，不满足则为 `CAPABILITY_CONDITION_NOT_MET`。supported/满足条件的 conditional 且无匹配/可见记录时返回 `items: []`；unsupported/unknown 不得返回成功空数组，分别使用稳定 `CAPABILITY_UNSUPPORTED` / `CAPABILITY_UNKNOWN`。权限失败、驱动错误和合法空结果相互区分。
- 元数据列表使用有界 keyset pagination，返回 `page: {nextCursor, hasMore}`；每个 cursor 与 project/datasource/database/schema/filter/sort 绑定，失效或跨范围复用返回 `CURSOR_INVALID`。默认 limit=100、最大 200；columns 默认 200、最大 500。任何全量列表需显式分页完结，不能因旧 FE 返回数组而静默截断。
- 完整对象引用 `ObjectRef={datasourceId,database,catalog?,schema?,kind,name,parent?}`；子对象响应回传完整路径。`listIndexes` 必须接收含 schema 的 table ObjectRef；`searchObjects` 返回 ObjectRef 而非仅 parent 字符串。显式限定名保持原义；未限定名按 driver profile 的 default schema 规则处理，不由全局 SQL 字符串重写猜测。
- driver/object/operation capability 与 API response 使用同一 `supported | conditional | unsupported | unknown` 枚举，conditional 约束及失败语义按本节首条执行。初始状态以真实运行时证据为准；现有静态 metadata PoC、UI datasource 标签和 Protocol 均不足以使任何 operation 晋级 supported。连接/权限/超时错误不得降级成 unsupported 或空列表。

## 3. 现有 R5-A 方法与明确扩展的服务合同

现有方法名继续由 FE service facade 暴露；wire request 可通过 adapter 扩展。所有方法均继承 §2 project/auth/envelope 约束。元数据列表方法 #1–7 均返回完整 `{items,capability,constraints,page}` envelope；`constraints` 在 capability=`conditional` 时必填，其他 capability 下可为空数组。下表为便于阅读省略重复列出的 envelope 字段，不构成省略字段。

## 4. 查询、变量、任务及 SSE 生命周期

1. 执行顺序冻结为：认证/项目授权 → datasource capability 与只读凭据校验 → R2 变量引用解析并形成执行 attempt snapshot → 变量解析后的完整语句切分 → 对最终 SQL 结构作 AST/driver 只读检查 → durable task/history/audit 原子创建 → 逐语句串行执行 → 持久化结果页/事件 → terminal event。任何一条语句写入或无法证明只读，整个 batch 在首条执行前拒绝。
2. 变量快照每项至少含 `snapshot_id/digest, attempt, expression, scope/namespace, name, resolved_value, value_type, source, resolved_at`，并由 execution/history/result/export 引用。业务变量的 `resolved_value` 严格遵从 R2 Q11 原值；R2 授权快照读取按其自身权限合同返回原值，不额外设置敏感变量打码分支。普通 SQL history/event/audit 存引用和必要摘要，不复制变量值；Datara 身份登录口令、数据源凭据和 bearer token 不得进入快照展示、日志、事件或导出。
3. 变量值不得以未经校验的文本拼接绕过只读门。R2 变量在其支持的 SQL 文本位置继续可引用；typed scalar 在 driver 支持时以 prepared bind 传值，identifier-context 变量由 R2 类型/driver profile 约束并安全引用。凡解析会改变 SQL 结构的上下文，必须在执行前对最终 SQL 完整解析和只读分类；R5-A 对不能安全分类的方言/上下文 fail-closed，但不得以此删减系统层 R2 命名空间或变量引用能力。
4. 仅 `mode=auto` 进入 R5-A。对一个 accepted task 先完整预检所有语句，再顺序执行；不承诺整批事务原子性，不承诺失败后自动继续。前序语句成功而后续失败时任务终态为 `partial_failure`，逐语句结果保留，不冒称回滚。执行使用真实只读数据库权限，AST/dialect policy 为第二道门。
5. 状态机：`accepted → queued → running`；queued/running 均可转 `cancel_requested`；终态为 `succeeded | failed | partial_failure | canceled | timed_out`。`cancel_requested` 竞态由 driver 确认结果裁定，可转任一适用终态，不得强行覆盖已完成成功的 task。终态不可逆，task 状态查询为权威状态，SSE 是持久事件的观察面。每个 accepted task 在接受时持久分配唯一 `historyId`；终态 `done` 必须携带该 ID；若任务/历史无法原子创建则请求不 accepted、不发 task 事件。没有结果集的 history 不可分页，返回 `RESULT_NOT_AVAILABLE`。
6. 取消是幂等请求，只有驱动确认语句终止、连接已 reset 或 discard 后才可记 `canceled`。取消/超时无法确认时连接隔离并销毁，任务不得伪报成功终止，稳定终态为 failed/timed_out 并带可恢复 code。
7. 单一 session/tab 内执行严格串行；session 身份由 FE 为每个 IDE tab 生成稳定随机 sessionId 并随 execute 请求提交，租约/最大并发/排队有界。不同 session 可并行但受 datasource/project quota 限制。连接归还前 reset schema/role/read-only/timeout 等状态；reset 失败则 discard。客户端断开不隐式取消 task。
8. SSE 使用 `executeSql` accepted 同源 HTTP 响应通过 `Set-Cookie` 按 task 隔离签发 HttpOnly event cookie；不把长期 bearer 放 URL、localStorage 或 sessionStorage。cookie 名由安全编码 taskId 派生，Path 精确匹配 `/api/v1/projects/{projectId}/sql-ide/executions/{taskId}/events`，设置 HttpOnly/Secure/SameSite=Strict 与 Max-Age。完整任务事件序列及 Last-Event-ID cursor 在运行期间保留，并自 task 终态起保留 7 日；事件资源 expiresAt=终态时间+7日。cookie 有效期覆盖 task 绝对 deadline（含排队时间）及终态后 7 日恢复窗；原生 EventSource 同源携带 cookie，FE adapter 使用 credentials，脚本不得读取 cookie 值。拒绝跨 task 重用。event sequence 先持久化后发布；重连仅重放已持久化序号，永不重放执行。result event 仅持久化不含数据的 result reference 元数据（historyId/stmtIndex/resultSetId/expiresAt），该事件元数据随事件序列保留 7 日；结果 snapshot 可读取 24 小时，过期后引用仍可重放但标记 `expired` 且不得 dereference 或重建结果行。cursor 在保留窗内失效或出现 gap 时发 `reset-required`；超过 7 日恢复窗返回 `EVENT_CURSOR_EXPIRED`，不伪造可恢复游标。客户端收到 `reset-required` 后通过 `GET /api/v1/projects/{projectId}/sql-ide/executions/{taskId}` 获取权威状态/最新 sequence，再按 historyId 调 `fetchResultPage`；状态/结果已过期时返回稳定错误，不执行 SQL。`done` 后 stream 可关闭。

9. 增加只读扩展方法 `getExecutionStatus(taskId)` → `GET /api/v1/projects/{projectId}/sql-ide/executions/{taskId}`，返回 `{taskId,historyId,status,stmtCount,elapsedMs,lastEventId,resultRefs,expiresAt}`，受相同 project/user ACL。该方法是现有 17 个 FE method 之外的恢复面，不改变其统计；由 FE adapter 在后续接线中新增，不能把恢复职责留给 UI 猜测。最小任务状态记录独立于可软删除的 history 内容保留至任务创建后 365 日；其中不得包含 SQL、变量解析值或结果行。删除 history 不取消正在运行的 task，也不删除最小状态记录；事件序列按 §4.8 保留，结果 snapshot 按 TTL 清除。事件日志/cursor 按 §4.8 独立保留 7 日。

## 5. 脚本、历史、结果和导出资源

- history 是执行证据；script 是用户可复用平台资产；二者不得合并生命周期。为可测试且可部署，v1.0 冻结以下最短保留期（部署可延长，不可缩短）：可见 history 内容自创建起 365 日或用户删除后软删除 tombstone 30 日（先到者决定内容清除）；最小 task status record 独立自创建起 365 日且不含 SQL/变量解析值/结果行；完整 task event sequence 与 Last-Event-ID cursor 在运行期间保留并自终态起保留 7 日；脚本活动版本保留至用户删除，软删除后可恢复 30 日，之后物理清除；result snapshot 自终态起 24 小时，SSE 中仅引用元数据随 event sequence 保留 7 日但快照过期后不可读取；成功导出物自完成起 1 小时，取消/失败的部分文件立即清理；审计记录 append-only 保留至少 365 日，不随 history/script/result/export 清理级联删除，期限后仅由受控 retention job 独立清理并产生清理摘要。所有可过期资源返回 expiresAt；过期访问返回稳定 404/410 域错误。
- history 是执行证据；script 是用户可复用平台资产；二者不得合并生命周期。历史删除软删除，不级联删除审计；结果快照依自身 TTL 过期。脚本项目共享、作者或项目管理员写入，revision CAS 防并发覆盖。
- SQL 原文与解析快照值分开存储；按现有授权历史 API 返回用户 SQL 内容，不对业务值做未经裁定的敏感值遮罩；凭据不得进入 SQL/历史/审计。安全日志只记录 actor/project/resource/action/time/outcome/requestId/errorCode，不记凭据、变量解析值、结果行或 driver 异常堆栈。
- 设计要求的结果及表数据导出不可静默删除，但现有 17 FE 方法无 export。查询结果导出独立使用 `POST /api/v1/projects/{projectId}/sql-ide/exports`（historyId,stmtIndex,format）→ exportId；表数据异步导出使用 `POST /api/v1/projects/{projectId}/sql-ide/table-exports`（datasourceId,ObjectRef,format,rowLimit）→ exportId；二者使用 `GET /api/v1/projects/{projectId}/sql-ide/exports/{exportId}` 查询、`GET /api/v1/projects/{projectId}/sql-ide/exports/{exportId}/download` 下载、`DELETE /api/v1/projects/{projectId}/sql-ide/exports/{exportId}` 取消/清理。结果导出只读取已持久化结果快照；表导出使用后端只读游标和行/字节上限，不接受任意 SQL，也不重复执行 IDE 查询。format 为 csv/json/xlsx；遵循项目权限、TTL、审计、取消和部分文件清理。FE service 后续显式新增 `exportResult/exportTable`，不得藏在 `fetchResultPage`。

## 6. 初始驱动矩阵与 GREEN 判据

- 契约对所有 driver 定义 capability vocabulary，但未完成目标环境实测的 operation 统一保持 `unknown`；MySQL/PostgreSQL metadata PoC 只能作为实现线索，不能从当前静态代码推断 production-supported。每一 driver profile 必须逐 operation/ObjectKind 提交真实授权/连接/跨 Schema/只读/结果/取消证据。
- A1-A7：A1 先红后绿并保留命令/原始输出；A2 由独立评审 PASS；A3 证据成对且可定位；A4 分离契约冻结、实现、GREEN、验收；A5 对 DBX 源码范围提供源码锚点+全覆盖声明；A6 契约变更升版本并双线会签；A7 不越 DDL 人工闸、不回传预览样本值、不泄漏 token/key。
- GREEN 还必须覆盖至少：真实项目/数据源授权拒绝、capability 与空结果区分、完整 ObjectRef/跨 Schema、R2 snapshot 与变量类型、真实只读账户+AST gate、多语句/partial failure、取消/超时连接回收、SSE 认证与游标恢复、固定结果快照分页、history/script revision/审计、查询结果和表数据导出 TTL/清理、显式生产 factory 装配。Protocol、mock、PoC、路由可达或协作者未附证据的 PASS 声明均不满足门禁。
