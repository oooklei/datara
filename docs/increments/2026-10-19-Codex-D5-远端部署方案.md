## 核定结论与范围

远端采用 bind-mount 源码部署：容器 `datara-rebuild-api` 将宿主 `/lei/datara/rebuild-source/rebuild` 挂载到容器 `/app/rebuild:ro`。监督线 S25 已核对该挂载与本地 `docker-compose.rebuild.yml` 一致；服务定义在根 compose:158。此部署不需要重建镜像，也不需要 Compose 服务操作。更新范围仅为本地 `datara-backend/rebuild/` 对应的远端 `/lei/datara/rebuild-source/rebuild/`，之后只重启 `datara-rebuild-api`。

旧预检记录 `docs/increments/evidence/2026-10-19-Codex-D5-preflight-blocked.txt` 曾显示 `/lei/datara` 不是 Git 工作树且根 Compose 无目标服务；该记录描述旧方案当时的阻塞。按监督线 S25 核定，新的版本证明采用同步前后 SHA-256 内容指纹清单，不再依赖远端 Git 元数据或 Compose 服务发现。

## 执行前审批与停止条件

- 本文先交监督线复评；远端任何连接和写操作均须用户明确批准本方案及执行窗口后才开始。监督线复评不等同用户执行批准。
- 执行时只接受干净且已提交的本地 HEAD。批准后记录实际 HEAD，并从该 HEAD 导出 `datara-backend/rebuild/`；不得使用工作区未提交内容。若目标目录缺失、容器/挂载与 S25 不符、本地目录包含无法映射到同步清单的特殊文件，或写权限/传输工具不满足预检，停止并报告，不猜测替代路径。
- 仅允许写入远端 `/lei/datara/rebuild-source/rebuild/` 及一个本次命名的备份归档；重启仅限 `datara-rebuild-api`。禁止镜像构建、Compose up、其他容器操作、数据库/配置/密钥/数据文件修改。
- 启动同步前必须完成回滚 tar 备份并核对归档可读；同步后必须在重启前完成远端清单与本地 HEAD 清单逐项 SHA-256 对照。任一项缺失或不一致，停止，不重启。

## 获批后的步骤

1. **只读预检与基线清单**：记录上海时间、本地 HEAD、`datara-backend/rebuild/` 的相对路径/SHA-256 清单；只读核对远端目标目录、容器存在且 healthy、容器挂载源/目标为 S25 所述路径。导出内容必须来自记录的本地 HEAD。预检结果与任一核定事实不符即停止。
2. **备份、同步与指纹核验**：将同步前远端 `/lei/datara/rebuild-source/rebuild/` 打包为带时间戳的 tar 备份，检查归档存在且可列目录；保留备份路径和 SHA-256。将本地 HEAD 中 `datara-backend/rebuild/` 内容同步至远端 `/lei/datara/rebuild-source/rebuild/`，不触及旁邻目录。生成同步后远端相对路径/SHA-256 清单，与步骤 1 的本地 HEAD 清单逐项对照；仅所有路径和摘要一致才继续。
3. **单容器重启与验收**：执行 `docker restart datara-rebuild-api`。记录 restart 返回值及容器状态；通过远端本机及获批入口只读请求 health 与 AI tools：health 必须 HTTP 200，`/api/v1/rebuild/ai/tools` 必须 HTTP 401。保存命令、时间、状态码、容器健康状态及日志错误标记定位。任一结果不符则进入下述回滚，不开展其他修复。

## 回滚

仅在本次用户批准的执行窗口内，使用同步前 tar 备份恢复 `/lei/datara/rebuild-source/rebuild/`，校验恢复后的 SHA-256 清单与同步前清单一致，再只执行 `docker restart datara-rebuild-api`；复验 health 200，并记录 AI tools 状态和最终容器健康状态。恢复或校验失败时停止并报告，不清理备份、不操作其他容器。备份路径、归档摘要及实际恢复结果须在执行证据中填写，不在方案阶段预填。

## 验收与交付证据

证据应记录：批准依据与执行窗口、本地 HEAD、同步前远端 tar 路径及 SHA-256、本地 HEAD 文件清单与同步后远端清单对照结果、实际同步命令和输出定位、`docker restart datara-rebuild-api` 输出、容器健康状态、health 200 与 AI tools 401 的请求/响应定位，以及是否回滚。不要记录密钥、环境变量值或业务数据。验收不通过或回滚时如实标记 FAIL/BLOCKED，不宣告部署成功。
