# 旧前端深度对标审计（二）：任务中心（DAG 工作流编排）+ 同步 + 流

- 审计日期：2026-10-28
- 审计对象：`datara-web/src/views/`（TaskCenterView、dag/、sync/、stream/、etl/、variables/）、`datara-web/src/graph/`（workbench、profiles、model）、`datara-web/src/stores/`、`datara-web/src/services/`
- 性质：只读研究，未修改任何源代码
- 用途：作为 1.9 部署新前端（datara-newweb）任务中心对标真源
- 约定：所有 API 路径基于 `services/http.ts`，`BASE='/api/v1'`；token 取 `localStorage['datara_token']`；`isMock` 双态指 seed 数据（mock）与真后端（real）

## 0. 全局架构总览

### 0.1 两层结构

| 层 | 文件 | 职责 |
|---|---|---|
| 宿主页 | `views/TaskCenterView.vue`（约 410 行） | 视角页签容器 + 画布多 Tab 管理 + 顶栏全局动作 |
| 图工作台 | `graph/workbench/GraphWorkbench.vue`（2255 行） | 统一设计器内核（工具栏/Palette/画布/Inspector/底部面板/全部弹窗） |

- 视角内核唯一：`views/taskCenterPolicy.ts` 的 `workflowEditorProfile(_type)` **恒返回 dagProfile**——任务编排/同步/ETL/流四类任务共用同一编排内核，差异仅为分类标签（profile 名徽标展示）。
- 旧协议与 rebuild 契约并存：旧协议（`/workflow-definitions` 等）为编辑主链路；rebuild 契约（`/api/v1/rebuild/variables`、`/rebuild/dependency`、`rebuild/streamApi`）承载变量/依赖页签与流列表只读查询。
- 双态（isMock）：mock 走 `dataStore` seed 数据；real 走 http。同步/流/ETL 列表页在 real 下部分动作禁用并给出提示文案。

## 5. 保存链路（W1 闸门）与 stores

### 5.1 stores/graph.ts save()

```ts
async save(remark?) {
  saving = true
  const { version } = await graphService.save(doc, remark)  // PUT /workflow-definitions/{id}
  doc = { ...doc, version }; dirty = false
  // 保存点刷新基线（不清历史：保存后仍可撤销到保存前）；lastSnap 与 lastDoc 恒同步
}
```

### 5.2 W1 保存闸门（GraphWorkbench 层）

| 步骤 | 内容 |
|---|---|
| 1 | 全量 validators（11 个，见 §3.8）逐项执行 |
| 2 | 边类型复检（branch 类边的端口/方向合规） |
| 3 | 任一 error 级错误 → 阻止保存，Badge 计数+ErrorPanel 打开 |
| 4 | 通过 → `PUT /workflow-definitions/{id}`；服务端返回版本号 |
| 5 | 并发冲突（HTTP code **2005**：他人已保存更新版本）→ 提示刷新/合并，本地不覆盖远端 |

### 5.3 11 个 validators（dagProfile.validators）

成环检测 / 断链（不可达 end）/ start 节点唯一 / 孤立节点 / 重复边 / 流子图完整性（stream_input→fuse→output）/ 必填缺失 / end 禁止出边 / 组件级校验（spec/params 域）/ 分支完整性（conditions/switch 的 true/false 支路）/ 依赖节点合法性。

### 5.4 自动打标（分类标签）

画布保存时按 meta 自动 `PUT /workflow-definitions/{wfId}/tags`：同步任务打「同步」标签（C23）、ETL 打「ETL」、流打 STREAM_TAG——sync/stream/etl 列表页即按标签过滤聚合。

## 16. 与新前端差异最大的要点（对标结论，供主 Agent 摘要）

1. **两层架构**：任务中心=TaskCenterView 宿主（4 视角页签+画布多 Tab≤5+KeepAlive+草稿快照）+GraphWorkbench 统一内核；四类任务共用 dagProfile，仅分类标签不同。
2. **F1 configure-first**：Palette 拖入必弹 DropConfigDialog（闸门=必填∧值域∧悬空引用），取消不落画布；模板链 staged 逐节点配置→原子提交。
3. **拖边即引用**：连线自动写 `inputs:nodeId:port` 具名引用（非顺序索引）；endpoint_select 双输出端口 sourceRef/targetRef。
4. **六区块+四道闸+W1 保存闸门**：Inspector 属性面板以①输入~⑥排除为框架层，业务表单叠加；11 validators 成环/断链/流子图/分支完整性等；保存前置全量校验+边类型复检+并发冲突 2005。
5. **运行监控三通道**：实例列表（10 列+5 行操作+批量删日志）、详情抽屉（只读 DAG 染色+任务表+变量快照全明文+节点日志 2s 轮询）、SSE 实例流 onerror 降级 3s 轮询。
6. **变量七级优先级链**：run>task>workflow>project>global>env>builtin；管理面仅 global/project，画布面板管 tmp/workflow/task；upsert 无删除。
7. **依赖配置面**：rebuild dependency 契约，九类源（现通 workflow/task），条件组 AND/OR+组间关系+失败策略+表达式预览/预演。
8. **同步/流页面为只读监控**：编辑一律落画布（自动打「同步/ETL/流」标签）；流列表查询已换绑 rebuild 只读契约，写操作仍旧 streamApi（start 用 docId、stop 用 job id）；流详情含 SQL/拓扑指标/Checkpoint/实时预览四页签+日志尾抽屉。
