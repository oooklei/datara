# I9 前置方案 · 信息架构简洁化与任务中心重构（对照 DolphinScheduler）

> 状态：**已裁定（09-19）——裁定结果 1A 2A 3B 4A**，见 §五裁定列；已并入 I9 设计文档 v3。
> 触发：用户 09-19 指令——「分析 DS 前端布局与菜单为何简洁、我们为何混杂；DAG（任务中心）可承载更多功能与交互，给出方案再定下一步」。
> 参照：DolphinScheduler 3.x（海豚机制参照既定原则）；本项目 routes.ts（45 条路由）、i9_baseline_workbench.png（critic 基线 4/10）。

## 一、DolphinScheduler 为什么简洁（六条归因）

| # | 归因 | DS 的做法 |
|---|---|---|
| 1 | **导航少而深** | 一级导航仅 6~7 个单一职责域（首页/项目管理/资源中心/数据中心/监控中心/安全中心），二级才见具体功能；到任何功能 ≤2 次点击 |
| 2 | **页面单职责** | 列表页只管列表（表格+筛选+行内操作）；画布页只管画布（全屏独立页+顶部窄工具条）；绝不在一页混多个视角 |
| 3 | **菜单=名词实体** | 菜单项是实体（工作流定义/工作流实例/任务实例/定时管理），不是「功能合集壳」；一个菜单对应一种数据对象 |
| 4 | **操作分层后置** | 行内只留高频操作（编辑/运行），低频收进下拉「更多」；画布工具栏主按钮唯一（保存），其余分组或收纳 |
| 5 | **视觉令牌统一** | 单色线性图标、一种主色、状态色仅 3~4 个语义色；组件栏可搜索、分类折叠 |
| 6 | **零内部话术泄漏** | UI 上无版本徽章、无里程碑话术、无内部编号直出 |

## 二、我们的系统为什么感觉混杂（七条根因，逐一对照）

| # | 根因 | 实况 | 对应 DS 差距 |
|---|---|---|---|
| 1 | 45 条路由压在 7 个一级菜单下 | 数据治理下 4 组 16 条平铺 | DS 一级域内先分「子域」再列实体（归因1） |
| 2 | 同壳页签路由双轨 | 脚本三合一、参数四合一、质量报告三合一（/script/env 与 /script/list 同壳）——菜单出现 3 个入口、页面又是页签 | DS 无此模式：一实体一菜单（归因3） |
| 3 | **任务中心单页过载** | 一页 6 页签（工作流/同步/ETL/流/运行监控/告警）× 4 种画布壳 + 列表弹窗 + 内嵌画布——四类实体视角混一页 | DS 拆为 4 个独立页面（归因2） |
| 4 | 真实功能与演示态模块并列同权、无标识 | 方案外 12 组视图与本期功能同菜单混排 | —（DS 无此问题，我们 I9 新增演示标识即可） |
| 5 | badge/话术泄漏 | Beta 徽章、Phase 1 话术、「对标 DolphinScheduler」备注、内部 ID 直出 | 归因6 |
| 6 | 色彩无语义 | 组件库彩虹图标 10 色 0 语义、多彩胶囊 | 归因5 |
| 7 | 画布核心面可供性弱 | 首屏构图失衡（节点挤一条线、70% 空白）、MiniMap 残缺、连线无提示、右面板 emoji 空态 | 归因4+5 |

**一句话诊断**：DS 的简洁=「层级少、页面单职责、实体化菜单」三条骨架纪律；我们的混杂=同一页装多个视角（根因3 最重）+ 菜单双轨（根因2）+ 视觉纪律松散（根因5/6/7）。

## 三、方案：三层重构（A 信息架构 / B 任务中心重组 / C 画布承载）

### 方案A 信息架构收敛（菜单层，改动小、收益大）

1. **任务中心提为一级菜单**（/dag 直接挂一级，对齐 DS 把工作流放显要位置）；数据开发保留（数仓建模/IDE/脚本/参数）
2. **同壳页签改单入口**：脚本库、参数配置、质量报告各只保留一个菜单项，页签在页内切换（/script/env 等路径保留重定向，书签不失效）
3. **二级条目瘦身**：45 条 → 一级可见二级约 25 条内；数据治理 4 组 16 条按组折叠默认收起
4. **演示态模块处置**（衔接裁定项1）：保留原菜单位 + 「演示数据」标识（低饱和 tag），不做折叠分组（避免用户找不到）
5. 菜单文案纪律：去重复项（质量报告 ×2）、去内部话术

### 方案B 任务中心重组：列表/画布分离（对齐 DS，**需裁定**）

- **现状模式（I1 既定）**：「画布直达 + 看列表弹窗」——打开即进上次编辑画布，列表收在弹窗里
- **建议改为 DS 模式**：
  - 任务中心页 = **纯列表**：四类型页签保留，每页签为列表表体（工作流定义列表：名称/类型/状态/调度/最近实例/修改时间），行内操作：**编辑（跳全屏画布）/运行/调度/版本/删除/详情**
  - 画布 = **全屏独立页**（/dag/design/:id 已有路由，无需新增）：顶部窄条=返回+文档名+校验状态+保存（主按钮）+溢出组（校验/自动布局/试运行/日志/AI/版本）；画布占满余下空间
  - 运行监控 → 独立（/dag/instances 已有）；告警与SLA → 保留为任务中心第 5 页签（纯列表）或独立菜单（见裁定项4）
- **收益**：画布获得最大空间（承接 N1~N17 交互增强）、列表获得完整表格能力（筛选/排序/批量）、每页单职责
- **代价**：推翻 I1「画布直达」既定模式，I1 门「画布直达」口径需改为「列表直达」，回归矩阵相应调整

### 方案C 画布交互承载（继承 v2 §3.1 N1~N17 清单，全屏后全部落位）

- 全屏画布使两侧面板收放（N12）、MiniMap/Controls（N10/N11）、大纲（N9）、搜索（N8）、过滤（N7）、成组（N6）有足够空间与必要性
- 视觉提纯项（v2 §3.2 基线差距 8 条）不变：右面板统计空态、工具栏层级、色彩语义、组件库降噪、文案清理
- critic 迭代机制不变：截图 → 全新上下文 critic（固定 prompt）→ 实现 → 复评，退出准则 critic 独立评分 ≥9/10
