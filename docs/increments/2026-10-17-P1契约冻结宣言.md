## 2. 议程一：R8-A 八工具契约 — 裁定：**冻结 v1**

核验与裁定依据（逐项对照设计正本）：

1. **五要素×8 全覆盖**（§13.9）：每工具含参数模型/返回结构/错误差异/权限/审计要点，另有跨工具统一信封、权限结构、审计字段——契约正文 §2-§7 完整，无空格。
2. **§13.14 冻结物清单逐项对应**：工具名和版本（`tool_version: 1`）✓、输入输出 Schema（§2.2/§2.3/§7）✓、权限上下文（§3）✓、审计字段（§4）✓、错误码（§5 十二码统一空间）✓、超时/重试/预算策略（§6 八行表）✓；假 Agent 测试与悬浮助手验证页为 GREEN 前证据（契约正文 §9，以冻结契约为输入）✓。
3. **红线贯穿**（§11）：单一调用端点 `/api/v1/rebuild/ai/tool-calls`（v2 词形勘误 2026-10-17 心跳 #151：统一前缀 `/api/v1/rebuild/ai`，监督裁定 #147 一）+ 注册表路由 =「统一执行/校验链路」传输面落点；八工具逐一标注复用锚（R5-A lint/execute 链路、统一 validate_graph、统计四表、既有血缘域），**不另建执行引擎**。
4. **既有裁定一致性**：Q9（`inspect_workflow_run` 六态枚举+`cancel_requested` 独立字段）✓；Q11（审计 request_payload 原值快照，不脱敏）✓。
5. **边界诚实**：双域证据索引证实八工具现无实现、无 Registry、FE 零直调——冻结在先恰是 §13.9 明文防「Backend 冻结后重新解冻接口」。

## 3. 议程二：N-A..N-E 逐项裁定

### 3.1 N-A（P1）工作流发布流 — 裁定：纳入 R4 冻结面，词形冻结

- **状态词形**：`publish_status: 'DRAFT' | 'PUBLISHED'`（与 R8-A 契约 `get_workflow.publish_status` 一致，联动闭合）。
- **发布语义**：发布动作将 workflow version 锁定为不可变（immutable）；正式运行必须绑定并验证 `PUBLISHED` 状态的不可变 `workflow_version_id`；草稿试运行使用独立 draft snapshot（§1.1-2；心跳 #22 R4 硬门禁表述吸收）。
- **权限点**：`workflow:publish`（§13.4 workflow 族动词）。
- **门禁效力**：N-A 为 R4 GREEN 前置（维持既有裁定不变）；R4 契约冻结面必须含 publish 端点契约与版本锁定语义。

### 3.2 N-B（P1）流状态机 — 裁定：采纳设计正本 §13.7 八态，词形冻结

- **冻结八态**（§13.7 原文词形，大写枚举）：`CREATED / STARTING / RUNNING / PAUSED / STOPPING / STOPPED / FAILED / RECOVERING`。
- **WIP 差异精确化**（登记源不改写，沿计数更正惯例）：WIP 现行 5 态 `STARTING/RUNNING/RECONNECTING/STOPPED/FAILED` 对设计八态为**缺 CREATED/PAUSED/STOPPING/RECOVERING 四态、多 RECONNECTING 一态**（监督登记「缺 CREATED/PAUSED/STOPPING、多 RECONNECTING」漏列 RECOVERING，此处补正）。
- **词形处置**：`RECONNECTING` 废弃，语义并入 `RECOVERING`（checkpoint 恢复/重连均属恢复语义域）；R8 实现期按八态重构 `StreamJobStatus`，契约测试以八态为准。

### 3.3 N-D（P1）流类七组件 allowlist — 裁定：采纳设计正本 §3 首期清单

- **冻结 allowlist**（§3 原文词形）：`START / END / CONDITION / FORK / JOIN / WAIT / SUB_WORKFLOW`。
- 后续任务类型插件化扩展不在首期（§3 明文「不加入大量 Spark/Flink/HTTP/Kafka 专用节点」）；R8/Palette 组件 allowlist 按七组件冻结，扩展须再冻结。

### 3.4 N-C（P2）角色与权限点 — 裁定：词形预登记（R1 identity 冻结面执行）

- **四角色词形**（§13.4）：`ADMIN / DEVELOPER / OPERATOR / VIEWER`——WIP 现行 `DEV/ANALYST` 废弃（监督复核证实实际角色名与设计连名称都不同）。
- **11 族权限点词形**（§13.4）：`project / workflow / task / datasource / sql / schedule / lineage / quality / standard / security / audit`（各族动词按 §13.4 原文：如 `workflow:read/write/publish/run/delete`）。
- P2 优先级不变：R1 identity 冻结面裁定具体映射；本宣言仅冻结词形基准，供 R8-A 契约 `roles`/`required_permissions` 引用（联动闭合）。

### 3.5 N-E（P1）治理域 — 裁定：R6/治理冻结面边界冻结

- **治理域七项清单**（§13.1 原文）：`data_asset`（主索引）/ `metadata`（目录）/ `lineage / quality / standard / security / semantic`（**五细分域**——登记源「五细分域」口径与 §13.1 清单对齐：主索引与目录外的五个细分能力域）。
- **边界**（§13.2）：新 Backend 为治理状态真源；OpenMetadata/DataHub 仅可选外部目录与 AI 上下文投影，不作执行真源；legacy_i19-i23 迁移件（现 governance/ 31 文件）不构成五细分域实现。
- **门禁效力**：R6/治理冻结面必须含五细分域契约；R6 GREEN 前置不变。
