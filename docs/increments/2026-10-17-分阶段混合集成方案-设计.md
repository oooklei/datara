## §2 配置架构

- **docker-compose profiles**：`core`（datara-backend + datara-web + 数据库）；`+ai`（**无新增容器**——Vanna 为库嵌入 backend 进程，chromadb 数据目录持久化于 Datara 数据区）。不再设 metadata profile。
- **版本锁定策略（D7）**：vanna 以精确版本入 `pyproject.toml` + vendor wheel 缓存 + 锁文件提交；部署/CI 脚本禁止依赖自动升级；升级须显式走增量+评审。
- **安全边界**：外部依赖零直连暴露，一律经 Datara 网关/适配层。

## §3 R8-V Vanna PoC 设计（Phase 1）

- **形态**：pip 固定版本嵌入 datara-backend 新增 `ai_copilot` 模块（设计 §2 既有域名），不独立进程/容器。
- **主权四条（验收即断言）**：
  1. LLM 密钥经 Datara 配置注入，Vanna 不持有；
  2. 数据查询只走 R8-A 已授权只读工具与连接权限，Vanna 不持任意 DB 凭证（`generate_sql`≠`run_sql`——SQL 执行一律经 Datara 通道）；
  3. 用户/项目隔离经 Datara 上下文注入，PoC 须演示跨项目隔离；
  4. 记忆存储（DDL/文档/SQL 样本）= chromadb 于 Datara 数据目录内，全部访问落 Datara 审计。
- **隔离边界**：`vanna_adapter` 单文件适配层，R8-A 契约面不暴露 vanna 类型；极端弃用时仅替换适配层，契约面不受影响。
- **LLM**：OpenAI 兼容端点（D5），PoC 开工时用户注入 key。
- **门禁**：R8-B 悬浮助手测试页 + 假 Agent 测试扩展为 PoC 验收，A1-A7 全适用；**成功判据 = 自然语言→SQL→经授权执行→结果解释全链路 + 隔离/审计证明**（不把「跑起来」当「集成完成」）。
