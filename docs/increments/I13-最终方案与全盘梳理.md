## 3. 最终落地方案

### 3.1 组件目录与基线化工作台

最终口径是“一套目录源、两条治理链”：

- 单一目录源：后端 `components/catalog.py` 定义执行语义集合，`common/dag_catalog.json` 是前后端消费快照。
- 系统内置组件：走 `/components/baseline/*` 基线工作台，按 35 个 DAG type 逐组件设计、体检、实测、认可发版。
- 用户自建组件：走 `/components` 草稿、冻结、发布、下线、回滚、影响面治理链。
- 工作流引用：已基线/已发布组件通过 `componentRef` 固定版本；保存宽松兼容存量，发布严格校验。
- 服务端守门：`api/graph_rules.py` R0-R6 是 DAG 保存/发布的统一校验层，不允许前端独自决定有效性。

本轮查缺补齐：

- 恢复本地缺失的 `datara-backend/api/graph_rules.py`、`datara-backend/components/`、`common/vars_render.py`。
- 补齐 `api/component.py`、`api/component_design.py`、`componentApi.ts`、`componentSpec.ts`、`baselineSpec.ts`、`FieldRenderer.vue`、`fieldCtx.ts` 等缺失契约。
- 修复前端 profile/type 契约，使现有 `rows/resource/mapEditor/runtimeOnly/maxOut/validators` 等声明能被构建系统识别。
- 修复 mock 模式独立读函数穿透真实后端；恢复 DAG/组件目录专用控件类型与联动（var-table、deps-list、exec-node-tag、runtime-node、args-table、datasource、field-select、upstream-ref）；同步编排测试基线更新为 C29~C31 编排 + C37/C34/C36/C35 细项组件，C17/C24 锁定为 runtimeOnly。
- 恢复 DataNode `componentRef.version` 版本角标；基线工作台 EightSectionEditor 恢复八段 DSL 导航入口；组件设计器恢复禁代码片段前端红线。

### 3.2 血缘分析新增量

最终口径是“设计态 + 运行态双源，表级 + 字段级 + 图聚合三层”：

- 运行态：worker 实际成功执行后的 SQL/同步/流相关血缘，保留实例追溯。
- 设计态：工作流保存/发布/回滚后从 GraphDocument 重算，用 `src_type=design` 区分。
- 聚合图：`/lineage/graph` 按 table/field 级别聚合，支持 source、wfCode、中心表、direction、depth、limit，并显式返回 `truncated`。
- 字段挂靠：同表对多语句/多节点场景按 `(node_id, stmt_no, from, to)` 精确挂靠，存量 design 行通过 redesign 自然收敛。
- 前端：LineageView 消费真实 graph/stats/fields/trace，不额外制造声明级 stub。

本轮查缺补齐：

- 将包含 `lineage_graph` 的 `api/lineage.py` 与 `common/lineage_extract.py` 同步进 `/lei/datara-i13-work` 验证目录。
- 扩展无 pytest 探针，验证 `/lineage/stats` 与 `/lineage/graph` 空态契约。

### 3.3 运行时节点与集群监控

最终口径是“在线性与指标分离，能证明才展示”：

- master/worker 在线性：ZooKeeper live registry 是在线/离线真源。
- 指标：Redis `monitor:{module}:{node}` 是短期 CPU/内存/磁盘指标源；`monitor:known:{module}` 保存近期已知节点，指标过期后仍可展示离线节点。
- SSH 节点：以 `t_ssh_node` 注册表和探活状态为真源，不虚构主机资源指标。
- 前端页面：只展示后端返回的真实节点、指标状态、生成时间；失败保留错误提示，不生成随机趋势。
- Kafka：作为默认 Compose 依赖，worker 等待 Kafka health，避免流任务隐式依赖。

本轮查缺补齐：

- `common/monitor.py` 增 `reportedAt` 与 known node 索引。
- `/monitor/nodes` 返回 `generatedAt`、`metricState`、live+known union。
- `DeployMonitorView.vue`、`DeployRuntimeView.vue` 接真实数据并消除随机/重复定时器。

### 3.4 告警闭环

最终口径是“站内消息持久化成功，外部通道必须真实投递成功”：

- `system` 通道代表数据库持久化站内消息。
- webhook/email 未配置、失败或不支持必须进入失败状态，禁止误标 sent。
- App 顶部消息中心 real 模式读取 `/alerts`。
