## S3 改动影响

S3 新增 `rebuild/governance/migrations.py`、`rebuild/governance/revisions/v0001_governance_catalog.py`、治理 migration tracking model、以及失败/续跑/校验和测试。迁移 runner 没有接入 `rebuild.api.app` 启动流程，因此 R1 远端服务和其数据库没有运行 R3 DDL。已通过本地 SQLite 的 rebuild 30 tests、Ruff、compileall，证据为 `evidence/R3/s3-migration-tests.txt`。

## S4 目标与影响面

- 仅在 `rebuild/` 内新增治理 API 契约和路由，不修改旧 `datara-backend/api/*`、旧 qc_engine/Qc ORM、正式业务前端或旧表。
- 所有治理查询/写操作必须要求 Bearer token，并先核验 project owner/member 与请求的 Permission；已登录但不属于 project 返回 403，缺失/失效 token 返回 401。全局 admin 可按既有 RBAC 策略跨项目访问。
- 只支持资产目录/筛选与详情、字段/标签、表/字段 lineage、质量规则/运行摘要、标准、语义指标、操作审计的最小真实 API。列表分页与可过滤结果由后端查询产生；不得在 API 返回中拼接静态成功数据。
- 写入路由同事务新增 audit event；审计字段不保存 token/validation key。不得实现敏感内容扫描、脱敏、加密或内容隐藏。
- S4 单元/集成测试用内存 SQLite，并显式开启外键；运行数据 `generated_at` 从 DB 默认产生。未在这步接入 MySQL 数据源执行器/质量 SQL；这些连接与运行行为必须在后续闭环前单独立项。

## 步骤

1. 测试先行：401、跨项目 403、分页/filter、标签关联、字段 lineage、质量运行结果排序、标准/指标唯一键、审计记录与事务回滚。
2. 新建独立 governance router/service/repository 与 Pydantic 请求/响应契约，路由共享 R1 TokenService 和 project-scoped authorization。
3. 测试 API 同事务审计；验证拒绝操作不产生业务写入/审计成功事件。
4. 跑全部 rebuild tests、Ruff、compileall；API 尚不并入 remote runtime，直到 R3-S7 的 migration dry-run 门禁。
