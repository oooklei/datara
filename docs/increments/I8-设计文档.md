## 3. 实现要点

### 3.1 流任务运行态模型（F40，独立于批实例）

- **DDL**（models.py 新增，init_db 兜底建表）：
  - `t_stream_job(id, doc_id, wf_name, name, spec_json, status, last_error, started_at, updated_at)`——spec_json=流子图规格（源/算子/汇参数+拓扑）；status ∈ starting/running/reconnecting/stopped/failed。
  - `t_stream_offset(job_id, source_key, offset_json, updated_at)`——位点持久化（主键 job_id+source_key）：Kafka partition offset / binlog file:pos / HTTP cursor / 文件 offset。
- **生命周期**：画布试运行流子图 → master 解析生成 spec → upsert t_stream_job → 投递 Redis 控制消息 `datara:flink:ctl` → worker StreamEngine 起线程；停止=控制消息 stop；**worker 启动恢复**：扫 status ∈ starting/running/reconnecting 的 job 重新拉起（位点续跑）。
- **状态机**：starting→running↔reconnecting（自动重连，指数退避 1s×2ⁿ 上限 30s，连续 N=10 次失败→failed）；stopped（人工）/failed（告警）为终态；状态变更写 t_stream_job + Redis 镜像（前端 5s 轮询）。
- **日志与指标**：流线程写 Redis List `datara:flink:logs:{job}`（Last-500，含重连/位点提交/错误留痕）；指标 Hash `datara:flink:metrics:{job}`（速率/累计条数/位点/滞后/错误计数/最后心跳，2s 周期，TTL 90s）——复用 I7 psutil 上报同款模式。

### 3.2 四源接入（F36~F38，C18 分型）

统一 Source 接口：`open(offset) → poll(batch) → commit(offset)`，异常抛出由引擎统一重连：

| 分型 | 实现 | 位点 |
|---|---|---|
| Kafka | kafka-python KafkaConsumer，指定分区分配，JSON/CSV 反序列化 | 每 partition offset 周期提交 t_stream_offset（批次处理成功后） |
| CDC(MySQL/GreatDB) | mysql-replication BinlogStreamReader（only_schemas/only_tables 白名单），写事件→{op,row,before/after} JSON | file:pos 持久化（at-least-once） |
| HTTP 拉取 | requests 轮询，鉴权 header/参数模板；响应按 JSON 数组/分页字段提取 | cursor（响应序号/时间戳/分页 token，表单声明提取路径） |
| 文件尾随 | 逐行读取+偏移跟踪+文件滚动跟随（inode 变化重开） | 字节偏移 + 文件名 |

数据行统一内部格式：`{source, ts, data}`（ts=事件时间，供窗口与水位线）。

### 3.3 融合算子与输出（F39/F41，C19/C20）

- **C19 算子**（统一 Op 接口：`push(row, emit)`）：union（字段对齐映射表）/ filter（条件表达式，沙箱求值沿用变量求值器安全子集）/ map（字段转换表达式表——表达式进入流转换细节，与 C11 血缘转换细节同构落库 lineage_detail）/ join（两路流，关联键+窗口内缓存匹配）/ 窗口聚合（分组键+聚合函数表 sum/count/avg/min/max+滚动/滑动窗口+水位线延迟，定时触发 emit）。
- **C20 Sink**：API 通道=写 Redis List `datara:flink:buf:{job}`（Last-N 保留窗口，N 由表单）+ schema 声明校验；库表通道=按数据源批量 upsert（1s 或 500 条触发）；Kafka topic=生产者；文件滚动=按大小/时间切分。
- **api/streamdata.py**：`GET /api/v1/stream-jobs/{id}/data?mode=poll|sse|ws`——poll 返回最后 N 条+指标；SSE=StreamingResponse 增量推送；WS=fastapi 原生 websocket；鉴权沿用平台 token（header/查询参数），schema 由 t_stream_job spec 声明。

### 3.4 流任务入 DAG（F40 编排侧）

- **前端**：dag.ts 三组件解禁+分型表单（C18 四分型/C19 五分型/C20 四通道，按 02 表单定义）；ports：C18 出 1、C19 进 ≥1 出 1、C20 进 1；保存校验流子图连通（源→算子→汇）。page 浮窗：C18 消费速率/位点/滞后、C19 吞吐/窗口触发、**C20 展开实时数据展示页**（表格+指标卡，SSE 刷新，供大屏联调，意见⑩示例场景）。
- **master**：保存/试运行时解析流子图生成 spec（校验必填与连通）；流任务状态查询代理 worker 指标；failed 状态走既有告警通道。
- **运行监控**：任务中心「运行监控」视角与流任务列表展示常驻任务（状态/速率/最后心跳/生命周期按钮 start/stop）；DAG 画布节点按流任务状态染色（对齐批实例染色语义）。

## 11. 1.9 实测门（七项）

1. **Kafka 订单流接入**：模拟生产者脚本持续投递订单 JSON → C18 消费（消费组/起始位点 earliest）→ 浮窗速率/位点/滞后实时可见。
2. **src binlog CDC 接入**：datara-mysql-src 建表并 INSERT/UPDATE → C18 CDC 分型捕获行变更 → 位点 file:pos 落 t_stream_offset。
3. **C19 融合**：订单流窗口聚合（按品类 sum 金额，滚动窗口）+ CDC 变更流 union → 输出融合流；映射表达式生效。
4. **C20 API 输出**：curl 轮询端点取实时数据 → SSE 增量推送验证 → 前端 C20 实时数据展示页刷新（大屏联调形态）。
5. **断流恢复**：docker stop kafka → 任务转 reconnecting（日志留痕）→ 重启后自动重连，**位点续跑不丢**（停投期间积压消息恢复后补齐）。
6. **容错**：kill datara-worker（流任务宿主）→ 其余 worker 或重启后自动拉起 → 位点续跑不重复推送（at-least-once 抽验）。
7. **全链路（计划原文门）**：模拟订单流 + src binlog CDC → 融合 → 大屏通过 API 消费实时数据，端到端时延秒级可见。
