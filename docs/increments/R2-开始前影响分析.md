## 2. R2 实施范围

1. 复核并冻结 `tables.yaml`、`dirty_rules.yaml`、seed 和分区窗口契约。
2. 实现 src/dw 初始化 SQL、配置驱动生成器、脏数据注入、锚定样本和独立 verify。
3. 实现 reconcile 报告、确定性指纹、reset/import/uninstall/install 四脚本，并保证源库清空联动目标库。
4. 准备 CSV/TXT/XLSX 样例文件及后续 R4 可消费的稳定路径。
5. 在 192.168.1.9 增加/重建 src、dw 运行资源；不得占用 3308，使用 3310/3309。
6. 增加独立 R2 验证页，展示容器状态、表/行数、对账、样例文件和最后生成时间。

## 4. 关键约束

- R2 不实现数据质量规则引擎或安全权限能力，只提供后续 R4/R6/R9 的实证数据位。
- 运行表和报告必须有 `created_at`、`updated_at`、`generated_at` 或等价明确生成时间；报告文件也必须记录生成时间与 seed。
- 生成器必须可复现：同一 seed、同一配置、同一窗口的核心表指纹一致。
- 任何与总体设计冲突的端口、表模型、脚本语义或门禁规则，先暂停并按第 1 条法条更新设计/计划/台账。
- R2 运行时不允许回退使用 8090，也不把 API/curl 结果替代 browser-use 控件级证据。
