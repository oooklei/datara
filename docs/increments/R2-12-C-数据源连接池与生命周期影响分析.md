## 范围与非目标

目标：

1. 建立按 project/datasource profile 身份隔离的服务端 connector registry；同一 profile 的并发 metadata 请求复用连接池，不同项目/数据源绝不复用连接。
2. 配置明确的 pool size、max overflow、pool timeout、recycle、pre-ping 与 DB connect/read/write timeout 上限；默认采用保守值，拒绝无限连接/等待。
3. profile 更新、密码轮换、删除后旧 engine 必须失效并 dispose；进程 shutdown 时 dispose 所有 engine。连接错误后不得记录 DSN、密码或连接 URL。
4. 将 MySQL probe 与 metadata browse 移至共用 connector 生命周期；每个业务操作仍使用只读事务并保证 rollback/连接归还；连接池复用不改变接口权限、schema-qualified identity、分页或响应语义。
5. 通过本地契约/集成测试与 1.9 控件验证，覆盖并发调用、跨 project 隔离、连接池上限、失效/重建、错误回收和关闭清理。

不包含：PostgreSQL 驱动/运行时、SQL 执行与 DDL、SYNC 执行器、跨 worker 分布式池、凭据静态加密改造、旧前端融合和治理迁移。多 API 进程各自持有本地有界池；不得宣称跨进程全局限额。

## 关键设计约束

- cache key 使用不可逆 profile fingerprint（包含 project_id/datasource_id 与连接字段版本摘要）；日志、异常、指标均不得暴露 credential-bearing URL。profile 更新/删除必须以 repository 生命周期钩子显式 invalidate，不能只等待 TTL。
- pooled SQLAlchemy Engine 的所有连接在每个 operation 边界归还；异常路径 rollback 后归还。不得在 `Session`、全局 request context 或 browser session 中持有数据库连接。
- `pool_size`/`max_overflow`/`pool_timeout`/`pool_recycle` 均受服务端配置硬上限约束；外部 datasource 的实际最大连接数按 worker process 数乘每池上限估算并在 remote-final 中记录。
- READ ONLY 是操作级事务约束；不得把 pool reset 等同于只读授权。数据库测试用户仍仅获得本 fixture 的 SELECT/SHOW VIEW 权限。
- 不向普通业务 API 暴露连接池内部信息或健康密钥；只在管理审计日志与受控验证产物中记录非敏感的 checkout/timeout/invalidations 计数。

## 验收标准

- 针对同一 profile 的并发 UI 请求共享同一有界 pool；跨 project/profile 不共享；超过配置连接上限的请求按有界等待失败而非无限堆积。
- update/password rotation/delete 后旧连接不能被下一请求复用；shutdown 清理所有 pools；异常及超时返回稳定错误并归还/淘汰坏连接。
- MySQL 只读权限、schema/object/column 结果、分页和 project isolation 与 B 契约保持；验证前后 datasource 临时行恢复为 0，fixture 删除。
- 本地代码检查通过，远端真实 UI→API→MySQL 测试和日志/资源证据齐全；R2-12 总体依然保留 PostgreSQL、SYNC/IDE/治理复用等后续项，除非它们各自完成独立增量。

## 风险与回退

- pool 清理不完整可能继续持有旧密码连接或耗尽 fixture。部署前保存 backend source/DB 备份；若 pool 行为异常，立即停止验证 runner、停止 API 容器并按备份恢复代码/页面，不删除持久服务数据。
- 多进程数会乘法放大连接上限；本批按真实远端 worker/process 拓扑计算 capacity，不以单进程测试数字推断生产最大值。
- 验证页面和 browser runner 不保存 token/key；所有失败 JSON 与截图保留并标注，不改写为 PASS。
