## 1. 总纲与原则

1. **海豚优先**（用户 09-18 意见⑥）：所有后台实现参考/照搬 dolphinscheduler-dev，**海豚已实现的能力直接参考，不重复不自创**；仅海豚没有的能力自创。每个阶段设计文档必须附"海豚对应机制参照"章节。
2. **四大目标为纲**（意见⑤）：方案与计划以四大目标为主线展开，逐目标细化实现任务与测试验证任务及依赖项。
3. **SQL 节点为业务实现主体**（意见③）：双层画布概念取消，ETL 算子组件与实现去掉；业务逻辑用 SQL 节点实现，SQL 代码解析取得血缘依赖流（表、字段级）并**记住转换细节**。
4. **变量承载流程控制**（意见②）：周期/批次等控制条件通过工作流变量实现，不在依赖组件里做；组件库增加**变量组件**。
5. **测试运行以 1.9 为准**（意见⑨）：本地只做语法验证，一切运行时测试部署 192.168.1.9 执行（00-流程与记录.md 已同步修订）。
6. **附加功能后置**（意见⑦）：开放接口等附加功能本期不做，主体核心功能做完后再考虑。
7. **组件化原则**（意见⑩）：能在 DAG 里组件化的就要组件化——组件拖入画布即节点，右侧 Inspector 细化配置表单（统一含输入/输出/参数/条件/限定约束/排除六区块，兼顾全局变量与工作流变量），组件可页面化展示（如流输出=可展示页面）。**穷尽清单见《02-DAG组件清单与定义.md》（C1~C23）**；组件可为聚合模板形态（拖入→选模式→展开为节点链，如同步编排 C23，意见⑬）。

## 2. 总体架构

```
datara-web   (8090, Vue3, 已建成)
──────────────────────────────────────────────
datara-api      (8000)  前端网关：REST、鉴权、定义 CRUD（海豚 api-server）
datara-master           调度内核：DAG 解析、派发、状态机、容错（海豚 master-server）
datara-worker           任务执行：SQL/Shell/Python/SSH/同步/流执行器（海豚 worker-server）
datara-alert            告警服务（海豚 alert-server）
datara-logger           日志服务（海豚 logger-server）
──────────────────────────────────────────────
registry (2181) ZooKeeper（注册/心跳/选主）     queue (6380) Redis（队列+缓存）
meta     (3307) 平台元数据库                    src (3310) 业务源库（测试数据基座）
dw       (3309) 目标数仓（派生态）
```

- 工作流定义 JSON 落库，GraphDocument 契约向后兼容；**单层画布**（无子画布/双层结构）。

## 5. 关键设计要点

### 5.1 变量组件与周期/批次控制（意见②）
- 组件库新增**变量组件**节点：表单定义变量（名/值/作用域=工作流级），运行至该节点时注入运行时
- 控制范式：变量组件定义 `wf.period=20261002`、`wf.batch=01` → 下游节点参数引用（`$[wf.period]`）→ Dependent/条件节点以变量值匹配实现"哪个周期哪个批次跑不跑"
- 与既有裁定衔接：Workbench 顶部工作流变量管理（增删改查/复制）保留，变量组件是画布上的运行时注入点；变量快照打印任务日志（F48）

### 5.2 SQL 节点与转换细节（意见③）
- 业务实现统一为 SQL 节点（+SSH 脚本节点）；ETL 算子组件与实现删除
- 解析 SQL 节点代码 → 血缘依赖流（表级 + 字段级）+ **转换细节**（输出字段 ← 来源字段集 + 表达式/加工逻辑）入库 lineage_detail
- 血缘图点击边/字段可查看转换细节，实现"数据来去 + 怎么来的"双重追溯

### 5.3 动态 schema 返选（意见与会议要求）
- 以目标表为基准选源时，可勾选源端多个 schema 的同名表，生成 union all 语句并自动附加 schema 标识列
- 每行记录带来源 schema 标识（既有裁定：合并策略=schema 标识列）；新增 schema 时按运行时探测策略（自动纳入/待确认）处理
