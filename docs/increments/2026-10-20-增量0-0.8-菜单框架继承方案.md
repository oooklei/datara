# 增量 0-0.8：菜单框架继承方案

> 版本：v0（待监督线审定）  
> 日期：2026-10-20  
> 性质：方案文档；本包不修改 `datara-newweb/` 代码  
> 权威输入：`2026-10-19-纠偏重构前端权威设计.md` §3.3、§4.1～§4.5；`2026-10-20-单线多增量WBS开发计划.md` 增量 0 包 0.8  
> 旧框架实锚：`datara-web/src/App.vue` 的 `MenuGroup`、`MenuItem`、`menus`、`groupFolded` 与 AI 悬浮入口

## 1. 目标与边界

本方案把权威设计 §4.2 的菜单语义归类表和 §4.3 的 18 项删除判定表，转译成新前端可直接实施、可测试的菜单配置契约，并明确“后续批次”折叠组及 AI 助手的全局挂载方式。

本包只冻结信息架构和显隐规则，不创建路由、页面、组件或 API 接线。菜单配置不得反向创造尚未登记的功能、路由或后端能力。

实施边界如下：

1. 继承旧前端的分组、一级直达、图标风格、激活判定和 `foldable` 折叠交互。
2. 不继承“扩展（演示）”组及其 `demo` 语义，不复制演示数据或演示页面。
3. §4.3 判定为删除的项目不进入任何菜单配置；能力另有承载时只保留能力映射说明。
4. 未到实施批次、路由未注册或产品裁定未闭合的条目不渲染正式菜单，也不形成可点击空壳。
5. 所有路径均以路由契约为准。本文保留权威设计已经给出的旧路径作为继承候选；权威设计未给路径的项目标记为 `routeName/path = TBD`，禁止自行编造。

## 2. 菜单配置契约

### 2.1 数据结构

建议把静态信息架构放在 `src/navigation/menu.ts`，布局层只消费过滤后的结果。配置模型如下；字段名是实施建议，语义为本方案冻结内容。

```ts
type MenuDisposition = 'formal' | 'future' | 'embedded' | 'deleted'

interface MenuItemConfig {
  id: string
  label: string
  routeName?: string
  path?: string
  icon?: string
  children?: MenuItemConfig[]
  disposition: MenuDisposition
  source: string
  batch?: string
  permission?: string
  decisionGate?: string
}

interface MenuGroupConfig {
  id: 'overview' | 'task-center' | 'integration' | 'development' |
      'governance' | 'operations' | 'system' | 'future'
  label: string
  items: MenuItemConfig[]
  direct?: boolean
  foldable?: boolean
  defaultFolded?: boolean
}
```

字段规则：

| 字段 | 规则 |
|---|---|
| `id` | 稳定键，不用中文标签或路径充当持久标识 |
| `routeName/path` | 至少一个能解析到已注册路由时才允许渲染可点击项；`TBD` 不进入运行时配置 |
| `disposition=formal` | 已进入当前正式批次且路由、权限、功能出处齐备 |
| `disposition=future` | 已登记且已裁定纳入，但尚未到正式批次；只能按 §5 的“后续批次”规则呈现 |
| `disposition=embedded` | 能力存在，但承载在其他页面、页签、按钮或组件中，不产生侧栏菜单 |
| `disposition=deleted` | 仅用于迁移审计清单，构建时不得进入 `MenuGroupConfig.items` |
| `source` | 必填，指向 §3 功能清单、I 增量或用户裁定，满足 §4.4 登记前置 |
| `decisionGate` | 存在未决产品形态时必填；门未闭合不渲染独立菜单 |

### 2.2 唯一显隐函数

菜单是否可见由同一过滤函数决定，页面组件不得散落自定义显隐判断：

```text
正式菜单可见 = disposition=formal
            AND source 已登记
            AND 当前批次已启用
            AND routeName/path 可解析
            AND 用户具有 permission（如配置）
            AND decisionGate 已闭合（如配置）

后续批次项可见 = disposition=future
              AND source 已登记
              AND 路由已实现并明确允许预览
              AND 用户具有 permission（如配置）
```

路由守卫仍是访问控制真源；菜单过滤只是导航呈现，不能代替鉴权。无可见子项的组整体不渲染。

## 5. “后续批次”折叠组设计

### 5.1 复用范围

复用旧框架的 `foldable`、折叠状态和组头箭头交互，不复用 `demo` 标签及“演示数据”含义。新组固定配置：

```ts
{
  id: 'future',
  label: '后续批次',
  foldable: true,
  defaultFolded: true,
  items: eligibleFutureItems,
}
```

### 5.2 纳入与渲染规则

“后续批次”不是所有未实现功能的占位清单。条目只有同时满足以下条件才可进入：

1. 已在权威设计 §3 功能清单登记出处与承载域，且用户裁定为纳入；
2. 已有可解析路由和可进入的页面，不会点击后 404、空白或显示 mock 数据；
3. 监督线明确允许在正式批次前预览；
4. 权限过滤通过。

任何条件不满足时，条目只留在方案/台账，不进入运行时菜单。`eligibleFutureItems.length === 0` 时整个组不渲染；非空时默认折叠，用户展开后才显示项目。折叠状态建议用稳定键 `future` 存储，不能用可变中文标签作键。

首批候选包括数仓建模、运行时节点、集群监控、质量五项、脱敏、审计、API 管理、API-Key 管理及 LLM 模型配置；“候选”不等于立即显示，仍逐项经过上述四门。

### 5.3 转正和撤销

- 转正：功能进入当前批次并验收，配置从 `future` 移到对应 A～G 正式组，保持同一 `id`，避免收藏、测试选择器和权限映射漂移。
- 撤销：裁定不纳入时从候选配置删除，在决策记录保留原因，不把它改回演示项。
- 路由未就绪：继续不渲染，禁止用禁用菜单或“敬请期待”页面替代。

## 6. AI 悬浮助手全局挂载点

AI 助手属于 H 全局能力，不属于 A～G 菜单。挂载点位于认证后的全局应用布局，即包裹项目工作区的 `AppShell`/根布局，与 `<RouterView />` 同级，生命周期跨页面保持：

```vue
<AuthenticatedAppShell>
  <SidebarNavigation />
  <main><RouterView /></main>
  <AiAssistantLauncher />
</AuthenticatedAppShell>
```

挂载规则：

1. 登录页、无权限页等非业务壳不挂载；进入任意已认证业务页面均可唤起。
2. 入口使用固定定位且由布局统一处理层级、移动端避让和可访问名称，页面不得重复挂载。
3. 助手打开状态可跨路由保持；页面上下文由路由元信息和显式上下文提供者注入，不读取页面组件私有状态。
4. API 只经新前端契约层访问新后端 `ai_bridge`，遵守单 BASE；不得复制旧 `services/*.ts` 或添加第二上游。
5. 当前八工具契约与实际接线状态分离：未接线工具保持不可调用，不以菜单或假按钮伪装已交付。
6. LLM 端点未闭合时，入口的产品态由对应批次决定；不得回退到旧前端 mock Agent 作为正式能力。

## 7. 实施落点与测试锚

| 落点 | 职责 | 验收锚 |
|---|---|---|
| `src/navigation/menu.ts`（建议） | 唯一菜单配置、处置状态和来源 | §3 表每行有且只有一个配置结论 |

| 路由表 | 提供稳定 `routeName` 与元信息 | 菜单项均能解析；删除项不因残留路由回到菜单 |

最低测试集：

1. §4.2 七组加 H 挂载逐行快照核对，任务中心为空组标题且一级直达。
2. §4.3 18 项参数化测试：10 项归组、#14 内嵌、7 项删除，数量与目标组一致。
3. `/sync/list`、`/script/list`、`/param/global`、`/qc/score`、`/dep/center`、`/dep/log`、`/dep/alarm`、`/dep/ops` 不出现在菜单生成结果。
4. 后续批次为空时整组隐藏；非空时组存在且默认折叠；展开不改变路由。
5. 未注册路由、未闭合 `decisionGate`、未授权项均不可见。
6. AI 入口在两条不同业务路由中保持单实例；登录页不渲染；切换路由后上下文更新。
7. 菜单隐藏后直接访问受限路由仍由路由守卫拒绝，证明显隐没有替代鉴权。

## 9. 待后续批次闭合事项

以下事项不阻塞本方案审定，但会阻止对应菜单渲染：

1. 资源管理与 LLM 模型配置的正式路由路径需在各自实施批次冻结。
2. 调用日志采用 API 管理独立页签还是管理页附属列仍待用户确认；确认前按 `embedded + decisionGate` 处理。
3. 各条目从 `future` 转 `formal` 的具体批次开关、权限码由对应增量的路由/权限契约给出。

结论：本方案完整覆盖权威设计 §4.2 的八类落位和 §4.3 的 18 项判定；没有把未实现、未裁定或无路由能力包装成可点击菜单，可作为增量 1 最小外壳及后续正式菜单实现的输入。
