- **逻辑外键、不建物理 FK 约束**：脏数据矩阵含引用断裂（孤儿行），物理 FK 会拒收 → DDL 无 FOREIGN KEY，外键关系在 tables.yaml 中声明（血缘/同步对账的数据依据）。

### 4.2 ER 关系概要（tables.yaml relations 声明）

```
dim_user 1─N dim_user_address / ods_cart / ods_order / ods_coupon_usage / sec_user_identity / sec_bank_card
dim_supplier 1─N dim_goods；dim_supplier 1─N sec_supplier_contract
dim_category 1─N dim_goods
dim_goods 1─N ods_cart / dim_inventory / ods_order_item
ods_order 1─N ods_order_item / ods_payment / ods_refund / ods_coupon_usage
ods_coupon 1─N ods_coupon_usage
```

### 4.3 90 天滚动分区

- 3 张交易大表按天 RANGE 分区：`p20260621 ~ p20260918`（T-89 ~ T0，T=灌数运行日）+ `pmax` 兜底。
- 滚动语义：每次执行生成器/重灌，窗口重算为「运行日 T-89 ~ T」→ drop 重建分区后灌数，天然滚动。
- 其余表不分区（量级无必要）。

## 5. 脏数据矩阵（9 类）与三规则实证位

### 5.1 9 类定义（01 文档 F8 口径；旧 I0 稿为 8 类，按 01 文档 9 类执行）

| # | 类别 | 注入点（示例） | 比例 | 复现机制 |
|---|---|---|---|---|
| 1 | 空值/缺失 | dim_user.nickname 5%、ods_order.remark 8% | 声明式 | seed 随机 + 锚定段 |
| 2 | 重复记录 | ods_cart 连续双行同内容 0.5%、dim_user 同号不同户 | 声明式 | 生成时成对产出 |
| 3 | 格式错误 | 手机号位数错/含字母 2%、身份证校验位错 2% | 声明式 | 变换函数确定 |
| 4 | 越界值 | 金额负数/超大 0.3%、qty 负数、age=255 | 声明式 | 锚定段 |
| 5 | 枚举外值 | order.status='X9' 0.2%、pay_channel='bitcoin' | 声明式 | 锚定段 |
| 6 | 引用断裂 | ods_order.user_id 孤儿 0.3%、ods_order_item.order_id 孤儿 0.1% | 声明式 | 生成不存在的 ID |
| 7 | 时间异常 | pay_time < order_time 0.5%、未来时间戳 0.1%、退款早于下单 | 声明式 | 锚定段 |
| 8 | 编码/脏字符 | 前后空格、全角半角、emoji、控制字符 1% | 声明式 | 变换函数 |
| 9 | 敏感明文植入 | dim_user.id_card/phone、sec_bank_card.card_no、sec_supplier_contract.credit_code（供三规则实证 + I8 脱敏样例） | 全量 | 真实格式生成 |

### 5.2 复现与对账机制（裁定：脏数据矩阵可复现、可对账）

- **全局 seed=20260918**（写入 tables.yaml）；每表/每列派生独立随机源 = f(seed, table, column)，faker 策略按「表:列/计算名」命名空间独立播种（实测修正 09-18：修复前 faker 共享未播种实例导致跨运行漂移），任何机器重跑同库同种子结果逐行一致。
- **锚定样本段**：每类脏规则除随机注入外，额外固定注入 N 条**锚定行**（确定性主键段，如 ods_order 锚定 user_id=999999001~999999010 为孤儿行）→ 1.9 核对 SQL 用锚定 ID 段断言，不受 seed 漂移影响。
- dirty_rules.yaml 每规则声明：目标表/字段/类型/比例/锚定量 → 生成器产出精确条数 → reconcile 报告 expected vs actual。

### 5.3 三预制规则实证位映射（数据质量后置另立，数据先行）

| 预制规则 | 业务表载体 | 机密表载体 |
|---|---|---|
| 身份证号码 | — | sec_user_identity.id_card |
| 手机号 | dim_user.phone、ods_order.receiver_phone | sec_user_identity.phone |
| 企业信用代码 | dim_supplier.credit_code | sec_supplier_contract.credit_code |

## 6. 生成器设计（datara-backend/tools/datagen/）

### 6.1 运行载体

- 生成器代码置于 `datara-backend/tools/datagen/`，随 datara-backend 镜像构建（I1"同一镜像不同 command"原则延续）；运行方式：`docker compose exec datara-api python -m tools.datagen.run`——api 容器已在后端网络，直连 mysql-src/mysql-dw，宿主机无 Python 环境依赖。
- requirements 追加：`Faker`、`pymysql`（若无）、`openpyxl`（顺带为 I4 文件源就位）。

### 6.2 配置驱动（两份 YAML）

**tables.yaml**：全局（seed、时间窗 T、批量、目标 DSN 环境变量名）+ 按 schema 分组的表清单，每表：字段定义（名/类型/生成策略 faker 表达式/NULL 率）、行数、主键、逻辑外键（引用表.字段 + 孤儿比例）、分区策略（分区键/天数/兜底分区）、密级标记（sec 表）、脏规则引用。

**dirty_rules.yaml**：§5.1 的 9 类规则声明（表/字段/类型/比例/锚定量/锚定 ID 段）。

生成器运行分四模式：`gen`（灌数）、`verify`（独立对账）、`plan`（dry-run 只算计划不写库，本机静态验证用）、`samples`（生成 §9 样例文件）。

### 6.3 生成与写入策略

- 拓扑序生成（先维表后事实：category→supplier→goods→user→address→order→item→payment→…），外键引用先行表已生成 ID 池（大表 ID 池只存区间抽样，控内存）。
- 写入：pymysql 直连 + `executemany` 批量 5000 行/批 + 每表单事务；**不落中间 SQL/CSV 文件**（规避脏数据含引号/emoji 的转义重灾区）。
- 性能预算：108 万行 + 分区表，1.9 机器预算 **≤10 分钟**；分表打印进度（[gen] ods_order_item 400,000/400,000）。超预算属异常，报告提示。
- 分区：DDL 含分区定义（init SQL 建表即分区，边界按 T 重算 → 由生成器 `gen` 前置步骤 REORG：DROP TABLE→按 T 重建→灌数），保证滚动。
- 内存约束（用户规则）：ID 池按需抽样、分批生成即释放、单表行对象不驻留全量。

### 6.4 dw 派生种子（src→dw 实物流水）

- `infra/mysql/dw/init/01_schema.sql`：建 dwd_order_detail（订单明细宽表）。
- `--with-demo-data` 时执行 `02_seed_dwd.sql`：`INSERT INTO datara_dw.dwd_order_detail SELECT ... FROM ec_retail.ods_order JOIN ods_order_item ...`（执行期打印源/目标行数）。
- 价值：I3 SQL 执行器、I5 血缘解析即刻有真实跨库流水素材；dw=派生态原则第一次落地。

## 7. reconcile 对账设计

- **报告结构**（reconcile.json，分库标记，落 /datara/logs/datagen/ + 容器内保留最近 3 份）：

```json
{ "generated_at": "...", "seed": 20260918, "window": {"from":"2026-06-21","to":"2026-09-18"},
  "databases": {
    "ec_retail": { "tables": [ {"table":"ods_order","expected":250000,"actual":250000,
        "partitions": 91, "dirty": {"rule_6_orphan_user": {"expected":750,"actual":750}}} ],
      "summary": {"tables": 17, "rows": 1220200, "mismatch": 0} },
```

- 生成即对账（gen 末步自动 verify）；`verify` 可独立重跑；import.sh 导入后强制触发 verify 并**更新** reconcile.json（裁定：导入后自动对账更新报告）。
- 随报告产出 **核对 SQL 清单**（verify_queries.sql：9 类规则锚定段命中断言 + 三规则实证位命中断言），1.9 实测直接执行比对。

## 8. 四脚本行为设计（infra/bin，产品交付物）

### 8.1 install.sh（扩展 I1 版）

1. 前置检查追加端口 **3310/3309**（src 原规划 3308，因同宿主机 genieppt-mysql 占用，09-18 裁定改绑 3310）；HEALTHY_CONTAINERS 追加 datara-mysql-src / datara-mysql-dw。
2. schema 初始化追加：src/dw init SQL（幂等 CREATE IF NOT EXISTS）。
3. **`--with-demo-data` 落地**：exec datara-api 依次跑 `tools.datagen run`（灌 src 14+3 表）→ `02_seed_dwd.sql`（dw 种子）→ verify 对账 → 打印对账摘要表；缺省则打印"未灌演示数据（--with-demo-data 开启）"。
4. 其余行为（前置检查/健康等待/账号/输出）不变。

### 8.2 reset.sh（新建）

- 用法：`reset.sh [--scope src|dw|all] [--refill]`，默认 `--scope all`。
- 行为：DROP DATABASE → CREATE → 重放对应 init SQL（结构彻底重置，分区一并清）。
- **联动清空（裁定）**：`--scope src` 时自动联动清 dw 并输出"目标库=派生态，源库清空必牵连"警告；`--scope dw` 仅清 dw。
- `--refill`：清空后立即重灌演示数据（等价 install --with-demo-data 的数据段）。
- 输出派生失效警告（含 dw 表清单与重灌指引）。

### 8.3 import.sh（新建）

- 用法：`import.sh --type csv-dir|sql-dump --path <路径> [--schema ec_retail] [--truncate]`
- **csv-dir**：目录内 `<table>.csv`（首行列名映射表字段，列失配报错退出）→ exec datara-api `python -m tools.datagen.import_csv`（复用容器环境，规避 mysql local_infile 配置）。
- **sql-dump**：dump 文件 scp 至远端后 `mysql source` 直放。
- 导入后：自动 verify 对账 → 更新 reconcile.json → 输出**派生失效警告**（dw 已物理化表清单 + 最后更新时间 + 平台内失配风险提示，本期提示语预留 I3 后充实）。
- 安全边界：仅允许 target=src/dw 业务库，拒绝 meta 库（平台数据不导入）。

### 8.4 uninstall.sh（新建）

- `docker compose down -v --remove-orphans`（含全部 6 数据卷）+ 打印"主机目录（dist/部署包）未删除"提醒；幂等（重复跑无报错）。
