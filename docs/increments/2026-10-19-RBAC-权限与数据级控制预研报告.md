## 四、缺陷清单（P0 / P1 / P2）

### P0（功能性/安全缺陷，建议立即派单）

**[RBAC-D1] `EXECUTE_SQL` 权限枚举缺失导致 SQL 执行永久 403（功能缺陷）**
- 证据锚：`rebuild/sql_ide/routes.py:49-50` 声明 `executeSql`/`cancelExecution` 的 permission 为字符串 `"EXECUTE_SQL"`；`rebuild/api/app.py:236-240` 的 `sql_ide_authorize` 执行 `Permission[permission]`，而 `Permission` 枚举（`contracts.py:21-25`）无 `EXECUTE_SQL` 成员 → **KeyError**；该异常被 `routes.py:106-109` 的 `except Exception` 捕获 → 返回 `PERMISSION_DENIED`。
- 实跑佐证：命令 #2 输出 `EXECUTE_SQL in enum: False`。
- 影响：**所有角色（含 admin）** 的 `executeSql`/`cancelExecution` 永久返回 403（fail-closed，非越权但功能不可用）。测试 `tests/sql_ide/test_routes.py:66` 使用 stub `authorize`（断言 `("authorize", 23, "EXECUTE_SQL", "executeSql")`），**未覆盖**真实 `app.py` 路径，故 30 项全绿仍未暴露。
- 越权/绕过面：无（fail-closed）；但掩盖了真实授权链路的验证。

**[RBAC-D2] metrics 域 6 端点无项目级授权（越权面）**
- 证据锚：`rebuild/metrics/api.py:36-53` `build_metrics_router(session_factory, token_service, active_tokens)`，`principal()`/`window_guard()` **仅校验 token 有效**，无 `project_permission_error`、无 `Permission` 校验；6 个 POST 端点全部只做登录态校验。
- 影响：**任意登录用户**可读取任意项目的指标/统计/血缘回写（横向越权，若 body 含 project 维度则跨项目 IDOR）。

**[RBAC-D3] rb 域 4 端点无项目级授权（越权面）**
- 证据锚：`rebuild/rb/api.py:33-53` `build_rb_router(facade, token_service, active_tokens)`，`guard()` **仅校验 token 有效**；4 端点（validate-policy/preview-impact/confirm/execution-records）无项目级授权、无 `Permission` 校验。
- 影响：**任意登录用户**可对任意项目发起 DDL 策略校验/影响预览/确认/查执行记录（越权面，涉及 `sql:write-ddl` 语义）。

### P1（缺陷/范围待裁定）

**[RBAC-D4] `add_member` 无项目存在性/成员关系校验，且成员管理端点不全**
- 证据锚：`rebuild/api/app.py:878-899` `add_member`：仅校验全局 `MANAGE_USER`（仅 admin 持有，`contracts.py:29`），**不校验 `project_id` 是否存在、不校验调用者与项目关系**；直接 `ProjectMemberRecord(project_id=project_id, ...)` 写入（L892）→ 可对任意（含不存在）project_id 造孤儿成员行。**无** `list/remove/update member` 端点。
- 影响：管理面完整性缺陷 + 孤儿数据；非越权（admin 可信）但契约不完整。

**[RBAC-D5] 角色模型与设计不一致（OPERATOR 缺失 / 命名漂移）**
- 证据锚：`contracts.py:14-18`（`admin/dev/analyst/viewer`）vs 设计 §13.4 L649-652（`ADMIN/DEVELOPER/OPERATOR/VIEWER`）。
- 影响：设计-实现词汇不对齐，后续按 §13.4 派工易产生"运维角色"歧义。

**[RBAC-D6] 权限点矩阵缺口（约 30 → 4）**
- 证据锚：§二矩阵；`contracts.py:21-25`。
- 影响：`project:write`、`workflow:publish/delete`、`datasource:manage`、`schedule:manage`、`standard:approve`、`security:read/manage`、`audit:read` 等约 10 项无独立承载；约 20 项被粗粒度点替代（可用但不可分级授权）。

**[RBAC-D7] `active_tokens` 为进程内存，撤销/登录态不跨 worker**
- 证据锚：`app.py:152` `active_tokens: set[str] = set()`（进程级 `set`）；`login`（L296）、`validation_token`（L314）、`i23 preview`（L337）写入，`logout`（L415）`discard`。多 worker/多副本部署下撤销不共享，`contracts.py:47` 注释亦承认"后续可在外部 Redis 加入撤销/TTL"。
- 影响：多实例部署时登出/撤销失效（安全风险），单实例部署下可用。

**[RBAC-D8] 数据级控制统一出口零实现（范围待裁定）**
- 证据锚：§三全表；Glob/Grep 无 `access_control.py`/`fetch_masked`/`t_mask_rule`/`t_access_log`。
- 影响：§13.4 数据级控制未落地；但受 §1.4 范围裁定冲突，**须先由用户裁定首期范围**（详见 §六）。

### P2（改进项）

**[RBAC-D9] 普通路由无 capability 细粒度，仅 i23 preview 例外**
- 证据锚：`app.py:344-353` `current_user` 对带 `capability` 的 token 一律拒绝（L351-352）；仅 `current_i23_preview_capability`（L401-410）用 `validation_token_service` 校验 `legacy:i23:preview`。设计上"最小权限短时 token"（§1.3）目前只服务于验证运行器。
- 影响：非缺陷，但能力令牌机制覆盖面窄。

**[RBAC-D10] validation bootstrap 发 DEV 全权 token（最小化不足）**
- 证据锚：`app.py:303-319` `validation_token` 换取 `Role.DEV` 全权 token（900s），仅按 key 校验，无 capability 限定（对比 `app.py:321-342` i23 preview 已做 capability 限定）。
- 影响：§1.3 要求"最小权限 token"，DEV 全权 + 900s 的粒度偏粗；建议对齐 i23 preview 的 capability 收敛模式。

| **RBAC-03** | rb 域接入项目级授权：`build_rb_router` 校验 `EDIT_DEFINITION`（write-ddl 语义）+ 项目成员关系 | RBAC-06 | 4 端点：非成员 → 403；`confirm` 仅 owner/成员可调；越权回归单测 |
| **RBAC-04** | 成员管理端点补全 + 项目校验：`add_member` 增项目存在性/调用者关系校验；补 `GET/DELETE/PATCH members` | 无 | 不存在的 project_id → 404；重复成员 → 幂等/409；list/remove/update 各 ≥1 用例；admin 可管、dev 403 |
| **RBAC-05** | 角色/权限点模型对齐 §13.4：明确 `OPERATOR` 取舍，建立 `角色 × 权限点` 显式矩阵（收口 D5/D6） | 用户裁定角色范围 | 矩阵单测：4 角色 × 权限点逐项断言；文档与 `contracts.py` 一致 |
| **RBAC-06** | token 撤销跨 worker：`active_tokens` 进程内存 → Redis/DB 持久化（或引入 TTL-only 无状态撤销） | 无 | 多实例（2 worker）登出后旧 token 立即失效；TTL 到期自动失效；`contracts.py:47` 注释落地 |
| **RBAC-07** | 数据级控制范围裁定 + 落地（条件触发）：先由用户裁定 §1.4 vs §13.4；若纳入首期则实现 `fetch_masked` 统一出口 + `t_mask_rule`/`t_access_log` + 4 接入点 | 用户范围裁定 | 裁定为"纳入"：4 接入点全走统一出口 + 访问审计落库 + 脱敏单测；裁定为"不纳入"：文档显式记录豁免并关闭 RBAC-D8 |
| **RBAC-08** | validation bootstrap 最小化：`validation_token` 收敛为 capability 限定（对齐 i23 preview 模式），移除 DEV 全权 | RBAC-05 | 验证 token 仅含最小 capability；越权调用被拒；bootstrap 单测更新 |
| **RBAC-09** | 权限/越权回归测试套件：建立"角色 × 端点 × 项目"越权矩阵测试（覆盖 metrics/rb/sql_ide/datasource/members） | RBAC-01~04 | 越权矩阵测试全绿；每条 P0 缺陷有对应用例；CI 可跑 |
| **RBAC-10** | 权限审计补齐：操作授权/拒绝审计落地（§13.4 L677 的"访问允许/拒绝审计"，与 §1.4 保留项一致） | RBAC-02~04 | 授权拒绝/允许产生审计记录（含 actor/target/result/reason）；审计读取端点或查询验证 |

**关键路径**：`RBAC-06 → RBAC-02 ∥ RBAC-03 → RBAC-09`；`RBAC-01` 独立可先做；`RBAC-07` 阻塞于用户裁定。

## 六、依赖与风险

1. **范围裁定风险（最高优先）**：§1.4 与 §13.4 对数据级控制首期范围**直接冲突**（L49-51 vs L671-677）。**必须由用户先裁定**，否则 RBAC-07 无法开工，且大盘 #32 的"数据级统一读取出口未验收"无法定性。
2. **授权工具收敛依赖**：metrics/rb 域当前构造函数签名 `(..., token_service, active_tokens)`，未注入 `project_permission_error`（对比 resources/execution/workflow 等域已注入）。RBAC-02/03 需先统一授权注入模式（RBAC-06 顺带收敛），否则易产生第二套鉴权实现。
3. **测试盲区风险**：`tests/sql_ide/test_routes.py:66` 用 stub `authorize`，**掩盖了真实 `Permission[...]` 枚举缺口**（RBAC-D1）。同类"契约测试用桩、集成测试缺位"的模式可能在其他域复现，RBAC-09 需补真实装配路径测试。
4. **部署形态依赖**：`active_tokens` 进程内存（RBAC-D7）在单实例下无碍，多副本/多 worker 才暴露；RBAC-06 的紧急度取决于最终部署拓扑（待核）。
5. **旧线兼容**：旧线 `api/auth.py:36-47` `ROLE_PERMS` 含 `design_component/publish_component/model:write/meta:write/ind:write/std:write` 等点，重建线未继承。若重建要承接旧线语义，RBAC-05 需一并梳理（待核）。

## 七、结论

### 7.1 本域最大缺口

**本域最大缺口 = "最小 RBAC 已成型但与设计 §13.4 严重不对齐（4 权限点 vs ~30）+ 3 处 P0 越权/功能缺陷未修 + 数据级控制零实现（范围待裁定）"。**

- **已具备**：identity 域 token 服务（HMAC 无状态）、密码摘要（PBKDF2）、4 角色粗粒度 `authorize`、项目级授权 `project_permission_error`（admin 例外 + owner/成员校验）、validation bootstrap（§1.3）——**基础骨架可靠，30 项单测全绿**。
- **未具备**：设计要求的细粒度权限点矩阵、`OPERATOR` 角色、数据级控制（clearance/biz_domain/maskRow + 统一出口 + 访问审计）。

### 7.2 核心风险点

1. **RBAC-D2 / RBAC-D3（P0 越权面）**：metrics、rb 两域**完全绕过项目级授权**，任意登录用户可横向访问任意项目——**安全红线**，建议最高优先派单。
2. **RBAC-D1（P0 功能缺陷）**：`EXECUTE_SQL` 枚举缺口使 SQL 执行对**所有角色**永久 403，且被 stub 测试掩盖。
3. **§1.4 vs §13.4 范围冲突**：数据级控制是否属首期**未裁定**，是 #32 定性的前置阻塞。

### 7.3 建议派单方向

- **第一优先（安全线）**：`RBAC-01`（EXECUTE_SQL）+ `RBAC-02`/`RBAC-03`（metrics/rb 越权），建议由 Codex 实施侧承接，前置 `RBAC-06` 授权注入收敛。
- **第二优先（管理面）**：`RBAC-04`（成员端点）+ `RBAC-06`（token 撤销）+ `RBAC-09`（越权回归套件）。
- **待裁定后启动**：`RBAC-07`（数据级控制）需用户先裁定 §1.4/§13.4 范围；`RBAC-05` 需用户裁定 `OPERATOR` 取舍。
- **收尾**：`RBAC-08`（bootstrap 最小化）、`RBAC-10`（权限审计）。
