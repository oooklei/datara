## 四、G1 方案建议（待监督线执行）

**目标**：mailbox.jsonl done 消息定期清出，控制文件体积。

**方案选项**：

1. **mailbox_loop.py 增加 compact 逻辑**（推荐）
   - 触发条件：done 消息占比超阈值（如 50%）或文件行数超上限（如 500 行）
   - 动作：把 done 消息移入 `docs/handoff/archive/mailbox-<日期>-compact.jsonl`，主文件只保留 pending + 最近 N 条 done
   - 优点：与 STATE.md 滚动归档节奏一致；append-only 信道语义保持
   - 风险：需处理 compact 与并发写入的冲突（单循环实体场景下窗口极小）

2. **独立 compact 脚本**
   - 定时或手动执行 `python agents/compact_mailbox.py`
   - 优点：与循环实体解耦
   - 风险：需额外维护调度

**建议**：方案 1，在 mailbox_loop.py 中增加 `--compact-threshold` 参数，由循环实体在标 done 后顺带检查并执行 compact。
