### 3.2 项 13 两轮实测（首轮暴露缺陷 → 修复 → 复测）

- **首轮**：卸载干净（卷/网络全删）；重装灌数时 gen 报 `Connection refused`（init SQL/init_accounts 走 exec+socket 成功，gen 走 TCP 失败）
- **根因**：MySQL 官方镜像全新卷初始化存在「临时 server（--skip-networking，仅 socket）→ 正式 server」约 15s 窗口；healthcheck 在临时 server 期间即返回 healthy，TCP 探测（connect_ex）天然区分两者
- **修复**：install.sh 新增 wait_mysql_tcp（从 datara-api 容器探测 src/dw TCP 3306，60s 未就绪 fail_exit）
- **第二轮**：全流程绿——卸载 → 重装（探测通过）→ gen 灌数 → 对账 PASS → 部署完成横幅 → INSTALL_EXIT:0 → fp_c 与 fp_a 逐表一致

## 5. 工具链教训（沉淀至项目记忆）

- **MySQL 官方镜像 fresh volume 初始化陷阱**：healthcheck 绿 ≠ TCP 可服务（临时 server 阶段即绿）；依赖 TCP 的客户端（应用/gen）前必须 TCP 探测；socket 路径（exec mysql）不受此窗口影响
- **compose 环境变量覆盖 YAML 缺省**：config 类代码 `os.environ.get(env, default)` 时，compose 注入优先——改服务名须同步改 compose 环境块，只改 YAML 无效
- **同 seed 确定性验证方法**：`SUM(CRC32(CONCAT_WS('|',...)))` 逐表指纹 + 多采集点对比链，可同时暴露漂移列与定位根因范围
- gen 全程时长实测：首跑 ~10.5 分钟（略超 ≤10 分钟预算，NAS 性能所限）；reset --refill 全程 ~15 分钟；卸载重装全闭环 ~15 分钟
