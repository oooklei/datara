## 1. 设计结论

 R5-A 建议采用 Datara 自有、项目隔离的 SQL IDE 后端模块，以 DBX 的查询语义和能力分级为参考，通过现有 HTTP/SSE 形态适配 Web。DBX 桌面前端通过 Tauri command await 获得请求/响应结果，内部仍可用 Tokio 异步任务与 oneshot/超时控制；两者属于不同层次。Datara 可保留 taskId 与 SSE 作为传输手段，但业务语义必须收敛为 DBX 已证实的单连接会话串行执行、明确结果、明确取消和超时，不得借传输层引入隐式重试、重放或额外并发语义。

R5-A 仅允许 database/schema/对象目录、列与索引等结构化元数据读取，另含 lint/解析、只读 SQL 执行、结果读取、历史管理、SQL 脚本资产管理及查询结果导出。对象源码（DDL/source text）读取/预览、源码编辑器与表结构编辑器的编辑能力均不在 R5-A；读取策略及对象写入链归 R5-B 按对象/驱动另行裁定。任何保存/执行 DDL 都归 R5-B。脚本资产的保存/重命名/删除是 Datara 应用资产操作，不会向外部数据库写数据；数据库历史删除同样只影响 Datara 自有审计/历史存储。

## 2. DBX 复刻和 Datara 适配

| 能力 | DBX 复刻语义 | Datara 适配决定 | 边界/证据 |
|---|---|---|---|
| 数据源等级 | PoolKind/驱动家族分发；连接、元数据池、Agent、ExternalDriver、Plugin 等差异显式化 | Datara `datasourceId` 映射至项目授权的数据源与驱动 profile；返回 capability matrix，不能从 UI 声明推断后端已支持 | DBX `connection/mod.rs`；P1-7 §1/§2.4；每驱动需有实测等级 |
| 元数据树 | database→schema→对象；对象类型过滤、分页；对象/驱动能力不作全局泛化 | 按 P1-7 当前九类 `ObjectKind` 收敛映射作为拟议基线；BE 枚举及逐驱动支持矩阵待 A5 冻结。每个列表端点按驱动能力返回 `supported/unsupported/unknown`，未知不得伪装为空结果 | P1-7 §2.3/§2.4；DBX `schema/mod.rs` |
| SQL 执行 | DBX 单会话执行，语句边界与执行上下文由 SQL 语义层处理 | HTTP `executeSql` 返回 Datara taskId，SSE 承载状态和分语句结果；保持每个 datasource/session 串行；同一任务禁止自动重试/重放 | DBX `commands/query.rs`、`query/mod.rs`；P1-7 §1 执行行；生命周期细节需 A5 冻结 |
| 结果网格 | 数据网格、行列型结果与分页/预览能力 | 返回稳定列元数据、页偏移/上限、总行数口径和截断标记；结果按 historyId+stmtIndex 寻址 | P1-7 §1；FE `SqlResultPage` |
| 跨 Schema | 按数据库类型保留/改写 schema，并对未限定对象作受控上下文注入 | 明确 database/schema/catalog 参数语义；只能通过方言适配器执行已验证策略；失败关闭，不对未知驱动猜测注入规则 | DBX `query/mod.rs`；映射 v2.2 §1；矩阵逐驱动验收 |
| 历史与脚本 | 查询历史与文件式 SQL 资产分离 | 历史记录执行摘要与审计关联；脚本库做项目隔离、版本戳/并发更新保护，绝不与外部组件共用真源 | DBX `commands/history.rs`、`saved_sql.rs`；D6 主权边界 |
| 导出 | DBX 查询结果导出和长任务导出分开，长任务可取消并清理未完成产物 | R5-A 仅导出当前只读查询结果；异步任务按用户/项目授权、短期有效句柄、过期清理；表级全量导出需 A5 明确纳入，否则延后 | DBX `query_result_export.rs`、`table_export.rs`；结果隐私与容量限制待定 |
| 对象定义 | ObjectSourceKind 源码对象与 table 结构化模型双轨；驱动编辑策略各异 | R5-A 仅返回对象身份及结构化元数据，不返回 DDL/source text；对象源码读取/预览策略与逐对象写权限、编译/发布链均留给 R5-B 裁定 | DBX DDL 精读 evidence；P1-7 v2.3 §2.3 |

DBX 语义优先规则：与原版 `/ide` 的冲突以 P1-7 v2.3 §1 决议为准。保留原版异步 taskId/SSE、服务端结果导航、执行日志的 Web 适配价值，但不能沿用原版短接数据库、未分级的查询能力作为安全或驱动契约。CodeMirror、补全和编辑器交互属于前端阶段；本方案只定义服务端可提供的元数据和变量执行服务。P1-7 消化笔记的补充裁定直接进入 A5 待决：执行目标遵守完整语句边界，选区只是收集输入；不得提供普通快捷路径执行半条语句。结果分页优先复用同一执行结果的 cursor/物化快照，绝不默认重跑历史 SQL。若不能避免重跑，须显式冻结副作用、数据漂移和资源成本并默认禁止对任意查询静默重放。

旧版 `/ide` 的可吸收价值只作为后续 UI 验收输入：表/视图操作菜单只生成 SQL 草稿、不自动执行；结果页可回看/复制原始 SQL 与单元格；结果页间数据漂移要提示；失败停止/警告/取消状态可区分；IDE 使用 Datara 数据源中心管理连接。键位、搜索/goto、Peek、拖拽等不属于本后端设计范围；只有它们依赖的对象能力、稳定 task/statement 标识、脱敏 SQL 摘要和分页快照接口由本设计承接。

## 3. 后端模块边界

建议新增 `datara-backend/rebuild/sql_ide/`（仅为目录建议，实际实现等 A5 冻结）：

1. `router.py`：HTTP 请求校验、认证、统一错误包络、SSE 响应，不含 SQL 方言逻辑。
2. `schemas.py`：与 17 方法对应的请求/响应模型；snake_case 是 BE 内部规范，前端适配负责 camelCase 映射，最终字段以 A5 为准。
3. `service.py`：逐请求执行项目/用户授权、数据源解析、能力检查、变量解析、只读门禁和审计关联。
4. `driver_registry.py` + `drivers/*`：按 datasource kind/profile 解析连接工厂、元数据能力、跨 Schema 策略、结果类型；能力级别不得由数据库名称单独推定。
5. `execution.py`：受控执行会话、语句切分、超时/取消、结果页快照、事件发布；同一连接执行队列串行。
6. `store.py`：SQL 历史、执行任务状态、结果分页快照、脚本资产、导出任务元数据；所有记录带 project/user/datasource 归属。
7. `security.py`：只读授权和 SQL 分类门；只读 DB 凭据为权威保护，AST/方言分析作第二道校验；未知语句、混合批次、存储过程调用及无法分类的语句 fail-closed。
8. `variables.py` 适配共享 R2 解析服务：不复制变量语义、不自行实现命名空间解析。

production factory 必须在应用装配时注入明确的数据源 registry、项目授权器、R2 variable resolver、持久化 store、审计 writer、SSE event broker、只读策略和时钟。任何依赖缺失不得回退到内存假实现或默认放行；模块未装配时按未接线错误返回。该方案只记录装配需求，不修改 app/router。

## 4. 17 方法的服务职责映射

方法名、参数形状和 FE 类型当前以 `sqlIdeApi.ts` 为输入，不在本设计中变更签名。A5 需逐项把它们补成 BE 权威定义。

| 方法 | 后端职责与主要约束 |
|---|---|
| `listDatabases` | 认证→项目授权→数据源能力检查→数据库列表；不支持与空列表区分 |
| `listSchemas` | 校验 database 对当前 datasource 合法；返回 schema 与默认 schema 元数据 |
| `listRelations` | 仅 table/view；支持 schema/filter/page 的最终分页参数由 A5 定义；驱动缺能力显式返回 unsupported |
| `listColumns` | 校验父对象路径，返回类型/nullability/key/comment；避免未授权跨库读取 |
| `listRoutines` | 仅 function/procedure/trigger 的对象身份/可用元数据；不得返回 DDL/source text，驱动能力差异显式标示 |
| `listIndexes` | index 作为 table 子对象；验证 table/schema/database 一致性 |
| `searchObjects` | 仅在当前 datasource 与授权 database/schema 范围搜索；结果包含 parent/kind，不做越权全局搜索 |
| `lintSql` | 纯解析/静态诊断，不执行、不解析变量值、不写历史；lint 不能被宣传为数据库编译验证 |
| `executeSql` | 提交单个只读请求/批次，生成 taskId；校验变量、上下文、只读性与额度，持久化创建状态后启动串行执行 |
| `cancelExecution` | 用户/project/task 三方归属校验；只确认取消请求状态，执行器确认后发 canceled 终态；幂等但不得虚报已终止 |
| `openEventStream` | 事件携带 taskId、单调 event sequence、stmtIndex；断线重连需有明确 replay cursor 策略，不能重复执行 SQL |
| `fetchResultPage` | 经 historyId、stmtIndex、offset/limit 读结果快照；限制最大页大小；结果被清理时返回稳定过期错误 |
| `listHistory` | 当前用户/项目/数据源范围过滤；历史内容按敏感字段策略存储/展示 |
| `deleteHistory` | 删除前授权；审计记录保留删除人/时间/目标；是否软删除与保留期由 A5 冻结 |
| `listScripts` | 列出当前 project 的文件式 SQL 资产；明确用户个人脚本是否在本期 |
| `saveScript` | 仅修改 Datara 脚本资产；创建/更新用 revision/ETag 防止覆盖并发修改；SQL 文本可含未解析变量 |
| `deleteScript` | 仅删除 Datara 脚本资产；项目授权、版本校验与操作审计 |

目前 FE `SqlExecuteRequest` 只含 datasourceId/db/sql/mode=auto，尚不能完整表达跨 Schema `schema/catalog`、变量来源上下文、幂等键、批次策略、结果限制和恢复游标。不得由 BE 私自改变冻结签名；A5 需通过兼容扩展或明确的 request context envelope 补齐，见 §9。

## 5. 查询流程、状态与只读保证

推荐流程：

`request → auth/project scope → datasource/capability resolve → variable resolve → immutable variable snapshot → statement boundary parse → readonly policy → create durable task+audit start → execute serially → persist result page snapshot/history → emit statement/result/terminal events`。

- 变量输入是原始 SQL 文本中的 `${scope.name}` 与 `$[时间表达式]`；执行前调用 R2 解析器，记录版本化不可变解析快照 ID/digest，执行历史不得只留已展开明文。敏感值在日志/SSE/错误响应脱敏。
- 运行上下文以 Datara 的 `project_id/user_id/run_id` 等主权字段为准，外部 DBX/驱动不成为身份、项目、变量或审计真源。手动 IDE 运行是否生成 `run_id` 是 A5 决议；不得伪造工作流运行关联。
- SQL 只读必须组合数据库只读账号/权限与服务端 AST/方言策略。静态检查仅能辅助识别；多语句逐条检查，任何一条写入或无法分类则整个批次拒绝。禁止依赖简单前缀/正则作为授权。
- 超时在服务端以单调时钟起算并限定最大值；客户端断线不隐式取消。取消结果以驱动实际终止为证；无法确认终止时保持 cancelling/unknown，不得返回 canceled。
- 执行错误分为权限、能力不支持、解析/变量、只读策略、连接、数据库语句、超时、取消、结果持久化等稳定 code；不得把驱动原始异常或凭据泄漏给客户端。
- Datara Web 的 SSE 是观察同一执行的传输方式。重连只重放已持久化事件/结果游标；不得重做 SQL。事件顺序、保留时长与 cursor 格式待 A5 明确。
- 数据源池耗尽、Agent/ExternalDriver/Plugin 驱动进程治理、启动/重启能力不由 DBX UI 的监控入口直接推导。R5-A 只消费 Datara 已批准的 datasource/connection ID 和能力协商结果；若一期目标驱动需独立 Agent/JDBC/插件进程能力，必须先有 Datara 部署与运行时证据及对应任务，不把它塞成 SQL IDE 的隐含子系统。
- 多语句行为须明确逐语句状态和失败后的后续策略，warning 与 error 分开；若部分语句已成功、后续失败，整体状态要表达 partial failure，不能冒充事务回滚。默认建议在执行前发现批次中任何非只读/不可分类语句时整批拒绝。

## 6. 建议数据模型

所有实体主键及数据库方言仍由 A5 选型；以下为最小逻辑模型，不表示迁移已获准。

| 实体 | 核心字段 | 不变量 |
|---|---|---|
| `SqlExecution` | task_id, project_id, user_id, datasource_id, db, schema, sql_digest, variable_snapshot_ref, status, started_at, finished_at, timeout_ms, error_code | taskId 随机不可枚举；终态不可逆；归属不可变 |
| `SqlExecutionStatement` | task_id, stmt_index, normalized_kind, status, elapsed_ms, rows_total, affected_rows, error_code | 顺序执行；R5-A 仅 query/read；结果列定义可保留 |
| `SqlResultSnapshot` | history_id, stmt_index, columns_json, rows/page storage ref, rows_total, truncated, expires_at | project/task 隔离；分页读取为同一快照，不重新跑 SQL |
| `SqlHistory` | history_id, project_id, user_id, datasource_id, db, schema, sql_text/redacted_sql, status, stmt_count, elapsed_ms, created_at, audit_ref | 索引按 project/user/datasource；保留策略明确；删除有审计 |
| `SqlScript` | id, project_id, owner_id, folder_id, name, sql_text, revision, created_at, updated_at | 文件资产只在 Datara；并发更新需 revision compare-and-swap |
| `SqlExportJob` | export_id, project_id, user_id, task/history ref, format, status, object_ref, expires_at | 授权下载、短期过期、取消和未完成清理；导出不能再次执行查询 |
| `SqlIdeAudit` | audit_id, actor/project/datasource/task, action, timestamp, outcome, correlation_id, redacted_detail | 与历史删除、执行、导出、脚本管理分开；不可被历史清理级联删除 |

R5-A 导出格式和结果容量策略需冻结后选型。若结果太大，不应无限缓存所有行；可采用有上限的服务端分页快照或受控临时文件，并将过期错误/下载授权纳入契约。

## 7. 变量体系与跨 Schema

- 共享 R2 resolver 为唯一变量语义实现；IDE 编辑/补全 UI 不在后端阶段。执行请求需带 resolver 所需的显式 scope/context 引用，不由 datasource 或当前登录用户隐式猜测命名空间。
- 解析成功生成不可变快照，并保存 `snapshot_ref`、digest、命名空间版本信息；原始 SQL 和渲染后 SQL 都应受敏感信息分级，默认不给普通 history API 返回明文解析值。
- 解析失败应在执行前返回结构化错误定位（变量名/SQL 区间/code），无数据库副作用，不写成成功历史。
- 跨 Schema 策略按数据库类型/驱动 profile capability 明确：显式限定的 schema 不得被重写；未限定名称是否注入当前 schema 由方言适配层决定；系统 catalog/特殊 schema 必须保护；未知驱动 fail-closed 或要求显式限定名。
- 结果及元数据请求的 project/datasource/database/schema 组合需一致性校验，避免把 SQL 执行权限与元数据浏览权限混为一谈。

## 8. 阶段门禁和验收

实施必须等 P2-1 冻结和 A5 通过。推荐阶段顺序：

1. **A5 契约冻结**：17 方法逐项 request/response/error/auth/persistence 定义；状态、事件序列、跨 Schema、只读边界、数据保留及厂装配均有 owner 决议。
2. **P2-2-1 元数据只读**：驱动 registry 与能力矩阵；按拟议九类映射浏览（最终 BE 枚举待 A5 冻结）；仅对象目录及结构化元数据，不含 DDL/source text；未知能力和权限错误可区分；每个目标驱动有集成证据。
3. **P2-2-2 lint/变量/只读执行**：R2 snapshot、AST/dialect read-only policy、真实只读凭据；多语句边界、跨 Schema 方言向量、取消/超时和失败语义。
4. **P2-2-3 结果/事件/持久化**：SSE 顺序/重连不重放、页快照一致、历史/审计、任务过期与清理。
5. **P2-2-4 SQL 资产/结果导出**：项目隔离脚本、并发写冲突、导出额度/过期/取消/清理。
6. **验收封门**：A1 红绿测试、A2 独立评审、A3 成对证据、A4 O7 诚实、A5 DBX 复刻矩阵、A6 A5 冻结纪律、A7 红线；所有只读数据库探针确认无写入；生产 factory 每项依赖显式注入；契约端到端集成测试全部 PASS，方可称 R5-A GREEN。

本设计及设计阶段的静态源码研读不构成上述实施验收。不能将 17 方法签名 RED 合约或 mock 测试称为功能页/后端 GREEN。

## 9. A5 必须裁定的议题

1. 17 方法参数缺口：`schema/catalog`、变量上下文、结果行数上限、历史筛选/分页、SSE `Last-Event-ID`、幂等标识如何兼容现有前端签名。
2. 执行生命周期：DBX 同步请求语义与 Datara taskId/SSE 的边界；单 datasource/session 串行粒度；并发任务策略；取消请求与驱动终止确认；断线恢复 cursor/保留窗口；是否采用 `cancelling` 状态词。
3. 批执行：选区/当前语句/多语句解析选择顺序；事务模式是否排除 R5-A；任一不可分类/非只读语句时整批拒绝还是逐条拒绝。建议默认整批拒绝以避免部分执行歧义。
4. 数据源等级：一期必须支持的 driver profile 清单、每个元数据/执行 operation 的级别和真实测试环境；Agent/JDBC/插件路径是否纳入 R5-A。
5. 只读门：支持的 SQL AST 方言与限制；存储过程/函数调用是否一律禁止；DB 只读账户的配置、凭据保管、无法创建只读账号的 datasource 如何处理。
6. 结果策略：分页快照容量、最大行/字节、截断标志、TTL；查询结果导出格式；是否纳入全表导出；导出下载 URL/鉴权和清理策略。
7. 历史与脚本资产：项目共享还是个人私有；SQL 文本/变量快照保存和脱敏；历史删除是软删还是物理删；审计保留期限；脚本目录模型和冲突策略。
8. 手动 IDE 执行关联字段：是否生成独立 Datara `run_id`，以及与工作流 run_id 的禁止混用规则。
9. 对象详情：R5-A 只冻结对象身份与结构化元数据字段；九类映射及逐驱动元数据能力待 A5 确认。DDL/source preview 可用级别、驱动只读/Unknown 时的读取协议属于 R5-B 后续议题，不授权 R5-A 返回源码或保存 DDL。
10. 错误包络与 HTTP 状态码：能力缺失、授权失败、过期结果、用户取消和未知驱动分别采用哪些稳定 code。

未裁定前，以上均为明确的设计待决，不允许实现时由单个开发者静默定案。
