## 2. 契约冻结前置裁定清单（进实施前必须裁定，非本线可自裁）

| # | 裁定点 | 选项与影响 | 建议倾向 |
|---|---|---|---|
| D1 | 重试 interval 语义 | DS task 级分钟 interval 为基线 vs 保留分类退避为主；attempt 独立实体 vs task 行内递增 | DS interval 为基线+退避登记为 Datara 扩展；attempt 是否独立实体影响工作量 M→L |
| D2 | 人工失败恢复预算规则 | 重置 retry budget（DS FailedRecover 语义）vs 沿用原预算 | 对齐 DS：重置，且与自动 retry/failover 三语义分离 |
| D3 | 补数批次模型 | 持久 ComplementBatch 实体+每日 runId（L）vs 无批次仅命令展开（现状，M 但可追溯性缺失） | 持久批次（客户九项要求可追溯性支撑） |
| D4 | 补数日期源与时区 | 仅范围 vs 范围+列表+时区/DST | 范围+列表起步，时区显式字段（禁隐式 UTC 推定） |
| D5 | 优先级枚举方向 | 对齐 DS（小值高优，存量数据迁移）vs 保留 Datara 方向+显式转换 | 对齐 DS enum code，映射表+迁移一次性落位 |

## 3. 分批验收顺序与关门条件（沿 evidence §6 + 预研收敛）

1. **先 P0 retry + failover 语义裁定**（D1/D2）——两者共用 attempt/run/幂等约束，不得分开设计后再拼接；
2. **再 P1 backfill**（D3/D4）——冻结 batch/date/timezone/order/parallelism 契约后实现逐日实例追踪与恢复；
3. **最后 P2 priority**（D5）——任务与队列语义稳定后裁定映射与公平性；不与补数或 R6 查询 API 混为一个需求；
4. 四项关门条件统一：Datara 实现锚 + 自动化边界/故障注入测试 + 可复核运行结果，**任何一项缺证保持 RED，不得宣称 R6 执行引擎 GREEN**；每项语义/配置/恢复结果映射到 DS 源锚形成 parity traceability。
