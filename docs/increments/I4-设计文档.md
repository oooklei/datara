## 3. 数据源中心（F10~F14）

### 3.1 类型框架

| type | 连接参数 | 连通测试 |
|---|---|---|
| mysql | host/port/db_name/user/pwd | connect + SELECT 1 |
| greatdb | 同 mysql（默认端口 3316 仅前端表单缺省差异） | 同 mysql |
| file | params JSON：`{format, path, encoding, delimiter, header, sheet}` | 路径存在+可读+解析头 5 行（推断列数） |

- **连接工厂** common/dsconn.py：`open_connection(ds: DataSource)` → pymysql.Connection（mysql/greatdb 同路）；`parse_file_source(ds)` → 解析器句柄。密码明文直用（裁定）。
- **文件路径规范**：仅允许 /datara/files/ 下相对路径（compose 挂载 datara-files 卷：宿主机 /mnt/lei/datara/files → datara-api/worker /datara/files）；越界路径拒绝（防目录穿越）。
- **解析器**：CSV/TXT 按编码+分隔符逐行流式（csv 模块 delimiter 参数，自定义串如 `\\|\\.` 直接传入）；Excel 用 openpyxl read_only 模式流式迭代（内存约束，复用 I2 datagen 经验）。

### 3.2 API（api/datasource.py）

| 方法/路径 | 说明 |
|---|---|
| GET /datasources | 列表（keyword/env/group/type 筛选；pwd 不脱敏回显——裁定） |
| POST /datasources | 新建（type=connection 时校验 host/port；type=file 时校验 params） |
| PUT /datasources/{id} | 编辑 |
| DELETE /datasources/{id} | 删除（被工作流引用时 409——扫 graph_json 引用计数） |
| POST /datasources/{id}/test | 连通测试（§3.1 表）；结果回写 status |
| GET /datasources/{id}/tree | 库表树：连接型→SHOW DATABASES/TABLES + INFORMATION_SCHEMA.COLUMNS；文件型→单文件 schema 推断结果 |

## 5. C22 文件读取组件（F62，自创核心）

### 5.1 组件定义（对齐 02 文档 §3）

- **NodeSchema**：type=file_reader，分组=数据计算组；六区块照常；业务表单：
  - 来源模式：`数据源中心文件源`（下拉 type=file 数据源）/ `手动参数`（路径+格式+编码+分隔符+表头+sheet）
  - 是否注册临时数据 + 命名（name，正则 `[a-z][a-z0-9_]{2,31}`）+ 保留策略（`立即清理` / `保留N天`（N 输入）/ `转正式表`（目标数据源+目标表名））
- **页面化展示**（NodeSchema.page，F61 框架）：数据预览与检验网格——分页预览（t_tmp_data.preview_json/分页读抽样）/ 字段类型推断表（schema_json）/ 空值统计列；入口=实例详情节点日志抽屉「数据预览」按钮 + Inspector 表单侧。

### 5.2 worker 执行器（executors/file.py）

1. 读参数（数据源中心文件源或手动参数，同 §3.1 路径规范）。
2. 流式解析：CSV/TXT（csv.reader）/ Excel（openpyxl read_only）。
3. schema 推断：抽样前 1000 行类型判定（int/float/bool/datetime/str），空值率统计。
4. 产出（按注册选择）：
   - **临时表形态（默认）**：在文件源同域目标库（表单选目标数据源，默认内置数仓）建 `{instance_id}_{node_id}_{name}` 表（TEXT 列全量承载，类型仅作文档）+ LOAD DATA LOCAL INFILE / 批量 INSERT（Excel）；写 t_tmp_data(kind=table, ref=表名)。
   - **结果集引用形态**：抽样 200 行 JSON + schema + 行数统计写 t_tmp_data(kind=resultset)；不落目标库。
   - **文件形态**：仅登记路径+schema（文件已在共享卷），写 t_tmp_data(kind=file)——供 Shell/Python 上游产出的文件被下游引用（C22 也可用此形态快速注册既有文件）。
5. 日志：行数/列数/类型推断结果/耗时/注册结果（输出参数 rows_count、columns、tmp_name 注册到 outputs，对齐 KEY=VALUE 解析约定）。
6. 保留策略执行：`立即清理`=实例终态后 master 清扫（§5.4）；`保留N天`=t_tmp_data.expire_at，F50 脚本扩展清扫；`转正式表`=实例成功后 RENAME 去前缀（master 实例收口时执行，失败告警不阻断）。

### 5.3 ${tmp.*} 变量扩展（master/variables.py，待确认点④）

- resolve 新命名空间：`${tmp.<name>}` → 查 t_tmp_data（同实例或上游实例链）：
  - kind=table → 替换为实际临时表名（同库可直接 FROM/JOIN）
  - kind=file → 替换为共享卷文件绝对路径（Shell/Python/再读）
  - kind=resultset → 替换为临时表名（若已物化）或空串+日志告警（仅预览无实体，SQL 语境不可用——表单侧即时校验提示）
- 解析失败（未注册/已过期）→ 变量保留原样 + 任务日志告警行（对齐 I3 变量链容错口径）。

### 5.4 生命周期与清扫

- t_tmp_data.status：`active → consumed(转正式表) / expired / cleaned`。
- master 实例终态收口时：`立即清理` 策略行 → DROP 临时表/删文件 + status=cleaned。
- F50 clean_logs.sh 扩展：过期 expire_at 行同清扫（复用既有 `{instance_id}_` 前缀清扫逻辑，补 t_tmp_data 索引清理与统计列）。
- 实例详情页「临时数据」区块：列表（形态/名称/行数/保留策略/状态），手动清理按钮（run_instance 权限点）。

## 8. 海豚机制参照（I4 范围逐项对照）

| Datara I4 设计 | 海豚对应机制 | 对齐方式 |
|---|---|---|
| 数据源中心 CRUD/连通测试 | DataSource 服务 + 数据源中心页 | 对齐（表单裁剪：无 Kerberos/资源中心） |
| IDE SQL 编辑器/执行/多结果集 | SQL 任务编辑器 + SqlClient | 对齐（交互式独立模块，非任务态） |
| C15 存储过程 | ProcedureTask | 对齐 |
| C16 HTTP | HttpTask（JSONPath 提取） | 对齐（提取简化为点路径子集，不引 jsonpath 依赖） |
| C22 文件读取 + 临时工作数据 | 无（海豚资源中心为脚本/文件管理，非数据集语义） | **自创**（意见⑫） |

## 14. 风险与预留

- **C22 大文件**：临时表全量 TEXT 承载在大数据量下慢——本期样例级数据；I6 C17 落地时文件读端升级 STREAM LOAD 式批量（预留 dsconn.parse_file_source 接口）。
- **结果集引用无实体**：仅 C20 类展示可消费；SQL 语境误用靠表单提示+变量解析告警双兜底（§5.3）。
- **GreatDB 真实差异**：协议兼容覆盖 95% 场景，特有语法（如分布式表 DDL）不在本期适配范围，待客户提供实例后按需补。
- **IDE 长查询**：60s read_timeout 截断；导出走独立重放链路不受执行超时限制（导出上限 10 万行，超出报错提示走 C22/同步通道）。
