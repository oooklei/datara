## 实施顺序与门禁

1. **阶段 1：A8 入口与上下文**。产物：导航/上下文映射方案；验证锚：项目与 datasourceId 授权边界及现有数据源中心静态实现；停止条件：权限责任或入口目标不清时停在设计评审，不新建数据源 UI。
2. **阶段 3：A1、A3、A6**。产物：对象草稿、快捷键、变量视觉/补全的 UI 设计与验收案例；验证锚：A5 #3/#9/#16、R2 变量权威和完整语句边界；停止条件：SQL IDE 页面/编辑器落点未盘点，或快捷键保存目标、对象能力、变量规则与契约不一致时不实施。
3. **阶段 4/5：A7、A2、A4、A5**。产物：执行状态与结果体验验收案例；验证锚：A5 #9–#13、事件终态、固定快照分页及 TTL；停止条件：服务端事件/分页语义未落实或证据不足时保留“待验证”，不由 UI 宣称能力。

上述步骤仅为同一融合派单内前后依赖的规划顺序，不授权实施。每项进入开发前仍须满足对应 Phase 3 门禁；A5 冻结契约不得由本清单改写或扩展。
