## 1. 总体架构

```
规则（5 维度 SQL 受控映射）→ 任务（规则集 + 手动/crontab 定时）→ 运行记录 t_qc_run
   → 异常记录（样本 SQL + 修复/忽略）→ 告警判定（复用 alerts）→ 报告生成/导出 → 评分卡聚合
```

- 执行引擎 `common/qc_engine.py`：规则→受控 SQL，与 I20 同白名单原则（字段 quote_ident、条件表达式校验、禁分号/注释/多语句）
- 调度：master/schedule.py 扩展质量段——扫 `t_qc_task(enabled, crontab)`，croniter 到期→线程池执行→写 run/exception→告警判定

## 2. 数据库表（6 张新表，含 create_time/update_time）

| 表 | 关键字段 |
|---|---|
| `t_qc_rule` | name / dim(完整性、唯一性、准确性、及时性、一致性) / rule_type(null_check、dup_check、range_check、freshness_check、cross_table_check) / ds_id / db_name / table_name / column_name / params_json（阈值、条件、时间窗、对照表） / threshold（通过阈值或最大异常数） / status(enabled、disabled) / owner / remark |
| `t_qc_task` | name / crontab(String64 nullable) / enabled(bool) / rule_ids(JSON) / status(idle、running) / last_run_at / last_result / owner / remark |
| `t_qc_run` | task_id Index / trigger(manual、schedule) / started_at / finished_at / result(pass、fail) / score(0-100) / stats_json（逐规则命中数与状态） |
| `t_qc_exception` | run_id / rule_id / task_id / target / sample_sql / hit_count / status(open、fixed、ignored) Index / fix_note / handled_by / handled_at |
| `t_qc_report` | title / scope / period / content_json（统计汇总） / created_by |
| `t_qc_alarm_policy` | name / scope(task_id、rule_id、all) / metric(exceptions_count、score) / op(gt、lt) / threshold / enabled / last_fired_at |

种子数据：`t_qc_rule` 预置原型三个预制规则（对齐 DB.qcRules）。

## 3. 规则→SQL 映射（qc_engine）

| rule_type | SQL 形态 | 通过判定 |
|---|---|---|
| null_check 完整性 | `SELECT COUNT(*) WHERE col IS NULL` + `SELECT COUNT(*)` | 空值率 ≤ 阈值 |
| dup_check 唯一性 | `SELECT COUNT(*)-COUNT(DISTINCT col)` | 重复数 ≤ 阈值 |
| range_check 准确性 | `SELECT COUNT(*) WHERE NOT (expr)`（expr 校验后拼 WHERE） | 违规数 ≤ 阈值 |
| freshness_check 及时性 | `SELECT COUNT(*) WHERE time_col < NOW()-INTERVAL n HOUR` | 逾期数 ≤ 阈值 |
| cross_table_check 一致性 | `SELECT COUNT(a 条件)` vs `SELECT COUNT(b 条件)` | 差异率 ≤ 阈值 |

命中样本：`SELECT * FROM <target> WHERE <同条件> LIMIT 1000`（预览/CSV 下载）。

## 4. 后端 API（/api/v1 前缀，ok()/ApiError 规范）

```
CRUD  /qc/rules[/{id}]                 # 规则 CRUD + 启用/禁用
GET   /qc/rules/templates              # 预制规则模板（3 个，套用即复制参数）
POST  /qc/rules/{id}/test              # 试跑：即时执行返回命中数与通过判定
CRUD  /qc/tasks[/{id}]                 # 任务 CRUD（crontab 校验复用 wf_schedule 规范）+ 启停
POST  /qc/tasks/{id}/run               # 立即运行（同步执行，60s 超时，返回 run 摘要）
GET   /qc/tasks/{id}/rules             # 任务规则明细 + 最近结果
GET   /qc/runs?task_id=&page=          # 运行历史
GET   /qc/exceptions?status=&task_id=&page=         # 异常清单 + 统计卡（open/fixed/ignored）
GET   /qc/exceptions/{id}/sample?limit=&download=   # 样本预览 / CSV 下载
POST  /qc/exceptions/{id}/fix          # {note} → fixed
POST  /qc/exceptions/{id}/ignore       # {note} → ignored
POST  /qc/reports/generate             # {title, scope, period} → 汇总生成
GET   /qc/reports[/{id}]               # 报告列表/详情
GET   /qc/reports/{id}/export          # HTML 报告下载
CRUD  /qc/alarms[/{id}]                # 告警策略 CRUD + 启停
GET   /qc/alarms/fired                 # 最近触发记录（告警中心 source=qc 回读）
GET   /qc/score                        # 评分卡：维度通过率 + 近期 run 趋势
```

- 权限：`ROLE_PERMS` 增补 `qc:write`（admin/dev）；评分/报告读登录即可
- 审计：规则/任务增删改、立即运行、修复/忽略、报告生成写 logger（`audit.qc`）

## 6. 错误处理

| 场景 | 处理 |
|---|---|
| 规则 SQL 执行失败/超时 | run 内该规则记 error，不阻塞其他规则；60s 超时 |
| crontab 非法 | 400 附校验原因（含未来 3 次预览失败） |
| range_check expr 非法 | 400 校验明细 |
| 任务运行中重复触发 | 409「任务正在运行」 |
| 告警中心写入失败 | 触发记录本地留存+重试标记 |
| 调度线程执行异常 | 记 run(trigger=schedule, result=fail) 不中断调度循环 |
