- **关联台账**：STATE.md S144（调查闭环）、S146/S147（裁定与本文档产出）

## 1. 结论摘要

Codex token 消耗异常不是单点问题，而是「固定起步价 × 轮数 × 拆单乘数」三重放大：

1. **input 占 99.6%**，且缓存命中不省配额；
2. **每线程固定起步约 4 万 tokens**，新开会话只清历史、不清固定开销——这是「新开会话也很快耗尽」的直接解释；
3. **一单自动拆多线程**（subagent），每线程独立付起步价，乘数 3–4 倍；
4. **aoci MCP 零义务纯注入**（裁定 #85 下 Codex 无 AOCI 义务）；
5. **工具输出常驻每轮重发**，探索越多浪费越大。

佐证：2026-10-19 单日 157 线程累计 4.4 亿 tokens。

## 3. 根因明细

### a) input 占 99.6%，缓存命中仍计配额

S135 会话 4 线程 153 轮 input 合计约 **1670 万 tokens**（缓存命中率 95–98%，但 cached_input_tokens **仍计入 rate limit 配额**），单轮最高 16.8 万。

机制：Codex 每轮请求全量重发上下文——system + developer 人设 + AGENTS.md + 全部工具定义 + 全部历史消息 + 全部工具输出。轮数越多，重复重发越多。

### b) 每线程固定起步约 4 万 tokens

| 构成 | 体积 | 折合 |
|------|------|------|
| 12 插件全开的 additional_tools 工具定义 | 85.7KB | ≈2.4 万 tokens（大头） |
| developer 人设消息 | 1.8 万 chars | — |
| AGENTS.md（workspace rules，含 AOCI 全节） | 16.4KB | — |

**新开会话只清历史对话，不清固定开销**——用户观察「新开了会话还是耗得快」即源于此。

### c) 一单自动 spawn 多 subagent（乘数 3–4 倍）

S135 拆 1 主 + 3 子线程，每个子线程独立付约 4 万起步价；本仓 spawn_edges 累计 510 条。

**用户裁定（2026-10-20）：暂缓禁用。** 理由：子线程是复制主的上下文，主的上下文减小（措施①②落实后），总量自然减小；且拆单带来并行能力提升。即③与①②存在依赖——先压缩主上下文，拆单的边际成本自动下降，不必牺牲并行性。

### d) aoci MCP 零义务纯注入

裁定 #85 已明确 Codex/Trae 实施线对 AOCI 义务为零、禁调 aoci_* 工具，但 Codex config.toml 仍挂 aoci MCP server → 每线程启动即注入其工具 schema，纯浪费。

### e) 工具输出常驻每轮重发

单条工具输出最大 42k chars，常驻上下文随每轮重发。派单若无精确验收命令与文件路径边界，Codex 需多轮探索（读文件、试跑命令），每轮探索输出都永久计入后续所有轮次。

## 5. 组合效果估算（以 S135 案例为基准）

- ②插件 11 个全关：起步价大头（≈2.4 万）直接清零；
- ①注释 aoci 段：aoci schema 实测 35.8KB ≈ 1 万 tokens/线程，随①清零；
- ④精确验收命令：探索轮次下降 → 全量重发总轮数下降；
- ⑤effort 降档：思考类 token 减半。

综合估算：S135 案例的 1670 万 input 有望降至约 **1/6 ~ 1/10**。③暂缓不影响估算主体——其成本随①②落实自动下降；⑥使每次交接的常驻开销有硬上限（≤30 行 + 首读后 compact）。

## 6. handoff 交接提示词模板（措施⑥落地）

背景：用户追问「handoff 交接是否也推高新会话 token」。实测本段会话 handoff 4.5KB ≈ 2000 tokens，常驻 153 轮仅约 30 万（小头）；**大头是触发效应**——handoff 引导新会话连锁首读+探索，其输出全部常驻重发（可达数百万）。故交接优化的核心是：指针化、限读、首读后 compact。

### 6.1 调用 handoff 技能时的附加指令

本仓 handoff 技能（`.claude/skills/handoff/SKILL.md`）已含「路径引用、不重复 artifacts、删敏感信息」，调用 `/handoff` 时再附以下约束：

```text
并附加约束：
- 五要素：任务一句话 / 首读白名单 / 纪律红线 / 验收命令 / 回执方式
- 禁止粘贴任何文件内容原文，一律用路径引用
- 首读白名单 ≤2 个文件，并注明「其余用到再读」
- 全文 ≤30 行
```

### 6.2 交接文档结构模板

```markdown
# HANDOFF — <角色/主题>（<日期>）

## 任务
<一句话：完成什么 + 验收标准>

## 首读白名单（仅读以下，其余用到再读）
1. docs/handoff/STATE.md — 活动区最新 3 条 S#
2. <任务直接相关的文件路径>

## 纪律红线
- <如：不 push；diff 域约束；AOCI 禁令>

## 验收命令（完成时执行并回贴输出）
<命令 1>
<命令 2>

## 回执
<如：STATE.md 追加 S# 条目，格式参照上一条>

## suggested skills
<需要则列出；无则省略>

<!-- 新会话：完成首读后立即 /compact，再开始任务 -->
```

### 6.3 五要素与根因的映射

| 要素 | 堵住的漏洞 |
|------|-----------|
| 路径指针不贴原文 | handoff 文本常驻每轮重发（§3.a 机制的小头） |
| 首读白名单 ≤2 | 首读链+探索常驻（§3.e，大头） |
| 验收命令前置 | 减少探索轮次 |
| 首读后 `/compact` | 一次性清掉 handoff+首读的常驻成本 |
| 全文 ≤30 行 | handoff 自身成本硬上限 |

## 7. 后续借鉴要点

1. 评估任何 agent 平台的 token 消耗，先看**每线程固定起步价**（工具定义注入 + 人设 + 仓库规则），再看**轮数乘数**（每轮全量重发），最后看单轮峰值。
2. **缓存命中 ≠ 省配额**：cached_input_tokens 仍计 rate limit，缓存优化不解决配额焦虑，只有减少总量才解决。
3. **subagent 拆单是乘数也是并行收益**：处置前先压缩主上下文（固定开销），再权衡，不要先牺牲并行。
4. **派单提示词自带精确验收命令与文件边界**，可显著减少探索轮次——探索输出的代价是常驻的。
5. **对无义务的 MCP server 应从 config 移除**：schema 注入是每线程固定成本，与是否调用无关。
6. **交接文档的代价不在文字本身，而在触发效应**（首读链+探索常驻重发）——交接要指针化、限读、首读后 compact；本段会话 handoff 实测 4.5KB≈2000 tokens，153 轮常驻仅约 30 万，而其触发的首读链可达数百万。

### 8.2 共享配置链的关键判断

项目 `.mcp.json` 只挂 aoci 一个 server，同时喂 Trae 线与 Claude 线（本项目所有会话）。守护线运行环境决定它能否动：

- **若守护线跑在本项目**（Claude Code 或 Trae 会话）：`.mcp.json` 必须保留，Trae 线改用 Trae MCP 面板单独禁用（IDE 内按 server 开关，不影响其他线）。
- **若守护线只用 CLI**（`D:\aoci\aoci.exe` 子命令；`settings.local.json` 的 allow 白名单存在 `Bash(/d/aoci/aoci.exe *)` 直接调用痕迹）：`.mcp.json` 可整体移除 aoci，三线全部零注入，守护线走 CLI。

**待用户拍板**：守护线跑在哪个环境 / 是否只用 CLI。拍板前 `.mcp.json` 与 `settings.local.json` 不动。
