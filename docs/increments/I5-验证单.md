## 4. 执行期间问题与修复

| 问题 | 根因 | 修复 |
|---|---|---|
| tmp_flag 语义缺陷（产品级，门 #10 首测 tmp_flag=0） | `lineage.py _collect` 落库 `tmp_flag=to_tmp` 只认**目标侧**映射；门 #10 场景 C22 临时表在**来源侧**（from=注册名），标记被丢弃。模型注释「目标为临时…」为实现期口径偏差，设计 §9 门 #10 口径为「血缘显示注册名 raw_txt（tmp_flag=1）」 | 修复为 `from_reg, from_tmp = _map_table(...)` 并落库 `tmp_flag=to_tmp or from_tmp`（任一侧映射为注册名即 1）；models.py 与 03_meta_i5.sql 注释同步改「边涉及临时注册名」；闭环：py_compile/ruff → docker cp 热修三容器复测（tmp_flag=1）→ 重打增量 tgz 走 deploy 通道 rebuild 固化 → 固化后回归复现 ✅；历史实例行（20260919011626-16-f5c3，tmp_flag=0）按实例维度追溯口径不回改 |
| 门 #8 首轮 0 边（测试构造错，非代码缺陷） | 测试 SQL `INSERT INTO dwd_i5_order_wide SELECT id, order_no, username, amount ... FROM ods_order` 两处不合法：username 属 dim_user 非 ods_order（1054 Unknown column）、目标列实为 net_amount；首语句即失败 → executed=[] → 0 边（旁路代码行为正确） | 重测照抄 test1 合法 JOIN 语句作首语句 + 语法错次语句 → §3 #8 结果全对；任务日志为裁决证据（此前 `/datara/logs/*.log` 通配 grep 不中系日志实际落 `{log_dir}/{instance_id}/{task_id}.log` 子目录分层） |
| i5_check1.sh 任务行查询空（排查期顺带修正） | 查询列 `node_name` 不存在（t_task_instance 列名为 `name`），`2>/dev/null` 吞掉 MySQL 报错 | 脚本修正为 `SELECT node_id, name, state, attempt` |
