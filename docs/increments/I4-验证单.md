## 4. 执行期间问题与修复（实测暴露，6 项）

| 问题 | 根因 | 修复 |
|---|---|---|
| seed 乱码重复条目（首查列表 id=5/6，name 为 UTF-8 双重编码乱码） | 历史某次数据写入通道编码事故（非 I4 代码路径；I3 项 13 幂等重装后计数对，疑似更早手工导入残留） | API DELETE 清理 2 条脏数据；类型框架层 _DS_TYPES 白名单不受影响，留痕备查 |
| master 派发链不含新 worker 类型（i4-7 走查发现） | engine.py `_execute_node` 白名单 tuple、`check_timeouts`/`_resume_sweep` 的 worker_types 三处各自硬编码，未含 procedure/http/file | 三处收敛为模块常量 `WORKER_TYPES = ("sql","shell","python","ssh","smoke","procedure","http","file")`，杜绝后续扩容漏改 |
| C16 successCodes 表单字符串陷阱（i4-7 走查发现） | 表单存 "2xx,200" 字符串时 `_ok_code` for 循环按单字符遍历 | http.py 入口加 str 分支：按逗号 split 去空 → 规则列表 |
| 数据源删除 409 防护失效（§3 #1 首测 id=3 被删成功） | `_REF_RE` 按「params key/value 行」形态写正则，实际 graph_json 节点 data 是对象属性形态（`"datasource":"<name>"`），匹配数恒 0 | datasource.py 正则改为属性形态 `"(?:datasource|targetDs)"\s*:\s*"([^"]*)"` + 数字 id 形态 `_REF_ID_RE`；1.9 rebuild 后复测 3 例 409 拦截 + 1 例无引用放行 |
| ${tmp.*} 替换为裸表名 SQL 1064（§3 #10 首测） | 临时表名 `{instance_id}_{node_id}_{name}` 数字开头且含连字符，FROM 裸标识符不合法（建表侧有反引号，引用侧替换无） | variables.py `_resolve_tmp`：kind=table/resultset 的 ref 反引号包裹（kind=file 为路径不包）；1.9 rebuild 重跑后 down_cnt=5000 命中 |
| /echo 测试端点缺失（§3 #13 依赖，设计 §6.2 要求） | i4-3 未含此路由 | health.py 补 `@router.api_route("/echo", methods=[GET,POST,PUT,DELETE])`：回显 method/headers/body + 固定嵌套结构（items/nested）供点路径提取断言；免鉴权（对齐 /health 无 Depends 口径）；rebuild 后实测提取命中 |
