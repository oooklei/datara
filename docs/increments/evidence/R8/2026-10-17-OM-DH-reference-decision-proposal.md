# R8 OpenMetadata / DataHub 参照选择决策提案（待会签）

- 日期：2026-10-17
- 状态：**提案草稿，待用户/会签方裁定；不构成批准，不改变任何正式规范、契约冻结或 GREEN 状态。**
- 证据范围：仅依据《2026-10-17-R8批次三组件源码锚点对照表》§1–§5、《2026-10-17-R8-A八工具契约》v1，以及《2026-10-17-核心业务功能实现规范与验收标准》S5、§4 R8 清单与 §5 修订治理；未在本提案中新增源码研读结论。

## 1. 建议裁定

建议将 **OpenMetadata（OM）作为元数据目录与实体 REST 交互的主要参照**，将 **DataHub（DH）的 aspect/关系建模作为表级与列级血缘表达的补充参照**，并将 **Vanna 的工具调用、检索、SQL 生成与执行分离、自校验回环作为方法论参照**。三者均为设计和实现的语义参照，均不成为 Datara Backend 的运行时依赖或执行真源。

这是一项面向后续 R8/A5 的决策提案。落地范围仍受标准稿 S5、R8-A v1 冻结契约和 Datara 自有权限、审计及执行边界约束；若需改变冻结字段或语义，须另走标准 §5 和冻结宣言规定的变更流程。

## 3. Datara 必须保留的所有权与控制边界

1. **实体和状态真源归 Datara。** `data_asset`、`metadata`、`lineage`、`quality`、`standard`、`security`、`semantic` 及工作流/运行状态继续由 Datara 新 Backend 管理。OM/DH 可作为可选的导入来源或上下文投影，不能成为写入真源、工作流状态真源或运行状态真源。
2. **租户/项目隔离由 Datara 强制。** 每次工具调用按 R8-A 权限上下文核验 `user_id`、角色、`project_id` 与已授予权限；外部 OM/DH 的实体 ID 或 URN 不能替代 Datara 项目归属校验。跨项目读取必须由 Datara 权限策略明确允许并审计，不能由外部目录可见性推定授权。
3. **执行授权由 Datara Backend 决定。** AI/Agent 只能请求 R8-A 注册的工具；权限检查、预算限制、统一错误映射和审计由信封层执行。`run_sql` 复用 R5-A 既有执行 API/共享执行引擎，不能绕开授权、审计或另建执行引擎。来自 OM/DH/Vanna 的建议或元数据不能自动触发 SQL、工作流或写操作。
4. **审计由 Datara 负责。** R8-A 要求成功、失败调用都形成带调用者/角色/项目/参数快照/结果/耗时及关联实体的审计记录。外部系统自身审计不能替代 Datara 审计；外部调用若未来纳入，应形成可关联的 Datara 审计记录。
5. **外部依赖可选且隔离故障。** 不要求 Datara Backend 部署 OM、DH 或 Vanna；若未来配置外部导入/投影，应作为有边界的可选适配能力，断连不能把外部系统提升为执行关键路径或破坏 Datara 本地真源。具体降级、重试、数据保留策略仍需单独设计。

## 4. 接受、拒绝、暂缓事项及其影响

| 处理项 | 提案结论 | 若采纳/拒绝/暂缓的影响 |
|---|---|---|
| OM 作为目录实体与 REST 交互主参照 | **建议采纳，待批准** | 采纳：后续目录/搜索/实体详情适配优先对照 OM 实体与 REST 语义，减少契约转译。拒绝：需指定另一主参照并解释如何覆盖现有 REST 证据和 Datara 的契约节奏，否则 R8/A5 的参照选择仍未闭环。暂缓：继续按 Datara 已冻结契约实施，不得宣称主参照已定，相关功能验收要登记未决依赖。 |
| DH aspect/关系模型用于表级、列级血缘表达 | **建议有界采纳，待批准** | 采纳：只将 `fineGrainedLineages`、上游/下游关系与输入校验作为血缘语义参考；仍以 Datara `lineage` 模型及项目权限为准。拒绝：必须提供达到标准 S5/设计所需列级血缘能力的替代语义依据。暂缓：不影响 R8-A 当前 `get_lineage` 查询契约，但不得宣称已完成细粒度血缘参照决策。 |
| Vanna 工具调用方法论 | **建议采纳，受限于 R8-A** | 采纳：借鉴检索上下文、生成/校验/执行分离和错误反馈回环；依 R8-A 注册表、统一端点及既有域服务实现。拒绝：需要另行说明如何满足 S5 的 Vanna 思想要求。暂缓：AI 助手仍必须满足已冻结 R8-A 工具契约，不能因此推迟工具契约或改变其状态。 |
| OM/DH/Vanna 成为 Backend 必需运行时依赖或执行真源 | **建议拒绝** | 接受将引入多套状态/权限/审计来源和外部故障依赖，冲突于核心设计中 Datara 自有治理与运行真源、单一工具执行链路及“外部目录仅作可选投影”的边界。拒绝不影响其作为源码/语义参照或可选适配目标。 |
| 外部实体标识直接代表 Datara 权限或项目成员关系 | **建议拒绝** | 会使外部可见性越权替代 Datara RBAC 与项目隔离。拒绝后由 Datara 在本地实体与外部来源标识间维护经授权的映射；若需跨系统身份映射，须另有明确的绑定、冲突、撤权和审计方案。 |
| 扩展或改动 R8-A v1 八工具字段、权限/审计语义 | **暂缓，另走正式再冻结** | 本提案本身不授权改契约。确有必要时先形成字段级差异、兼容与迁移方案，再按标准 §5/冻结宣言申请新版本和双边会签；未完成前保持 v1。 |
| OM/DH 导入、投影同步、数据冲突、跨项目映射和故障降级的具体机制 | **暂缓到独立设计** | 现有锚点与契约能支持参照选择，不能证明完整同步语义。暂缓可避免从参照模型推断 Datara 数据所有权、覆盖规则或一致性策略；相应能力不得标为已实现或 GREEN。 |

## 5. 与 R8-A 的兼容约束

- 八工具边界维持原样：`search_schema`、`validate_sql`、`run_sql`、`get_workflow`、`validate_workflow`、`inspect_workflow_run`、`get_task_metrics`、`get_lineage`。
- `search_schema` 继续使用 Datara R5-A 元数据目录；R8-A v1 返回 `TABLE|VIEW` 的既有形状不因 OM Schema 中的其他对象概念而扩张。SQL IDE 对存储过程/函数等对象的能力属于 R5-IDE 的独立范围，若需进入 AI 检索契约必须另提变更。
- `get_lineage` 查询 Datara 血缘存储；DH 的细粒度 aspect 只用于评估血缘关系表达，不能将外部 URN 暴露为未经映射/授权的 Datara 实体。
- `project_id`、权限上下文、审计字段、错误码、超时/重试/预算仍按冻结 v1。外部来源失败应按契约允许的错误语义处理；具体适配器故障分类在实施设计中给出，不在此处擅自增加错误码。
- Vanna 的聊天通道不自动改变 R8-B 交互方案，也不证明需复制其旧 API；本次采用的是方法论而非 HTTP 外形。
