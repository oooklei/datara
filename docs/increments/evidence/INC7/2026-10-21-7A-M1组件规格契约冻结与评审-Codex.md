## 2. HTTP 契约

### 2.1 请求

```http
GET /api/v1/rebuild/components/spec HTTP/1.1
Authorization: Bearer <token>
If-None-Match: "<sha256>"   # 可选
```

- 无 query/body；不得接受 projectId 来改变发布清单。
- 该清单是全局已发布目录，调用者必须是有效登录主体；读取不要求项目成员权限。
- 认证复用 rebuild 装配层 `TokenService.verify` 与 active-token 检查，不自建 token 解析。

### 2.2 200

```json
{
  "items": [
    {
      "type": "SQL",
      "publishedVersion": 3,
      "identity": {},
      "description": {},
      "inputs": [],
      "outputs": [],
      "visual": {},
      "behaviors": null,
      "dropPolicy": null,
      "extensions": null,
      "specVersion": null,
      "ports": null
    }
  ]
}
```

- 上例只说明外层与既有八要素兼容骨架，不替代 7C 对八段 DSL、白名单和发布闸门的冻结。
- 只返回组件主表 `state=published` 且版本表精确匹配 `published_version`、版本行也为 published 的记录。
- 未发布、版本不匹配和无有效发布版本的组件不下发。
- 清单按稳定主键升序；序列化使用固定字段顺序、UTF-8 和确定性 JSON 参数。
- ETag 是**强验证器**，格式为带双引号的完整 SHA-256 十六进制摘要：`"<64 hex>"`。哈希输入必须是实际发送的响应 body 字节，不得先算一份再由框架二次序列化另一份。
- 响应不得加入时间戳、requestId 等逐请求变化字段。

### 2.3 304

- `If-None-Match` 与当前强 ETag 精确匹配时返回 304。
- body 长度为 0，不得返回 JSON、`null`、空对象或通用信封。
- 回传当前 `ETag`；不得产生新的清单查询结果形态。

### 2.4 错误

| 场景 | HTTP | body | 缓存约束 |
|---|---:|---|---|
| token 缺失、失效或已撤销 | 401 | 既有 rebuild 错误信封 `{code,msg,data}` | 不返回 ETag，不可把错误缓存为 spec |
| 发布数据 JSON 损坏、版本不一致或转换失败 | 500 | 稳定错误信封，`data` 不泄露数据库内容 | 不得降级为 200 空清单 |
| 数据库/服务不可用 | 5xx | 稳定错误信封 | 客户端可保留最后成功响应；首次失败必须阻断 |

裸 JSON 例外只覆盖成功清单和 304。错误继续使用既有错误信封，便于统一身份和错误处理，但不得走成功响应解包逻辑。

## 3. 数据读取与适配边界

### 3.1 冻结的数据路径

```text
component_spec router
  -> read-only service
  -> read-only repository/adapter
  -> Component + ComponentVersion published 精确 join
  -> deterministic serializer
  -> SHA-256(body bytes) + Response
```

选择**复用旧治理表并建立新域只读 repository/adapter**：

1. 现有 `Component`/`ComponentVersion` 已提供发布状态与精确版本关系，没有建第二套发布表的证据；
2. 新域不得 import 旧 `api.component_spec.router`，也不得在 app 中挂载旧 router；
3. 可以迁移 `_spec_item` 的纯映射语义，但应放入新域 mapper/service，并按 COPY_LEDGER 登记复制或改写程度；
4. `common/dag_catalog.json` 只可作为基线导入或对照证据，运行时响应不得直接读它；
5. 坏 JSON 或无效发布记录快速失败，禁止伪造空 `items`。

### 3.2 认证与权限

- router 注入现有 `token_service` 与 `active_tokens`，验证 Bearer token 或现有兼容 token header。
- 端点返回全局已发布规格，不接收 projectId，也不调用项目权限映射。
- 匿名请求与撤销 token 返回既有 401 错误；认证失败前不得读取发布表。
- 本端点为只读；发布、下线、改版本均不在 7B 范围。

## 4. 零私设 degraded 状态机

| 当前缓存 | 请求结果 | 客户端允许行为 |
|---|---|---|
| 无 | 200 | 保存 body+ETag，渲染清单 |
| 无 | 304 | 契约错误；没有可复用实体，阻断并重试 |
| 无 | 401/5xx/超时 | 阻断 palette，展示可重试错误 |
| 有最后成功响应 | 200 | 原子替换 body+ETag |
| 有最后成功响应 | 304 | 继续使用缓存并刷新校验时间 |
| 有最后成功响应 | 401/5xx/超时 | 保留最后成功响应并显式标陈旧；允许重试 |

任何状态都禁止从静态 profile、硬编码组件列表或 `dag_catalog.json` 补回缺失组件。未知 `{type,version}` 必须显示规格不可用，禁止静默替换为同 type 最新版。
