## 2. 权威证据与分类结论

### 2.1 reroute：保留候追认（1 项）

`reroute` 没有 I0~I11、会议纪要或权威设计组件编号，但不是无实现占位：`master/dag.py:16-68` 会在执行前消除该节点并桥接所有前后边，旧编辑器也有明确节点定义。它是编辑结构，不是运行任务。

建议监督线追认为“编辑器结构节点”，补一条权威登记。未经追认前不得把它作为普通无出处运行组件直接删除，否则历史画布的折线路由可能丢失。

### 2.2 旧 ETL palette：建议移出白名单（17 项）

权威设计 §5A.2 明确删除 ETL 工作流分类，并把存量 ETL 标签降级为普通工作流；§5A.3 要求无出处组件经裁定从后端 spec 移除。会议决策记录 `[09-18]` 更明确推翻早期“算子 UI 保留”，要求删除 ETL 算子组件与实现，以 SQL/脚本节点承载业务逻辑。

这 17 项仍存在于旧 catalog 与 worker 注册表，属于历史实现被后续裁定覆盖。建议结论为“移出白名单”，但执行前必须取得现网 published 与 workflow `componentRef` 只读快照；只有零引用或历史图迁移方案闭合后，才能另立执行票删除 spec、palette 和注册项。

### 2.3 旧 stream palette：建议由正式组件替代（10 项）

这组只有 Flink 风格来源，当前权威体系已用 C18/C19/C20 与 `page_board` 承载流输入、融合、输出和展示。旧 `s_* / p_* / o_* / op_*` 没有逐项映射，不能因“概念相似”自动获得权威出处。

建议先产出旧 type 到 C18/C19/C20 的迁移映射，再基于现网引用迁移历史图；映射和引用未闭合前不直接删除。`op_script` 的全局 type 冲突单列第二票处理。

### 2.4 topo 设备：移出 DAG 治理范围（13 项）

这 13 项均为 `profile=topo`、`dagRelevant=false`、`nonExecutable`，服务拓扑展示，不产生 DAG 任务实例。它们缺少 DAG 组件出处是分类边界问题，不等于拓扑产品应被删除。

建议保留于拓扑专属注册表，并从 DAG component-spec 白名单、无出处删除统计和发布裁定中剥离。
