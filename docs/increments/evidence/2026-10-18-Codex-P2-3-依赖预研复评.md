## 2. 逐段评审意见

### 2.1 §2-§3：依赖判定 — FAIL

1. **#21 `getDefinition` 的依赖组件写错。** P2-3 §2 第 17 行、§3 第 27 行将其依赖写为 `SqlExecutionPort` 只读连接。A5 v1.0 §1 第 12 行、§3 #18/#21（契约文件第 12、55、58 行）规定它复用 R5-A shared `getDefinition`/source reader，按完整 ObjectRef、capability 和 `sourceVersion` 返回只读对象定义；它不是 SQL 查询执行端口。建议改为“依赖 R5-A #18 source-reader/对象定义读取能力；同一 wire route，无独立副本”。

2. **#22 `ddl_policy.py` 只能标作局部策略扫描器，不能标“可直接复用”或等价于已交付 `validatePolicy`。** 当前 `evaluate_ddl_policy` 是纯本地检查，不连接数据库；代码明确返回 `dependency_analysis_unavailable` 与 `syntax_validation_unavailable` 警告，并指出无法验证目标身份。A5 v1.0 §3 #22 还要求 project/ObjectRef/sourceVersion/next-DDL digest 绑定的 policy snapshot、稳定 `snapshotId`、block 阻止 confirm、版本漂移 409。应改为“局部 tokenizer/policy 逻辑可复用；适配与持久快照、版本绑定及生产验收仍缺”。17 项测试仅证明当前函数断言，不证明完整 facade。

3. **#23 `DatasourceEngineRegistry` 不等于元数据目录或血缘服务。** P2-3 §2 第 19 行、§3 第 36-38 行称已有元数据目录；当前仓库的 `DatasourceEngineRegistry`（`datara-backend/rebuild/datasource/pool.py`）是按 project/datasource 缓存连接引擎的连接池注册表，仅支持 MySQL/PostgreSQL profile，不枚举对象依赖或下游血缘。A5 v1.0 §3 #23 要求只读返回依赖视图/例程/下游血缘/权限范围影响，无法证明时明确 `unknown`，并与同一 policy snapshot digest 绑定。建议列为“连接能力可复用；目录/血缘采集、unknown 语义与影响快照均待实现/验收”。

4. **#25 `SqlIdeAuditRecord` 不是已证明的 R5-B DDL 执行记录存储。** 当前模型 (`datara-backend/rebuild/sql_ide/audit.py`) 记录 SQL IDE query execution 的 actor/project/datasource/task、SQL digest、状态和耗时；`DbBackedAuditWriter` 对同一条记录执行 start/end 更新。它不证明 DDL `recordId` 生命周期、定义变更 action、对象、脚本 hash、人工确认、补偿/rollback 记录或 append-only 保留。A5 v1.0 §3 #25 与 §5 要求 DDL 操作者、目标对象、脚本 hash、时间、状态/失败摘要，审计至少 365 日且不随历史清理级联。应将其标为“可参考字段/平台 DB seam；R5-B DDL record schema/API/保留策略未交付”，不能写“可直接复用”。

5. **实现状态断言过期/越界。** P2-3 §3 第 28、32 行写“Gap 1+2 已交付”“Gap 3 已交付”，但监督线 #283 已按 Codex #280 复核正式记录 Track A 实施验收 FAIL，待 schema migration、真实 `create_app` 装配、数据库集成及 A3 证据。P2-3 必须区分“代码对象存在”“局部测试通过”“生产 factory/数据库集成验收通过”三态；当前 R5-A 整体不得称 GREEN，且不能把 #21/#22/#25 标为“P2-2 GREEN 后立即可用”而不加条件。

### 2.2 §4：G-B1~G-B7 缺口清单 — FAIL，方向部分正确

- **认可并保留**：G-B1 DDL 执行器、G-B2 补偿/回滚、G-B3 人工确认校验、G-B4 依赖/血缘服务、G-B6 policy snapshot、G-B7 impact snapshot 均与 A5 #22-#24 的责任边界大致一致。
- **G-B5 必须重写**：不要把已有 R5-A `SqlIdeAuditRecord` 写成 R5-B 执行记录依赖已经解决。改为明确新增/扩展 DDL execution record 的 schema、repository、分页 facade、事件状态和独立保留/审计路径；与 query audit 关联即可，不得让 R5-B 写入覆盖 query audit 或被历史级联删除。
- **至少补充两类缺口**：
  - `G-B8`：project/user/datasource/ObjectRef 逐请求授权、跨项目隐藏 404、项目内权限 403；完整 ObjectRef 和 `sourceVersion`/ETag 在 policy→impact→confirm 全链路 CAS，版本漂移 409。
  - `G-B9`：执行前原定义快照/备份、策略和影响 snapshot ID/digest 绑定同一对象/版本/DDL 文本、用户原样确认短语、执行结果 recordId/status 与失败补偿闭环；确认短语不得由 Agent 或后端静默代填。
- 缺口条目应至少包含：契约锚点、现状证据、待实现行为、验收证据/测试场景、优先级和解除条件。现表只有描述和组件名，无法判断修复是否闭环。

### 2.3 §5-§6：开工路径 — FAIL，建议修订成分层并行路线

1. **保留 P2-2 生产验收作为接线前置，但不要阻止 R5-B 设计。** R5-B 的 shared definition、政策输入、影响快照与持久记录依赖 R5-A 的生产权限/对象读取/持久化 seam；所以在这些 seam 未验收前，不得把相关生产 facade 标 GREEN。监督线 #283 已明确 Track A 实施验收 FAIL。另一方面，A5 v1.0 已冻结（handoff #283）；契约与设计深化可以并行，不必等 P2-2 GREEN 才开始写设计。

2. **删除 P2-1 GREEN 作为 R5-B 全部开工的硬前置。** P2-3 §5 第 60 行列的 P2-1 retry/failover/backfill/priority 与 A5 #21-#25 的 SQL IDE 对象定义编辑/人工确认/DDL 执行闭环没有直接依赖映射。若未来某项 R5-B 操作被明确编排成 DAG task，可把相应调度能力列为该集成场景的条件依赖；在未给出契约锚点前不得作为 R5-B facade 的整体阻断项。

3. **建议将路径改为可验证阶段**：
   - 阶段 A（现在可并行）：修订 P2-3 依赖矩阵，冻结 R5-B 子设计/record 状态机/安全边界；P2-2 仍标 RED，不冒称 seam 可生产使用。
   - 阶段 B（P2-2 对应 seam PASS 后）：接 `getDefinition` shared read、对象/项目 ACL 和 sourceVersion CAS；接 policy/impact snapshots；新增 DDL 专用 records。
   - 阶段 C（独立人工闸与生产证据具备后）：实现 confirm phrase 与 DDL executor、前像备份、补偿/回滚；逐项跑成功/失败/权限/漂移/回滚集成场景并按 A1-A7 交 JSON+PNG remote-final 配对证据。
   - 阶段 D：只在所有 R5-B 方法逐项满足 A5 与标准 v4 后声明 R5-B GREEN；P2-2 GREEN 和 R5-B GREEN 各自独立记录，不以一方替另一方背书。

4. **§6 结论应改为条件性。** 删除“#21/#22/#25 可直接复用 P2-2 已交付组件”；替换为“有可复用 seam/局部逻辑，但未证明完整生产能力；共享读取、policy/impact snapshot、DDL records 需逐项满足 A5”。“P2-2 GREEN 是 R5-B 开工前置”应收窄为“生产集成所依赖的 P2-2 seam 验收是该 seam 的前置；R5-B 设计与不依赖该 seam 的实现准备可并行”。

## 3. 需要澄清的边界

1. R5-B 未来是否会将 DDL 发布建模为 DAG task？若是，仅调度集成部分另列 P2-1 依赖；否则删除 P2-1 总体前置。
2. `SqlIdeAuditRecord` 是否要扩展承载 DDL 发布记录，还是新建独立 `SqlIdeDdlExecutionRecord`？A5 要求记录不可被 history 清理级联删除；需由实施设计明确迁移和保留策略。
3. P2-3 §5 所称“P2-1 冻结生效”是否有此 R5-B 任务的权威条款链接？当前 A5 v1.0 与 P2-2 R5-A 设计未找到该依赖依据。
