### 1.3 唯一载体适配（resourceApi.ts）

`uploadResource` 真实 multipart 实现由 `FormData.append('file', blob, filename)` 改为直接构造 `File([bytes], filename)`：

- **起因**：`datara-web/vitest.config.ts` 为 `environment: 'node'`（Node 原生 FormData 采纳 filename 实参）；`datara-newweb/vitest.config.ts` 按方案 §2.2 #18 为 `environment: 'happy-dom'`，实测 happy-dom 20.14.6 的 `FormData.append(name, blob, filename)` **不采纳** filename 实参（返回 `File.name === 'blob'`）。
- **处置**：`base64ToBlob(base64): Blob` → `base64ToFile(base64, filename): File`，`new File([bytes], filename)` 在**浏览器 / Node / happy-dom 三载体一致**保留文件名。
- **改动面**：`diff --strip-trailing-cr` 实证**仅 3 hunk**（函数签名+体重命名 / `new Blob`→`new File` / `form.append` 调用点），契约面（方法签名、端点、multipart 语义、`Content-Type` 不手工设置）零变更。
- **实证**：`node -e` 直测 happy-dom 三方案——`A1 blob+filename → blob`（复现缺陷）、`A2 File(name) → etl.sql`（修复）、`A3 File+filename → other.sql`。
- **契约面无变更**：方法签名、端点 `/api/v1/rebuild/resources/uploads`、multipart 语义、`Content-Type` 不手工设置（浏览器自动带 boundary）均不变；`resourceApi.contract.test.ts` 11 passed。

### 2.1 adapterKit 共享机械原语（六类，零改写迁移）

| 类别 | 导出 | 契约语义 |
|---|---|---|
| 包络类型 | `ApiEnvelope` | 后端成功包络 `{code?, msg?, data?}` |
| 包络解包 | `unwrapEnvelope` | **三态冻结**：`code === 0/200/undefined` → `resolve(data)`；`code ≠ 0/200` → `throw ContractApiError`；非 2xx → 调用方解包前抛错 |
| 归一失败标记 | `ID_NORMALIZATION_FAILED` | id 归一失败哨兵 |
| 错误类型 | `ContractApiErrorInit` / `ContractApiError` | 归一错误（`httpStatus` / `code` / `msg` / `raw?`） |
| 命名映射 | `snakeToCamelKey` / `camelToSnakeKey` / `snakeToCamel` / `camelToSnake` | 深度 key 双向映射 |
| id 归一 | `wireIdToNumber` / `numberToWireId` / `wireIdToString` | wire（number\|string）↔ FE（number\|string）归一 |

- **共享实测**：`variableApi` / `dependencyApi` / `resourceApi` / `metricsApi` / `streamApi` / `__tests__/mockAgent` 六处 import `adapterKit`；`adapterKit.test.ts` 52 passed。
- **包络一致性**：10 域 GREEN 契约统一 `{code,msg,data}` 三态；RED 契约（`sqlIdeDdlApi` / `scheduleApi`）保留 `*_NOT_WIRED` 活哨兵，接线时沿用 `unwrapEnvelope`。
