## 三、表达式索引反射判重潜伏缺陷（实证）

### 3.1 缺陷源：`rebuild/llm/models.py:38-45`

```python
# False rows map to NULL, so the unique expression constrains only the single
# global default.  Building the index from the mapped column also binds it to
# the table for create_all/migration DDL.
Index(
    "uq_rebuild_llm_model_single_default",
    func.nullif(LlmModelRecord.is_default, False),   # ← 表达式索引
    unique=True,
)
```

这是一个**基于表达式的唯一索引**（`nullif(is_default, 0)`）。

### 3.2 反射侧：SQLAlchemy **跳过**表达式索引

```
$ python -c "... LlmModelRecord.__table__.create(e); inspect(e).get_indexes('rebuild_llm_model')"
SAWarning: Skipped unsupported reflection of expression-based index uq_rebuild_llm_model_single_default
indexes: []                       # ← 反射结果为空
unique_constraints: [{'name': None, 'column_names': ['name']}]
model index: uq_rebuild_llm_model_single_default | unique= True | columns= ('is_default',) | expressions= ['nullif(...)']
```

⇒ 反射侧 `get_indexes()` **返回空**（SQLAlchemy 对表达式索引抛 `SAWarning` 后跳过）；模型侧该索引 `columns=('is_default',)`、`unique=True`。

### 3.3 判重侧：`_compare_table` **误报 conflict**（实测）

`migration_preflight._compare_table:147-160`：

```python
for index in expected_table.indexes:
    expected_columns = tuple(column.name for column in index.columns)
    if not any(
        tuple(item.get("column_names") or ()) == expected_columns
        and bool(item.get("unique")) == bool(index.unique)
        and (not index.unique or _unique_index_is_full_column_index(item))
        for item in actual_indexes            # ← 空集（表达式索引被跳过）
    ):
        conflicts.append(f"{expected_table.name}: missing or incompatible index {index.name}")
```

实测：

```
$ python -c "... _compare_table(inspect(e), LlmModelRecord.__table__)"
llm table preflight conflicts:
  ['rebuild_llm_model: missing or incompatible index uq_rebuild_llm_model_single_default']
```

⇒ **确认误报**：反射侧因「跳过表达式索引」而为空，判重侧据 `columns` 匹配失败，**把已存在的表达式唯一索引判为「缺失/不兼容」**。

### 3.4 与 s325 所述吻合

s325「表达式索引反射判重缺陷」的描述与本节 3.1–3.3 逐环吻合。**缺陷真实存在**，只是**当前未触发**（见 §四）。

## 四、触发条件与风险

| 条件 | 现状 | 若成立 |
|---|---|---|
| llm 表纳入 `R3_GOVERNANCE_MIGRATIONS` 比较集 | **否**（该表仅经 `app.py:319` 的 `create_all` 建，未注册 governance 迁移） | `inspect_governance_schema` 将报 `rebuild_llm_model: missing or incompatible index` → preflight `ready=False` → 迁移门阻塞 |
| `Base.metadata.create_all(checkfirst=True)` 建 llm 表 | **是**（`app.py:287-330`） | **无影响**：`create_all` 对已存在表整体跳过，不逐索引比对；SQLite 建表达式索引 DDL 正常 |
| pytest `filterwarnings=error` 化 SAWarning | **否**（全库无 `filterwarnings`，conftest 无 warn 处理） | `SAWarning: Skipped unsupported reflection of expression-based index` 将被提升为错误 → 任何触发该反射的测试失败 |
| 换 MySQL 方言 | 本机 SQLite | MySQL 对表达式索引的反射行为不同，需在 1.9 定向复核 |

⇒ **当前潜伏**：llm 表未进 preflight 比较集，且无 warning-as-error，故全量 1F 不含此项。**风险点**：一旦 llm 域引入 preflight 校验（或做 1.9 MySQL 联调），此误报将阻塞迁移门。

## 五、建议（供监督线采纳）

1. **销 496F 记录**（不复现），或补明复现配置以便定向复核。
2. **修复表达式索引判重**（择一）：
   - a) `_compare_table` 对 `expected_table.indexes` 中含表达式的索引（`index.expressions` 非空）改用**按名匹配**或**跳过**，避免与反射空集比较；
   - b) 反射侧以 `get_indexes` + 方言特定表达式索引查询补齐；
   - c) 将该索引从 `__table_args__`/模块级 `Index` 改为**表内 UNIQUE 约束的等价形态**（若业务允许）。
3. **回归锚**：新增一例 `_compare_table` 对表达式唯一索引**不报 conflict** 的契约测试，锁死该行为（当前 `test_governance_preflight.py` 无表达式索引用例）。
