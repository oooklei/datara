### 1.2 六要点逐项拟案（草案 L432-439 原文逐条）

**要点① 路径冻结**——「新路由前缀是否统一为 `/api/v1/rebuild/...`？」
- 拟案：**统一 `/api/v1/rebuild/...`**（四分片按草案建议：`/api/v1/rebuild/models`、`/api/v1/rebuild/monitor`、`/api/v1/rebuild/runtime-nodes`、`/api/v1/rebuild/ssh-nodes`）。
- 理由：与 rebuild 既有域路由规则单一化一致，网关/代理契约一条规则覆盖；若四分片各自挂载反而引入多前缀运维债。

**要点② 信封兼容**——「新后端是否保持 `{code, msg, data}` 信封？」
- 拟案：**保持 `{code, msg, data}`**。
- 实锚：rebuild 既有 `datasource/metadata.py:205-206` 成功包络 `{code:0, msg:"success", data}`、错误 `JSONResponse(status_code, {code, msg, data:None})` 已是现行口径，四分片跟随即可。

**要点③ 错误码映射**——「旧 4xxx/8xxx 错误码是否原样保留或映射到新体系？」
- 拟案：**原样保留**（旧 4xxx/8xxx 语义与数值不映射不重编）；**吸收 R2 注记**：4101-4103 系旧侧硬编码业务码（实锚 `sshnode.py:55,74,76,102,105` 与 `runtime_node.py:91`），实施时**禁止从 `common/resp.py` 导入**（该文件 4xxx 段仅 4001-4006），须在域内显式定义并保留语义映射。
- 理由：映射重编会破坏 17.2~17.5 已登记的逐票验收锚（30 票票面错误码断言全部按旧码写成）。

**要点④ 鉴权换轨**——「旧 `get_current_user`/`require_perm` → 新 `TokenService`/`authorize` 的权限点映射」

## 三、增7-O1/O2/O3 随票注记裁定

按裁定登记 v3 补记定性「O1/O3 随票注记」；O2 无单独裁定记录，本拟案三项一并落裁（定义原文=`PRE/2026-10-20-增量7-组件spec治理与重点组件表单预研-Codex.md` §4.2）：

| # | 开放问题 | 拟案（采预研建议） | 理由 |
|---|---|---|---|
| O1 | M1 路径与承载域 | **独立承载域 `rebuild/component_spec/`**，路径 `GET /api/v1/rebuild/components/spec` | 并入业务域会造成职责与权限混乱 |
| O2 | degraded 与零私设冲突 | **新前端仅用最后成功响应**：degraded=继续使用内存/持久化的最后一次成功响应并明确陈旧状态；从未成功加载则阻断 palette 并允许重试；**静态 profile 兜底不进新前端正式链** | profile 兜底=重新引入前端组件真源，违背零私设口径 |
| O3 | 裸 JSON vs rebuild 包络 | **保留裸 JSON `{"items":[...]}`+强 ETag/304 空 body**，契约注册表标注例外 | 套包络若含动态字段破坏 ETag 字节稳定性；硬套通用 adapter 会误解 304 |
