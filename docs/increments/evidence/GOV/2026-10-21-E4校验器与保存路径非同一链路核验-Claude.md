## 一、结论（四条）

1. **§7.5 红线字面不成立**：契约要求「复用统一 `validate_graph` 校验链路（**与定义保存路径同校验器**）」，但**保存路径根本不存在 `validate_graph` 函数**——校验分散在 `upsert_draft_node` / `upsert_draft_edge` / `publish` **三处内联**。故「复用统一校验器」**当前不可实现**（无器可复用）。
2. **E4 是第二套实现**：`ai_tools.py` 模块私有 `_validate_graph()` 为**独立重写**，非保存路径同器 ⇒ 确属「非同一链路」，s345③ 判定**成立**。
3. **但无 false-accept 风险**：逐规则比对，E4 的**拒收**语义与保存路径**一致**（§五）；E4 甚至更严（多 `DUPLICATE_NODE_CODE` / `EMPTY_GRAPH`）。即**不存在「E4 判 valid 而保存路径拒收」的方向性缺口**。
4. **真实风险是「双轨漂移」+ 两处实质缺陷**：同一规则两套 code 词形；保存路径缺参即 **500**（非 4xx）；`valid` 聚合规则**契约未定义**、E4 自选「任一 issue 即 invalid」致 WARN 失效。

|---|---|

## 五、语义比对：拒收一致，无 false-accept

| 规则 | 保存路径 | E4 | 判定 |
|---|---|---|---|
| 空图 | `publish` → `WF_DRAFT_EMPTY`（硬拒） | `EMPTY_GRAPH`(WARN) 但 **`valid=false`** | **一致**（都拒） |
| node_type 非法 | `WF_NODE_TYPE_UNKNOWN`（硬拒） | `INVALID_NODE_TYPE`(ERROR) | **一致**，词形不同 |
| 边端点不存在 | `WF_EDGE_INVALID`（硬拒，2 处） | `EDGE_UNKNOWN_FROM/TO`(ERROR) | **一致**，词形不同 |
| node_code 缺失 | `node["node_code"]` 裸下标 → **KeyError** | `NODE_MISSING_CODE`(ERROR) | **E4 更稳**（见 §六.2） |
| 重复 node_code | **结构不可能**（upsert 以 node_code 为键） | `DUPLICATE_NODE_CODE`(ERROR) | E4 独有，针对 inline 图，**合理** |

**`valid` 聚合实证**（`ai_tools.py` E4 handler 尾部）：

```python
return {"valid": len(issues) == 0, "issues": issues}
```

⇒ **不分 severity，任一 issue 即 `valid=false`**。故 `EMPTY_GRAPH`(WARN) 亦致 invalid——与保存路径「空图硬拒」**语义巧合一致**。

⇒ **结论：E4 拒收 ⊇ 保存路径拒收，无「E4 判 valid 而系统拒收」的方向性缺口。**

## 六、两处实质缺陷

### 6.1 同规则两套 code 词形（保真缺口）

| 同一规则 | 保存路径 code | E4 code |
|---|---|---|
| 节点类型非法 | `WF_NODE_TYPE_UNKNOWN` | `INVALID_NODE_TYPE` |
| 边端点不存在 | `WF_EDGE_INVALID` | `EDGE_UNKNOWN_FROM` / `EDGE_UNKNOWN_TO` |
| 空图 | `WF_DRAFT_EMPTY` | `EMPTY_GRAPH` |

⇒ 调用方（AI 侧 / 前端 / 测试）**无法把 E4 的 issue.code 关联到保存路径的错误码**；两套词形各自演化即**语义漂移**。

### 6.2 保存路径缺参即 500（错误模型违规）

```python
# repository.py:172-174
node_code = str(node["node_code"]).strip()      # 裸下标
node_type = node["node_type"]                   # 裸下标
```

实测捕获面（三重否定，逐条 grep）：

| 检查 | 结果 |
|---|---|
| `grep -c "except WorkflowDomainError" rebuild/workflow/api.py` | **11**（:131/:168/:196/:220/:253/:278/:307/:333/:365/:385/:407） |
| `grep -c "except KeyError" rebuild/workflow/api.py` | **0** |
| `grep -c "except KeyError" rebuild/api/app.py` | **0** |
| `grep -n "middleware\|BaseHTTPMiddleware\|exception_handler\|@app.exception" rebuild/api/app.py` | **零命中**（无中间件、无全局异常处理器） |
| `grep -rn "except KeyError" rebuild/` | 仅 `sql_ide/error_catalog.py:51/:64`（**非本链路**） |

⇒ 客户端缺 `node_code`/`node_type` 时 KeyError **无任何捕获** → FastAPI 默认 → **HTTP 500**，违反契约 §7.5「INVALID_PARAMS（格式非法）」的 4xx 语义。

> **限定**：本条为静态推断（未实测 500）。`node` 为内联 dict，缺键即 KeyError；链路（repository → workflow/api → app）三层均无捕获，亦无中间件/全局处理器兜底。

### 6.3 `valid` 聚合规则契约未定义

契约 §7.5 定义 `severity: ERROR|WARN|INFO` 三级，但**未定义 `valid` 如何由 `issues` 聚合**。E4 自选 `len(issues)==0`（任一 issue 即 invalid）⇒ **WARN 失效**，与 severity 分级的直觉（WARN 不应致 invalid）相悖。

⇒ 若监督线本意为「无 ERROR 即 valid」，则 `EMPTY_GRAPH` 应降为 `INFO`。**需裁定**。

## 七、修复建议（供补课清单③定案，非本线动作）

| 项 | 动作 | 评价 |
|---|---|---|
| **③-a（推荐）** | **抽取共享校验器**：在 `rebuild/workflow/` 新增 `validate_graph(graph) -> list[issue]`（唯一校验源），保存路径 `upsert_draft_node`/`upsert_draft_edge`/`publish` 改为**委托**它，E4 改为**调用**它 | **真正闭合 §7.5 红线**（"与定义保存路径同校验器"）；消除双轨漂移；一处改、三处受益 |
| ③-b | 补 6.2：保存路径缺参改抛 `WorkflowDomainError("WF_NODE_FIELD_MISSING", …)`（4xx） | 顺带修复错误模型；若做 ③-a，可并入共享校验器统一返回 |
| ③-c | 裁定 6.3：明确 `valid` 聚合规则并写入 §7.5；据此定 `EMPTY_GRAPH` 的 severity | 契约消歧；**建议随 §7.4 契约修订同批报备**（与 E3 ④ 的 §7.4 报备合并） |
| — | ~~E4 直接复用保存路径某函数~~ | **不可行**：保存路径无校验函数（§三） |

**核心判断**：③ 的**字面**（"与保存路径同校验器"）**不可能通过「让 E4 去调一个已有函数」实现**——该函数不存在。故 ③ 的实质是**新建共享校验器并双向收编**，工作量与风险高于「复用」的字面预期，**排产时须按新建计**。
