## 二、「流表」语义考证（本次新增证据链，旧记录所无）

旧 13-05 按预研口径将「流表」定性为流处理引擎配套（DDL/物化/背压）。本次溯源「流表」一词的文档语义链，补充考证如下：

| 来源 | 「流表」出现情况 | 语义 |
|---|---|---|
| 原始重建设计 `docs/increments/archive/2026-10-20/2026-10-14-datara-platform-rebuild-design.md` | 全文仅 1 处（L867）「I8 新增流表时复用模板」 | **流运行时表**（=stream_job 等五张，§13.7）——已全部实现 |
| v1 `archive/2026-10-20/2026-10-16-纠偏重构方案设计.md` + 执行附录 | **零命中** | 词不存在 |
| v3 `2026-10-19-纠偏重构前端权威设计.md` | 4 处（L229/L555/L642/L864），全部为状态注记「流表新域未开工」 | 无定义、无验收标准；L229 将「实时流任务、流表」并列为流数据处理域语义对象，对标出处=I8 |
| 会议纪要（§5A.9 纪要⑦） | 仅要求实时生产观摩链路 | 无流表 |
| 用户裁定（2026-10-21 两批：数仓建模/访问审计/脱敏） | 无流表条目 | 无新语义输入 |
| 旧系统存量 | 旧后端 `api/streamjob.py`（流任务定义）+ `api/streamdata.py`（流任务实时数据，I8 F41）+ `worker/stream/`（流引擎）；旧前端 stream profile 画布仅暴露 C18~C20+C24（`datara-web/src/graph/profiles/stream.ts` L3-5 I11 收敛注记），「上游流表」仅为 dataScope 注释口语指代（L78） | 旧线无「流表」独立功能对象 |

**考证结论**：「流表」作为**独立功能对象**（流表 CRUD/注册/schema 管理，对标 Flink SQL 表管理一类）在全部权威文档链中**无需求出处**——原始设计无、v1 无、纪要无、用户裁定无；v3 状态注记是唯一载体且语义悬空。v3 §3.4 口径要求功能必须有对标出处，故「流表新域」按现状不满足立项前置条件。

## 三、13.3 处置结论（现行票）

延续旧 13-05 建议（本票复核未推翻任何前提），处置结论为 **b（登记阻塞）+ a（立项草案报批）并行**：

1. **b · 即期**：「流表新域」登记为阻塞域（无需求出处 + 无引擎承载），增量 13 观摩链路以 **simulate 源 + 指标透传闭环**收口（C18 七模式 → producer → 六表 → observe/metrics REST → 观测面），零依赖引擎；C19 节点在 13.2 验收中按旧 13-05 §3.3 行为锚（跳过执行+占位登记，不中断整流，负向断言入 Playwright 锚）。
2. **a · 中期**：流表新域建设（流表 DDL 与物化建模 → C19 算子执行引擎 → 背压观测指标扩充，三步拆解见旧 13-05 §3.4 立项草案）**候监督线/用户排期裁定**；本次语义考证（§二）追加立项前置条件：**需先由用户/监督线裁定「流表」的功能语义与需求出处**（对标何物、验收何标准），无此前置则 a 无从建模。
3. **建议 v3 注记刷新（候批，非本票动作）**：v3 L229/L555/L642/L864 四处「流表新域未开工」建议按裁定结果刷新（如「流表新域：无需求出处登记阻塞，候语义裁定（13.3 处置复核）」）；v3 契约刷新权在监督线，本票零触碰 v3。
