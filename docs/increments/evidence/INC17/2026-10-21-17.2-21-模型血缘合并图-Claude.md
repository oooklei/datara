## 三 ★候裁 ①/②：`t_lineage_edge` 的承载决策（本票核心）

rebuild 侧**原本没有** `t_lineage_edge`。A6 对照登记
（`2026-10-20-17.1-A6-数仓建模对照登记-Claude.md:80`）将本表登记为建模域关联表，
`:259` 明确写「`t_lineage_edge` 由运行时写入，**迁移时需决定沿用还是重建**」。

rebuild 侧现有的另一张表 `metrics/models.py:133` `lineage_writeback` 由 **C22 SYNC 执行器**写入，
项目作用域、列为 `source_entity`/`target_entity`、无 `tmp_flag`/`src_type`；
而旧侧 `t_lineage_edge` 由 **I5 SQL 血缘 worker** 写入（`common/sqlparser.py` 解析后回写），
实例作用域、含 `wf_code/instance_id/node_id/stmt_no/stmt/from_table/to_table/tmp_flag/src_type`。

**二者语义不同、不可替代**（形态同 17.2-17 的 `DataSourceRecord` 取舍）。
缺 `t_lineage_edge` 则 A6-21 的 runtime 半边「可声明不可执行」，违反域规范发布闸门。
故本票采取 **Shape A**：在 `rebuild/model/models.py` 新增 `LineageEdgeRecord`（逐列/默认值/
索引/唯一约束照抄 `common/models.py:460-493`），并纳入 `MODEL_TABLES`（8 → 9）。

- ★**候裁 ①**：rebuild 侧 `lineage_writeback` 是否应升级为/替换本表？（若裁定「沿用
  `lineage_writeback`」，则 runtime 半边需改写为项目作用域语义，与旧侧出参**不兼容**，
  须另行冻结契约面差异。）
- ★**候裁 ②**：后续 I5 血缘票若在共享 `rebuild.common.db.Base` 定义同名表，将触发
  `InvalidRequestError: Table 't_lineage_edge' is already defined`。届时由监督线裁定
  「全局血缘边表唯一归属域」；**本票不擅自合并两域**。

## 四 三处「照抄而非优化」

1. **`rel_type or ""` 的兜底分支经 DB 不可达**：旧侧 `common/models.py:839` 与 rebuild
   `models.py:152` 的 `rel_type` 同为 `String(8), default="1:N"` 且**不可空**。
   契约测试 `test_lineage_declared_rel_type_falls_back_to_empty_string` 双向验证：
   DB 层拒 NULL（NOT NULL 约束），服务层兜底分支以未落库实例验证为 `""`。
2. **`DwModel.id.in_(rel_ids)` 空集**：`rel_ids` 为空时 SQLAlchemy 产出 `IN ()`。
   旧侧同（无 `if rel_ids` 前置）。契约测试 `test_lineage_declared_empty_graph_is_model_only`
   覆盖该路径（无关系时 `name_by_id` 为空、不报错）。
3. **`impact` 为递归 DFS 而非旧侧 docstring 所称的 BFS**：旧侧 `:796` docstring 写
   「下游递归清单（声明血缘 BFS，环防护）」，但 `:805-815` 实现是**内嵌递归 DFS**。
   本票照抄实现（DFS），并在新侧 docstring 写明「DFS」以免误导；旧侧 docstring 的
   BFS 措辞属**旧侧笔误**，见候核 ③。

另：`impact` 的递归深度受 Python 栈上限约束（默认 1000）。旧侧同 → 未改动，见候核 ④。

  （无模型行 → 8001/404，证明命中本处理器而非被 `/models/{model_id}` 吞并）锁定可达性。

## 九 测试中的三处「被旧侧约束拦下」的修正（差分/约束的价值）

1. **`rel_type` NULL 用例无法经 DB 构造**：初版测试以 `r.rel_type = None` + `flush()`
   构造 NULL → 触发 `IntegrityError`。核对旧侧 `common/models.py:839` 确认该列**不可空**，
   兜底分支不可达。**测试改写为「双向验证」**（§四.1），把「不可达」本身变成被断言的事实。
2. **重复 `stmt_no` 撞唯一键**：去重用例初版写了两条 `(trade.orders, ext.src, stmt_no=1)`
   → 撞 `uk_lineage(wf_code, instance_id, node_id, stmt_no, from_table, to_table)`。
   旧侧写入同样会撞该键 → 测试数据改为 `stmt_no` 互异，**并把这个约束写进用例 docstring**。
3. **`.limit(200)` 后节点数不是 401**：封顶用例初版断言 `1 + 200 + 200` 个节点。
   实际 201 —— 因 200 条边的 `from` 端均为 `dbN.orders`，**归一化为模型节点**（不新增 ext），
   仅 `to` 端新增 200 个互异 ext 节点。修正断言为 `1 + 200` 并加注释说明归一化效应。
