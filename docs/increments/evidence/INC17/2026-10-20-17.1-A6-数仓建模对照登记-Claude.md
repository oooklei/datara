## 结论摘要

旧实现由 `datara-backend/api/model.py` 提供 22 条 API，统一挂在 `/api/v1` 下（模块 `APIRouter(tags=["model"])` 无前缀，应用装配 `/api/v1`）。数据真源为 `t_dw_model` 主表 + `t_dw_model_field`/`t_dw_model_relation`/`t_dw_model_version` 子表 + `t_dw_layer`/`t_biz_domain`/`t_engine_type` 字典表 + `t_lineage_edge` 运行时血缘表。功能覆盖：模型 CRUD、字段全量保存（乐观锁）、发布/修订/版本快照/回滚、ER 画布、DDL 预览/物理化、逆向工程（information_schema 内省 + DDL 文件导入）、血缘合并图与下游影响分析。

新后端 `datara-backend/rebuild/` 当前没有 `model/` 域、数仓建模 ORM、对应路由装配或等价端点。WBS 已明确由 17.2 新建 `rebuild/model/` 并联通 `/model/list` 页面。因此当前结论是"待迁移的真实缺口"，不能以旧 API 仍可用判作等价承接。

- `id`: Integer PK 自增
- `code`: String(64) unique，物理表名
- `name`: String(255) 中文名
- `layer`: String(16) → `t_dw_layer.code`
- `type`: String(16) 默认"明细表"（事实表/维度表/宽表/明细表）
- `biz_domain`: String(64) → `t_biz_domain.name`
- `engine`: String(64) → `t_engine_type.name`
- `ds_id`: Integer nullable → `t_data_source.id`
- `db_name`: String(64) nullable
- `security_level`: String(16) 默认"内部"
- `status`: String(16) 默认"draft"（draft→published→built→produced）
- `version`: Integer 默认 1（乐观锁基准）
- `er_pos`: JSON nullable，ER 画布坐标

- `built_at`: DateTime nullable
- `built_by`: String(64) nullable
- `owner`: String(64)
- `remark`: String(255)
- `create_time/update_time`: DateTime

**DwModelField（`t_dw_model_field`）**：
- `id`: Integer PK 自增

- `seq`: Integer 字段序（1 起）

- `nullable`: Boolean 默认 true
- `default_value`: String(255)
- `comment`: String(255)
- `is_pk/is_partition`: Boolean

**DwModelRelation（`t_dw_model_relation`）**：

- `id`: BigInteger PK 自增

## 五、迁移风险注记（承载域 17.2）

### 1. 新后端现状核查

- 对 `datara-backend/rebuild/**` 搜索 `model`、`dw_model`、`DwModel`、`数仓建模` 无命中（`rebuild/` 下无 `model/` 域）。
- `rebuild/api/app.py` 当前路由装配区无模型路由。
- WBS 将 17.2 明确为 `rebuild/model` + `/model/list` 页面联通闭环，实锚 `docs/increments/2026-10-20-单线多增量WBS开发计划.md:501`。

结论：不存在新后端等价实现，也没有代码级命名冲突。17.2 已冻结承载域名 `rebuild/model/`，除非 17.1 契约评审统一调整，否则不应另造 `dw_model` 或 `warehouse` 域。

### 2. 风险登记

| 风险 | 证据与影响 | 17.2 处置要求 |
|---|---|---|
| 状态机复杂度 | draft→published→built→produced 四态 + version 乐观锁 + redraft/rollback 版本回迁 | 重构需完整实现状态机语义；不能简化为 CRUD + status 字段 |
| 乐观锁冲突 | `save_fields` 使用 `rev` 乐观锁，冲突返回 422 + `data.currentRev` | 重构 repository 需保持 422 语义和 currentRev 回传 |
| 物理化执行安全 | exec 模式真实连接执行 DDL，白名单仅 CREATE，sqlglot 拆语句防注释内分号误拆 | 迁移时保持 CREATE 白名单 + 空语句列表拒绝；执行失败返回已执行条数 |
| 逆向工程内省 | information_schema 内省 + DDL 文件导入双路径，编码兜底（utf-8→gbk） | 需保持双路径；编码兜底逻辑不能丢失 |
| 血缘合并图 | 声明血缘（`t_dw_model_relation`）+ 运行时血缘（`t_lineage_edge`）合并，边端点归一化 | 重构需保持合并逻辑；`t_lineage_edge` 由运行时写入，迁移时需决定沿用还是重建 |
| 权限语义 | 写操作 `model:write`（admin/dev），读操作登录即可 | 映射到重构 identity 权限时需冻结具体权限点 |
| 静态路由优先 | `/models/er` 必须在 `/models/{model_id}` 之前注册 | 路由注册顺序不能颠倒 |
| 字段全量替换 | `save_fields` 是全量替换（先 delete 再 insert），非增量 | 保持全量替换语义；前端依赖此行为 |
| ER 画布桥接 | `erAdapter.ts` 以动作替换方式接入 GraphStore，不改共享基建 | 迁移时需决定新前端如何桥接；不能破坏 GraphWorkbench 共享基建 |
| DDL 方言 | 支持 mysql/greatdb/doris 三种引擎方言 | 重构需保持多方言支持；doris 仅物理化支持，逆向不支持 |
| API 路径/响应包差异 | 旧前端调用 `/api/v1/models...` 且期望旧 envelope；重构域通常挂 `/api/v1/rebuild/...` | 17.1 冻结最终路径和 envelope，17.2 必须同步新前端服务层；旧路径下线留给 17.6 |
| 跨包落地顺序 | 页面同时依赖 model、datasource（数据源选择） | 17.2 联通验收应以 datasource 已冻结契约为前提 |
| 版本快照存储 | `snapshot_json` 为 MEDIUMTEXT 全量 JSON，含主数据+字段+关系 | 重构需保持快照格式兼容或提供迁移路径 |
| 删除引用检查 | 删除前检查血缘引用（`DwModelRelation`），返回 `data.refs` | 保持引用检查；重构需返回相同结构 |
| 命名规范校验 | 编码正则 `^[a-z][a-z0-9_]*$` + 分层命名规范（`DwLayer.rule` 前缀匹配） | 保持校验逻辑；分层规则从字典表读取 |

### 3. 建议冻结的最小等价范围

17.2 至少应交付：
1. 数仓建模模型与持久化（`t_dw_model` + 子表 + 字典表）
2. 上述 22 条端点的等价能力
3. 重构鉴权与权限映射（`model:write` → 重构权限点）
4. 状态机完整语义（draft→published→built→produced + version 乐观锁）
5. 物理化执行（CREATE 白名单 + sqlglot 拆分 + 失败恢复）
6. 逆向工程双路径（information_schema 内省 + DDL 文件导入）
7. 血缘合并图（声明 + 运行时）
8. ER 画布桥接（`erAdapter` 等价物）
9. 前端 `/model/list` 页面联通闭环

### 4. 前端迁移影响

- `modelApi.ts` 的 22 个函数签名与后端契约一一对应，迁移时需保持函数签名不变或提供适配层
- `erAdapter.ts` 的 `installErAdapter`/`loadErIntoStore`/`saveErFromStore` 桥接逻辑需在新前端中重建
- 5 个页面（列表/设计/版本/血缘/ER）的消费模式不变，仅服务层 URL 前缀可能调整
