## 四、路由次序回归：本票发现并修正（重要披露）

**问题**：本票首次落地时，`PUT /models/{model_id}` 被注册在 `PUT /models/er` **之前**，
导致 `PUT /api/v1/rebuild/models/er` 被吞为 `model_id` 并因 int 转换失败返回 **422**
—— 17.2-05 的 6 条 ER 保存用例全红（全量基线一度为 `7 failed, 909 passed`）。

**根因**：17.2-04 建立的路由次序断言**只比路径键**，而 openapi 把同一路径的 GET/PUT **合并为单一键**
（`/models/er` 与 `/models/{model_id}` 是不同键 → 断言通过），无法发现**同前缀异方法**的吞并。

**修正**（两处，已完成）：

1. **路由重排** —— 最终注册序（`(method, path)` 展平表，与请求匹配同序）：

   ```
   GET  /api/v1/rebuild/models                 (A6-2)
   POST /api/v1/rebuild/models                 (A6-3)
   GET  /api/v1/rebuild/models/er              (A6-4)  ← 静态段整体前置
   PUT  /api/v1/rebuild/models/er              (A6-5)  ← 静态段整体前置
   GET  /api/v1/rebuild/models/{model_id}      (A6-6)
   PUT  /api/v1/rebuild/models/{model_id}      (A6-7)
   ```

2. **断言升级为逐 (method, path)** —— `tests/rebuild/test_model_er_read_api.py`
   与 `tests/rebuild/test_model_update_api.py` 各增/改为 `_route_pairs(app)` 辅助：
   展平 openapi 为 `(method, path)` 有序对（本版 FastAPI `app.routes` 为惰性 `_IncludedRouter` 包装，
   须取 openapi 展平表），断言**每个**静态路由下标 < **任意**动态路由下标。

**现行断言形态**已能捕获本类吞并（同前缀、异方法、静态段后移）。

> 诚实记录：该回归由本票引入、由本票修正；17.2-04 的断言设计有缺陷（过弱），已一并加固。
