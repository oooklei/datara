## 三、目标方案

### 3.1 分层架构

建议按「管理面 → 画布面板 → run-snapshot 三层分清 → 引用校验五诊断码 → 现时值 → 补全提示 → 全域引用组件」落地：

1. **变量管理管理面**（5.1）：任务中心主页面按钮入口（§5A.5）；全局/项目变量 CRUD；七级 namespace 选择器 `run > task > workflow > project > global > env > builtin` 不收窄。
2. **画布内工作流级变量面板**（5.2）：增量 4 画布内变量面板承接，C21r 已收口语义。
3. **引用校验按钮**（5.3）：任一可引用变量输入位提供校验按钮；五诊断码 SYNTAX/UNDEFINED/TYPE_MISMATCH/SCOPE_INVISIBLE/CYCLE 显式展示；走 `/check-reference`。
4. **现时值 label**（5.4）：变量值 label 展示当前时点解析值；走 `/preview` + run-snapshot 契约。
5. **补全提示**（5.5）：编辑变量时类似 SQL IDE 的补全提示供选择；后端补全契约 P0-2 六端点已备，FE 交互落地。
6. **全域引用组件**（5.6）：`${scope.name}` / `$[时间表达式]` 全域引用组件（可复用输入组件供各表单嵌入；旧版兼容语法不可静默破坏——U2）。

### 3.2 管理面设计

| 区块 | 字段/交互 | 默认与校验 | 结果反馈 |
|---|---|---|---|
| namespace 选择器 | 七级 `run > task > workflow > project > global > env > builtin` | 不收窄 | 即时展示层级 |
| 变量 CRUD | scope/name/value_type/value/description/sensitive + VAR-06 五字段 | scope/name 强一致 | 字段级诊断 |
| 引用校验按钮 | 任一可引用变量输入位 | 五诊断码显式展示 | SYNTAX/UNDEFINED/TYPE_MISMATCH/SCOPE_INVISIBLE/CYCLE |
| 现时值 label | 变量值 label | 当前时点解析值 | 引用展开格式样貌可见 |
| 补全提示 | 编辑变量时补全 | 类似 SQL IDE | 补全弹出与选择回填 |

### 3.3 全域引用组件设计

| 组件 | 语法 | 说明 |
|---|---|---|
| `${scope.name}` | 七级 namespace + 变量名 | 可复用输入组件 |
| `$[时间表达式]` | yyyy-MM-dd + 时区 + 业务日偏移 | 旧版兼容语法不可静默破坏（U2） |

1. **VAR-07 tmp 生命周期收窄**：tmp 为项目级持久（`tmp:{project_id}`），设计 §13.5 要求 tmp 只在当前工作流实例有效——需用户批准语义收窄 + 迁移方案。

4. **VAR-12 FE 契约对齐**：FE VariableValueType 为四值，需同步八值 + timezone/business_calendar 字段——前后端契约耦合。
5. **全域引用组件嵌入范围**：哪些表单需要嵌入引用组件（SQL/Python/Shell/依赖/同步）——建议全域扫描，无裸输入位。
