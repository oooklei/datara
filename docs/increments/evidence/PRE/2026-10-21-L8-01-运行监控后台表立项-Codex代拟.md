## 一、立项目标与真源

本立项为任何工作流处理结果提供独立于日志的结构化运行统计，记录成功记录数、失败记录数，并为具有源表/目标表语义的任务保存表级对账明细。前端最终由任务中心的运行监控视角页签承载，本票仅冻结后端建模输入。

最高验收真源及顺序：

1. `docs/increments/2026-10-19-纠偏重构前端权威设计.md` §3.3 B 组“工作流运行监控”及 §5A.10；
2. `docs/increments/2026-10-17-核心业务功能实现规范与验收标准.md` §3 通用门禁 A1–A7；
3. `docs/increments/2026-10-20-单线多增量WBS开发计划.md` 8.1–8.4；
4. 增量 8 预研及监督线验收、拆票登记。

客户参考表 `ods_data_sync_stat_detail` 只提供以下业务语义：源/目标数据量、`data_param`、起止时间、`dag_name` 和表级一行对账。**不得照抄其表名、字段布局、主键、状态枚举或写入机制。**

## 三、数据模型提案

### 3.1 `workflow_run_stat`：run 级统计主表

每个 `workflow_instance` 最多一行，作为一次工作流运行结果的权威统计快照。

| 字段 | 建议类型/约束 | 语义 |
|---|---|---|
| `id` | bigint/UUID，PK | 统计记录标识 |
| `project_id` | 非空，索引 | 项目隔离边界 |
| `workflow_id` | 非空，索引 | 工作流定义标识 |
| `workflow_instance_id` | 非空，UNIQUE | 幂等键；一实例一统计主表行 |
| `instance_type` | 非空枚举 | `TRIAL | FORMAL | STREAM` |
| `dag_name` | 非空字符串 | 运行时固化的工作流名称快照 |
| `data_param` | 可空 JSON | 业务参数快照；须经过 token/key/敏感字段过滤 |
| `success_count` | 非空整数，默认 0，`>= 0` | 成功处理的业务记录数 |
| `failure_count` | 非空整数，默认 0，`>= 0` | 失败处理的业务记录数 |
| `total_count` | 非空整数，默认 0，`>= 0` | `success_count + failure_count`；写入时校验 |
| `started_at` | 非空时间戳 | 工作流实例开始时间 |
| `finished_at` | 可空时间戳 | 终态完成时间；STREAM 运行中允许为空 |
| `created_at` / `updated_at` | 非空，DB 默认时间 | 沿用 `RunTimestampsMixin` 的 `CURRENT_TIMESTAMP` 无 NULL 契约 |

约束：三个计数字段不得为负；批运行终态时 `total_count = success_count + failure_count`；项目、工作流、实例的归属关系必须由服务端校验，禁止信任请求体中的跨项目标识。

### 3.2 `workflow_run_reconcile_detail`：表级对账明细

一条主表记录可以有零到多条明细。每条明细表示本次 run 中一个逻辑源对象到一个逻辑目标对象的对账结果。

| 字段 | 建议类型/约束 | 语义 |
|---|---|---|
| `id` | bigint/UUID，PK | 明细标识 |
| `run_stat_id` | 非空 FK，级联受控 | 关联 run 级统计主表 |
| `source_object` | 非空字符串 | 源表/逻辑源对象标识 |
| `target_object` | 非空字符串 | 目标表/逻辑目标对象标识 |
| `source_count` | 可空非负整数 | 源侧记录数；无法获取时为空而非伪造 0 |
| `target_count` | 可空非负整数 | 目标侧记录数 |
| `success_count` | 非空非负整数 | 该对象对成功数 |
| `failure_count` | 非空非负整数 | 该对象对失败数 |
| `difference_count` | 可空整数 | `target_count - source_count`；两侧均有值时计算 |
| `data_param` | 可空 JSON | 该对象对的业务参数快照，执行敏感字段过滤 |
| `started_at` / `finished_at` | 可空时间戳 | 对象对处理区间 |
| `created_at` / `updated_at` | 非空，DB 默认时间 | CURRENT_TIMESTAMP 无 NULL |

建议唯一键：`(run_stat_id, source_object, target_object)`。同一对象对的重试采用 upsert 更新同一行，避免 attempt 重试制造重复明细。

## 四、开放问题裁定提案

### 4.1 开放问题②：对账明细粒度

**提案：采用 run 级主表 + 表级明细两级模型。**

- run 级主表回答“这次工作流整体处理了多少条、成功/失败多少条”；
- 表级明细回答“哪一对源/目标对象产生了多少条及差异”；
- 普通 SQL、Python、Shell、Dependency 等不具备表对账语义的任务只写主表，明细允许为零条；
- 同步、ETL 等能提供对象对计数的任务同时写主表与明细；
- 明细不下钻到逐条业务记录，避免复制数据、扩大敏感数据面和造成无限体量。

此粒度兼容“任何工作流结果可记录”与客户样例的表级对账语义，同时保持统一 execution 域模型。

### 4.2 开放问题③：统计写入点挂接时机

**提案：以工作流实例进入终态为权威落表点；attempt 完成只提交计数贡献，不直接生成新的 run 级记录。**

1. executor/attempt 在完成时产生结构化计数贡献，绑定 `workflow_instance_id + task_instance_id + attempt_id`；
2. attempt 重试时只采纳该 task 的最终有效 attempt，旧 attempt 的贡献被替换，禁止累加两次；
3. 工作流实例进入 `SUCCESS | FAILED | CANCELLED` 等终态时，由 execution 服务在同一业务事务或可靠 outbox 消费中聚合并 upsert 主表和明细；
4. 重复终态事件使用 `workflow_instance_id` 唯一键幂等；失败后可安全重放；
5. `STREAM` 在运行中按 checkpoint 进行可覆盖的增量快照，终止时写最终快照；checkpoint 只更新同一主表行，不创建多个 run；
6. 现有 `/result-stat` 若继续保留，必须经服务层校验并归一为上述贡献模型，不允许调用方直接覆盖其他项目或实例的统计。

选择实例终态作为权威点，可避免 attempt 重试重复计数，并与“工作流处理结果”语义一致。L8-02 应对终态写入失败、重复投递和 STREAM checkpoint 重放建立测试。

## 五、查询与安全契约输入

L8-02 可在 `/api/v1` 下提供查询能力，具体路由命名由契约冻结流程确定。最低查询面：

- 按项目分页列出 run 统计，支持 workflow、instance_type、状态和时间范围过滤；
- 查询单个 workflow instance 的统计主表与对账明细；
- 明细分页，避免一次返回无限数据；
- 所有查询从认证主体推导项目权限，跨项目返回 404/403 按既有 identity 契约执行；
- `data_param` 输出前再次脱敏，禁止 token、密码、私钥、连接串等秘密回显；
- 统计端点不返回日志正文或业务样本值。

索引建议：主表 `(project_id, started_at)`、`(workflow_id, started_at)`、`(instance_type, started_at)`；明细 `(run_stat_id)`。索引最终由 L8-02 根据实际查询计划验证后确定。

## 六、L8-02 实施与验收锚

### 6.1 交付范围

1. execution 模型与 migration；
2. repository/service 的幂等 upsert 与查询；
3. workflow instance 终态和 STREAM checkpoint 挂接；
4. 查询端点及项目权限校验；
5. 对应 pytest 与门 7 时间戳实测证据。

### 6.2 必测场景

- 主表/明细初始 RED，再实施转 GREEN（A1）；
- 成功、失败、取消三种终态计数；
- attempt 重试只计最终有效 attempt；
- 相同终态事件重复投递不重复累计；
- 普通任务零明细合法，同步任务多表明细正确；
- STREAM checkpoint 重放保持单行且计数不倒退；
- `CURRENT_TIMESTAMP` 字段无 NULL；
- 项目越权被拒绝，`data_param` 敏感字段不回显；
- 统计写入失败可重放，不影响运行状态终态提交；
- 查询分页、过滤与总数一致。
