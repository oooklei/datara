## 交付内容

### 1. 业务输入位稳定类型面

新增 `datara-newweb/src/services/rebuild/variableReferenceField.ts`：

- `VariableReferenceFieldDescriptor` 以 `surfaceId + fieldPath` 构成可审计稳定键，业务表单必须显式登记，避免把用户名等普通文本字段误纳入变量引用范围；
- `inputKind` 覆盖 text/textarea/script/sql/expression/variable，`expectedValueType` 复用既有八值 `VariableValueType`；
- `allowScopedReference: true` 与 `allowTimeExpression` 明示 `${scope.name}` / `$[...]` 能力边界；
- `defineVariableReferenceField` 拒绝空 surface/path/label，产出可作为后续 schema 元数据消费的只读描述。

### 2. 显式按钮与五码展示契约

- `VariableReferenceFieldCapabilities` 固定 `checkTrigger='explicit-button'`、`checkMethod='checkReference'`；
- `VARIABLE_REFERENCE_DIAGNOSTIC_CODES` 固定 SYNTAX/UNDEFINED/TYPE_MISMATCH/SCOPE_INVISIBLE/CYCLE 全五枚举；
- `diagnosticPresentation='explicit-code-and-message'`，`VARIABLE_REFERENCE_DIAGNOSTIC_LABELS` 为各 code 提供稳定中文标题；
- `checkVariableReferenceField` 委托既有 `VariableContract.checkReference`，上下文与表达式原样传递，保留多诊断顺序及服务端消息，传输错误继续交给表单错误边界。

### 3. 契约测试

新增 `datara-newweb/src/services/rebuild/__tests__/variableReferenceField.contract.test.ts`，覆盖：

- 稳定输入位键和显式按钮能力；
- 五诊断码完整性及显示标题；
- 空身份字段拒绝；
- `/check-reference` 契约动作参数不变；
- 五码逐项参数化映射；
- 多诊断不折叠且顺序保留；
- 传输错误不伪装为业务校验结果。
