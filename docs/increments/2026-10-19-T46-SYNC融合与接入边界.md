# T46 SYNC 新旧执行器融合与共享层接入边界

日期：2026-10-19。范围：SYNC-06/07 的域内实现和接入契约；不改共享 `rebuild/api/app.py`、`rebuild/execution/` 或旧 worker。

## 结论：并存，按工作流域分流

- 旧线 `worker/executors/sync.py` 通过 `@register("sync")` 注册，消费旧 `ctx.param`；覆盖多 schema/前缀探测、连接型与文件型读取、union/src_flag/partition 合并、autoSchema、旧版读写参数、坏行阈值和 `worker.lineage`。
- 新线 `rebuild/sync/` 保存 `(project, workflow, version, task)` 槽位快照，字段映射为 §6.4 八字段，并保存结构化 transform/target 属性。新增 `rebuild/sync/executor.py` 只处理该快照及通用映射/过滤/统计编排，通过 `SyncRuntimeAdapter` 注入驱动操作。
- 两者配置形态与连接、目标策略语义不同；当前无无损双向转换或调度器注册契约。因此保留旧 executor 供旧工作流继续运行，新 rebuild 工作流由 shared execution integration 显式调用 SYNC 域 adapter。不得把新节点 alias 到旧 `register("sync")`，也不得删除旧注册。

## Shared integration 接入清单

1. 将保存的计划快照传入 `execute_sync(snapshot, adapter=..., run_context=...)`；`run_context` 至少应能定位 instance、task、attempt，以支持幂等统计。
2. `SyncRuntimeAdapter` 实现 `read_rows`、`include_row`、`transform_value`、`write_batch`、`write_statistics`、`write_lineage`。数据源连接由已有 datasource registry/pool 创建；adapter 负责 SQL 方言、增量/分区读写及冲突策略。
3. 把 `SyncExecutionMetrics` 八项计数按 R7 认可口径写入 task-instance / workflow aggregate，并用 attempt 身份防重复；当前共用 metrics schema 未提供八个独立字段，本域不扩改共享表。
4. 将返回结果映射到 execution result/status，确保异常和取消状态沿共享执行状态机收口。调用层需在创建 run 时持有不可变 workflow-version snapshot。
5. SYNC-04/08 还需目标 MySQL/完整部署环境可达后执行迁移、时间戳、端到端与异常注入验收；本轮 `192.168.1.9:3306` TCP 探测失败，故不宣称远端 GREEN。

## 验收边界

域内单元测试用注入 fake adapter 证明快照验证、映射、过滤、批写、八计数和血缘边生成。它不证明真实数据库方言执行、共享调度挂载、数据库持久统计或远端部署；这些由上述 integration/环境前置闭环。
