## 四、路由模式（History，§2.4）

### 4.1 决策落实

**决策**：`datara-newweb` 采用 **History 模式**（`createWebHistory`），弃用 hash 模式（§2.4）。

**理由**：
- 消除 §1「缺 `#/` 即落首页」认知陷阱；URL 语义化；
- nginx `try_files $uri $uri/ /index.html` 天然支持回退。

### 4.2 路由约束

| 约束 | 内容 | 真源 |
|---|---|---|
| 不占 `/api` 前缀 | 前端路由路径不得占用 `/api` 前缀（避免与反代冲突） | §2.4 |
| 零 demo 零验证页 | `routes.ts` 无 `demo:true`、无 `/rebuild/validation` | 红线 5 / §7.3 |
| 正式产品路由 | 仅正式产品路由；菜单路由归增量 2.1 填充 | §2.2 |

### 4.3 登录守卫设计

```ts
// src/router/index.ts（设计示意）
import { createRouter, createWebHistory } from 'vue-router'
import { routes } from './routes'
import { getToken, TOKEN_KEY } from '../services/http'

const router = createRouter({
  history: createWebHistory(),   // §2.4 History 模式
  routes,
})

// F5 登录守卫：非 /login 且无 token → /login（History 模式 → router.push）
router.beforeEach((to) => {
  if (to.path === '/login') {
    if (getToken()) return { path: '/' }
    return true
  }
  if (!getToken()) return { path: '/login' }
  return true
})

export { TOKEN_KEY }
export default router
```

> 与旧前端差异：旧前端 hash 模式用 `location.hash='#/login'`；新前端 History 模式用 `router.push('/login')`。

## 五、构建与代理（§7.1 单 BASE 拓扑）

### 5.1 拓扑三行对照（§7.1）

| 服务 | 端口 | 角色 | 本方案设计 |
|---|---|---|---|
| `datara-api` | 8000 | 旧后端（**不进入新前端调用链路**） | 不设代理、不设反代、代码零引用 |
| `datara-rebuild-api` | 8001 | **新后端（新前端唯一事实源）** | vite proxy + nginx 反代唯一上游 |
| `datara-newweb` | 18092（建议，待部署单定） | **新前端** | dev server.port = 18092 |

### 5.2 vite 代理（dev，单线）

```ts
// vite.config.ts（设计示意）
import vue from '@vitejs/plugin-vue'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 18092,   // §7.1 建议端口
    proxy: {
      '/api/v1': {
        target: 'http://localhost:8001',   // 新后端，唯一上游（§7.1）
        changeOrigin: true,
      },
    },
  },
})
```

**单线纪律**：
- 仅 `/api/v1` → `localhost:8001` 一条代理规则；
- **无第二上游、无旧后端 8000 代理**（红线 1 / §6.1）；
- `http.ts` 的 `BASE = '/api/v1'`，契约层一律走 BASE。

### 5.3 http.ts 单 BASE 底座（设计输入，实现归增量 1.2）

```ts
// src/services/http.ts（设计示意，§7.1）
const BASE = '/api/v1'   // 单一 BASE；nginx/vite 统一反代到 rebuild-api(8001)
// 契约层（services/rebuild/*）一律走 BASE
// 底座自动携带 token、统一解包（包络三态）、1xxx 跳登录、15s 超时
// 无 LEGACY_BASE、无第二后端分派
```

### 5.4 deploy 首版设计

**nginx.conf**（生产反代，单源）：

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    # docker 内嵌 DNS 动态解析上游（容器重建后 IP 漂移自动跟随，I16 实证）
    resolver 127.0.0.11 valid=10s ipv6=off;
    set $rebuild_api_upstream http://datara-rebuild-api:8001;

    gzip on;
    gzip_comp_level 5;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;

    # SPA（History 路由）：任何路径兜底回 index.html（§2.4）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反代到 rebuild-api 容器（单源，§7.1）
    # proxy_pass 含变量时 URI 按字面传递，故用 $request_uri 完整透传
    location /api/v1/ {
        proxy_pass $rebuild_api_upstream$request_uri;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # SQL IDE SSE 推流（禁缓冲防心跳攒包 + 长读超时防长任务断连）
    # 路径按新后端 sql_ide 域实际 SSE 端点落位（增量 11 实施时校准）
    location /api/v1/rebuild/ide/stream {
        proxy_pass $rebuild_api_upstream$request_uri;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }

    # 静态资源长缓存（Vite 产物带内容 hash）
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    location = /index.html {
        add_header Cache-Control "no-cache";
    }
}
```

**单源纪律**：
- 所有 `/api/v1/` 请求落 `datara-rebuild-api:8001`，**无第二后端旁路**（红线 1 / §7.3 联通判据「仅连 8001 抓包无例外」）；
- 旧后端 `datara-api:8000` 不出现在 nginx 配置中。

**Dockerfile**：

```dockerfile
# Datara 新前端镜像：dist 已在本地/CI 构建完成，远端仅需 nginx:alpine
FROM nginx:1.27-alpine

COPY dist /usr/share/nginx/html
COPY deploy/nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80
```

> 与旧前端 Dockerfile 同模式（L1 结构借鉴）；构建命令 `npm run build`（`vue-tsc -b && vite build`）。
