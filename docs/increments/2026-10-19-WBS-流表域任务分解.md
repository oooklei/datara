### STREAM-03 8 状态闭合流转测试强化

- **任务名**：对 `STREAM_TRANSITIONS` 18 条转移做全矩阵测试覆盖，补并发与终态边界用例
- **所属设计章节**：§13.7（8 状态）、§9（时间戳契约 started_at/finished_at）
- **前置依赖**：无（可与 STREAM-01 并行）
- **验收标准**：
  1. 状态机全矩阵测试：8 状态 × 8 动作 = 64 组合，合法转移断言 next_state，非法转移断言 `code=4002`
  2. 终态不可逆测试：STOPPED / FAILED 状态下任意动作均抛 4002（除 failed→recover）
  3. 时间戳契约测试：`start` 动作设 `started_at` 且 `attempt_no += 1`；`complete_stop` / `fail` 设 `finished_at`
  4. 并发转移测试：两个并发 `transition` 调用，仅一个成功（数据库行锁或乐观锁），另一个抛 4002
  5. 测试覆盖率 `repository.py` ≥ 90%
- **工作量**：0.5 人日
- **并行/串行**：与 STREAM-01 并行；STREAM-07 的前置

### STREAM-04 生产节点 7 模式 runtime_config schema 定义与校验

- **任务名**：为 fixed_rate / random / abnormal / duplicate / delayed / out_of_order / burst 7 种生产模式定义 JSON schema 与入参校验
- **所属设计章节**：§8（生产节点支持固定速率、随机数据、异常数据、重复数据、延迟数据、乱序数据和突发流量）
- **前置依赖**：STREAM-01
- **验收标准**：
  1. 新建 `datara-backend/rebuild/stream/producer_schema.py`（或同等模块），定义 7 模式的 JSON Schema：
     - `fixed_rate`：`{rows_per_sec: int, columns: list[str]}`
     - `random`：`{interval_ms: [min,max], columns: list[str]}`
     - `abnormal`：`{base: fixed_rate, abnormal_ratio: float, abnormal_values: list}`
     - `duplicate`：`{base: ..., duplicate_ratio: float}`
     - `delayed`：`{base: ..., delay_ms: [min,max]}`
     - `out_of_order`：`{base: ..., skew_ms: [min,max]}`
     - `burst`：`{base: ..., burst_every_sec: int, burst_count: int}`
  2. `POST /jobs` 创建时校验 `runtime_config` 必须匹配某一模式 schema；不匹配抛 `code=4001`
  3. 补 7 个参数化测试：每模式各 1 合法 + 1 非法
  4. 现有 `test_stream_domain.py` 中 register 测试的 `runtime_config` 改为合法 schema 样例
- **工作量**：1 人日
- **并行/串行**：串行于 STREAM-01；STREAM-08 的前置

### STREAM-08 生产节点 7 模式数据生成器实现

- **任务名**：基于 STREAM-04 的 7 模式 schema，实现运行时数据生成器（producer），供流处理任务启动时装配
- **所属设计章节**：§8（生产节点 7 模式）
- **前置依赖**：STREAM-04
- **验收标准**：
  1. 新建 `datara-backend/rebuild/stream/producer.py`（或同等模块），实现 7 模式生成器：
     - `FixedRateProducer`：按 `rows_per_sec` 匀速生成
     - `RandomProducer`：按 `interval_ms` 随机间隔生成
     - `AbnormalProducer`：按 `abnormal_ratio` 注入异常值
     - `DuplicateProducer`：按 `duplicate_ratio` 重复上一行

     - `OutOfOrderProducer`：按 `skew_ms` 乱序投递
     - `BurstProducer`：按 `burst_every_sec` / `burst_count` 突发
  2. 生成器输出统一行事件 `{source, ts, data}`（与 `sources.py` 现有契约对齐）
  3. 每模式补 1 个单测：断言生成速率 / 比例 / 延迟 / 乱序符合 schema 参数
  4. 生成器支持 `open(offset)` 从指定位点恢复

## 5. 风险与开放问题

1. **STREAM-02 决策风险**：§13.7 设计的第 5 张表 `stream_job_attempt` 是否独立建表，影响 STREAM-05 契约设计。建议优先决策。
2. **STREAM-07 状态映射风险**：旧线 5 状态与新线 8 状态非一一对应（PAUSED / STOPPED / CREATED 无旧线映射），需定义降级策略。
3. **STREAM-09 上报链路风险**：旧线 `_pipeline_once` 双写（Redis + 新线表）可能引入一致性冲突，需明确主存储与降级顺序。
4. **前端契约版本**：`streamApi.ts` 类型为前端单方面提案（非冻结），联调时可能与后端实际响应不一致，需在 STREAM-05/06 联调中对齐。
5. **Kafka/Redis/MySQL 首期沿用**：STREAM-07/08/09 依赖旧线运行时环境，需确认测试环境 Kafka / Redis 可用。
