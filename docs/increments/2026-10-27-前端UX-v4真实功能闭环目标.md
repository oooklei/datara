# Datara 前端 UX v4：真实功能闭环目标

> 日期：2026-10-27  
> 来源：用户最新裁定、UX v3 优化设计、`datara-ux-prototype.html`、192.168.1.9:18091 实测及源码 click-path 审计。  
> 本目标修正“页面存在/测试数量通过即视为完成”的错误口径；后续完成度只按用户可完成的端到端业务结果计算。

## 1. 总体裁定

1. 原型的框架、信息架构、作用域、布局逻辑和关键交互作为实施蓝本；颜色、密度、组件细节参考原型。
2. 原型不适配真实后端的部分，不复制静态表单或 toast 演示，按现有后端能力创造更直接、更稳健的产品实现；必要时补最小后端契约。
3. 可见控件必须产生可观察的最终状态：真实路由、真实 API、真实抽屉/弹窗、真实下载或明确禁用原因。仅 toast、空白页、永久 loading、静态假数据不算完成。
4. LongCat 只需一个模型真实可用即可通过当前验收；当前采用 `LongCat-2.0`。Ark、SiliconFlow 是后续冗余项，不阻塞本目标。
5. 本机仅做代码、单元、类型与逻辑稽核；部署、容器、数据、中间件和关键 E2E 仅在 192.168.1.9 进行。

## 2. 2026-10-27 实测基线

### 2.1 已真实存在，可保留完善

- 四账号登录表单可用；角色信息能显示。
- UX v3 壳层、项目作用域路由、桌面/移动侧栏、主题切换已存在。
- 项目工作台具备 13 个 KPI、3 个本地 ECharts 图表和最近运行区。
- DAG 能加载电商同步样例，画布含 7 个同步节点；Palette、画布、属性检查器和左右分割拖宽已存在。
- 变量管理、版本、试运行、定时弹窗入口存在；同步组件 Palette 已收敛为目标 7 项。
- SQL IDE 选择数据源后能显示 CodeMirror 6、对象树、分割布局和历史/资产入口。
- 电商项目存在 6 个可选数据源。
- 电商实时订单流样例能由复选框载入；流处理观摩、数据生产与融合入口可见。
- 系统管理、API、API-Key、LLM、部署运维已有真实页面；LongCat-2.0 连通。

### 2.2 阻塞用户使用的事实缺口

| ID | 级别 | 实测问题 | 目标结果 |
|---|---|---|---|
| G01 | P0 | IDE 执行 `SELECT 1 AS ok` 超过 15 秒仍为“执行中…”，无结果、终态或错误 | SSE 有终态、断线重连和超时回落；10 秒内成功或给出明确可操作错误；取消真实生效 |
| G02 | P0 | 工作台 KPI/“进入运行监控”写入 `?view=runs`，任务中心只读取 `?tab=` | 所有 KPI、最近实例和监控入口准确进入运行监控，并保留 status/runId 过滤 |
| G03 | P0 | 已登录后刷新 `/p/33/ide` 返回登录页 | 使用安全的服务端会话/HttpOnly 刷新机制恢复当前账号和原 URL；API key、token 不进入 URL或浏览器持久存储 |
| G04 | P0 | 默认项目为 `I1浏览器验证项目`；项目下拉混入 34 个验证项目 | 首次进入默认电商项目；普通用户只见业务项目；验证数据迁入独立测试租户/数据库 |
| G05 | P0 | 电商项目仍叫“电商数据全域治理项目” | 幂等迁移为裁定名称“电商全域数据治理项目”，保持 ID、归属和关联数据 |
| G06 | P0 | DAG “版本”显示 No Data；变量管理显示“暂无变量” | seed 产生可回滚版本、全局/项目/环境组变量及运行快照；页面能查看和复查 |
| G07 | P0 | DAG Inspector 只有单一属性区，缺少原型规定的属性/变量/依赖/试运行贯穿 Tab | 节点选中后四类能力同屏切换，读写真实 spec、变量、依赖和试运行状态 |
| G08 | P0 | 多弹窗关闭不稳定，后续按钮可能被前一遮罩阻塞 | 单一受控 overlay 栈；关闭、Esc、取消、提交后状态一致，禁止透明遮罩残留 |
| G09 | P1 | “另存为模板”只提示后续接驳；模板中心、告警与 SLA 是可点击空框架 | 有后端契约则实现；无契约前隐藏或禁用并给出明确原因，禁止可点击空白态 |
| G10 | P1 | AI 浮窗固定右下；业务弹窗没有统一可拖动/位置记忆 | 实现统一 `useDraggable`，视口钳制、移动端降级、位置记忆；发布确认同样适用 |
| G11 | P1 | IDE 仍展示内部“R5-A/增量 16”文案，初始大片空白；对象树需要人工选数据源后才显现 | 去除研发票据语言；默认选中项目首个健康数据源，提供示例查询和明确空/错/加载态 |
| G12 | P1 | 流工作流点击整行未使“载入选中”可用，点击复选框才可用 | 整行与复选框行为一致；载入后观摩面板直接定位并展示实时状态 |
| G13 | P1 | 主目录与 worktree 前端一致，但后端 `rebuild/api/app.py`、`llm/provider.py` 存在分叉，线上还有容器热补丁 | 开发前将已验证后端改动归并进唯一候选树；部署只从可追溯镜像构建，禁止长期热补丁漂移 |
| G14 | P1 | 视觉仍明显弱于原型：DAG/IDE 空白面积过大、信息层级和密度不足 | 以原型 1440 布局为骨架，按真实数据自适应；1024 功能完整，375 使用抽屉且无横向失控 |

## 3. 目标信息架构

### 3.1 全局层

- 登录与会话恢复。
- 项目管理与项目切换器。
- 部署运维：运行时节点、集群监控、SSH 节点。
- 系统管理：用户、RBAC、审计、API、API-Key、LLM。
- 全局 AI 助手。

### 3.2 项目层

维持五组、16 个项目菜单：

1. 总览：工作台。
2. 任务中心：任务编排与运行监控；同步/流是特殊工作流，不另设侧栏菜单。
3. 数据集成：数据源、资源。
4. 数据开发：SQL IDE、数仓建模。
5. 数据治理：血缘、资产地图、元数据、标签、标准、指标目录、指标看板、一致性、质量规则、检查任务、异常核查、质量报告、质量告警。

页面可以按后端领域合并实现，但每个菜单必须有独立、可理解的任务目标和真实交互，禁止多个菜单静默落到同一内容而无视图状态说明。

## 4. 核心业务闭环目标

### 4.1 工作台

- 默认展示当前业务项目真实数据；所有 KPI 卡、图表图例和最近运行行均可下钻。
- 下钻统一使用任务中心认可的 `tab/status/runId/workflowType` 查询契约。
- loading、empty、partial failure、error/retry 四态齐全；不得用静态数字填充。

### 4.2 DAG 与工作流

- Palette / VueFlow / Inspector 三栏维持可拖宽和持久化。
- 只突出 SQL、Python、Shell、依赖，以及同步 7 组件；流工作流由独立观摩面板承载。
- 所有节点表单由真实 component spec 驱动；保存前执行后端校验。
- 保存、发布、版本比较、回滚、定时、试运行、错误聚合均有真实成功/失败结果。
- 发布必须显示可拖动确认弹窗；发布后版本立即进入历史。
- 运行监控展示实例、任务明细、日志、变量解析快照及成功/失败/跳过记录数。

### 4.3 变量管理

- 管理面支持全局、项目、环境组三层；表格展示 namespace、类型、脱敏现时值、来源和更新时间。
- 工作流级变量位于 Inspector；节点输入旁可执行引用校验。
- 引用校验统一返回 SYNTAX、UNDEFINED、TYPE_MISMATCH、SCOPE_INVISIBLE、CYCLE。
- 试运行和正式运行固化 run snapshot，日志首屏可复查解析链：节点参数 > 工作流 > 环境组 > 全局。

### 4.4 SQL IDE

- 默认选中首个健康数据源；对象树按数据源→库→Schema→表/视图/例程/索引渐进加载。
- CodeMirror 提供格式化、语法检查、变量插入/校验、停止、保存脚本、历史、分页结果、CSV 导出和血缘跳转。
- 执行必须有总超时、SSE 心跳、断线重连上限及轮询终态回落；任何路径最终解除 executing。
- 读查询在测试数据源真实执行；DDL/DML 根据后端能力与权限显式开放或阻止，不使用研发票据文案。

### 4.5 同步、普通任务与依赖

- 同步样例完成端点选择、字段映射、条件、源/目标/文件基准配置，表单可保存、校验并运行。
- SQL、Python、Shell、依赖样例在同一正常工作流内真实执行；运行监控记录任务级结果和 `success_count/failure_count`。
- 依赖组件支持工作流、任务、相对窗口、轮询/超时与失败策略，并可通过试运行依赖模拟验证。

### 4.6 流处理

- 页面可启动/停止观摩任务、实时生产测试数据、执行聚合/融合、刷新窗口结果。
- 展示输入、输出、成功、失败、检查点、错误样本、恢复事件及最近融合结果。
- 验收必须由 1.9 实际生产至少一批数据并在 UI 看到融合后的业务行，不能只调用后端 seed 脚本。

### 4.7 治理与全局页面

- 16 个项目入口及全局页面的筛选、创建、编辑、状态切换、详情、分页和错误反馈与对应 API 一致。
- 指标目录与指标看板保持独立视图；质量报告、告警、异常核查提供真实查询和处置路径。
- 权限决定可见性和可操作性：管理员、开发者、分析师、观察者分别验证，不只验证登录成功。

## 5. 数据与基础设施前置任务

这些任务必须先完成，否则 UI 验收会被脏数据和空数据误导：

1. 固化唯一候选代码树，归并线上热补丁并生成可回滚镜像。
2. 将验证项目、临时资源、临时工作流迁入独立测试数据库；业务项目列表只保留可演示项目。
3. 幂等修正电商项目名称并初始化成员、数据源、资源、变量、工作流版本、定时与治理数据。
4. 确认 SQL SSE、工作流日志、流观摩所需服务和反向代理超时配置。
5. 保留一个可用 LongCat 配置和开发 key；密钥不进入仓库、静态产物、URL或浏览器持久存储。

## 6. 实施顺序

1. **P0 基线修复**：唯一代码树、数据清理、默认项目、会话恢复、SQL 终态、工作台跳转契约。
2. **P1 任务中心闭环**：DAG Inspector、变量、版本/发布/回滚、运行监控、弹窗状态机。
3. **P2 样例闭环**：同步、SQL/Python/Shell/依赖、流生产与融合 UI 观摩。
4. **P3 IDE 完整化**：对象树默认态、SQL 执行/取消/超时、历史、脚本、导出、血缘。
5. **P4 全页面与 UX**：治理/全局页面按钮矩阵、拖动/滚动、视觉、响应式和角色权限。
6. **P5 统一验收**：1.9 一次关键 E2E、回归、证据与候选镜像固化。

## 7. 验收门槛

- 建立“路由 × 控件 × handler × API × 成功态 × 失败态 × 权限”矩阵；每项必须有证据，测试数量不能替代矩阵。
- 登录后默认进入电商项目；四角色登录、刷新、深链接恢复均通过。
- `SELECT 1 AS ok` 在 UI 返回一行结果；超时与取消也有终态。
- 工作台 KPI 能准确进入过滤后的运行监控。
- 同步及普通四组件样例运行成功，并在后台运行结果表显示成功/失败记录数。
- 流样例从 UI 生产数据并显示聚合/融合结果。
- DAG 发布后生成版本；变量解析快照可复查；Inspector 四类贯穿能力可用。
- LongCat 至少一个模型真实调用成功。
- 1440、1024、375 三档检查；无未处理控制台错误、无永久遮罩、无永久 loading、无 CDN 运行依赖。
- 最终部署和关键 E2E 只在 192.168.1.9；迭代期本机只跑目标单测/类型检查，票尾一次全量回归。

## 8. 不再接受的“完成”定义

- 路由能打开但主体为空。
- 按钮有 click handler 但只 toast。
- API 单测通过但 UI 永久 loading。
- 组件存在但真实项目没有可用数据。
- 脚本直接调用后端成功，但用户从页面无法完成同一流程。
- 只检查 DOM 数量、data-testid 或截图，不检查最终业务状态。
