# R3-S8 开始前影响分析：I18–I23 旧治理资产映射与只读取证

前序状态：R3-S1 至 S7 的各自范围已完成；R3 总体仍为 PARTIAL。R1 auth-bootstrap 补充验证已由提交 `9e8e69d` 收口，不改变 R3 数据范围。

## 1. 目标和边界

本子步骤只回答旧 I18–I23 治理资产分别是什么、谁在写/读、与新治理模型如何对应，以及是否具备安全迁移条件。产物是可追溯的资产映射和差异清单，不在本步骤导入、更新、删除或重命名任何业务数据。

范围包括旧数仓建模、元数据/标签、指标、质量、标准、权限相关的 ORM、迁移/建表 SQL、API 路由、菜单/页面调用、服务内部消费者，以及 192.168.1.9 上旧元数据库的表结构和只读行数。新目标只检查已部署的隔离 schema `datara_rebuild_i0` 中 R3 governance 表及其键/约束，不写目标库。

明确不做：改旧表/旧 API/菜单；迁移真实数据；把旧表声明为废弃；将密级/脱敏作为本次必须实现项（内部系统决策已明确不要求）；改正式 Vue 页面；运行任何 INSERT/UPDATE/DELETE/DDL；将用户 XLS/XLSX/DOCX 纳入版本控制。

## 2. 前序影响与风险

- S6 在隔离 schema 安装 additive governance migration；S7 已通过真实验证页产生新治理数据。盘点须将这些验证 fixture 与历史旧资产严格区分，所有查询限定 schema 和明确只读账号/SELECT。
- QC 旧路由与执行引擎已退役，但 `Qc*` ORM、表和数据仍保留；其处置状态不得外推到所有 I18–I23 资产。
- 旧库对象可能与文档、ORM 或远端当前 schema 不一致；不得以菜单存在、类名存在或空表为由判定资产可迁移/可废弃。
- 资产映射会约束 R3 最终关闭及后续 R5 血缘、R6 治理目录/质量/标准、R11 AI 元数据工具；映射不清或主键/外键无法对齐时停止并记录差异，不启动写入步骤。
- 本地只做源码、测试和映射逻辑检查；部署资源及运行库均在 192.168.1.9。远端盘点不得重启容器或接触 `datara_dw`、`ec_retail`。

## 3. 细化执行步骤

1. 固化本次只读范围：记录旧库 schema、目标隔离 schema、查询时间、数据库版本、账号权限证明和两侧表清单；验证盘点账号不具备写权限。
2. 本地静态盘点 I18–I23：逐个读取模型、迁移/初始化 SQL、API 注册和处理器、前端 API 调用及路由/菜单引用；对每项记录文件/符号/表名/HTTP 方法/主要读写调用方。仅路径扫描用来定位，结论必须由实际源码内容核实。
3. 远端只读盘点：逐 schema 采集 `information_schema` 对象、列/类型/索引/外键、行数及最小必要业务状态分布；保存查询原文、执行时间、脱敏外的内部测试库数据不导出。旧 schema 使用专用只读连接；若权限不满足，则记录阻塞，不借用高权限账号写操作。
4. 对照新 `rebuild/governance/models.py`、migration revision 与 API：按实体、键、关系、状态、时间戳、审计字段建立一对一/一对多/无目标映射；区分“承接（仍由旧系统真源）”“迁移到新真源”“只读兼容”“冻结保留”“待裁定”，不能把未知强行归为废弃。
5. 做静态和只读数据核对：识别 orphan、重复自然键、枚举差异、时间戳缺失、跨项目归属缺失及关系无法表达项。只生成差异报告；任何候选修复数据留待后续独立增量。
6. 在页面冻结边界内不部署新 UI。本步骤交付后，按“源对象→新模型→迁移规则→校验/回滚方案”生成候选导入计划及行数/关系校验公式，再对该写增量另建影响分析和审批门；未获明确执行门前不写远端数据。
7. 完成本机静态契约检查、定向测试与 `git diff --check`；保存只读 SQL/输出摘要、文件映射、schema 指纹和限制说明至 `docs/increments/evidence/R3/`，并更新权威计划/台账。

## 4. 验收与停止条件

- I18–I23 每个域至少有旧表/模型、API/消费者、菜单/调用路径、新模型候选、远端对象/行数、映射状态和证据定位；无证据的项目标记 UNKNOWN。
- 所有远端 SQL 均为只读；旧 schema 与新隔离 schema 的对象、行数边界可由另一条独立查询复核；日志无 DML/DDL。
- 报告明确数据来源和查询时点，保留旧/新两套主键，不把测试 fixture 混入历史迁移统计。
- 发现写权限、目标 schema 不唯一、活动任务使用旧 API、业务键冲突无法解释、行数查询导致运行影响或与台账/实际 schema 冲突时立即停止该对象核验，记录证据并升级裁定。
- 本子步骤最多推进到“资产映射完成、候选导入计划形成”。它不是数据迁移通过，也不关闭 R3；R3 只有在已批准的迁移/承接边界及对应逐行/关系验收完成后才能评估 PASS。
