## 1. 根因实证（历史事实存档）

### 1.1 结论

**不存在"旧系统前端首页"这一独立站点**。全仓只有一个前端 SPA（`datara-web`）。实测"全跳首页"的真实原因：该 SPA 使用 hash 路由（`createWebHashHistory`），而上轮列出的验证页地址是 path 式（不含 `#/`）。path 式地址经 nginx `try_files` 兜底回 `index.html` 后 URL 中 hash 为空，vue-router 解析到根路径 `/` → 渲染工作台。

### 1.2 证据链（可复现）

| 证据 | 事实 | 位置 |
|---|---|---|
| A | 路由为 hash 模式（`createWebHashHistory()`） | `datara-web/src/router/index.ts` L6-9 |
| B | nginx 对任意未知 path 兜底回 index.html（`try_files $uri $uri/ /index.html;`） | `datara-web/deploy/nginx.conf` |
| C | 实测 `http://192.168.1.9:18091/` 三种 URL（path 式/hash 式/根）服务端均返回同一 `index.html` 外壳（引用同一 bundle `/assets/index-CZ4iV8Mm.js`）；区别仅在浏览器端 hash 解析 | 远程实测 |
| D | 10 条 `/rebuild/validation/*` 验证页路由全部注册，路由本身无缺陷 | `datara-web/src/router/routes.ts` L97-107 |

**判定**：交付文档表述缺陷（地址缺 `#/` 前缀标注），非代码缺陷。

### 2.3 复制准入条件（裁定 3 改写）

旧前端/旧代码复制准入以 **§3 功能清单对标** 为准绳，不以"后端有对应实现"为判据。**三判据，缺一不可**：

1. **对标功能清单**：被复制代码对应的功能必须在 §3 功能清单中已登记（有 I0~I11 对标出处与承载域）。未登记的功能先进清单、再复制。
2. **API 一源**：复制后的 API 消费必须指向新后端 `datara-rebuild-api`；若新后端无对应端点，先按 §6.2 五步规则将旧后端实现迁移进新后端并联调验证，再接前端。禁止复制直连旧后端的数据层（旧 `services/*.ts` 一律禁复制）。
3. **非全盘照抄**：不得整目录 `cp -r`；须逐文件判定。业务逻辑与数据流可复制，载体（HTTP 层/状态管理/组件库适配）必须适配新前端工程规范；菜单框架与页面布局按 §4 继承规则处理。

**登记留痕**：每个被复制文件在 `datara-newweb/COPY_LEDGER.md` 登记「源文件 → 目标文件 → 功能清单出处 → 复制/改写程度 → 联调验证证据」。

**复制分级**：

| 级别 | 含义 | 允许度 |
|---|---|---|
| L0 语义参考 | 仅参考业务语义，代码全部重写 | 允许 |
| L1 结构借鉴 | 借鉴文件组织与数据流结构，代码重写 | 允许 |
| L2 局部复制 | 复制函数/组件级代码块并适配载体 | 允许，须登记 |
| L3 整页移植 | 复制整页并适配契约层与单 BASE | 允许，须登记 + 联调验证 |

### 2.4 路由模式决策

**决策：`datara-newweb` 采用 History 模式**（`createWebHistory`），弃用 hash 模式。

- 消除 §1 "缺 `#/` 即落首页"认知陷阱；URL 语义化。
- nginx `try_files $uri $uri/ /index.html` 天然支持回退。
- 约束：前端路由不得占用 `/api` 前缀（避免与反代冲突）；实施首单落地并在 nginx 配置显式固化。

### 5.4 契约层架构（组件集成的底座）

**契约工厂 + adapterKit 六类机械映射**：

| # | 机械映射 | 说明 |
|---|---|---|
| 1 | 命名映射 | `camelToSnake` / `snakeToCamel`（FE↔BE 命名差异） |

| 3 | 包络解包 | `unwrapEnvelope` 三态（下） |
| 4 | 错误归一 | 统一 `ContractApiError` |
| 5 | SSE 事件归一 | 流事件归一 |
| 6 | 分页归一 | 分页结构归一（统一 limit 200） |

**包络三态（已冻结）**：

```
{code, msg, data}
  ├─ code === 0 / 200 / undefined  → resolve(data)
  ├─ code ≠ 0 / 200（业务错误）     → throw ContractApiError{httpStatus, code, msg, raw?}
  └─ 非 2xx（系统错误）             → 调用方解包前抛错
```

`adapterKit.unwrapEnvelope` 为冻结结论共享原语，全域统一（含 RED 契约接线时沿用）。

### 5A.2 工作流三分类（v3 收窄裁定）

工作流 tab 分类收窄为**三分类**（用户裁定 2026-10-20）：

1. **同步工作流**（sync）——特别工作流，承载同步任务语义（I4 SYNC）；
2. **流处理工作流**（stream）——特别工作流，承载流处理语义（I8）；
3. **普通工作流**（wf）——**默认**：不显示分类时默认普通工作流。

- **客户自建分类**：参照旧前端目录树分类目录 + 行操作机制（§5A.1 蓝本第 4 行）。

## 5B. 变量管理细化设计（v3 新增）

> 依据：用户裁定 2026-10-20（同 §5A）；规范 S3「变量体系 = 系统灵魂」。本章为变量体系前端承载细化设计；变量语义、契约与验收以规范 v4 S3/R2 门为最高锚。

### 5B.1 定位与三层分清

| 层 | 语义 | 前端承载 | 状态 |

| 实例变量 / 时间戳参数 | 运行实例变量与 `$[时间表达式]` | run-snapshot 透传（设计时/运行时/维护时三时态） | ✅ run-snapshot 语义 |

### 5B.2 语法与全域引用

- 引用语法：`${scope.name}` + `$[时间表达式]`（S3）。
- **所有支持输入文本的位置均可引用不同命名空间的变量**（S3 契约面覆盖声明，全域扫描验收）；旧版兼容语法不可静默破坏（S3/U2）。

### 5B.3 引用校验（会议纪要③-1）

- 五诊断码：SYNTAX / UNDEFINED / TYPE_MISMATCH / SCOPE_INVISIBLE / CYCLE，走 `/check-reference` 契约（P0-2 六端点已备）。
- **全域引用位 = 校验按钮**：任一可引用变量的输入位必须提供校验按钮——触发引用校验并显式展示五诊断码结果（用户补充 3191c0b，规范 R2 门）。

### 5B.4 现时值展示（会议纪要③-2）

- **变量值 label**：展示所引用变量的**当前时点解析值**，走 `/preview` + run-snapshot 契约，供用户确认引用展开后的格式样貌（用户补充 3191c0b）。

### 5B.5 补全提示（会议纪要③-3）

- **编辑变量时类似 SQL IDE 一样可补全提示供选择**。
- 分层：后端补全契约（P0-2 六端点）已备；FE 补全交互 = 前端重构阶段落地（与 S3 SQL IDE 分工同款纪律——后端阶段交付契约面，交互属前端阶段）。

### 5B.6 与核心模块的关系

- **SQL IDE**：变量体系实现 = 该模块核心重点工作（S3）——SQL 文本承载 `${scope.name}`/`$[时间]` 引用，执行前经共享变量解析服务消解引用、产出不可变解析快照回传；`GlobalParamDrawer` 数据源对齐 R2 变量管理契约（§5.5）。
- **DAG 工作流**：各组件（SQL/Python/Shell/依赖/同步）参数面统一经变量契约（§5A.3/§5A.6/§5A.8）。
- **AI 助手**：工具调用经变量契约；S6 主权边界——变量七级作用域 + run-snapshot 唯 Datara 持有。

1. **唯一事实源**：新前端所有后端调用唯一指向 `datara-rebuild-api`（端口 8001）。

## 8. 验收红线（七条，冻结）

1. **API 一源**：新前端所有后端调用唯一指向 `datara-rebuild-api`(8001)；无 LEGACY_BASE、无旧后端代理/反代、无双源；新后端缺口按 §6.2 五步规则迁移并三重验证，禁止前端直连旧后端。
2. **清单对标**：任何进入新前端的页面/菜单/功能，必须先在 §3 功能清单登记出处（I0~I11 **或经用户裁定登记的出处，§3.4 口径**）与承载域；未登记不得实施。
3. **契约优先**：一切后端消费经 `services/rebuild/*.ts` 契约层；禁裸 fetch；包络三态/错误归一全域统一。
4. **复制准入**：旧代码复制须过 §2.3 三判据 + COPY_LEDGER 登记；旧 `services/*.ts` 数据层一律禁复制；菜单/布局按 §4 继承规则处理。
5. **零 demo / 零验证页**：`datara-newweb` 正式路由零 demo、零验证页（验证页为实现候选，不属于本设计管理范围）。
6. **旧前端冻结**：`datara-web` 仅作 §4/§5A 菜单/布局参考源与 §1/附录证据锚；本设计不含针对它的任何修改任务。
7. **可观测可验证 + 八门**：每个功能须 pytest + vitest 契约测试 + 联调冒烟三重验证；融合授权以八门为唯一准绳，域 GREEN ≠ 正式融合授权。
