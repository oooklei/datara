## 二、范围

**纳入**：
- 开放 API 定义登记/发布/启停（受控 facade 语义）；
- API-Key 签发/校验/轮换/吊销（hash-only 存储策略）；
- API 调用鉴权（scope/有效期/吊销状态）与调用日志写入及检索；
- 前端 G 组两菜单（/open/api、/open/key）+ 调用日志附属展示（形态候 C1 裁定）。

**排除**：
- 任意 URL 代理（发布对象仅限登记过的受控 facade，候 C2 裁定）；
- LLM provider key 管理（已另立项 `rebuild/llm/` 独立域 15.5，AES-256-GCM 可逆加密；与 API-Key hash-only 策略**分表、分服务、分测试，不得共享存储或序列化器**，预研 §4.3）；
- 独立调用日志一级菜单（0.8 约束，见 §五）。

## 三、建模方案（预研 §4.3 三表建议）

| 表 | 核心字段 | 约束 |
|---|---|---|
| `rebuild_api_definition` | id、name、path、method、description、required_permission、status、version、created_by、timestamps | method+path+version 唯一；仅登记受控 facade；状态机 draft→published→disabled |
| `rebuild_api_key` | id、name、key_prefix、key_hash、scopes_json、expires_at、status、last_used_at、created_by、revoked_at、timestamps | 原始 key 仅签发响应显示一次；库内只存 hash（不可逆）；支持吊销/轮换 |
| `rebuild_api_call_log` | request_id、api_id、key_id、principal/project、status_code、latency_ms、result、error_code、requested_at | 不记录原始 key、敏感 body 或完整 SQL；索引时间/api/key；request_id 回链 |

**最小服务链**：创建 API 定义 → 发布/启用 → 签发 key（一次性明文）→ 携 key 调用受控 API → 鉴权 scope/有效期/吊销状态 → 写调用日志 → 管理页可检索。

## 七、验收锚（汇总）

1. **门 7**：三表建模评审（`rebuild_api_definition`/`rebuild_api_key`/`rebuild_api_call_log`）；
2. **pytest**：端点契约全绿（唯一性约束/权限/状态机/scope 校验/过期吊销拒绝）；
3. **安全红线**：原 key 仅签发响应显示一次；DB hash-only 非明文断言；调用日志敏感字段零落盘断言；证据不得含真实 key（成对证据纪律）；
4. **闭环 E2E**（15.3 页面票）：签发→复制→调用→日志检索→轮换→吊销→调用失败全链 Playwright；
5. **菜单合规**：/open/api、/open/key 实现+验收后 future→formal；/open/log 维持 embedded 无独立菜单（0.8 计数校验不变：迁入正式语义组 10 项、#14 并入 #12、删除 7 项）；
6. **退出标准**（WBS L463）：API 管理立项经用户确认（含调用日志并入形态）且建模落地 pytest 全绿；两页签发/调用/日志闭环。
