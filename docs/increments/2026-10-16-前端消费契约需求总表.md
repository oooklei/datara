## 三、缺口请求清单（供 Codex 契约冻结时明确）

以下均为源文件头注释、草案常量标注或类型缺口中**真实存在**的悬空点：

1. **端点前缀**：9 个契约文件的端点前缀均为草案——`/api/v1/rebuild/{sync,dependency,resources,schedule,variables,metrics,sql-ide,stream}/*`，最终以后端契约为权威，冻结时逐一确认。
2. **DEPENDENCY / RESOURCE 无 Codex 草案**：SYNC 有草案文件（`R4-SYNC-API-contract-pending.md`），DEPENDENCY 与 RESOURCE 的语义仅来自前端侧设计文档引用，属前端占位，需 Codex 出具草案并确认（含 DEPENDENCY 的 `upstreamWorkflowVersion` 缺省语义「随上游最新已发布版本」、组间 AND 约定、`asOf` ISO 格式）。
3. **RESOURCE 上传细节**：20MB 大小上限为前端草案常量（设计仅要求「有大小限制」，具体值待后端契约冻结）；上传正文真实实现为 multipart（契约层 `contentBase64` 仅元数据描述），编码与分片口径待定。
4. **分页 / 时间窗参数口径**：`TimeWindowQuery{from, to, offset, limit}` 的 `from/to` 格式（ISO？日期？时区）与 `offset/limit` 语义需与 Codex 统一；且 SCHEDULE 全部 5 个 list 方法、R5-A 的 `listHistory`/`listScripts` 均为无分页全量草案、SCHEDULE 无 projectId 参数——是否统一补齐待定。
5. **SSE 事件结构（R5-A）**：`openEventStream` 返回 `EventSource`，事件名与 `SqlLogEvent`/`SqlResultEvent`/`SqlDoneEvent` 三类载荷结构待 A5 契约冻结；认证 token 沿 R3 runner 注入先例、禁止落 storage。
6. **variable_snapshot_id/sha256 无消费落点**：共享协议通报了快照身份字段，但 `VariableSnapshotEntry`（快照行）无 id/sha256 字段，前端无法展示或对账快照身份，需后端冻结时补充进快照查询返回。
7. **错误结构对齐**：前端仅有的错误字段均为弱类型——`SyncAttemptDetail.errorCode: string`、`SqlLogEvent.error?: string`、`DdlExecutionRecord` 失败时无错误字段；与共享 `error{code, category, stage, retryable}` 的映射（含 retryable 展示）待冻结。
8. **log_ref 无消费落点**：共享协议通报了 `log_ref`，但 9 个契约文件均未定义日志引用消费字段（最接近的是 `SqlDoneEvent.historyId`——结果/历史引用，非日志）；`log_ref` 应进入哪个返回结构待明确。
9. **计数口径**：`WorkflowResultStatRow.retryCount` 在共享 metrics 五字段中无对应；`TaskInstanceDataStatRow.rowsIn/rowsOut/errorRows` 与 `read/write/failed_count` 为语义候选映射，需确认精确口径。
10. **开放枚举全集**：R8 的 `StreamWindowResult.status`、`StreamErrorSampleRow.flow`、`StreamJobRow.kind/state` 均为开放字符串（允许后端扩展），冻结时需给枚举全集。
11. **R2 值类型枚举**：`VariableValueType('string'|'number'|'boolean'|'json')` 为草案，具体枚举以后端契约为权威。
12. **SCHEDULE 字段确认**：`nextFireAt/lastFireAt/misfirePolicy`（触发注册）与 `concurrencySlot`（队列）为前端期待字段；`ScheduleQueueEntry` 缺 workflow_version 维度（共享 `workflow_version_id` 语义）。
