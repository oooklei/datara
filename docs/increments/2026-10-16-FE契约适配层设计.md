## §1 目标与范围

1. **覆盖面**：B2 登记的 9 页 66 个契约方法全覆盖（SYNC 11 / DEPENDENCY 5 / RESOURCE 5 / SCHEDULE 5 / VARIABLE 6 / METRICS 6 / SQL-IDE 只读 17 / SQL-IDE DDL 5 / STREAM 6，与 B2 §二总览一致）。
2. **唯一职责**：BE 实态（P1 冻结产物）→ FE 冻结契约（`trae/r4-red` worktree 的 9 个 `.ts` 契约文件，签名与类型已冻结）之间的**机械映射**。映射范围限六类：命名、id 归一、包络解包、错误归一、SSE 事件归一、分页归一（§2）。
3. **不做的事（语义加工负面清单）**：
   - 不做枚举同义词映射（如 FE `cancel_requested` ↔ BE `cancelling`，挂 R4-SYNC Q9——**Q9 已裁定（2026-10-16）：BE `cancelling` 为权威状态、`cancel_requested` 仅布尔请求标记，FE 应统一用 `cancelling`**；词形落点在 FE 契约与页面层对齐（GREEN 前按裁定改词形，非适配层职责），适配层仍不做值映射表）；
   - 不做计数推导/口径折算（如 `targetWritten = inserted + updated`、`rows_rejected ≡ skipped`，挂 R4-SYNC Q7——**Q7 已答复（2026-10-16）：`targetWritten = rows_inserted + rows_updated` 可推导获 BE 确认（FE 推导可行）；`rows_rejected` 是 sink 拒收 ≠ `skipped`，二者等号不成立；`failed` 无 BE 计数器需补显式计数，FE 不猜**。targetWritten 推导式以冻结确认形式补充进 §2 后方可实施，届时属机械规则而非当期臆断；`skipped` 的 BE 来源与 `failed` 计数仍待冻结裁定）；
   - 不补默认值、不裁剪字段语义、不代写 `confirmPhrase`（sqlIdeDdlApi.ts:45 红线：用户下发，agent 不得代写——适配层对该字段仅透传）；
   - 不解决语义差异本身：语义差异仍走各域清单 Q 答复（§5）。
4. **生效时点**：本文规则在 P1 冻结产物到达并经各域「冻结确认」后，进入 GREEN runbook 逐方法实施；RED 期间不写任何实现代码。

## §2 适配规则（六类）

> 每类给出映射规则 + 真实例子。例子仅取自实读源码；BE 侧行号如引自各差异清单，均注明出处（Codex 在飞编辑中，以符号名为锚）。

### §2.1 命名映射：snake_case ↔ camelCase

| 规则 | 内容 |
| --- | --- |
| R1.1 字段级映射表优先 | 每个契约方法配一张显式 wire→contract 键映射表，靠近该方法的 DTO 类型定义放置；未登记键不映射（fail-visible，接线期契约测试可暴露遗漏） |
| R1.2 通用递归兜底 | 登记为「递归」的 DTO，其嵌套对象与数组元素按 snake→camel 递归转换；深度以 DTO 定义深度为上限（当前最深层 3 层：`StreamObservation.offset.current: MetricValue`，streamApi.ts:81 → metricsApi.ts:12-16） |
| R1.3 字符串值不递归 | `string` 类型字段值一律原样透传，不做内部转换：opaque `checkpoint`（syncComponentApi.ts:165）、`sqlText`（sqlIdeApi.ts:121/:131）、`sampleData`（metricsApi.ts:62）、`constantValue`（syncComponentApi.ts:64）、`ddlText`（sqlIdeDdlApi.ts:17） |
| R1.4 保留字/非法标识符 | TS 属性位允许保留字与连字符，**不做改名映射**；若 BE 键含非法标识符字符，按原样键访问（`obj['x-y']`），不改 BE 词形 |
| R1.5 枚举值词形另议 | 枚举**值**（非字段名）的词形差异不属本规则：`'rolled-back'`（sqlIdeDdlApi.ts:51）vs BE 可能的 `rolled_back` 待 A5 冻结确认；`cancel_requested` vs `cancelling` **已裁定（R4-SYNC Q9，2026-10-16）：FE 统一采用 `cancelling`**，词形修正落在 FE 契约/页面层，适配层默认不做值映射表 |
| R1.6 请求方向 | FE→BE 请求体的 camel→snake 映射，以 P1 冻结端点签名为唯一依据逐字段登记；BE 未声明消费的字段是否随请求发送，待各域 Q 答复（例：R4-SYNC 清单 §2 #3 实证 BE `create_plan` 现不消费 mapping/strategy/writeMode/targetPolicy/incremental——取舍挂 R4-SYNC Q10） |

**真实例子 1（响应方向，第一手 BE 实证）**：BE `_definition_payload` 返回 `{name, value, value_type, scope, sensitive}`（`rebuild/variables/api.py:185-193`）→ FE `VariableDefinition { scope, name, valueType, value, description?, sensitive? }`（variableApi.ts:26-34）。映射表：`value_type → valueType`；`description` 无 BE 对应列（挂 R2 Q12）。

**真实例子 2（响应方向，引自 R4-SYNC 清单）**：BE checkpoint payload 计数字段 `rows_read/rows_inserted/rows_updated/rows_rejected`（R4-SYNC 清单 §3-D 引 runtime.py:450-453）→ FE `SyncRunCounts { sourceRead, targetWritten, inserted, updated, skipped, failed }`（syncComponentApi.ts:117-124）。`rows_read → sourceRead` 为纯命名映射；`rows_rejected → skipped`、`targetWritten/failed` 为**语义条目，挂 R4-SYNC Q7**，不得由命名规则收编。**Q7 已答复（2026-10-16）**：`targetWritten = rows_inserted + rows_updated`（FE 推导，冻结确认后进 §2 机械规则）；`rows_rejected ≠ skipped`（sink 拒收非跳过，`skipped` BE 来源待冻结）；`failed` 需 BE 补计数、FE 不猜。

### §2.2 id 归一：BE 数值/string id ↔ FE number/string id

| 规则 | 内容 |
| --- | --- |
| R2.1 逐字段配置 | id 类型**逐字段登记**，不设全局开关——FE 自身即不一致：`SyncRunSummary.runId: number`（syncComponentApi.ts:140）、`HistoryEntry.historyId: number`（sqlIdeApi.ts:118）为 number；`LineageWritebackEntry.runId: string`（metricsApi.ts:81）、`StreamJobRow.jobId: string`（streamApi.ts:18）、`SqlExecuteRequest` 返回 `{taskId: string}`（sqlIdeApi.ts:179）为 string |
| R2.2 无损正向 | FE number → wire string：`String(id)` 序列化，无争议（BE `run_id` 为 ≤128 字符字符串、`mapping_id = str(uuid4())`，R4-SYNC 清单 §3-E.3 引 api.py:111/runtime_api.py:393-396） |
| R2.3 有损即拒绝 | wire string → FE number：仅当 `Number.isSafeInteger(Number(s))` 时转换；非纯数字串（如 uuid）**无法无损落入 `planId: number`**（syncComponentApi.ts:93），适配层抛归一错误（§2.4 `ContractApiError`），**禁止截断/哈希/本地重映射表**。该情形不属机械映射可解范围，升级为契约冻结裁定项（挂 R4-SYNC Q12；若 BE 维持 uuid，FE 契约类型变更须走设计差异注记并经用户批准） |
| R2.4 对账一致性 | 同一实体 id 在一次会话内不做二次变换，保证 FE 展示值与 BE 原值可对账（配合 R2.3：有损变换被禁即天然满足） |

**真实例子**：FE `getPlan: (planId: number, projectId: number) => Promise<SyncPlanDraft & SyncPlanVersion>`（syncComponentApi.ts:201）——若 BE 返回 `plan_id: "3f2a…-uuid"`（R4-SYNC 清单 §3-E.3：`mapping_id = str(uuid4())`），R2.3 使该方法在接线期 fail-fast 并回流 Q12 裁定，而不是静默展示错值。

### §2.3 包络解包：`{code, msg, data}`

**BE 第一手实证**（`rebuild/variables/api.py`，本次直接读取）：

- `_success`（api.py:196-197）：`return {"code": 0, "msg": "success", "data": dict(data)}`
- `_error`（api.py:200-201）：`return JSONResponse(status_code=status_code, content={"code": code, "msg": message, "data": None})`

| 规则 | 内容 |
| --- | --- |
| R3.1 解包判定 | HTTP 2xx 且 `code === 0` → resolve `data`；否则（非 2xx 或 `code !== 0`）→ 抛归一错误（§2.4） |
| R3.2 落点唯一性 | 解包**只发生在一处**：原语模块的 `unwrapEnvelope()`；各契约方法实现体 = fetch → unwrap → 字段级映射，**禁止**映射函数内二次判 `code/msg`。FE 契约类型（如 `Promise<VariableDefinition[]>`，variableApi.ts:107）描述的均为**解包后**形状 |
| R3.3 域级可配置 | 包络是否 9 域统一**待 Codex 确认**（开放问题 1）：当前第一手实证仅 variables 域；R4-SYNC 清单所载 sync 域返回（如 `_plan_payload`）未记载成功包络，且其 `_error(503, 5031, …)`（R4-SYNC 清单 §3-A.3 引 runtime_api.py:279-288）表明错误包络 `{code, msg, data: null}` 形态在 sync 域同样出现。解包器按域配置开关，冻结时逐域确认 |
| R3.4 数据键包裹 | BE 以命名键包裹列表的（实证：variables 清单端点 `return _success({"items": [...]})`，api.py:36）→ unwrap 后取 `data.items` 返回数组。该「items 包裹」是否全域一致待确认（开放问题 2） |

**真实例子**：FE `listVariables: (projectId, scopes?) => Promise<VariableDefinition[]>`（variableApi.ts:107）→ BE `GET /api/v1/rebuild/projects/{project_id}/variables` 返回包络 `{code:0, msg:"success", data:{items:[_definition_payload…]}}`（api.py:36 + :196-197 + :185-193）→ 适配链 = unwrap → `data.items` → §2.1 例子 1 的字段映射 → `VariableDefinition[]`。`scopes?` 过滤为 FE 本地行为还是 BE 服务端参数，挂 R2 Q1（不属机械映射）。

### §2.4 错误归一：BE 错误包络 → FE 契约期望错误形状

| 规则 | 内容 |
| --- | --- |
| R4.1 归一错误类型 | 定义 `ContractApiError { httpStatus, code, msg, raw? }`：传输层失败（HTTP 非 2xx 或 `code !== 0`）统一 rejected promise 携带该类型——与 RED 哨兵「异步契约方法 rejected promise」形态一致（syncComponentApi.ts:213-216 注释自述 rejected promise 设计意图），UI 捕获方式不因接线改变 |
| R4.2 两条错误通道分离 | **传输层错误**（包络）走 R4.1；**业务字段错误**（DTO 内字段）只是字段映射：BE checkpoint payload 的 `error` 字段（R4-SYNC 清单 §3-D 引 runtime.py:435，失败置 `error=type(exc).__name__`）→ FE `SyncAttemptDetail.errorCode?: string`（syncComponentApi.ts:154）。后者不经过 ContractApiError |
| R4.3 弱类型错误字段 | FE 现有错误字段均为弱类型：`SyncAttemptDetail.errorCode: string`（syncComponentApi.ts:154）、`SqlLogEvent.error?: string`（sqlIdeApi.ts:89）、`DdlExecutionRecord` 失败时无错误字段（sqlIdeDdlApi.ts:49-58）——与共享协议 `error{code, category, stage, retryable}` 的对齐（含 retryable 展示）挂 **B2 缺口 #7**；BE 是否补 category/stage/retryable 待 Codex（开放问题 5）。若冻结要求 FE 承载结构化错误，属契约类型变更，走差异注记，不在适配层私加 |
| R4.4 fail-visible | 适配层不吞错、不重试、不降级默认值；重试策略（若有）属 service 编排，另议 |

**真实例子**：BE `PUT /projects/{id}/variables/{name}` 校验失败 `return _error(400, 4001, str(exc))`（api.py:65）→ HTTP 400 + `{"code": 4001, "msg": <原因>, "data": null}` → 适配层抛 `ContractApiError{httpStatus:400, code:4001, msg}`；同域 404/403 实证：`_error(404, 4043, "project variable not found")`（api.py:79）、`_error(403, 1003, "permission denied")`（api.py:88/:99）。

## §3 架构落点

### §3.1 两个候选方案

| 方案 | 形态 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A：适配函数放每 API 文件内部 | 9 个 `.ts` 各自内联 fetch/解包/映射 helper | 单文件自包含 | snake→camel、包络、id 转换、ContractApiError、SSE 门面**重复 9 份**；同修一处横切 bug 要改 9 处 |
| B：独立 adapter 模块 | 全部映射集中于一个模块，契约文件只透传调用 | 原语单份 | 契约字段映射表远离契约类型定义，契约测试与映射表分家，漂移风险高；接线 diff 面大 |

### §3.2 推荐：混合式——「共享机械原语模块 + 每 API 文件内薄映射层」

- **共享原语模块**（GREEN 接线期新增，如 `services/rebuild/adapterKit.ts`，命名冻结时定）：仅含**无业务语义的纯函数**——snake↔camel 递归（§2.1）、`unwrapEnvelope()`（§2.3）、id 转换器（§2.2）、`ContractApiError`（§2.4）、SSE 归一门面（§2.5）。不含任何 fetch、不含任何具体 DTO 字段名。
- **每 API 文件内**：每个契约方法一张字段映射表 + 一个实现体（fetch → unwrap → map）。映射表与契约 DTO 同文件演进，契约测试改动与映射改动出现在同一 diff，防漂移。
- **理由**：
  1. **哨兵机制不动**：契约工厂签名、`*_NOT_WIRED` 常量、`*_CONTRACT_METHODS` 数组、`notWired`/`notWiredSync` 全部保留导出；
  2. **契约测试不动**：契约测试（与视图同目录的 `*.contract.test.ts`）断言方法清单与哨兵，工厂结构不变则测试骨架不变；
  3. **接线期 diff 最小化**：GREEN 每方法替换点是工厂 return 语句中的一行（`方法名: notWired` → `方法名: 实现体`），66 方法可按 runbook 逐个/分批切换，未切换方法继续抛哨兵，页面无感（B2 §二「UI 层不感知切换」）。

### §3.3 哨兵替换点与适配层的关系

替换形态（以 SYNC `getRun` 为例，示意，非实现授权）：

```
// RED（现状，syncComponentApi.ts:230）
getRun: notWired,
// GREEN（替换后）：实现体 = fetch + unwrap + 字段映射；notWired 与哨兵常量保留
getRun: async (runId, projectId) => {
  const wire = await requestEnvelope(getRunEndpoint(runId, projectId))   // 原语：fetch + §2.3 解包
  return mapSyncRunSummary(wire)                                        // 本文件内映射表（§2.1/§2.2）
},
```

- `notWired`（syncComponentApi.ts:214-216）与 `notWiredSync`（sqlIdeApi.ts:199-201）**不删除**：既是 RED 测试断言对象，也是 GREEN 分批接线期的未接线方法缺省实现与回滚开关。
- 适配层在实现体**内部**，位于哨兵替换点之后：`哨兵替换点（工厂方法绑定）→ 实现体（fetch）→ 适配层（unwrap + 映射）→ 契约返回类型`。UI/契约测试只见契约类型，适配层不可见。
- `openEventStream` 的替换点特殊：绑定目标为实现 `EventSource` 兼容门面的同步函数（§2.5-R5.2），签名 `(taskId: string) => EventSource` 不变。
