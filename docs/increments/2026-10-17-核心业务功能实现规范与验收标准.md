## §0 优先级总则（冲突裁决序）

1. **DAG 工作流 = 系统核心骨架**：设计、试运行、运行三环节为核心；依赖组件是其核心节点，**必须 100% 过硬实现全部功用**；DAG 达标后系统基本可用于生产，其他附属功能均服务于该核心。
2. **变量体系 = 系统灵魂**：后端各组件数据交互、设计时/运行时/维护时数据透传的基石，贯穿所有核心业务，验收从严。
3. **SQL IDE = 独立工具**：相对独立，除变量插入外无其他功能破坏其独立性（数据源管理等为复用）；DBX 与原版冲突时**优先级以 DBX 为准**。
4. **AI 助手 = 加分功能**：方法论/架构层增值，不与核心骨架争优先级，但其工具契约面（R8-A）已随冻结完成。
5. **后端阶段绝对优先**：后端夯实=可靠稳健优先；前端重构与融合设计在后端代码**完全冻结后独立开展**。

## §2 四大实现规范 + AI 助手（S1-S5）

### S1 源码复刻规范（DBX + DS + 原版融合规则）

**规范**：后端重构阶段**必须复刻** DBX（SQL IDE 能力面）与 DS（依赖组件）的功能实现——除非有更优方案（源码路径见头注）。

- **复刻对象 = 语义，不是载体**：复刻契约行为、组合语义、状态机、策略与判定；**不照搬** DS 存储/调度实现、DBX Tauri 壳。执行/安全/权限/审计权威始终是 Datara Backend 契约。
- **原版 SQLIDE 融合规则**：与现有原版 SQLIDE 融合；冲突歧义时**优先级以 DBX 为准**；原版 SQLIDE 在界面操作层面的特色优势，条件允许下可吸收融入。
- **复用规则（六条反馈 1）**：DBX 模块后端=能力复刻（本阶段）；前端=后冻结阶段独立开展；不得在未充分理解需求时盲目开发。
- **「更优方案」例外判定**（防逃避复刻）：①须**提前沟通确认**（时点前置，不得先斩后奏）；②证明**全覆盖**被复刻语义（逐项对照源码锚点，不允许静默省略——A2 v1 五项静默省略为反面判例）；③文档明示对照表+**取得用户批准**。无批准记录即按 DS/DBX 语义执行。
- **诚实纪律（六条反馈 3）**：严禁偷懒或隐瞒实现细节——复刻实现细节须在 evidence/契约文档可追溯。
- **验收锚**：每项复刻能力可回溯源码锚点（研读映射 §1/§2 逐行锚点列）；锚点缺失=验收不通过。

### S2 验证分层与页面参考规范

**分层**：

| 层 | 载体 | 职责 | 时点 |
|---|---|---|---|
| 契约接线验证层 | 现 R 系列验证面板 | 验证后端契约接线（TDD/哨兵/包络/门禁），并承担后端功能的**可视化与交互性验证** | 后端夯实阶段（现在） |
| 功能验证与前端重构层 | 功能验证页+正式前端 | 功能完整性/UX/交互验证 | 后端全部冻结后单独立项 |

- **页面参考标准（条款二）**：每个独立测试页面必须以**被测产品/组件自身的前端交互逻辑**为参考（DS/DBX/DataX/Vanna/OpenMetadata/DataHub 的 UI+使用文档+源码），以**真实表单字段、默认值、校验规则、交互顺序、结果反馈**五要素作为验收依据。**禁止**：以 Datara 旧版正式前端为参考标准（设计专门说明除外）；把仅能点击 API 按钮的调试面板称作功能验证页。
- **双向复刻逻辑（注解）**：后端严格参考第三方=低试错成本功能集成；前端页面参考同批组件=组件到页面的一体化方案；前端参考仍**以后端实现为根本**；仅当集成问题所迫才允许自创。
- **既有面板对齐方式**：R 系列面板=契约接线验证层，本就不称功能验证页；各批次接线时 View 深化按五要素校准（R7 批 View 深化即此方向），不单独立项返工；完整功能验证=后端冻结后独立立项（五要素为该立项验收标准）。
- **验收锚**：路由隔离与负断言锁（`rebuild-validation.test.ts`）。

### S3 变量体系契约化规范（系统灵魂）

**规范**：**所有支持输入文本的位置均可引用不同命名空间的变量**（`${scope.name}` + `$[时间表达式]`）；基于旧版现有实现**统筹优化与能力拔高**，达成统一契约标准（R2 已冻结域）。

- **定性（条款四注）**：变量规范及相关功能是**整个系统的灵魂**——后端各组件数据交互、设计时/运行时/维护时数据透传的基石；为工作流设计、调度任务设计、数据脚本编写、数据开发编程提供基础支撑。验收从严：三时态透传覆盖须有契约面证明。
- **SQL IDE 分工（六条反馈 5）**：后端核心职责=**资源管理与能力引入**；**变量体系实现=该模块核心重点工作**（执行前经共享变量解析服务消解引用、产出不可变解析快照回传，沿 R2 run-snapshot 语义）；编辑器补全/校验交互=前端重构阶段，暂不纳入后端阶段范围。
- 作用域真源：设计 §5 七级优先级链 `run > task > workflow > project > global > env > builtin`（收窄须用户批准）。
- 与 DS `parameterPassing` 关系：观察项，随 A5 议程裁定；默认倾向变量引用替代。

### S4 DS 全链路复刻规范（依赖组件，核心骨架节点）

**规范**：纠偏方案「只对照任务/周期/日期/AND/OR」收窄口径被复刻令覆盖——按 DS 源码**全链路复刻** + 按设计 §6.5 扩展；依赖组件**必须 100% 过硬**实现全部功用。契约面以 A2 v2 为准，九能力对照：

| 用户条款三九能力 | A2 v2 契约面 | DS 源码锚 |
|---|---|---|
| 工作流依赖 | `kind: workflow` | `DependentItem.dependentType=DEPENDENT_ON_WORKFLOW` |
| 任务依赖 | `kind: task`（缺省=整工作流成功，对应 `DEPENDENT_ALL_TASK_CODE`） | 同上 |
| 文件依赖 / 表状态依赖 / 外部任务依赖 | `kind: file\|table_state\|external_task`（设计 §6.5 承接，**必做**——源自权威设计而非临时自创） | Datara 扩展 |
| 时间范围配置 | 时间窗双轨：DS 命名窗输入（cycle+dateValue）+ ISO 8601 窗口输出 | `DependentUtils.java:L64-L153` |
| 轮询周期配置 | `check_interval_seconds` | `DependentParameters.checkInterval` |
| 超时配置 | `timeout_seconds` | 注解"超时"对应 |
| 满足和失败策略配置 | `dependResult: success\|failed` 极性 + `failure_policy: fail\|waiting` + `failure_waiting_seconds` | `DependentItem.dependResult` + `DEPENDENT_FAILURE_*` |
| （组合判定） | AND/OR 双层三态机 satisfied/pending/failed+timeout，照搬 DS | `DependentUtils.java:L36-L62`、`DependentExecute.java:L124-L240` |

- **100% 过硬的验收语义（A5 复刻完备性）**：九能力逐项 + DS 三态机逐分支（AND：任一 FAILED→失败/有 WAITING→等待；OR：任一 SUCCESS→通过/有 WAITING→等待/否则失败）+ `DependentExecute` 三分支（整工作流/全任务/单任务存在·禁用·成功）全覆盖对照表，静默省略即退回。
- **复刻强制、拓展非强制（条款三注）**：DS 语义复刻强制；自身业务拓展可做可不做（认为没必要非强制）；**未来新增**拓展项须走裁定。既有三扩展项源自设计 §6.5，维持必做。
- **100% 实现前不标依赖域 GREEN**（验收锚=本表逐行）。

### S5 AI 助手规范（条款五，加分功能）

**规范**：基于 Datara Backend 集成四能力：**OpenMetadata/DataHub（元数据语义源）+ 数仓语义层 + 自研 AI Agent + Vanna 工具调用思想**。

- 承载：R8-A 八工具契约（统一信封+权限+审计+12 错误码，已冻结 v1）=工具调用面，其方法论锚即 Vanna 工具调用思想；R8-B 悬浮助手+系统级验收=用户面。
- 定位：从方法论和架构层为系统提供更优实现手段（自然语言完成数据治理/开发/运维作业）；为加分功能，不与核心骨架争优先级（§0.4），但 R8-A 契约面已冻结故工具边界不可缩水。
- GREEN 前证据：假 Agent 测试+悬浮助手测试页（R8-B 门禁），以冻结契约为输入。

## §5 开放项与修订治理

1. 本标准为用户裁定链的验收化提炼，语义以用户原文为最高锚；修订须走裁定流程（提案→用户批准→新版本号+心跳通报），不得静默修订。
2. 不改批次序（R2→R4→R7→R5-A→R5-B→R6→R8）与外部前置矩阵；等待前置批次维持 RED 不抢跑。
3. **开放项（升格后性质）**：①DBX 对象 DDL 编辑深度——**精读必做前置**（R5-A 批次），不再是可选观察；②DBX Agent/ExternalDriver/PluginConnection 三类特殊连接语义——精读后并入 A5；③parameterPassing 取舍——随 A5 裁定。三项裁定后并入本标准对应节。
