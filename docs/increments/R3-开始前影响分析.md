## 1. R2 → R3 影响分析

| R2 已完成基线 | 对 R3 的影响 | 控制措施 |
|---|---|---|
| 专用重建 MySQL schema 和用户已创建 | 治理新表、迁移暂存与导入验证只能落在隔离 schema | 远端核对当前 schema/user 和表清单；不得碰共享旧 schema |
| `mysql-src`/`mysql-dw` 测试资源及样例已生成 | 可作为元数据采集/跨域关联的只读来源 | R3 仅执行只读探查；写操作仅在专用目标 schema |
| R2 运行记录和报告有生成时间戳验证 | R3 新运行/导入记录复用 DB 默认生成时间戳约定 | MySQL 真实插入后逐列断言 `created_at/updated_at/generated_at` |
| 18091 独立验证页面链路已存在 | R3 仍须有可操作的治理 UI，而非只用 API/curl | 页面按 OpenMetadata/DataHub 对应资产目录、标签、血缘/质量交互组织，browser-use 失败按技能切 Playwright 同页 |
| 正式前端和旧 Backend 冻结 | 不能调用旧 API 或向旧业务表写入 | 只在 `rebuild/` namespace 增加实现；旧 I18-I23 先只读适配 |

## 2. 范围和非目标

R3：完成 I18-I23 资产承接的只读盘点与新治理模型基线，涵盖 data asset、metadata/tag、table/column lineage、quality、standard、project/role authorization、operation audit、semantic/indicator 查询边界，以及迁移 dry-run/导入校验契约。按用户裁定，内部系统首期不实现敏感值识别、列级脱敏、敏感值加密或密级驱动的内容隐藏；历史 `security_level` 仅作为可迁移/展示的治理属性，不等同于安全控制。

R3 不实现 SYNC/核心节点执行器（R4），不修改旧 API/旧表/正式前端，不清理旧数据，不把 OpenMetadata/DataHub 设为 Datara 工作流/执行状态真源。治理迁移默认 `dry_run=true`；写入新治理 schema 前须有源/目标计数、键冲突策略、可重复执行条件和回滚证据。

## 3. 认证与验证页面前置

- 验证 UI 不展示登录表单；受控运行器从部署环境取得统一 Backend 验证 key，通过后端专用 bootstrap 交换短时受限 token，并在测试上下文注入 token。
- Key 不进入静态页面、URL、浏览器 localStorage/sessionStorage、证据截图、源代码或日志。验证 bootstrap 未配置或未启用时必须 fail closed。
- 页面按 OpenMetadata/DataHub 可核实的产品交互构建：资产目录/搜索过滤/详情、标签与业务域、血缘图、质量检查结果、权限拒绝与操作审计；页面显示预置 fixture 供人实际修改/筛选/浏览，不是 API 操作按钮集合。
- 现有 R1 页面的人类账号密码登录证据仍是其历史验收证据，但不满足新验证 bootstrap 契约。受影响的页面/auth 需列入 R1 carry-forward，在适配和复验前不纳入 Backend 冻结通过条件。

## 4. 逐步执行

1. **R3-S1 只读核查**：本机读取迁移清单、新旧模型和测试；远端只读采集隔离 schema 状态、I18-I23 相关表 DDL/行数/主键/索引/最近写时间及日志。保存源指纹与时间戳，不复制敏感数据。
2. **R3-S2 契约与失败测试**：定义新治理实体、外部 ID、唯一键、迁移批次/检查点/审计、时间戳和权限上下文；先建立 schema/API/校验/回滚失败测试。
3. **R3-S3 新模型与迁移适配**：建立独立 SQLAlchemy 模型和版本化迁移；旧数据 adapter 只读源端、写隔离目标端，支持 dry-run、幂等键、冲突报告、计数校验和可恢复批次。
4. **R3-S4 查询/治理 API**：实现资产/标签/目录、表与字段血缘、质量规则与运行摘要、标准/语义对象、项目/角色授权和操作审计的最小可验证契约；所有路由经过 RBAC/项目范围检查。不得新增敏感值脱敏/加密/内容隐藏实现。
5. **R3-S5 参考式验证 UI**：准备项目自有 R3 页面和 Playwright 场景，以目录搜索、详情、标签筛选、血缘导航、质量结果、无权限拒绝为主路径；预置数据可编辑但不得预置绕过 API 的结果。
6. **R3-S6 本地稽核**：运行新模块单元/契约测试、迁移 dry-run 测试、SQL 安全/权限逻辑审查、ruff/compileall；仅代码检测，不启动本地容器或 DB。
7. **R3-S7 远端资源与迁移演练**：在 192.168.1.9 隔离库应用迁移，先 dry-run，再可回滚的最小样本导入；检查计数、重复执行、冲突、事务/断点恢复、DB 默认时间戳和后台日志。任何失败先回滚专用目标库并保留证据。
8. **R3-S8 页面闭环与收尾**：验证器取短时 token 后由 browser-use 操作 R3 页面；browser-use 控件访问阻塞时，按技能对同一 URL 重试一次后切 Playwright。核对浏览器请求、API、数据库、权限结果和容器日志；落盘截图/结构化报告与时间戳；更新计划、设计和台账，列出 PASS/PARTIAL 及遗留项。

## 5. 证据与验收

证据目录：`docs/increments/evidence/R3/`。至少包含 `impact-analysis.md`、`local-tests.txt`、`remote-schema-inventory.txt`、`migration-dry-run.txt`、`migration-rollback.txt`、`remote-runtime-logs.txt`、`browser-entry.txt`、页面截图与结构化 browser report。

R3 只有在源资产映射和迁移计数可解释、重复导入幂等、失败回滚成功、目标端时间戳由 MySQL 生成、RBAC/项目边界生效、参考式页面控件操作及真实后台日志闭环后才能 PASS。用户已裁定不实现敏感数据脱敏，因此不把敏感值扫描/脱敏列为验收项。API 单测、静态页面、curl 或浏览器内直接打 API 均不能代替控件级验收。若浏览器桥接阻塞但 Playwright 完整完成相同 UI 控件闭环，单独记录 `browser-use: BLOCKED` 和 `Playwright: PASS`，仍需其余全链路门禁通过。
