## 4. 偏差清单

### D1：dialect 硬编码为 "mysql"（HIGH）

- **位置**：`policy_snapshot.py:55`
- **现状**：`dialect="mysql",  # TODO: 从 datasource 获取真实方言`
- **契约依据**：#22 方法签名含 `datasourceId`，暗示 dialect 应从 datasource 解析；#22 行为约束要求 policy 评估正确
- **影响**：非 MySQL 数据源（PostgreSQL/SQLite）的 DDL 策略评估将使用错误的方言规则，可能导致误判或漏判
- **严重度**：HIGH
- **建议**：`evaluate_and_snapshot` 接收 `datasource_id` 后，从 datasource 配置解析真实 dialect，传入 `PolicyEvaluator.evaluate(dialect=...)`

### D2：PolicyEvaluator.evaluate() 不接收 datasourceId（MEDIUM）

- **位置**：`policy_evaluator.py:29-37`
- **现状**：`evaluate(*, dialect, object_kind, current_definition, current_definition_digest, expected_definition)`
- **契约依据**：#22 方法签名为 `validatePolicy(datasourceId, objectRef, sourceVersion, nextDdlText)`
- **影响**：evaluator 无法自行解析 dialect，调用方必须预先解析；当前调用方（snapshot 服务）硬编码 dialect
- **严重度**：MEDIUM
- **建议**：evaluator 可选接收 `datasource_id`，或保持无状态但在文档中明确 dialect 解析责任在调用方

### D3：validate_snapshot 抛出 ValueError 而非结构化错误（MEDIUM）

- **位置**：`policy_snapshot.py:114-127`
- **现状**：`raise ValueError(RbErrorCode.SOURCE_VERSION_CONFLICT)` 等
- **契约依据**：#22 "revision 漂移返回 409"；§2.1 "失败保留现有数值 code 兼容，同时在 data.errorCode 给稳定域错误枚举"
- **影响**：facade 层需捕获 ValueError 并映射为 HTTP 409 + `errorCode`；当前实现未直接产出契约要求的错误响应结构
- **严重度**：MEDIUM
- **建议**：定义 `PolicySnapshotError` 异常类（含 error_code + http_status），或让 validate_snapshot 返回结构化结果对象

### D4：POLICY_BLOCKED 错误码未在评估器中使用（LOW）

- **位置**：`rb_errors.py:13`、`policy_evaluator.py`
- **现状**：`RbErrorCode.POLICY_BLOCKED` 已定义，但 evaluator 仅设置 `blocked=True`，不抛出该错误码
- **契约依据**：#22 "block 必须服务端禁止进入 confirm"
- **影响**：facade 需自行检查 `blocked` 并抛出 `POLICY_BLOCKED`；evaluator 未直接产出该错误码
- **严重度**：LOW
- **建议**：在 facade 层文档中明确：检查 `blocked` 后抛出 `POLICY_BLOCKED`（409 或 400）

### D5：未产生 info 级别 finding（LOW）

- **位置**：`ddl_policy.py`
- **现状**：所有 finding 级别为 `block` 或 `warn`，无 `info`
- **契约依据**：#22 `level: block|warn|info`
- **影响**：契约允许 info 级别，实现未使用；不构成违约，但 info 级别语义缺失
- **严重度**：LOW
- **建议**：保留 info 级别供未来扩展；或在文档中说明 v1.0 不产生 info

### D6：snapshot_id 命名 snake_case（LOW）

- **位置**：`rb_models.py:42`
- **现状**：字段名 `snapshot_id`
- **契约依据**：#22 返回 `snapshotId`（camelCase）
- **影响**：wire 层需 facade 做 camel/snake 适配；契约 §3 末尾已说明"FE facade 对新增字段/分页 envelope 做显式 camel/snake 与 ID 适配"
- **严重度**：LOW
- **建议**：facade 层做 `snapshot_id` → `snapshotId` 映射

### D7：PolicySnapshot 含契约未要求的额外字段（LOW）

- **位置**：`rb_models.py:40-52`
- **现状**：`project_id, datasource_id, object_ref, source_version, next_ddl_digest, policy_version, created_at, expires_at` 均不在契约 #22 返回结构中
- **契约依据**：#22 返回 `{findings, snapshotId, blocked}`
- **影响**：这些是内部快照管理字段，不应出现在 wire 响应中；facade 需过滤
- **严重度**：LOW
- **建议**：facade 层仅映射 `findings, snapshot_id, blocked` 到 wire 响应

### D8：current_definition / current_definition_digest 为契约外扩展（LOW）

- **位置**：`policy_evaluator.py:34-35`、`policy_snapshot.py:37-38`
- **现状**：evaluator 和 snapshot 服务均接收 `current_definition` 和 `current_definition_digest`
- **契约依据**：#22 方法签名不含这两个参数
- **影响**：实现扩展了 preimage 校验能力，契约未要求但不违约；属于实现增强
- **严重度**：LOW
- **建议**：在实现文档中说明此为契约外扩展，用于 preimage 完整性校验
