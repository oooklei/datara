## 1. 构建策略总裁定

**演进式改造现有 `datara-newweb`，不重写、不换栈。对标真源 = 旧前端冻结版（18093 + 源码），数据真源 = rebuild 后端。**

依据（实测事实）：
- 技术栈已齐：Vue 3.5 + Vue Router 4 + Pinia 4 + Vite 8 + Element Plus 2.14 + ECharts 6（npm 本地包）+ CodeMirror 6 + splitpanes + vitest；无新增运行时依赖。
- 新前端 `menu.ts` formal 项 A1+B1+C2+D2+E13 = 19 项（本方案 §2.1 冻结）；B 组五项（运行实例/日志/调度/变量/依赖）在任务中心页内承载，同步/流为 embedded 不设菜单。
- 壳层、项目作用域路由、双主题、工作台 KPI/三图、DAG 三栏、CodeMirror IDE、LongCat-2.0 连通均已在 1.9 真实存在。
- `projectMenu.ts` 已具备项目侧栏生成、活跃项目记忆、电商项目优先选中（删"电商数据全域治理项目"旧名兜底）、别名集合。

本方案 = 旧前端交互形态 + rebuild 真实契约 + 新前端壳层现状的交叉互齐融合工程（§7.5），产出物全部落在 `datara-newweb` 与 `datara-backend/rebuild` 的增量修改。

### 2.2 视觉与交互基准（原型已废弃，基准改为真实系统）

**视觉基准 = 旧前端冻结版 18093 的页面密度、布局与组件形态；壳层主题/项目作用域/全局入口保留新前端已实装形态**（`designTokenClosure.contract.test.ts` 继续作为令牌闭环守卫）。

- 布局：左侧栏 + 顶栏（项目切换/面包屑/部署运维/系统管理/主题/用户）+ 主工作区自适应占满高度；紧凑密度、清晰字阶，与旧前端一致。
- 工作台：双 KPI 带（管线 6 卡：工作流总数/调度启用/近7天成功/近7天失败/运行中实例/最近调度批次；治理 6 卡：数据源/资源/质量规则/未处置异常/告警策略/资产·标准·指标）+ 三图（近7天运行趋势、工作流类型分布、运行状态分布）+ 最近运行实例表。

- SQL IDE：元数据树 | 编辑器 | 结果区三分割（splitpanes 持久化）+ 工具行（执行/停止/格式化/变量校验/GlobalParamDrawer/血缘/保存脚本/历史/CSV 导出）。
- 交互：弹窗默认可拖动 + 视口钳制 + 位置记忆；AI 助手全局浮动窗参照弹窗同一拖拽规则；侧栏宽度可拖拽调整并持久化；toast 仅作操作回执不作完成标志；明暗主题根变量切换。
- 滚动基线（全站强制）：所有表单页与交互展示页内容超出视窗自动出现右侧滚动条；菜单/页面/Inspector/Palette/弹窗体/AI 面板各有独立正确滚动容器，禁止内容截断。

## 8. 风险与依赖

1. P0 数据前置未完成则 UI 验收被脏数据误导——seed 幂等脚本是 P1–P4 的硬依赖，先于一切页面改造。
2. HttpOnly 会话改造触及登录闭环与 1.9 现有部署态，需与反向代理超时配置同批验证。
3. 聚合端点（D7）为唯一新增后端契约，若排期冲突则按降级 fan-out 先行，但禁止 N+1 逐工作流拉取。
4. 验证项目迁移（G04）涉及数据库隔离，需在 1.9 运维窗口执行；本机不承担部署验证。
5. Ark/SiliconFlow 密钥无现存记录，恢复实施前需人工保管值重新注入，不伪造。
6. 融合页"旧形态 × 新契约"字段不完全同构（旧 mock 字段多于或少于真实契约），逐页需一次契约对齐审查；decisionGate 类（部署中心/组件日志/运维操作/部署告警）若用户要求强制实现，须先立项后端域，前端不得先行。
7. S9 资源树根节点化需要后端"按用户可见数据源列表 + 逐级鉴权"契约就绪（sql_ide routes 已有项目级鉴权，需确认数据源粒度鉴权端点）；若后端仅支持项目粒度，则根节点过滤由前端以数据源列表+成员关系预过滤，展开鉴权由既有端点 403 兜底。
