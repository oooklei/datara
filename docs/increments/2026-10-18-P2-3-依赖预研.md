# P2-3 依赖预研：R5-B 写入闭环对 P2-2 GREEN 的依赖分析

**生成时间**: 2026-10-18
**生成者**: Claude 实施线
**用途**: P2-2 GREEN 后立即开工的 R5-B 写入闭环设计输入

## 1. 概述

R5-B 写入闭环依赖 R5-A 只读能力（P2-2 Track A 已交付的生产基础设施）。本文档分析 R5-B 对 P2-2 GREEN 的依赖关系和写入链路缺口。

**依据**: A5 契约 v1.0 §1.1/§3 #21-#25/§6

## 2. R5-B 五个 facade 方法（A5 契约 §3 #21-#25）

| # | 方法 | 依赖的 R5-A 能力 | 依赖的 P2-2 组件 |
|---|------|------------------|-------------------|
| 21 | `getDefinition(datasourceId, objectRef)` | #18 shared read | SqlExecutionPort（只读连接） |
| 22 | `validatePolicy(datasourceId, objectRef, sourceVersion, nextDdlText)` | DDL 策略引擎 | ddl_policy.py（已有） |
| 23 | `previewImpact(datasourceId, objectRef, sourceVersion, nextDdlText)` | 元数据目录+血缘 | DatasourceEngineRegistry（已有） |
| 24 | `submitConfirm(request)` | 执行器+回滚 | **缺口：无生产执行器** |
| 25 | `listExecutionRecords(datasourceId, objectRef?)` | 历史/审计存储 | SqlIdeAuditRecord（已有） |

## 3. 依赖分析

### 3.1 直接依赖（P2-2 GREEN 后立即可用）

- **#21 getDefinition**：复用 #18 shared read，依赖 SqlExecutionPort 只读连接
  - P2-2 状态：✅ 已交付（Gap 1+2）
- **#22 validatePolicy**：依赖 ddl_policy.py 策略引擎
  - P2-2 状态：✅ 已有（17 测试覆盖）
- **#25 listExecutionRecords**：依赖 SqlIdeAuditRecord 存储
  - P2-2 状态：✅ 已交付（Gap 3）

### 3.2 间接依赖（需额外组件）

- **#23 previewImpact**：依赖元数据目录+血缘分析
  - P2-2 状态：⚠️ 元数据目录已有，但血缘分析未实现
  - 缺口：血缘分析服务
- **#24 submitConfirm**：依赖 DDL 执行器+回滚管理
  - P2-2 状态：❌ 无生产执行器
  - 缺口：DDL 执行器、回滚管理器、确认短语验证

## 4. 写入链路缺口清单

| 缺口 | 描述 | 依赖的 P2-2 组件 | 优先级 |
|------|------|-------------------|--------|
| G-B1 | DDL 执行器（只写路径） | 无（需新建） | P0 |
| G-B2 | 回滚管理器 | DDL 执行器 | P0 |
| G-B3 | 确认短语验证 | 无（需新建） | P0 |
| G-B4 | 血缘分析服务 | DatasourceEngineRegistry | P1 |

| G-B6 | 策略快照绑定 | ddl_policy.py | P1 |
| G-B7 | 影响预览快照 | 血缘分析服务 | P2 |

## 5. P2-2 GREEN 对 R5-B 的前置条件

R5-B 开工前必须完成：
1. **P2-2 GREEN**：R5-A 只读基础设施全部验收通过
2. **A5 冻结生效**：会签回执落库
3. **P2-1 冻结生效**：retry/failover/backfill/priority 全部验收

## 6. 结论

- R5-B 的 #21/#22/#25 可直接复用 P2-2 已交付组件
- R5-B 的 #23/#24 需要额外组件（血缘分析、DDL 执行器、回滚管理器）
- P2-2 GREEN 是 R5-B 开工的前置条件
- 建议 P2-2 GREEN 后立即启动 R5-B 设计深化
