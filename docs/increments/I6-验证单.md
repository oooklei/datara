## 4. 问题修复留痕（实测期间）

### 4-1 缺陷①：master 侧执行器白名单漏 sync（阻塞级，产品缺陷）
- 现象：部署后实例秒败，任务日志 `[master] 执行器未实现（后续增量注册）: sync`、outputs={"error":"executor_not_implemented"}；worker EXECUTORS 已含 sync（部署自检过）但 master 不派发（worker 日志无消费活动）
- 根因：master 侧节点类型白名单三处均未注册 sync——`master/engine.py` WORKER_TYPES（执行器分派/超时扫描/容错重派共用）、`master/failover.py` WORKER_TYPES（容错恢复）、`master/dag.py` WORKER_TYPES（死代码，一致性同步修）
- 修复：三处补 `sync` → 本机 py_compile/ruff → 增量 scp → 重建 datara-master → 容器内自检 MASTER_WHITELIST_OK
- 教训：worker 注册≠master 可派发，新增节点类型必须两侧同加（已记 project_memory）

### 4-2 缺陷②：sync 读端 SSCursor 漏 execute（产品缺陷）
- 现象：白名单修复后实例 ~12s failure，任务日志 `[sync] 执行异常: ProgrammingError('execute() first')`；自动建表/SQL 拼接日志均正常
- 根因：`worker/executors/sync.py` `_sql_row_iter` 创建 SSCursor 后直接 `fetchmany`，从未 `cur.execute(select_sql)`（抽取 SQL 仅被日志打印）
- 修复：fetchmany 前补 `cur.execute(select_sql)` → 本机验证 → 重建 datara-worker
- 佐证：MySQL 读端场景全部转绿；文件读端（不走 SSCursor）在缺陷②未修复时即已可用
