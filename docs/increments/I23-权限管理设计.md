## 0. 目标与用户裁定

### 0.1 目标

将权限管理、脱敏规则、访问审计 3 页从演示态转为真实通道，并建立**统一数据访问控制层**：密级+业务域数据权限判定、列级脱敏应用于全部平台数据读取通道、访问审计全量落库。

### 0.2 用户裁定（2026-10-11，全程有效）

| # | 裁定 |
|---|---|
| R1 | 脱敏生效范围=**全部平台读取通道**：IDE 查询、元数据样本、质量样本、看板取数等统一走 fetch_masked 出口；结果集行数受平台既有 LIMIT 约束 |
| R2 | 审批权限=**admin+dev**（维持 I22 现文 `std:approve` admin/dev）；演示矩阵 SecPermView dev「审批」列实施时同步为 √，以与实际权限一致 |

### 0.3 本期不做

字段级权限（仅列级脱敏）、行级过滤（业务域拦截到表级）、动态脱敏策略编排（仅规则匹配）、LDAP/SSO 对接。

## 1. 总体架构

```
数据权限判定（密级+业务域）              脱敏（列级）
user.clearance ≥ 表.security_level       命中规则列 → mask / replace / hash_sm4
且 表.biz_domain ∈ user.domains（空=不限） 统一出口 fetch_masked(user, ...)（common/access_control.py）
admin 例外全通过                          每次数据读取写 t_access_log（允许/拒绝+原因）
```

统一接入点（4 处，全部改走 fetch_masked）：IDE 查询（ideApi）、元数据样本预览（meta sample）、质量样本预览（qc sample）、指标看板取数（ind trend/breakdown）。拒绝返回 403 附判定原因。

## 2. 数据变更（t_user 扩 2 列 + 新 2 表，含 create_time/update_time）

| 对象 | 内容 |
|---|---|
| `t_user` 扩展 | clearance(String16 默认'内部'：公开/内部/机密/绝密)；domains(JSON 业务域数组，空=不限域；admin 例外全通过) |
| `t_mask_rule` | type(手机号/身份证号/银行卡号/姓名/邮箱/自定义) / strategy(mask、replace、hash_sm4) / field_pattern（列名正则） / data_pattern（数据正则 nullable） / enabled / params_json（替换值/掩码格式）；种子=5 内置类型（仅可停用不可删） |
| `t_access_log` | ts / user_name / action / target(ds/db/table) / rows / result(允许、拒绝) / reason；Index(ts)、Index(user_name) |

密级解析顺序：t_dw_model.security_level（按 code 匹配）→ t_meta_table_ext.security_level（按 ds+db+tb）→ 默认'内部'。

## 3. 后端 API（/api/v1 前缀，ok()/ApiError 规范）

```
CRUD /sec/users[/{id}]        # 用户管理（admin only）：新增（bcrypt 初始密码）/改角色/许可/授权域/启停/重置密码
GET  /sec/role-matrix         # 角色权限矩阵（ROLE_PERMS 派生，非硬编码）
CRUD /sec/mask-rules[/{id}]   # 脱敏规则 CRUD + 启停（内置规则仅停用）
POST /sec/mask-scan           # 敏感发现：勾选数据源 → 抽样+列名+正则 → 发现清单
GET  /sec/access-logs?user=&result=&keyword=&page=   # 审计日志 + 允许/拒绝统计
```

- common/access_control.py：`check_table_access(user, ds_id, db, table) -> (allow, reason)`（拒绝写拒绝日志）；`apply_mask(columns, rows)`（列名匹配优先、值正则兜底，SM4 不可逆）；`fetch_masked(user, ...)` 统一出口（判定→执行→脱敏→写允许日志含行数）
- 权限：用户管理与脱敏规则=`sec:write`（admin）；审计查看=登录即可；矩阵只读
- 审计：用户管理/脱敏规则变更写 logger（audit.sec）；数据访问本身即 t_access_log
- 禁用用户 token 立即失效（get_current_user 校验 state）

## 5. 关键规则

- admin 全通过（功能+数据）；analyst/viewer 按许可与域访问
- domains 空=全部业务域；非空=仅列表内；密级判定取 SEC_ORDER[user.clearance] ≥ SEC_ORDER[table_level]（相等允许）
- 脱敏在结果集返回前应用；SM4 哈希不可逆
- 内置 5 类脱敏规则不可删除仅可停用
- 拒绝判定原因两类：密级不足 / 业务域未授权

## 6. 错误处理

| 场景 | 处理 |
|---|---|
| 数据访问被拒 | 403 附原因，前端提示；审计记拒绝 |
| 重置密码 | 新密码 bcrypt 存储，返回一次性明文提示（不落日志） |
| mask-scan 数据源不可达 | 跳过该源并计入结果摘要 |
| 内置规则删除 | 409「内置规则仅可停用」 |
| 密级/域配置缺失 | 默认'内部'+不限域，不阻塞读取 |
