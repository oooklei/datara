## 1. 目标与边界

首期用一组后端环境变量配置 OpenAI-compatible 模型调用，由 Datara 配置对象校验并注入 AI 适配器。LLM 供应商和协议是模型调用配置；不取代 Datara 项目、用户、数据源、权限、审计、变量或 SQL 执行主权。

P1-2 只负责统一模型配置读取、校验与 provider adapter。Vanna / 自研 Agent 的工具调用只访问 Datara 授权工具；SQL 执行须经 R8-A `run_sql` 授权通道及 Datara 项目/数据源权限和只读限制。不得向模型或 Vanna 直传生产数据库凭证，不允许请求体覆盖全局 API key/base URL。

本配置不扩展 DBX datasource 模型，也不定义 OpenMetadata/DataHub/数仓语义层的配置。项目级多供应商密钥若后续需要，应另立数据模型、vault 引用、隔离与权限审查，不从本机全局 env 配置推导。

## 2. 配置 Schema 建议

| 环境变量 | 类型/语义 | 缺省与校验 |
|---|---|---|
| `LLM_PROVIDER` | 字符串供应商/路由标识。当前确认值为 `siliconflow`；建议 provider adapter 将供应商选择与 OpenAI-compatible wire protocol 分层建模。 | 四项全空时关闭真实 LLM；任意一项配置后，provider 必须显式存在且在 allowlist（首期至少包含 `siliconflow`）。未知值启动校验失败或禁用 LLM 并给稳定配置错误，不静默 fallback。 |
| `LLM_BASE_URL` | HTTP(S) API 根 URL；具体 endpoint path 由 adapter 拼装。 | 按 provider 必需性校验；scheme 仅允许 http/https，规范化末尾斜杠。生产配置拒绝明文 HTTP，开发时仅允许受限 loopback/明示例外。不得因 URL 缺省静默切换供应商。 |
| `LLM_MODEL` | 上游实际模型/部署名，不作抽象模型等级推断。 | 任何非空配置都要求显式 model；不硬编码跨服务商“万能默认模型”，未配置时不进行真实调用，不静默降级到另一模型。 |
| `LLM_API_KEY` | Secret 类型（建议 Pydantic `SecretStr`），仅进进程运行时内存。 | 仅允许被信任的部署环境注入；不写数据库、项目配置、文件、缓存、prompt、审计事件或异常文本。空值仅在 provider 明确支持匿名时允许。读出/序列化/日志一律脱敏。 |

组合校验规则（待实现验证）：四项全部为空代表 `llm_enabled=false`，应用正常启动，假 Agent/冻结工具契约仍可用；只要任一项非空，就进入显式配置模式，校验 provider、model、URL 和认证字段。部分配置不完整时禁止真实模型调用并提供稳定诊断，不做静默默认、服务商猜测或降级回退。当前 `.env` 已有心跳 #70 所述四项有效配置，但 `Settings` 尚未声明这些字段，故不能把该事实表述为代码已消费或应用级校验已通过。

`common/config.py` 当前 `extra="ignore"` 可能让拼错 env 名被静默忽略；建议为 LLM 字段单独提供 `validation_alias`/设置名核验和不含密钥的诊断，不要为解决这一点全局切换 `extra="forbid"` 破坏现有配置兼容。

## 3. 调用策略建议

- 建议默认 connect timeout 5 秒、单请求/工具循环总超时先设 60 秒；最终值由 P1-2 adapter 配置和 PoC 实测裁定，避免重试导致超出总预算。
- 最多 2 次有界指数退避并加抖动；尊重上游 `Retry-After`。仅对连接错误、408、429、5xx 等可重试传输/服务失败重试；400/401/403/404、模型/参数错误不得重试。
- 工具调用有副作用风险：不得自动重放已执行或执行状态未知的 SQL 工具调用。模型请求重试与工具执行重试必须分开幂等建模。
- request/correlation ID 贯穿调用和工具结果；稳定记录 provider/model、耗时、结果类别及上游 usage（若提供），不记录 API key 或完整敏感 prompt/SQL。
- 对前端返回稳定错误码和脱敏说明；内部只记异常类型、trace ID 和安全诊断，不输出 Authorization header、完整环境变量或 secret repr。

## 4. 适配器契约边界

1. 启动期只构造已校验的全局模型 adapter；若未配置则显式 disabled，假 Agent/工具契约可独立验收。
2. Vanna 与自研 Agent 只依赖 Datara 抽象接口，不暴露 Vanna SDK/provider-specific 类型到 R8-A 契约。
3. 用户身份/项目/数据源权限由 Datara 服务端 session/context 注入；不能信任客户端传来的 `user_id`、`project_id`、`conversation_id` 作为授权事实。
4. `generate_sql` 与 `run_sql` 分离。生成 SQL 经过 Datara 校验/授权，执行经 Datara 只读工具、连接权限、超时/限量和审计；LLM adapter 只负责文本模型传输。
5. 探测连通性必须由显式运维操作触发，不在应用启动时消耗 token，也不向普通健康检查暴露密钥。

## 5. 落地前检查项

- 在 Settings 里明确四个变量名的 alias、字段验证与 secret 脱敏单测。
- Compose/deployment 注入按变量名白名单传递；`.env` 仅本地运行使用，必须被忽略，模板只能提供空值或占位符。
- 覆盖全空、部分配置、未知 provider、非法 URL、空 key、脱敏序列化、超时/重试边界和请求体不能覆盖全局配置。
- adapter 验收必须确认模型 key 没有写日志/数据库，AI 工具 SQL 执行没有绕过 Datara 授权和只读通道。
- 本草案未改动配置代码，也未读取 `.env`。真实连接/模型验证另走 P1-2 / P1-3 联调及 A1-A7 验收。
