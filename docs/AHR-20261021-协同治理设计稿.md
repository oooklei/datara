# 协同治理设计稿（候办票，出稿后再议）

- 来源：AHR-20261021-DATARA-01（综合评分 49/100）第三节三项，用户 2026-10-21 批注 ok 立项
- 性质：设计稿=上呈材料，**批复前不动多窗写入权结构**（s280③/S269③ 纪律）
- 对应发现：[CRITICAL] 系统控制面缺失 / [CRITICAL] mailbox 无法可靠表达真实积压 / [CRITICAL] 循环程序与单写者规程漂移 / [HIGH] B/C 多主循环瓶颈 / [HIGH] 首读上下文过大

## 一、唯一 Event Writer + 影子对账（P0）

**现状**：mailbox.jsonl 名义单写者（R-43），实际监督线各窗（B 终裁窗/裁定执行窗/C 窗）均落过笔；撞号让渡（R-43）与尾行防撞是补救纪律而非控制面；实施线已收口为只投 outbox/{claude,codex,trae}/（s279② 通道升级令，S268② 互认「双通道过渡态」）。

**设计**：
1. **终态**：全部治理事件（ruling/task/ack/done/心跳）仅由唯一 Writer 窗落 mailbox；实施线维持只投 outbox；监督线非 Writer 窗只读+对账，不再直写。
2. **影子双轨期**：Writer 上线后，旧路径（各监督窗直写）保留并行；新路径=各窗把拟发事件投 `outbox/draft/{from}/`，Writer 统一摘取、查重、定序后落 mailbox。两路径各自运转，互不阻塞。
3. **对账指标**（只读校验器自动产出）：行号连续 / id 全局唯一 / ts 单调不减 / from 枚举合法 / 尾行防撞通过率 / DUP-ABORT 次数 / 双轨内容一致率。
4. **切换条件**：连续 3 个监督日对账零差错 + 用户批准 → 收敛写入权，旧路径关闭。

**解决**：并发截断/覆盖/撞号漂移三风险；Writer 单点由 A/B/C 角互备接任规则兜底（Writer 挂起 >15 分钟，次序 C→A→B 自动候补接管，接管声明落 mailbox）。

## 二、event-envelope v2（P0）

**现状**：mailbox 每行 `{id,ts,from,to,type,ref,body,status}` 字段松散；task 状态无枚举（积压=人工解释，AHR CRITICAL-2）；幂等靠 id 后缀约定；校验是监督线人工纪律（s280④）非机器 schema。

**设计 v2**（向后兼容，v1 行不回填、按 v1 规则读取）：

```json
{
  "v": 2,
  "id": "s283-<slug>-<yyyymmdd>",
  "ts": "2026-10-21T10:40:00+08:00",
  "from": "supervisor-c | supervisor-exec | supervisor-b | claude | codex | trae",
  "to": "all | supervisor | claude | codex | trae",
  "type": "ruling | task | ack | done | query | notice",
  "ref": ["<被引事件 id>"],
  "task": { "ticket": "17.2-19", "state": "assigned | in_flight | done | accepted | rejected" },
  "manifest": { "files": [{ "path": "...", "sha256": "..." }], "base_commit": "..." },
  "idempotency_key": "<from>:<type>:<ticket|slug>:<yyyymmddhhmm>",
  "body": "..."
}
```

要点：
1. **task.state 五态枚举**：积压=state∈{assigned,in_flight} 实时计数，验收池=done，销项=accepted——mailbox 首次可机器表达真实积压，compact/续跑按 state 触发。
2. **manifest 必填规则**：type=done 时 manifest（文件清单+逐件 SHA256+基线 commit）为必填——把 s280② 报验 Manifest 三件套从纪律升为 schema 强制，缺项机器门直接拒收，退回不进验收池。
3. **idempotency_key**：Writer/校验器按 key 查重，替代纯 id 后缀约定。
4. **落地顺序（先只读后写侧）**：期1 只读校验器校 v2 schema（对 v1 行按 v1 规则放行）→ 影子期新事件双写 v2 → 切换后全量 v2。

## 三、角色级 Context Pack（P1）

**现状**：冷启动首读=STATE 全文+mailbox 尾部 N 行+权威文档三件套+裁定索引原文，固定注入大、多轮与子线程复制放大（AHR Token 效率 40/100）。

**设计**：
1. **Pack 四段**：`Policy Capsule`（角色纪律+现行裁定 R-01~R-44 逐条一行摘要，≤2K token）+ `当前任务包`（在飞票面+验收锚点+M 态漂移处置基线）+ `相邻依赖`（上下游票 state 一页）+ `evidence manifest`（证据件路径指针，不内联全文）。
2. **生成与放置**：Writer 随派单/验收结论/裁定落账三事件重生成 `docs/handoff/context-pack/{claude|codex|trae|supervisor}-latest.md`；实施线冷启动=读 Pack+STATE 头部，不再全文扫描 mailbox。
3. **约束**：Pack 是投影不是真源（真源仍=STATE+mailbox+裁定索引），冲突以真源为准；Pack 内容只增改随事件，不引入第二事实源。

**收益**：首读固定注入估降 60-70%，多窗重复首读消除，B/C 瓶颈缓解。

## 四、分期实施与候裁点

| 期 | 内容 | 写入权影响 | 前置 |
|---|---|---|---|
| 期1 | v2 只读校验器 + Context Pack 只读生成 | 无（纯只读） | 可先行，候批 |
| 期2 | Writer 影子双轨 + 对账器 | 无（旧路径保留） | 期1 运行稳定 |
| 期3 | 写入权收敛 Writer + envelope v2 全量 | **有** | 对账连续 3 监督日零差错+用户批准 |

**候裁点**：①期1 是否批准先行；②Writer 角色归属（C 窗兼任 vs 独立 Writer 窗）；③对账周期 3 监督日是否认可；④Context Pack 放置路径 `docs/handoff/context-pack/` 是否认可；⑤v2 schema 字段集是否增删。

**明确不动项**（维持现状）：三窗硬隔离（s280①）、R-43 撞号让渡、STATE ≤60 行、outbox 双通道、报验三步法、M 态漂移锚点（S270②）。
