前置：docs/数据同步工作流设计.txt（需求源）；上一轮重构（3 编排组件 + 5 细项组件）已完成并实测

## 1. 问题定性（证据）

预制的 3 个同步编排用例在画布点「校验」报 3 类警告，根因是**实现矛盾，非用户操作错误**：

| 警告 | 根因（代码证据） |
|---|---|
| 「字段映射-联合」必填项未配置：输入（前两个为目标端表/源端探测表） | ① W1 校验看表单 `inputs` 字段值（dag.ts validators L1094 + requiredMissing 判空），预制链只连边没填值；② upstream-refs 候选仅**直接前驱**（Inspector.vue upstreamOptions），串行链上字段映射-联合只有 1 个前驱，契约要求的 2 个引用**填不出来** |
| 「条件设定」必填项未配置：输入 | 同 ①，`inputs: []` 触发 requiredMissing |
| 「对账校验」分支「不通过」未连接下游 | assert ports 声明通过/不通过两端口（dag.ts L1104-1121），预制链未接不通过出口 |

深层矛盾：**契约文案（前两个=目标端/源端）↔ 串行拓扑（无法提供 2 个前驱）↔ 校验口径（表单字段）↔ 运行时口径（沿边递归收集，不读表单 inputs）** 四者互相脱节。

另有一条用户业务规则被违反：**工作流定义编排（设计态）中不允许存在运行态执行组件**（同步执行/文件入仓执行是上一轮"链内执行节点"产物，不在组件面板、却在画布出现，来历不明）。

## 2. 用户决策记录

1. **联动机制 = 端点合一组件**：源端选择 + 目标端选择合并为一个「端点选择」组件，联动在组件表单内闭环。
2. **inputs 机制 = 拖边自动填充**：连边即引用，系统按入边自动填充；契约按具名输出识别，废除"前两个"顺序索引。
3. **执行组件 = 删除**：同步执行/文件入仓执行不作为编排画布节点；执行是用户点「试运行/运行」按钮触发的系统行为，运行态物化，运行实例详情中可见。

## 3. 设计

### 3.1 端点选择合一组件（C37，type: endpoint_select）

删除 `src_select`（C32）、`tgt_select`（C33）两个细项组件及其 palette 项。

新组件 schema：

```ts
endpoint_select: {
  type: 'endpoint_select', label: '端点选择', code: 'C37', categories: ['sync'],
  outputs（具名输出端口）: sourceRef / targetRef,
  form:
    baseMode 基准类型: 'src_base' | 'tgt_base' | 'file_sync'（select，驱动全表单分拣）
    —— 源端区（src_base 模式）：srcDs(必选) + srcTable(table-picker 必选)
    —— 目标端区（src_base 模式）：tgtDs(必选) + tgtTable(可选) + autoCreate(bool "不存在则新建"，缺省 true)
    —— 目标端区（tgt_base 模式）：tgtDs(必选) + tgtTable(必选)
    —— 源端区（tgt_base 模式）：srcDs(必选) + probe(bool 缺省 true) + matchType(exact/prefix) + matchPrefix
        + probeResult(探测候选多选：参与 schema/表确认，联动数据来自 tgtTable)
    —— 源端区（file_sync 模式）：filePath/fileType/fileDelimiter/fileEncoding/fileHeaderRows/fileSheet
    —— 目标端区（file_sync 模式）：tgtDs(必选) + tgtTable(可选) + autoCreate(bool 缺省 true，建表类型按文件抽样推断)
  联动：tgt_base 模式下 tgtTable onChange → 调 API 探测 srcDs 各 schema 匹配表 → probeResult 候选刷新（formLinkage 纯函数 + Inspector 派生缓存，沿用 C22 onChange 先例）
}
```

- 具名输出端口：节点渲染两个输出口；下游 upstream-refs 引用值格式 `nodeId:port`。
- 探测 API：复用既有库表树/探测端点（api 侧已有 schema/table 枚举能力；若缺按目标表名跨 schema 匹配端点则新增 `GET /datasources/{id}/match-tables?table=&match_type=`，worker/api 共用 INFORMATION_SCHEMA 查询）。

### 3.2 设计态 / 运行态分离

**设计态编排画布（预制链新拓扑，节点 9 → 8）**：

- 源表基准：`开始 → 前置清理(sql) → 端点选择 → 字段映射-复制 → 条件设定 → 对账校验 → 结束`，对账校验「不通过」→ 消息通知
- 目标表基准：`开始 → 前置清理(sql) → 端点选择 → 字段映射-联合 → 条件设定 → 对账校验 → 结束`，对账校验「不通过」→ 消息通知
- 文件同步：`开始 → 前置清理(sql) → 端点选择(文件) → 字段映射-复制 → 条件设定 → 对账校验 → 结束`，对账校验「不通过」→ 消息通知
- 说明：前置清理(sql)与消息通知为用户可自主选用的通用组件（palette 在列），预制用例保留以覆盖"写前清理 + 不达标告警"完整业务；主链语义不受影响。

**执行组件处理**：

- `sync`（C17）/`file_sync`（C24）从编排画布与预制链删除；schema 保留并标记 `runtimeOnly: true`（运行实例详情页 NodeRunDetailPage 渲染仍需要）。
- runtimeOnly 类型：palette 排除、画布拖入排除、W1 必填/分支校验排除、保存闸门排除。
- palette「数据同步」组最终 7 项：`src_base_orch, tgt_base_orch, file_sync_orch, endpoint_select, field_map, field_map_union, condition_set`。

**运行态物化（master engine.py）**：

- 装载 doc 构建运行图时：检测到 `endpoint_select` 节点 → 在「对账校验（assert）节点」的直接前驱之后、assert 之前插入执行节点（即插入位置 = assert 的入边处；id 前缀 `sys_exec_`，类型按 baseMode 分拣：src_base/tgt_base→sync，file_sync→file_sync）；assert 与执行节点间的边继承原入边语义。
- 物化后的运行图进入既有派发流程，engine 派发逻辑零改动。
- `_merge_sync_chain_config` / `_apply_detail_config` 键映射改造：沿入边收集 `endpoint_select` 的 config，按 baseMode 产出执行契约键：
  - src_base：readerDs/readerTable（srcRef）+ writerDs/writerTable/autoCreate（tgtRef）
  - tgt_base：readerDs/readerSchemasText（probeResult 展开多 schema 表）+ writerDs/writerTable
  - file_sync：filePath/fileType/delimiter/encoding/headerRows + targetDs/targetTable/autoCreate
- 运行实例 taskInstances 含 `sys_exec_*` 步骤，名称显示「同步执行/文件入仓」，运行详情页正常打开。

### 3.3 拖边即引用（inputs 自动填充 + 具名化）

- GraphWorkbench 连边 onConnect：按 target 节点 schema 中 `upstream-refs` 字段的容量（pick.upstreamMax）自动追加引用值 `sourceNodeId:port`（默认取 source 节点第一个具名输出；endpoint_select 有 sourceRef/targetRef 两端口时按边起点 handle 确定 port）。
- 删边：同步从 target 的 inputs 中移除对应引用。
- 表单 upstream-refs 控件：显示具名引用（可微调/删除；手动追加仍限直接前驱集合）——"边=引用"恒一致。
- `field_map_union` 的源/目标识别改为**按引用端口语义**：引用 `:targetRef` 的为目标端，`:sourceRef` 的为源端（fieldMap pick 的 srcNodeType/tgtNodeType 改为 port 识别），废除 `[0]`/`[1]` 顺序索引。
- 校验与运行时同源：W1 检查的 inputs 由边派生；运行时沿入边收集——同一份数据。

### 3.4 校验规则修正

- W1 必填、孤立节点、重复边、流子图规则不变（自动填充后预制链不再误报①②）。
- 分支完整性规则保留；预制用例 assert 不通过分支接 notify 后不再报③。
- runtimeOnly 类型节点不参与任何画布校验。

### 3.5 预制用例重建与引导

- `tools/seed_sync_orch_usecases.py` 按 3.1/3.2 新拓扑重写（幂等删建；配置键换 endpoint_select 模式化键；assert → notify）。
- palette 引导：拖编排组件=物化新拓扑模板链；拖细项组件=自由搭建（端点选择 → 字段映射 → 条件设定 → 对账校验）。
- 前端测试同步重写：formLinkage.test.ts（palette 7 项断言、3 链新拓扑、endpoint_select 表单契约、拖边自动填充纯函数）、i12-components.test.ts、auth.test.ts。
