# Datara 目标设计收口与关键业务优先实现设计

**状态**：待用户书面复核  
**日期**：2026-10-24  
**目标依据**：`docs/increments/2026-10-19-纠偏重构前端权威设计.md` v3、`docs/increments/2026-10-17-核心业务功能实现规范与验收标准.md` v4、`docs/increments/2026-10-20-单线多增量WBS开发计划.md`，以及用户 2026-10-24 补充的九项最高优先级要求。

## 1. 目标与完成定义

Datara 必须形成可实际使用的数据开发和治理产品，而不是仅有路由、静态页面或契约测试。完成状态同时满足：

1. 新前端只连接重构后端，核心业务不依赖旧 API 旁路。
2. 左侧导航中的每个正式功能都有可达的右侧页面；页面上的按钮、菜单、链接、弹窗及弹窗内控件、画布和反馈状态均实现真实行为。
3. 数据开发 IDE、同步、变量、SQL/Python/Shell/依赖组件、流处理、运行统计形成端到端闭环。
4. 本机完成代码审查、编译、类型、单元和契约验证；部署、中间件、数据库、浏览器和实际运行验证只在 `192.168.1.9` 完成。
5. WBS 增量 18 的七项联通判据、八门验收、红线核验和部署固化全部有当前版本证据。

## 2. 当前状态与收拢策略

当前存在三层代码状态：隔离工作树、已提交主线、主目录未提交候选实现。主线已推进到 `40dab35`，但后端装配引用的组件规格迁移和 LLM 包仍只存在于主目录候选实现中。候选实现本机验证结果为前端 719 项测试全绿且构建成功，后端 1291 项通过、3 项失败、1 项跳过。

采用“逐域审查收拢”而非目录整体复制：每批从候选实现提取源码、测试和装配三者，确认契约与目标一致后落入隔离工作树。第一批必须先恢复应用可导入、pytest 可收集、前端可构建的健康基线。已确认需处理：组件规格迁移缺失、LLM 域未入库、运行统计测试基线漂移、SQLite 唯一索引断言可移植性、旧 token 表 `token_digest` 回填缺陷。

## 3. 最高优先级业务设计

### 3.1 数据开发 IDE

IDE 以项目和数据源为上下文，提供跨 Schema 对象树、SQL 编辑、变量补全与引用校验、多语句执行、结果集分页、多结果集、历史、取消、导出、SSE 状态恢复和运行实例状态。DDL 写路径包含结构化表编辑与非表对象源码编辑两轨，并完整实现预检、影响分析、人工确认、执行、审计、发布和回滚。任何写操作必须经过明确确认，预览不得泄露样本值。

### 3.2 DAG 工作台与核心组件集合

Palette 默认聚焦以下生产组件：

- 同步类：源端、目标端、文件同步、端点选择、字段映射、联合字段映射、条件集；设计态隐藏 runtime-only 执行节点。
- 流类：输入、处理、输出和观摩板所需最小集合。
- 通用核心：SQL、Python、Shell、依赖、开始、结束以及确有连线语义需要的控制节点。

非目标组件不进入默认 Palette；已发布定义仍按固定 `componentRef {type, version}` 可回读和运行。拖边自动派生具名 `nodeId:port` 引用，保存前执行组件 spec、端口、必填参数、循环和运行可达性验证。

SQL、Python、Shell 组件分别支持编辑内容、变量引用、资源引用或运行参数、超时、重试、退出状态和标准输出摘要。三个组件必须各有真实工作流样例，覆盖成功、失败和变量传递。

### 3.3 同步工作流

同步工作流作为 `/dag` 内独立 profile，而非单独菜单。端点选择组件支持 `src_base`、`tgt_base`、`file_sync` 三模式；字段映射先探查生成，再允许用户修改；表单包含连接、表/文件、字段、批次、重试、失败策略和校验反馈。运行时由引擎物化执行节点并按模式分拣。

至少提供并验证五类样例：全量表同步、增量表同步、目标反推源、文件入仓、多表并行。每个样例必须覆盖创建、表单配置、保存、试运行、正式运行、状态观察、记录数统计和错误反馈。

### 3.4 变量管理

变量解析优先级固定为 `run > task > workflow > project > global > env > builtin`。管理面提供全局/项目变量 CRUD；画布提供工作流变量面板；所有允许文本输入的核心组件支持 `${scope.name}` 与 `$[时间表达式]`。交互必须包含补全、当前解析值、五类诊断码和敏感值保护。试运行与正式运行都保存不可变变量快照，后续变量修改不得改变既有运行记录。

### 3.5 依赖组件

依赖组件完整支持五类依赖、命名窗与 ISO 时间窗、检查周期、超时、结果极性、失败或等待策略、分钟到秒换算、组内/组间 AND/OR、三态求值以及整工作流/全部任务/单任务三种依赖目标。提供成功、失败、等待、超时、依赖失败仍允许执行等样例，并在 DAG 运行视图中展示每次判定依据。

### 3.6 流处理与实时观摩

流工作流覆盖生产、接收、过滤、转换、聚合、窗口、关联/融合和输出。内置可控数据生产器至少支持电商、物联网和访问流场景，并支持固定速率、随机、突发、重复、异常、延迟和乱序模式。观摩页面实时显示输入速率、处理速率、成功/失败数、延迟、窗口结果、检查点、错误与恢复事件，能够从输入事件追踪到聚合或融合输出，以证明处理正确性和有效性。

### 3.7 工作流运行结果统计

在 execution 域维护工作流级统计主表和可选任务/对账明细表，独立于日志表。每次正式运行和试运行都记录输入、目标、成功、失败、跳过等计数以及时间、工作流版本、实例、任务和尝试维度。写入必须幂等，重试按 attempt 区分，工作流汇总只消费最终有效尝试；流任务支持单调递增检查点。API 提供项目范围内列表和详情，运行监控页展示汇总、明细和失败定位。

## 4. 全前端完成设计

视觉基线取自旧版前端的顶栏、侧栏、内容区布局、间距、配色、字体层级、表格、抽屉、页签和画布风格；业务数据和旧服务层不复制。新前端统一使用共享设计令牌和页面骨架，避免每页自行定义视觉体系。

所有正式导航项必须具备：加载、空态、错误、无权限、成功反馈；查询、筛选、分页或树浏览；域契约允许的创建、编辑、删除、测试或执行操作；危险操作确认；深链接刷新不落首页。弹窗必须实现标题、字段、默认值、校验、提交、取消、关闭保护、服务端错误映射和成功后的列表刷新。没有后端能力的控件不得伪装为可用。

“全前端完成”不是只完成视觉设计、页面源码或静态渲染。每个正式页面及其全部可操作控件必须连接重构后端，并通过真实联调证明查询、展示、操作、回写、权限、错误反馈以及刷新/断线恢复能够正常稳健运行。仅 mock、契约测试或静态页面通过不能将功能标记为完成。

页面覆盖范围包括总览、项目、任务中心、数据源、资源、IDE、数仓建模、治理十三页、运行节点、集群监控、SSH、权限、访问审计、API、API-Key、LLM 配置和全局 AI 助手。已明确移除的脱敏规则不作为正式页面恢复。

## 5. 数据流和错误处理

浏览器请求统一经过单 BASE HTTP 层进入重构 API。认证、项目上下文和权限在调用前校验；后端使用领域服务和仓储访问数据库或运行适配器；执行事件和统计持久化后由运行监控读取。错误统一映射为稳定业务码，并保留字段级错误供表单定位。网络中断、SSE 重连、重复提交和运行重试均需幂等或可恢复，禁止静默吞错。

## 6. 实施顺序

1. 收拢健康基线：组件规格迁移、LLM 配对文件、三项后端失败和前端候选页面。
2. 核心运行闭环：execution 统计、DAG 工作台、核心 Palette 和样例框架。
3. 变量、SQL/Python/Shell、依赖组件与样例。
4. 同步工作流表单、物化执行与五类样例。
5. 流处理、生产器、聚合/融合和实时观摩。
6. IDE 只读与 DDL 写闭环补齐。
7. 全导航页面和全部交互控件补齐，统一旧版视觉。
8. API/API-Key、LLM、AI 助手和其余治理页面收口。
9. 在 `192.168.1.9` 完成部署、数据库迁移、中间件联调、Playwright 全链和增量 18 总验。

实施中允许按依赖调整相邻批次，但不得以实现容易为由缩减上述完成定义。

## 7. 验证设计

每项能力采用领域单元测试、前后端契约测试和组件/页面交互测试作为日常开发门禁。为避免重复部署拖慢收口，不为每个小功能单独执行 `192.168.1.9` E2E；九项最高优先级业务在形成完整业务闭环后执行阶段性真实 E2E，其余功能完成后统一纳入最终集成联调和全量 E2E。核心工作流样例必须验证持久化定义、真实执行结果、状态迁移、变量快照、运行统计和页面展示一致。远端验收使用隔离部署目录和短时认证信息，不把凭证写入源码、URL 或浏览器持久存储。

最终完成审计逐项核对权威设计功能表、WBS 增量 0–18 退出标准、用户九项最高优先级要求、菜单路由、所有正式页面和全部可操作控件；缺失、间接证据或仅静态存在均判为未完成。

## 8. 明确非目标

- 不恢复已移除的脱敏规则。
- 不把旧前端服务层或演示数据复制进新前端。
- 不为了数量扩充 Palette。
- 不用 mock、静态占位或历史验收记录替代当前真实闭环。
- 不在本机启动 Datara 服务、中间件或浏览器 E2E 环境。
