# DBX/海豚嵌入直连网关改造方案

## 目标

两个嵌入系统均为独立容器服务。Datara 只承担身份、项目范围和嵌入会话签发，不再逐路由代理其全部业务 API，避免单个慢请求阻塞主站。

## 现状问题

- `ide_proxy.py` 在异步请求中同步调用上游接口，DBX 慢请求会拖死整个 API 事件循环。
- liveness、连接列表、变量补全、编排会话共享同一网关资源，异常会扩散为白屏和全站菜单无响应。
- nginx 反代与容器重启后的地址解析耦合，容易产生短时 502。

## 目标架构

```text
浏览器
  ├─ Datara API：登录、项目权限、短时嵌入令牌
  ├─ /ide/*：同源反代 DBX 容器（不经过 Datara 业务事件循环）
  └─ /dolphinscheduler/*：同源反代海豚容器

DBX/海豚容器：验证短时令牌 + X-Datara-User + project_id，自行执行业务权限过滤
```

## 实施规则

1. 新增统一 `POST /api/v1/rebuild/embed/session`，签发短时、单项目、单应用令牌；令牌不进入 URL、localStorage 或静态资源。
2. nginx 仅负责同源反代、超时、SSE 透传和必要的服务端令牌注入；禁止把 DBX/海豚业务请求回送 Datara API。
3. DBX 仅保留少数安全改造：连接列表、连接保存、查询执行按 `project_id/user_id` 过滤；其余原生 API 直通。
4. 海豚仅在入口拦截器解析嵌入令牌并建立会话；DAG、节点、运行、变量 API 走原生服务。
5. 两个嵌入系统分别设置连接池、读取超时和熔断；任一系统异常只显示 iframe 内重试态，不改变 Datara 路由状态。
6. 取消 `ide_proxy.py` 逐路由扩展；迁移完成后删除其业务转发代码，仅保留兼容期 410/重定向和审计记录。

## 切换步骤

### 阶段 A：旁路验证

- 新增 `/embed/session` 契约和 nginx 旁路 location；旧 `/ide/api/*` 保持可回退。
- 浏览器验证 DBX 静态资源、连接列表、保存、查询、SSE；海豚画布、节点保存、运行。

### 阶段 B：默认切换

- `/ide/` 与 `/dolphinscheduler/` 默认直连容器；只允许同源入口访问。
- 令牌过期、项目切换、用户切换均重新签发，不复用旧 iframe 会话。

### 阶段 C：下线旧代理

- 删除逐路由 DBX 业务代理和同步上游调用。
- 保留 7 天兼容观测，确认无 `/api/v1/rebuild/dbx/ide-proxy/*` 请求后移除。

## 验收

- DBX 容器停止时，Datara 首页、项目、用户、任务编排菜单仍可用。
- 海豚容器停止时，DBX IDE 和 Datara 菜单仍可用。
- 刷新任一嵌入页只影响对应 iframe，不出现整页白屏。
- 无权限用户得到空数据/明确操作提示，不得泄露其他项目连接。
- SSE 不占用 Datara API 事件循环；持续 10 分钟刷新和切换项目无 502/499 风暴。
