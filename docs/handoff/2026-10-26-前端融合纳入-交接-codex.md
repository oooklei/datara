### 3.2 四条不可打破的现存守卫

**(a) `workflowGraphWorkbench.layout.contract.test.ts`（已跟踪，当前 GREEN，源码文本断言）**

合并后源码必须**逐字**保留以下字面量：

```

.wf-flow { ... flex: 1 ... min-height: 0 ... }

@click="onAddNode(component)"
label: `${n.nodeCode} ${n.nodeType}...
@node-click="onNodeClick"
if (type === 'sql') return 'sql'
if (type === 'python' || type === 'shell') return 'script'
type === 'sql' || type === 'python' || type === 'shell' ? type : null
v-if="projectId !== undefined && scriptResourceKind"
:kind="scriptResourceKind"
nodeType ?? '').toLowerCase() === 'dependent'
v-if="selectedNodeRecord && isDependentNode && projectId !== undefined"
```

**(b) `services/rebuild/__tests__/workflowApi.contract.test.ts` L122-126（冻结）**

```ts
expect([...WF_NODE_TYPES]).toEqual(['sql','python','shell','dependent'])
expect(WF_NODE_TYPES).toHaveLength(4)
```

→ `WF_NODE_TYPES` **保持 4 项不动**。L12-02 测试里的 13 项来自它对 `workflowApi` 的全量 mock（`WF_NODE_TYPES_MOCK`），不是真实导出。

**(c) 托盘既要 13 又要 `availableComponents` 字面量** —— 解法：

```ts
// 托盘派生自 WF_NODE_TYPES：生产 4 项 / 测试 mock 下 13 项
const availableComponents = computed(() =>
  WF_NODE_TYPES.map((t) => ({ type: t, displayName: specNameOf(t) })),
)
function onAddNode(component: { type: string; displayName?: string }) { /* 用 component.type */ }
```

模板保持 `v-for="component in availableComponents"` + `@click="onAddNode(component)"` + 文本 `{{ component.displayName ?? component.type }}`。
→ 同时满足 layout 契约（字面量）与 L12-02 用例 1（`.wf-type` 13 个）。

**(d) 样式必须改回 `flex: 1 1 0`** —— stash2 写的是 `flex: 1`，会打破 (a)。
