# Datara 组件开发规范

> 本文是组件声明、工作台交互和运行时执行之间的交付契约。组件生命周期、权限与发布闸门以《组件管理与发布治理设计》为准。

## 1. 声明优先

组件规格必须是纯 JSON 数据。不能在 `spec` 中放入函数、脚本片段或前端回调；动态行为通过 `conditions`、`behaviors` 与 `extensions` 声明。已发布版本不可变，工作流节点通过 `componentRef: { type, version }` 固定消费版本。

选择字段控件时，优先使用与数据类型相符的 `uiType`；`required` 只用于运行前必须由用户或默认值提供的输入。输出使用 `outputs` 明确声明名称、类型和说明，避免依赖节点私有实现。

## 2. Behaviors

`behaviors` 只描述可预测的表单交互：

- `onChange`: `refreshOptions`、`resetFields` 或 `prefill`；目标字段放在 `target`。
- `prefillFromUpstream`: 仅允许 `input.table`、`input.columns`、`input.datasource` 三种上游来源。
- `pick`: 仅允许 `table`、`column`、`cron`、`sshHost`。

条件隐藏与清空应由 `conditions` 驱动；旧 profile 中的函数式 `showIf`、`onChange` 仅为存量兼容，不应为新组件增加。

## 3. Hidden inputs

`extensions.hiddenInputs` 可声明 `runId`、`nodeId`、`workflowId`、`tenantId`。这些值不是用户表单字段，也不会写入节点 `param`。

运行时仅从节点 `componentRef` 指定的不可变版本读取声明，并通过 `TaskContext.hidden_inputs` 交给执行器。系统只能注入有可信来源的键；当前实例模型未提供租户身份，因此声明 `tenantId` 不会生成伪造值。执行器不得把 hidden input 回写到用户参数、日志或可见输出。

## 4. 发布前自检

1. 规格能通过纯数据校验，字段键唯一。
2. 每个 behavior 的字段与 target 都存在，枚举值合法。
3. `hiddenInputs` 只使用白名单键；执行器只读取所需键。
4. 发布前检查 componentRef、端口、输出与执行器是否一致。
5. 在 192.168.1.9 的容器中运行相关 pytest/Vitest 和构建；本机结果不替代运行验证。
